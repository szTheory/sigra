# Requirements Archive: Sigra v1.27 — ENT-SSO

**Defined:** 2026-05-25
**Shipped:** 2026-05-26
**Archive Status:** All requirements satisfied and reconciled against summaries, retroactive verification artifacts, normalized validation records, and the passing milestone audit.

**Core Value:** Authentication that works out of the box with great DX on the happy path AND on the rough edges — so developers can ship SaaS apps fast and grow with confidence.

## v1.27 Requirements (all complete)

### Enterprise connection model

- [x] **SSO-01** *(Phase 122)* — Organization admins can configure an enterprise OIDC connection for their organization using validated discovery and client settings.
- [x] **SSO-02** *(Phase 122)* — Sigra refuses to activate an unusable enterprise connection and exposes setup truth clearly enough that operators do not need to reverse-engineer callback failures.

### Enterprise routing and login

- [x] **SSO-03** *(Phase 123)* — Users can enter enterprise login through an org-aware entry path that resolves the correct organization connection by explicit org route or verified email-domain discovery.
- [x] **SSO-04** *(Phase 124)* — Successful enterprise login signs the user into the correct organization and preserves Sigra's existing session and audit truth.

### JIT provisioning and reconciliation

- [x] **JIT-01** *(Phase 124)* — Enterprise login can provision or reconcile organization membership just in time without bypassing the existing org invariants.
- [x] **JIT-02** *(Phase 124)* — Ambiguous enterprise identity matches fail safely instead of silently linking the wrong account.

### Enforcement and operator truth

- [x] **ENF-01** *(Phase 125)* — Organizations can require SSO for members while preserving explicit break-glass exemptions for allowed users.
- [x] **OPS-01** *(Phase 126)* — Generated-host proof, diagnostics, and docs make the bounded enterprise SSO contract legible for adopters and operators.

## Requirement Outcomes

The v1.27 contract held without widening the milestone:

- **SSO-01** and **SSO-02** shipped in Phase 122 by creating an organization-bound enterprise connection subsystem with explicit `draft`, `validation_failed`, `active`, and `disabled` lifecycle truth.
- **SSO-03** shipped in Phase 123 by adding canonical org-scoped enterprise entry, exact-match bounded discovery, signed callback context, and installer/example parity for the generated-host routing surface.
- **SSO-04**, **JIT-01**, and **JIT-02** shipped in Phase 124 by reusing existing org, membership, invitation, and identity substrate for enterprise reconciliation instead of inventing enterprise-only write paths.
- **ENF-01** shipped in Phase 125 by adding an explicit org-owned auth policy plus break-glass exemptions and enforcing denial before any normal password-login success path can complete.
- **OPS-01** shipped in Phase 126 by closing the milestone with one bounded generated-host/example proof package, installer parity, canonical operator docs, and a clear `Proved / Did Not Prove` boundary.

## Future Requirements (carried forward)

## Out of Scope (final)

| Feature | Reason |
|---------|--------|
| Full SCIM / directory sync | Higher breadth and proof burden than the current org-login wedge; explicitly deferred until enterprise login truth is fully established. |
| Hosted control plane / Admin Portal equivalent | Outside Sigra's library boundary; generated-host and docs remain the primary operator surface. |
| Opinionated authorization / role engine | Sigra continues to provide identity and seams, not product-specific access policy. |
| Broad company-directory lifecycle automation unrelated to login | The milestone stayed anchored to enterprise authentication and org membership truth. |
