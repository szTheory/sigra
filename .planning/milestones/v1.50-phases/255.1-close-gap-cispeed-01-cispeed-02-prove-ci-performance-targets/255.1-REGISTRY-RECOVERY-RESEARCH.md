This changes the registry dependency without adding credentials, actions, packages, or an operated mirror. GitHub's current documentation says GitHub-hosted runners are exempt from Docker Hub pull limits under the GitHub/Docker agreement. This is a reason to prefer the native upstream registry here, not a promise of availability; it does not extend that exemption to local or self-hosted machines. [GitHub container-image documentation](https://docs.github.com/en/actions/how-tos/write-workflows/choose-where-workflows-run/run-jobs-in-a-container#defining-the-container-image)

Keep the same database major version, environment, port mappings, health checks, workload, and required check names. Do not add fallbacks that silently run tests without PostgreSQL. The phase's frozen source identities cannot silently inherit this amendment: apply it symmetrically to any future control/candidate comparison and freeze their new identities before collection. Old source records and spent budgets remain closed.

## What failed, and what we can actually prove

The four attempt-2 initialization failures repeatedly show `docker pull public.ecr.aws/docker/library/postgres:15`, followed by `toomanyrequests: Data limit exceeded`. An example is `diagnostic-ci-retry/failed-logs/121945436541.log:52–60`. Checkout and application tests had not begun. Follow-on missing-directory messages come from diagnostics running after initialization failed, not from executed application assertions.

AWS documents two distinct constraints: an unadjustable 500 GB/month data allowance for unauthenticated ECR Public consumers and a default unauthenticated pull rate of one per second. The error's reference to data is consistent with data-transfer exhaustion, rather than merely request pacing. The retained log does not identify the quota bucket, source IP's aggregate usage, actual HTTP status, or reset time, so that interpretation remains an inference. These records do not prove that this repository alone consumed an allowance. [AWS ECR Public quotas](https://docs.aws.amazon.com/AmazonECR/latest/public/public-service-quotas.html)

Authenticated ECR Public users have a separate 5 TB/month free Internet-transfer allowance, after which transfer can incur charges. Authentication moves the accounting and increases capacity; it does not eliminate every failure or spending limit. [AWS ECR pricing](https://aws.amazon.com/ecr/pricing/)

GitHub's REST request budget is independent of a Docker pull from AWS. More GitHub API headroom cannot fix this registry response. Similarly, a local successful pull would not prove the future hosted runner's registry access.

## Alternatives and tradeoffs

| Option | Advantages | Costs and failure modes | Decision |
|---|---|---|---|
| Retry unchanged anonymous ECR source | No source amendment | Two attempts already show the same image failure; runner-level retries also failed. A new full retry supplies little new information. | Reject as the next action. |
| Official Docker Hub image, fixed digest | Minimal source change; no new account or dependency; matches documented hosted-runner integration | Upstream availability remains external; artifact identity and platform must be checked | Preferred. |
| Authenticate to ECR Public | Retains host; separates account allowance from anonymous allowance | AWS IAM trust, token renewal, service-start ordering, possible transfer charges, and fork restrictions | Reserve for a genuine ECR requirement. |
| Maintain a public GHCR mirror | Public GHCR images can be pulled anonymously; ownership can improve control | Adds publishing authority, provenance checks, synchronization/security updates, storage and ongoing operations | Disproportionate for this incident. [GHCR documentation](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-container-registry#about-the-container-registry) |
| Serialize jobs or add delays | Can reduce request-rate pressure | Does not establish a monthly data allowance has reset; increases CI latency | Wrong first remedy for this error. |
| Install host PostgreSQL instead | Avoids service-image pull | Changes initialization, package sources, isolation and workload comparability | Avoid during this performance experiment. |

## Authentication and reproducibility footguns

- A normal first-step `docker login` is too late for a declared service container. The Actions runner queues container initialization before the workflow's main action steps. It already retries a failed pull up to three times. [Runner initialization source](https://github.com/actions/runner/blob/main/src/Runner.Worker/JobExtension.cs), [container-operation source](https://github.com/actions/runner/blob/main/src/Runner.Worker/ContainerOperationProvider.cs)
- If registry authentication is required, use the service's `credentials` map available at initialization, not an ordinary later step. [GitHub service authentication](https://docs.github.com/en/actions/tutorials/use-containerized-services/use-docker-service-containers#authenticating-with-image-registries)
- ECR Public Docker authentication uses a 12-hour token obtained in `us-east-1`. The token operation requires `ecr-public:GetAuthorizationToken` and `sts:GetServiceBearerToken`. A stored token is not a durable CI credential; adding safe refresh before service initialization is extra design work. [AWS registry authentication](https://docs.aws.amazon.com/AmazonECR/latest/public/public-registry-auth.html), [AWS token API](https://docs.aws.amazon.com/AmazonECRPublic/latest/APIReference/API_GetAuthorizationToken.html)
- Do not grant untrusted PR code privileged cloud credentials or use `pull_request_target` merely to make registry login easier. Restrict any necessary credentials and workflow-token permissions. [GitHub secure workflow guidance](https://docs.github.com/en/actions/reference/security/secure-use#mitigating-the-risks-of-untrusted-code-checkout)
- A mutable `:15` tag can change between runs. Pinning a verified digest fixes image content; maintain a deliberate update path because digest pinning also stops automatic security updates. Distinguish a multi-platform index digest from the Linux platform manifest/config/layers used by the runner. A same tag across registries does not by itself establish equal bytes. [Docker pull-by-digest documentation](https://docs.docker.com/reference/cli/docker/image/pull/#pull-an-image-by-digest-immutable-identifier)
