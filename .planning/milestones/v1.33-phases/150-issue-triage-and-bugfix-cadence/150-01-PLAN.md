<objective>
Establish a repeatable process for monitoring adopter feedback, diagnosing friction, and patching bugs. Document the process for distributing generated-host template updates via `mix sigra.upgrade`.
Purpose: Transition Sigra into a stable post-1.0 maintenance posture with clear maintainer and adopter expectations.
Output: Updated MAINTAINING.md, updated CHANGELOG.md, and a new 150-VERIFICATION.md file.
</objective>

<task type="auto">
  <name>Task 1: Formalize Issue Triage Cadence in MAINTAINING.md</name>
  <files>MAINTAINING.md, .github/ISSUE_TEMPLATE/bug_report.md</files>
  <action>
    Add a new section `## Issue Triage & Bugfix Cadence` to `MAINTAINING.md` (e.g., above the `## Milestone cadence and pause (v1.11+)` section).
    Outline the following processes:
    1. **Monitor:** Check GitHub issues (`gh issue list`) weekly.
    2. **Categorize:** Label issues as `bug` (core logic), `friction` (DX/documentation), or `enhancement` (feature request).
    3. **Prioritize:** Address `bug` and `friction` items in the next patch release. Defer `enhancement` items. Reference the severity classes (P0-P3) from `docs/release-runbook-v1-0.md`.
    4. **Communication Posture:** Keep updates factual and version-specific. State impact, workaround status, and next decision checkpoint. Avoid implying unsupported guarantees beyond documented release evidence.
    5. **Template Updates:** Explicitly state the maintainer rule: Whenever generator templates are touched, the maintainer MUST list `mix sigra.upgrade --yes` under a "Template Updates Required" header in `CHANGELOG.md`.

    Also, check if `.github/ISSUE_TEMPLATE/bug_report.md` exists and update it to require minimum evidence: Repro command/ref, failing run URL/log, affected version, and workaround status. Create it if it doesn't exist.
  </action>
  <verify>
    <automated>grep -c "Issue Triage & Bugfix Cadence" MAINTAINING.md</automated>
  </verify>
  <done>MAINTAINING.md contains the triage cadence, template update rules, and communication posture. Bug report template is verified.</done>
</task>
