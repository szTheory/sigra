# Milestone v1.26: PK-LIFECYCLE

**Status:** ✅ SHIPPED 2026-05-25
**Phases:** 115–121
**Total Plans:** 9

## Overview

v1.26 closes the remaining trust and proof gaps around Sigra's already-shipped passkey substrate. The milestone did not invent a new passkey product layer; it made the existing lifecycle surfaces operationally honest by tightening last-passkey deletion posture, preserving real fallback guidance in passkey-primary flows, clarifying cross-device and RP-ID/origin migration limits, and proving those claims through authoritative repaired-form verification artifacts.

The milestone ran in two legs:

- **Leg 1 — lifecycle truth and generated-host proof** (Phases **115–118**) — ship the last-passkey safety posture, recovery-first bootstrap flow, cross-device/RP-ID trust rails, and a bounded generated-host/browser proof.
- **Leg 2 — repaired-form backfill and Nyquist closure** (Phases **119–121**) — restore authoritative proof homes on the original implementation phases, reconcile the active truth surfaces, and close the remaining validation debt so the milestone can pass re-audit cleanly.

## Milestone Summary

**Decimal Phases:** None.

**Key accomplishments:**

1. Sigra now distinguishes ordinary passkey deletion from final-passkey deletion through a library-owned `delete_with_posture/4` seam and generated-host copy that stays explicit about fallback without implying Sigra-owned recovery.
2. Passkey-primary login, signup follow-through, and enrollment now keep real fallback and bootstrap guidance visible instead of dropping users into passkey-only dead ends.
3. Cross-device and RP-ID/origin migration truth is now settled across docs, runtime advisories, and generated-host copy without inventing a hosted sync or migration abstraction.
4. The canonical generated-host/browser proof now covers the bounded lifecycle claims, and the passkey settings/runtime boundary was repaired so real browser-created credential IDs work end to end.
5. `PK-02` and `PK-03` now resolve to authoritative repaired-form proof homes on Phases 115 and 116 rather than stale implementation summaries.
6. Phase 121 closed the remaining Nyquist and milestone-truth debt, allowing the re-audit to pass with no unresolved requirement, integration, or validation blockers.
