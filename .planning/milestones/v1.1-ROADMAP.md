# Milestone v1.1: Foundations

**Status:** SHIPPED 2026-04-16
**Phases:** 11-23
**Total Plans:** 68
**Closeout:** Phase 26 verification closeout completed 2026-04-16

## Overview

v1.1 Foundations shipped the two architectural pillars that the original roadmap reserved for the next major growth step: logical multi-tenancy through organizations and memberships, and passkey/WebAuthn authentication. The milestone also hardened the generator feature-manifest pattern introduced in Phase 11, extended audit and scope foundations so tenant-aware and passkey-aware flows compose cleanly, and closed the docs, testing-helper, browser-smoke, and upgrade-story gaps needed to make the release auditable and shippable.

## Phase Summary

- **Phase 11: Generator Feature System** — established the `core/` feature-manifest architecture that made organizations and passkeys additive generator features.
- **Phase 12: Scope + Session Foundation** — extended `%Scope{}` and `user_sessions` for active-organization state and future impersonation compatibility.
- **Phase 13: Organizations Schemas + Context** — shipped `Organization`, `OrganizationMembership`, `OrganizationInvitation`, last-owner protection, slug safety, and tenant query discipline.
- **Phase 14: Org Plugs + Scope Hydration** — hydrated org scope consistently across Plug and LiveView with stale-pointer handling.
- **Phase 15: Audit Integration** — moved tenant and effective-user context into real indexed audit columns and added worker context support.
- **Phase 16: Org LiveViews + Switcher** — shipped the end-user organization UX: switcher, org creation, settings, members, and zero/one/many-org login handling.
- **Phase 17: Invitation Flow + Email** — shipped replay-safe, email-bound organization invites with mismatch protection and revoke flow hardening.
- **Phase 18: Backfill + `--organizations` Generator Wiring** — shipped v1.0 -> v1.1 upgrade/backfill support and the organizations opt-out generator path.
- **Phase 19: Passkey Schema + Contexts** — shipped the passkey data layer, sign-count policy, credential-confusion defense, and encrypted key storage.
- **Phase 20: Passkey Challenge Plug + Runtime Config + JS Hooks Infra** — shipped server-owned challenge handling, runtime passkey config, throttling, and generated JS hook infrastructure.
- **Phase 21: Passkey LiveViews + POST-Auth Controller** — shipped passkey enrollment, passkey MFA, optional passkey-primary login, recovery invariants, and real browser/runtime proof.
- **Phase 22: `--passkeys` Generator Wiring** — shipped default-on passkeys plus clean `--no-passkeys` omission across generator and CI matrix coverage.
- **Phase 23: Docs, CI Smoke, Upgrade Guide** — shipped the v1.1 guide set, testing helpers, Playwright smoke coverage, and DX-09 enforcement outcome.

## Key Accomplishments

1. **Feature-manifest generator architecture proved out in production** — v1.1 shipped both organizations and passkeys as real additive features rather than special-case branches, validating the Phase 11 design for future milestones.
2. **Logical multi-tenancy shipped end to end** — org schemas, memberships, invites, scoped queries, session-backed active organization, switcher UX, settings, members, and invite acceptance now work as one coherent system.
3. **Passkeys shipped across data layer, runtime, UI, and generator** — Sigra now supports passkey enrollment, passkey MFA, optional passkey-primary login, challenge verification, and clean install opt-out with current verification coverage.
4. **Audit and scope foundations now support tenant-aware future work** — `organization_id`, `effective_user_id`, scope hydration, and worker context make v1.2 admin/audit work incremental instead of retrofits.
5. **Upgrade and install stories are exercised, not just documented** — organizations backfill, passkey generator wiring, install matrix coverage, and the guide set are all anchored in current test and smoke evidence.
6. **Release documentation and verification debt were fully closed** — the missing Phase 18/19/22/23 verification artifacts were written in Phase 26, making all 79 v1.1 requirements verification-backed.
