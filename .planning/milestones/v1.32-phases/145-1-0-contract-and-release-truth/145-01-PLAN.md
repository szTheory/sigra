<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internal planning labels -> public package version | Readers may mistake GSD milestone `v1.x` labels for installable Hex versions. |
| Library-owned code -> generated host code | Sigra ships library fixes, but host-owned generated code and product policy remain under the adopter's control. |
| Security invariant -> host deployment | Sigra can guarantee library behavior and generated patterns, not adopter TLS, mail deliverability, compliance, or authorization policy. |
| Contract docs -> release automation | Phase 146 release gates rely on Phase 145 docs/config being unambiguous. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-145-01 | Spoofing | Public version-axis messaging | mitigate | README, CHANGELOG, and contract page must all state planning milestones versus installable Hex SemVer. |
| T-145-02 | Information Disclosure | Ownership boundary docs | mitigate | Contract page must identify generated-host-owned code and host-owned policy so adopters do not disclose or delegate responsibility incorrectly. |
| T-145-03 | Elevation of Privilege | Security claims | mitigate | SECURITY.md must state authorization/business policy is host-owned and Sigra does not provide an opinionated authorization engine. |
| T-145-04 | Repudiation | Release contract | mitigate | Source assertions require contract page, README, CHANGELOG, and ExDoc extras to contain the 1.0 contract and version-axis truth. |

## ASVS Notes

ASVS Level 1 posture applies. This plan changes documentation only, but the security documentation must preserve existing auth/session/token/MFA/audit boundaries and must not claim host deployment compliance.
</threat_model>
