## Verification Structure

Phases 224–228 deliberately carry **no** `*-VERIFICATION.md`. Phase 229 is the milestone's
*Terminal Ratification* phase and its verification table spans every requirement in the
milestone. This is why the close reads `override_closeout` rather than
`verified_closeout` — the readiness projection expects a per-phase verification file and
finds five "missing", which is structural rather than a real coverage gap.

Worth reconsidering for future milestones: the terminal-ratification pattern concentrates
all verification in one place, which is coherent to read but makes automated readiness
checks report a false negative every time.

## Decisions

- Auth surfaces get a bounded semantic `sigra-auth-*` vocabulary with stable
  `--sigra-auth-*` tokens; DaisyUI-shaped selectors survive only as scoped compatibility
  bridges. Three CSS lanes stay separate: `sigra-auth-*` (generated, host-owned), `sg-*`
  (admin, library-owned), `vt-*` (Tasklane demo).
- First-admin bootstrapping is a *persisted grant* generated into the host app, not a
  first-user or email-domain inference. `mix sigra.admin.{grant,revoke,list,check}` is the
  explicit, repeat-safe path; no password handling.
- Customized policies are never overwritten — adopters get an additive opt-in
  migration/delegation recipe plus generated allow/deny policy tests.
- Audit filter presets (Failures, Impersonation) are GET routes with shareable URLs rather
  than LiveView events, so operator state is linkable.
- Human visual acceptance was reserved for exactly one thing — the login composition's
  hierarchy and taste. Every other clause of PROOF-03 was machine-gated.

## Issues Encountered

- **A superseded capture set nearly produced a false finding.** During PROOF-03 review, two
  Playwright output directories existed two minutes apart; the older one showed flat submit
  buttons. The action hierarchy was in fact correct in the post-CSS-specificity-correction
  run. Lesson: when reviewing run artifacts, establish which run is authoritative *before*
  reading the images.
- **A two-branch conditional was half-fixed.** The duplicate-`Email`-label fix (PR #113)
  changed the no-passkeys branch; the passkey-primary branch has the same collision and was
  missed until the milestone audit caught it. See W-1.
