<objective>
Centralize the Oban supervision guard into `Sigra.OptionalDeps.oban_running?/0` and fix the single
buggy site in `deletion.ex` that checks `oban_available?()` instead of `oban_running?()`. De-dupe the
private copy in `delivery.ex` and wire `forwarders.ex` to delegate to the SOT.

Purpose: A compiled-but-unsupervised host that calls `schedule_deletion/3` currently attempts a
`repo.insert` on the oban_jobs table that does not exist, producing a 42P01 crash caught by the rescue
block and logged as a warning. The fix closes that wasted-insert loop by checking supervision state
before the insert attempt.

Output: One new public function in `Sigra.OptionalDeps`; three call-site updates; one new regression
test case in `deletion_test.exs` proving the guard. D-01, D-02, D-03, D-04 resolved.

**Approach for the "compiled but not supervised" scenario:**

The standard ExUnit test environment does NOT supervise Oban (Process.whereis(Oban) returns nil
naturally in the test process). `Sigra.OptionalDeps.oban_available?()` returns true (Oban is compiled
as a dep). So this condition holds in the test environment without mocking.

The test therefore:
1. Verifies `Sigra.OptionalDeps.oban_available?() == true` (assert it's compiled)
2. Verifies `Process.whereis(Oban) == nil` (assert it's not supervised in test env)
3. Calls `Sigra.Account.Deletion.schedule_deletion(config, user, opts)` where opts include the
   host-context needed to pass the `Code.ensure_loaded?(Sigra.Workers.AccountDeletion)` check — pass
   a valid job context with a `repo` key. Follow the existing test setup pattern for this.

5. Asserts the user's `scheduled_deletion_at` is set

7. Asserts no oban_jobs table insert occurred — query `repo.all(Oban.Job)` where available, or
