**Create `scripts/ci/app-css-corruption-check.sh`:**

The guard must detect orphaned VALUE fragments inside the CSS `:root {}` block — specifically bare
multi-line CSS values with no property name. The target corruption patterns are:
- Lines starting with optional whitespace then digits followed by `0 0 1px rgba(` (bare shadow values)
- Lines starting with optional whitespace then `color var(--sg-` (bare transition values with sg ref)
- Lines starting with optional whitespace then `color-mix(in oklab, var(--sg-` (bare focus-ring value)
- Lines inside the dark-mode :root that are bare `* (~` comment fragment tails (orphaned close-comments
  that are themselves inside a larger block comment fragment)

The guard approach (simpler and more targeted than a generic unmatched-comment approach):

Use `awk` to track whether we are inside a `:root {` block (depth 1) and flag lines that match
the specific corruption signatures. Exit non-zero if any match found.

The script should:
1. Set `set -euo pipefail`
2. Accept the CSS file path as $1 (default: `test/example/priv/static/assets/css/app.css`)
3. Use `awk` to scan: when inside a top-level `:root {` block, look for lines that are bare numeric
   CSS values (not a CSS property declaration — no `--` prefix and no `property:` form). The simplest
   reliable check: look for lines matching `^\s+[0-9]` (bare numeric — shadow/transition value
   fragments with no property) OR `^\s+color var\(--sg-` (bare transition value with sg ref) OR
   `^\s+color-mix\(in oklab, var\(--sg-` inside `:root`. If any found, print the line and exit 1.
4. Print "OK: no orphaned value fragments in :root block" on success
5. Be idempotent (running on a clean file exits 0)

Make the script executable: `chmod +x scripts/ci/app-css-corruption-check.sh`.

**Wire into `.github/workflows/ci.yml`:**

Read the ci.yml to find the `fast_checks` job (or equivalent lint step). Add a step that runs
`bash scripts/ci/app-css-corruption-check.sh` (with the file path argument if needed). The step
name should be "Check app.css for orphaned corruption". Place it logically near other CSS/lint
checks or at the end of fast_checks steps.

The verification approach: boot the example app and use a Playwright snippet (or node --eval) to
load the page and check that `document.styleSheets` contains the CSS rules expected from the

resolves to a non-empty value.
