<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions job to repository token | Token permissions can mutate branches, PRs, actions, or issues. |
| Release runner to Hex.pm | Dry-run authentication and publication use distinct credentials and authority. |
| Workflow ref to environment secret | A manual dispatch can select untrusted workflow YAML; GitHub environment deployment policies must restrict secret-bearing jobs to main. |
| Concurrent workflow runs | A later event must not erase an active or only-pending release evaluation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-248-05 | Elevation of privilege | Release Please, merge, and publish jobs | high | mitigate | Use the dedicated release token only where event-causing PR operations require it; isolate read and write Hex keys by step and scope GITHUB_TOKEN permissions by job. |
| T-248-06 | Denial of service | release workflow concurrency | medium | mitigate | Use unique run and attempt groups with cancel-in-progress disabled so later main events cannot cancel or replace another release evaluation. |
| T-248-11 | Elevation of privilege | release-automation and hex-publish environments | high | mitigate | Require GitHub deployment branch policies containing exactly main, attach each credential-consuming job to its matching environment, and fail the live preflight on missing or broader policies. |
| T-248-SC | Tampering | package-manager installs | low | accept | No npm, pip, or cargo package installation task is introduced by this plan. |
</threat_model>
