# Phase 249 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| GitHub Actions artifact to release proof | Artifact bytes and nested diagnostic fields are untrusted. | JSON bytes, run/attempt identity, source SHA |
| GitHub, Hex, and HexDocs to release proof | Mutable service responses and redirects must resolve to the immutable release identity. | PR/run metadata, package metadata, effective URLs |
| Candidate source to documentation builder | Candidate Mix and documentation code runs without release-write authority. | Source and generated ExDoc output |
| Generated documentation to scoped writer | Build output is data; only the fixed index path and reviewed head may be updated. | One generated file, branch/head identity |
| Local worktrees and PR metadata to closeout ledger | Status bytes, paths, refs, and PR text can be incomplete or stale. | Raw porcelain status, path hashes, paginated PR identities |
| Closeout ledger to evidence refs | Captured identities can become stale between validation and write. | Canonical JSON bytes, object IDs, compare-and-swap ref updates |
| Protected main and Actions to final proof | Main, receipt, run, and job must describe the same final SHA. | Commit SHA, receipt blob, workflow run and ci-gate result |
