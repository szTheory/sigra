<objective>
Close the CR-01 (critical) determinism hole in the fix-queue builder. `scripts/ci/fix-queue-build.mjs`
selects the systemic-parent representative as `entries[0]` (line 264), where `entries` order is
seeded from unsorted `readdirSync` walks (lines 125/128/131). `readdirSync` order is
filesystem-dependent, so a systemic group's rep `finding_id` — and therefore the content and
`finding_id`-keyed ordering of the committed `guides/reference/fix-queue.json` — can differ between a
dev machine (APFS) and CI (ext4), producing spurious "diffs cleanly vs merge-base" gate failures.

Purpose: The fix-queue builder's contract is a deterministic committed artifact. This makes the
representative selection order-independent so the artifact is reproducible on any filesystem.
Output: Deterministic rep selection in fix-queue-build.mjs + a hermetic regression test proving it.

IMPORTANT — do NOT regenerate/commit `guides/reference/fix-queue.json` in this plan. The eval bundle
source dir `test/example/priv/playwright/eval/` is gitignored (.gitignore:59), so the committed
fix-queue.json is a hand-committed snapshot built from bundles that are NOT in the repo. Running the
live builder here would read an empty/partial eval dir and CLOBBER the 116-entry committed artifact.
The fix is forward-only: the next in-CI/full-harness regeneration (Phase 219) emits the deterministic
ordering. This plan proves determinism via the hermetic self-test only and leaves fix-queue.json
byte-unchanged.
</objective>
