## Cross-Phase Integration

**9 of 11 seams wired end-to-end.** Contributor required CI, docs-only classification,
cancellation ownership, PR/main/schedule gate honesty, Playwright economics, the protected
terminal evidence chain, and the contributor-parity `mix ci` alias are all live-verified.

### Broken seam 1 — Phase 233 -> Phase 234 (TEST-01/02/03)

Designed:

`timing receipt -> cost partition -> two ordinary shards + scaffold receiver -> Library tests aggregate -> ci-gate`

Actual at HEAD:

`library_tests_shard -> MIX_ENV=test mix ci -> Library tests aggregate -> ci-gate`

The current flow preserves correctness and the protected required context, but not
TEST-01/02/03's economics. What makes this worse than an ordinary regression is that the
guard was rewritten to bless it:
`phase_233_library_economics_contract_test.exs:19` now asserts exactly one
`MIX_ENV=test mix ci` in the shard, `refute body =~ "mix test"` for every library job, and
`refute workflow =~ "library_tests_scaffold:"`. The TEST-01/02/03 contract now *requires*
the replacement topology — which is why Phase 233 re-verified green against it.

### Broken seam 2 — Phase 232 composite action -> Phase 234 supply-chain guards

`.github/actions/example-playwright-boot/action.yml` pins four third-party actions by SHA,
but DX-01's guard scopes to `[release-please.yml, hex-publish.yml]` and DX-02's Dependabot
config scopes to `directory: "/"`. Neither reaches `.github/actions/**`. The action will
silently rot.
