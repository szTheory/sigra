<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| route param `:id` -> detail loader | Untrusted user identifiers drive detail queries and mutations |
| LiveView session actions -> Sigra.Auth APIs | Admin-triggered revoke events cross from UI into security-sensitive session operations |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-28-07 | Elevation of Privilege | `lib/sigra/admin/users/detail.ex` | mitigate | Load the target user through the same scope-safe path as the list and authorize organization access before exposing detail data. |
| T-28-08 | Tampering | `lib/sigra/admin/users/actions.ex` | mitigate | Route revoke-one and revoke-all through `Sigra.Auth` APIs only; never delete session rows directly from admin code. |
| T-28-09 | Repudiation | Session revoke workflows | mitigate | Reuse canonical Sigra revoke functions so audit emission remains centralized and test it directly in `test/sigra/admin/users_actions_test.exs`. |
</threat_model>
