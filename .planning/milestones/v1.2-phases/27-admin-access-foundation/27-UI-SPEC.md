## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, inline separators |
| sm | 8px | Compact row spacing, chip gaps, grouped controls |
| md | 16px | Default card padding, form spacing, shell gutters |
| lg | 24px | Section padding, page-header spacing, sidebar groups |
| xl | 32px | Shell offsets, page-level gaps between major blocks |
| 2xl | 48px | Sticky scope bar height and major section padding |
| 3xl | 64px | Desktop page top/bottom breathing room |

Exceptions: 44px minimum tap target for mobile bottom-nav items, scope switch trigger, drawer actions, and other icon-first controls.

## Color

Use existing daisyUI theme tokens instead of introducing new admin-only colors.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--color-base-100)` `oklch(98% 0 0)` | App background, page body, main content surfaces |
| Secondary (30%) | `var(--color-base-200)` `oklch(96% 0.001 286.375)` | Sticky scope bar fill, sidebar, bottom nav, cards, grouped filters |
| Accent (10%) | `var(--color-primary)` `oklch(70% 0.213 47.604)` | Primary CTA, active nav item, active scope chip, selected org indicator, owner/platform-admin emphasis |
| Destructive | `var(--color-error)` `oklch(58% 0.253 17.585)` | Destructive confirmations and denial/error states only |

Accent reserved for: primary entry actions (`Open admin`, `Switch scope`), active scope badge, active navigation state, owner/platform-admin badges, and focus-visible emphasis on scope-changing controls. Do not use accent for every link, every button variant, or neutral metadata badges.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Open admin |
| Empty state heading | No admin destination available |
| Empty state body | This account does not have a global admin view or an organization admin scope to open yet. Ask a platform admin to grant access or open an allowed organization URL. |
| Error state | You do not have access to this admin scope. Return to an allowed organization scope or contact a platform admin. |
| Destructive confirmation | None in Phase 27. If an implementation adds a destructive action, require scope name in the dialog body and a two-button confirmation row with the destructive action on the right. |

Additional copy rules for this phase:
- Persistent scope bar label is always `Admin`.
- Scope text is always one of `Global` or the active organization name.
- Denied states must name the scope problem directly; never imply the issue is a missing UI refresh.
- Page headers describe the current page or task and must not repeat the scope label as the only context cue.

## Interaction Contract

### Shell

- Use the existing Phoenix app shell conventions and extend them into an admin shell rather than replacing them with a separate frontend.
- The admin shell is a hybrid pattern from context decision `D-16`: sticky top scope bar plus conventional navigation.
- On first load, the sticky scope bar is the primary visual anchor and the page header is the secondary hierarchy cue for the current task or destination.
- The sticky scope bar stays visible on every admin page and contains, in this order: `Admin` label, active scope chip, optional special-session chip, and scope switch affordance when switching is permitted.
- Desktop navigation uses a grouped sidebar for durable wayfinding.
- Mobile navigation uses a bottom nav with 3-5 top destinations and a secondary drawer/menu for lower-frequency destinations.
- Do not ship hamburger-only navigation on mobile.

### Scope visibility

- The active scope must be visible without scrolling and without opening a menu.
- Global scope and organization scope must render with visibly different chips or badges, not just different text.
- When a platform admin intentionally enters an organization scope, the shell still shows that they are in admin mode and that the page is constrained to one organization.
- Any special session state that changes action meaning must appear in the sticky scope bar as a separate chip, never only inside flash text.

### Route and state behavior

- `/admin` is the global entry point.
- `/admin/organizations/:org` is the organization-scoped entry point.
- URL scope is the source of truth for authorization and for what the chrome displays.
- Session memory may restore the last visited admin org only as a redirect convenience after access has already been revalidated server-side.
- Org-admin users do not see cross-org affordances in the shell.
- Platform admins may see cross-org affordances, but cross-org entry points must look intentional rather than ambient.

### Authorization feedback

- Unauthorized admin states render as access-denied responses, not hidden controls plus a blank page.
- Do not use flash alone for authorization denial; the page or redirect target must also make the denial legible.
- Empty states are for valid-but-unconfigured states. Denied states are for invalid scope access.

### Forms, menus, and dialogs

- Reuse existing daisyUI primitives already present in the app: `btn`, `badge`, `menu`, `dropdown`, `alert`, and native `dialog.modal` patterns.
- Scope-switch actions that change request context use explicit POST-backed controls or server-side validated LiveView events, matching existing sensitive-action conventions.
- Any future destructive confirmation introduced inside this phase must follow the established modal pattern: concise reason text, scope callout above actions, secondary cancel button, destructive confirm button.

## Component Inventory

Implement or extend only the components this phase needs:

| Component | Contract |
|-----------|----------|
| Admin scope bar | Sticky, 48px minimum height, always visible, shows `Admin` + active scope + session-state chips + switch affordance |
| Admin sidebar | Desktop-only persistent nav with grouped sections and active-item styling |
| Admin bottom nav | Mobile-only primary nav with 3-5 items and 44px minimum tap targets |
| Admin overflow drawer/menu | Mobile secondary destinations and low-frequency links |
| Scope chip | Compact badge distinguishing `Global` vs org-scoped context |
| Access-denied state | Full-page state with direct explanation and recovery action |
| Admin empty state | Full-page state for valid admin user with no accessible destination |

Do not introduce data tables, analytics panels, or broad dashboard widgets in Phase 27. This phase establishes shell, scope, and access contracts only.
