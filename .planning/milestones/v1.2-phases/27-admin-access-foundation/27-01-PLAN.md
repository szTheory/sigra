<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| installer CLI -> generated host files | Untrusted option parsing decides whether admin code exists at all |
| generated host policy -> library runtime | Host policy decides who is admin; library must not invent fallback access |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-01 | E | `mix sigra.install` admin toggle | mitigate | Default `admin: true`, explicit `--no-admin`, and manifest tests stop accidental omission of admin scaffolding. |
| T-27-02 | E | generated `sigra_admin_policy.ex` | mitigate | Generate only explicit `platform_admin?/1` and `admin_org_ids/1` callbacks per D-05 through D-09; no signup-order, email-domain, or first-user fallback code. |
| T-27-03 | T | router injection | mitigate | Router fragment uses normal scopes and `live_session` instead of `forward`, preserving LiveView auth boundaries documented in 27-RESEARCH. |
| T-27-04 | R | feature ownership | mitigate | Coverage and feature tests pin every admin template to `Sigra.Install.Features.Admin` so later edits cannot silently move security-sensitive files into unrelated features. |
</threat_model>
