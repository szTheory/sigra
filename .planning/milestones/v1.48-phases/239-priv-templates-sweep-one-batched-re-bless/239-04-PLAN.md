## Exit semantics that must be asserted literally, not paraphrased

`--check` writes to a tmp dir, runs `diff -qr` against the committed tree **and** a byte equality on
`STDOUT.txt`, then either prints `OK: fixture is up-to-date (check mode).` and returns `:ok`, or
prints `DRIFT DETECTED:` and calls `exit({:shutdown, 2})` (`rebless_golden.ex:115-140`). So exit 0
means no drift and exit 2 means drift — and because `STDOUT.txt` is compared separately by byte
equality on its own line, `--check` exit 0 independently covers the D-13 hazard.

`STDOUT.txt` carries **zero** union-token lines at HEAD, so its expected diff is empty and the D-13
independent-drift risk is measured-nil for this phase. Check it separately anyway: if it *does*
change, a swept comment leaked into installer summary output, which means the sweep touched something
the installer prints. Stop-the-line.

No DB is needed for the re-bless itself — `InstallFixture.setup_tmp_app/1` uses
`mix phx.new --no-assets --no-install` under an isolated `MIX_ARCHIVES`/`MIX_HOME`
(`test/support/install_fixture.ex:15-27`). Postgres **is** needed for the other five members of
`ci.install_golden` (`mix.exs:161-163`) and for `install-smoke.sh` (`:23-26`). The **phx_new 1.8.8**
archive is required (D-14) — it matches the CI pin at `ci.yml:478,546,627,774`, and a different local
archive version produces spurious byte-diffs against the committed fixture.
