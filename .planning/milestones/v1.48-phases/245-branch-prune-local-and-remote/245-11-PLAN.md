  <name>Task 2: Match Git global options before prohibited subcommands</name>
  <files>scripts/maintainers/validate-milestone-cleanup-audit.mjs, scripts/maintainers/validate-milestone-cleanup-audit.test.mjs</files>
  <behavior>
    - Receipt argv arrays and command strings detect git -C path gc, git --git-dir=path/.git gc, and git -c gc.auto=0 reflog expire.
    - Output-log command lines detect the same forms, including separated and attached values for global options.
    - A command such as git -C path gc --prune=now is detected for both applicable prohibited families.
    - Malformed or unsupported pre-subcommand option syntax leaves the row unknown and the aggregate unresolved instead of producing no_occurrence.
  </behavior>
  <action>Replace the immediate-subcommand regex checks with one shared Git invocation classifier. Consume structured command argv arrays as argument vectors without joining them; tokenize recorded shell command text after the existing COMMAND=, dollar-prompt, or continuation prefixes. Before reading the subcommand, recognize Git global options that take values, including -C, --git-dir, --work-tree, -c, --config-env, --namespace, and --exec-path in documented separated or attached forms where supported, plus the known value-free global flags. Match gc and reflog expire after those options, and continue detecting --prune=now anywhere in the same invocation. If a string identifies Git but cannot be tokenized or an unrecognized option makes the subcommand boundary uncertain, return an explicit ambiguous result that keeps the row unknown and prevents a no_occurrence claim; do not label uncertainty as a confirmed command. Exercise committed command-receipt and output-log sources from temporary Git fixtures, including -C, --git-dir, and -c forms, and verify that generation and committed-source verification use the same matcher.</action>
