## Spacing Scale

Source: `sigra_admin.css` `:root` spacing tokens (verified). The `sg-*` system uses a 4px base with
rem multiples — not a pure 8-point scale, but every value is a multiple of 4px at the 16px browser default.

| Token | Value | px equiv | Usage |
|-------|-------|----------|-------|
| `--sg-space-1` | 0.25rem | 4px | Icon gaps, tight inline padding |
| `--sg-space-2` | 0.5rem | 8px | Compact element spacing (pill internal gaps) |
| `--sg-space-3` | 0.75rem | 12px | Small element spacing (dialog body top margin) |
| `--sg-space-4` | 1rem | 16px | Default element spacing (form field gaps) |
| `--sg-space-5` | 1.25rem | 20px | Medium element spacing |
| `--sg-space-6` | 1.5rem | 24px | Section padding (section-break gap) |
| `--sg-space-7` | 1.75rem | 28px | Large element spacing |
| `--sg-space-8` | 2rem | 32px | Layout gaps (card padding) |
| `--sg-space-10` | 2.5rem | 40px | Major spacing |
| `--sg-space-12` | 3rem | 48px | Major section breaks |

**Exceptions:**
- Touch target minimum: 24px documented-as-manual proxy (Tier-2 target-size gate). Admin controls
  use `--sg-control-xs: 1.75rem` (28px), `--sg-control-sm: 2.25rem` (36px), `--sg-control-md: 2.75rem`
  (44px). Interactive pill height: `--sg-pill-h: 1.625rem` (26px) — intentionally dense for admin
  operator UI; target-size is documented-as-manual per the Tier-2 fractal scorecard.
- Pill internal padding: `--sg-pill-pad-y: 0.1875rem` / `--sg-pill-pad-x: 0.625rem` — sub-4px values
  acceptable for non-interactive status pills (they are informational, not tap targets).

## Typography

Source: `sigra_admin.css` type scale tokens (verified). The system uses a ~1.2 minor-third scale.
The admin shell renders in Space Grotesk (loaded via the host app's asset pipeline).

| Role | Token | Size | px equiv | Weight token | Weight value | Line Height |
|------|-------|------|----------|-------------|--------------|-------------|
| Body / label | `--sg-text-sm` | 0.875rem | 14px | `--sg-weight-regular` | 450 | `--sg-leading-normal` (1.5) |
| Body / base | `--sg-text-base` | 1rem | 16px | `--sg-weight-regular` | 450 | `--sg-leading-normal` (1.5) |
| Sub-label / chip | `--sg-text-xs` | 0.75rem | 12px | `--sg-weight-semibold` | 700 | 1.0 (tight, pill/chip context) |
| Section heading | `--sg-text-md` | 1.125rem | 18px | `--sg-weight-semibold` | 700 | `--sg-leading-snug` (1.3) |

**Active weights for Phase 203:**
- Regular text: `--sg-weight-regular` = 450 (Space Grotesk optical weight)
- Emphasis / labels / headings: `--sg-weight-semibold` = 700

**Weight tokens available but NOT used for new markup in this phase:**
- `--sg-weight-medium` = 600 (existing component internals only; do not introduce for new elements)
- `--sg-weight-bold` = 800 (existing component internals only; do not introduce for new elements)

**Phase-specific note:** Phase 203 adds no new type styles. The pill-vocabulary reduction (D-02/D-03)
reuses existing `sg-status-pill` / `summary_chip` typography exactly as used on `users_index_live`.
The branding preview components promoted to `components.ex` (D-05) must use these same tokens —
no one-off `font-size` or `font-weight` values.

## Color

Source: `sigra_admin.css` `:root` color tokens (verified). Supports light/dark/system via
`[data-sg-admin-theme]` on `<html>` and `prefers-color-scheme` media query.

| Role | Token | Light value | Dark override | Usage |
|------|-------|-------------|---------------|-------|
| Dominant (60%) | `--sg-color-panel` | `#ffffff` | `#1f1d1a` | Page background, main content area |
| Secondary (30%) | `--sg-color-panel-alt` | `#fbfaf7` | `#25221e` | Cards, inset panels, sidebar, nav |
| Subtle fill | `--sg-color-subtle` | `#f6f5f2` | `#171614` | Hover states, zebra rows, chip backgrounds |
| Accent (10%) | `--sg-color-brand` | `#c2410c` | — | See reserved-for list below |
| Accent soft | `--sg-color-brand-soft` | `#fff0e8` | `rgba(243,90,16,0.16)` | Brand-tinted backgrounds |
| Destructive | `--sg-color-risk` | `#b42318` | — | Destructive actions only |
| Destructive soft | `--sg-color-risk-soft` | `#fff1f0` | — | Destructive dialog background tint |
| Warning | `--sg-color-warn` | `#a15c00` | — | Warning status pills only |
| Warning soft | `--sg-color-warn-soft` | `#fff7e6` | — | Warning chip backgrounds |
| OK / success | `--sg-color-ok` | `#176b43` | — | Decision-bearing positive status only |
| OK soft | `--sg-color-ok-soft` | `#ecfdf3` | — | OK chip backgrounds |
| Info | `--sg-color-info` | `#1d4ed8` | — | Informational status |
| Info soft | `--sg-color-info-soft` | `#eef2ff` | — | Info chip backgrounds |
| Body text | `--sg-color-ink` | `#151515` | `#f4f1eb` | All body copy |
| Muted text | `--sg-color-muted` | `#686868` | `#bdb5aa` | Secondary / helper text |
| Line / border | `--sg-color-line` | `rgba(21,21,21,0.1)` | `rgba(255,255,255,0.1)` | Borders, dividers |

**Accent (`--sg-color-brand`) reserved for:**
- Primary CTA buttons (`sg-btn--primary`, `sg-btn--brand`)
- Active navigation link indicators
- Focus rings (via `color-mix` in `--sg-focus-ring`)
- Brand mark / logo rail accent
- `summary_chip` elevated/active tone when `tone="brand"`

**Accent is NOT used for:** passive status indicators, info-level chips, all-users confirmations,
or any pill that does not represent a brand action.

**Phase 203 pill-reduction rule (D-02/D-03):**
- Drop the always-present green `Confirmed`/`ok` pill from the org roster — it uses `--sg-color-ok`
  and was removed from the Users Index in Phase 201 (D-04). The same removal applies here.
- Re-evaluate the global "Authentication coverage" chip: if the Users Index removed it as a
  non-decision-bearing KPI, remove it from the global overview too. If it was slimmed, apply
  the same slimming. The chip uses `--sg-color-brand-soft` background — demote or remove it so
  `--sg-color-brand` remains reserved for decision-bearing interactions.
- Decision-bearing pills ONLY remain: `Unconfirmed` (warn), `No MFA` (warn), `Locked` (risk),
  `Deletion scheduled` (risk). Role pill (info) remains where it identifies a functional role.

**CSS triple-copy constraint (D-12):**
Any new `sg-*` class introduced MUST be written byte-identically to all three CSS copies.
Pill-vocabulary REDUCTION (D-02/D-03) is expected to require ZERO new CSS classes.
Component promotion (D-05) may require new classes only if the promoted components use affordances
not already in the system — minimize this; prefer existing `sg-branding-*` / `sg-tabs` classes.

## Interaction Contracts

### ConfirmDialog — Branding "Restore defaults" (D-06 prerequisite)

The `#restore-defaults-overlay` dialog at `branding_live.ex:349-378` is already wired with the
`phx-hook="ConfirmDialog"` contract. The interaction contract is inherited from the user-sessions
dialog (verified passing in `admin-modal-interaction.spec.ts`).

7 APG gates that D-06 must assert:
1. Overlay visible after trigger click (`phx-click="open_restore_defaults"`, `:340`)
2. Initial focus on `[data-sg-confirm-cancel]` (the Cancel button, `:364`)
3. Tab containment — focus stays inside `.sg-confirm-dialog`
4. Shift+Tab containment — focus does not leave `.sg-confirm-dialog`
5. Escape closes the dialog (focus returns to trigger)
6. Click-outside scrim dismisses the dialog
7. `role="dialog"` + `aria-modal="true"` + `aria-labelledby="restore-defaults-title"` all present (`:352-354`)

axe gate: `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa` — zero violations while the dialog is OPEN.

**Hard ordering constraint:** D-06 modal test MUST land and pass before D-08 `branding-live` evidence
expansion cites overlay-axe / APG gates (Pitfall 6 from RESEARCH.md).

### Status Pills — reduced vocabulary (D-02)

Pill rendering contract for org roster after D-02:
- REMOVE: `data-tone="ok"` pill with label "Confirmed" (always-on — not decision-bearing)
- KEEP: `data-tone="warn"` "Unconfirmed" (decision-bearing — user has not confirmed email)
- KEEP: `data-tone="warn"` "No MFA" (decision-bearing — security posture gap)
- KEEP: `data-tone="risk"` "Locked" (decision-bearing — account action required)
- KEEP: `data-tone="risk"` "Deletion scheduled" (decision-bearing — account lifecycle)
- KEEP: role pill (info — identifies functional role of the org member)

The same status signal MUST render identically across the org overview and Users Index after this change.
Visual verification: `global-overview` and `org-overview` checkpoint slugs recaptured via `snapshot-recapture-gate.sh`.

### Motion

No new animations or transitions introduced in Phase 203. Existing motion tokens apply:
- No `transition: all` anywhere — use specific property transitions (`--sg-transition-tone`, `--sg-transition-enter`, etc.)
- Existing dialog enter/exit uses `--sg-transition-enter` / `--sg-transition-exit` — preserve these
- `prefers-reduced-motion` block at the bottom of `sigra_admin.css` governs all transitions; no override needed

### Theme Support

All three target surfaces already support Light / Dark / System via the `[data-sg-admin-theme]` cascade.
Phase 203 changes must not introduce any hardcoded `#hex` or `rgb()` colors — use only `--sg-color-*` tokens.
The CSS triple-copy constraint (D-12) ensures generated hosts receive the same token values.

## Design Archetype — Branding/Workbench (D-07)

This phase adds a new **Branding/Workbench archetype** to `guides/reference/admin-design-contract.md`.
The contract currently has exactly four archetypes: Overview, List, Detail, Audit Explorer.

**Workbench archetype composition:**
- Tab navigation (`sg-tabs`) with three disclosed panels (Identity, Colors, Email)
- Each panel contains a form section + per-panel preview rail
- Preview rail renders `color_field` / `preview_pair` / `detail_input` promoted components
- Restore-defaults destructive action in the form footer, triggering `ConfirmDialog` APG pattern
- No results table (content-equivalence proxy N/A)
- No pagination

**Archetype documentation must include:**
- Tab nav + disclosed-panel pattern (tab state managed via LiveView assigns, not JS)
- Preview-rail / preview-pair structure (left: input; right: rendered preview)
- ConfirmDialog restore-defaults trigger pattern (same hook contract as user-sessions dialog)
- Note: this is a single-instance workbench (one per admin install); not a repeatable list-driven surface
