# v1.37 AUTH-BRANDING-WHITELABEL Roadmap

**Shipped:** 2026-06-07

## Milestone Goal

Make Sigra's generated authentication forms and emails production-ready by default, while giving adopters a low-friction white-label path, an admin/operator customizer, a code/config path, and a full-control escape hatch.

## Phases

- [x] Phase 173: Auth Branding Contract + Token Model (1/1 plan) — completed 2026-06-07
- [x] Phase 174: Generated Auth Shell + Light/Dark/System CSS (1/1 plan) — completed 2026-06-07
- [x] Phase 175: Admin Customizer + Email Branding (1/1 plan) — completed 2026-06-07
- [x] Phase 176: Generated Host, Example, Docs, and Golden Parity (1/1 plan) — completed 2026-06-07
- [x] Phase 177: Verification, Generated-Host Smoke, and Audit Closure (1/1 plan) — completed 2026-06-07

## Shipped Scope

- Added `Sigra.Branding.Profile` and `Sigra.Branding` as the canonical brand-token contract for product identity, logo, theme, color, legal/support links, and email sender settings.
- Added generated `sigra_brand_profiles` persistence with auth-schema prefix awareness, JSON-safe token serialization, and safe runtime fallback when the table or repo is unavailable.
- Generated a scoped auth shell component and `sigra_auth.css` so installed login, registration, reset, confirmation, MFA, sudo, settings, OAuth settings, and organization invitation pages look intentional by default.
- Supported Light, Dark, and System themes in generated auth UI without mutating the host app's global design system.
- Added a generated admin `/admin/auth-branding` customizer with stable hooks, auth-form preview, email preview, save, and reset flows.
- Made generated transactional emails use the branding profile for sender identity, reply-to, logo/product name, CTA treatment, and footer links.
- Updated example app, install golden fixture, OAuth template, organization template, README, installation guide, and ExDoc recipe.
- Proved the change through focused unit/template/golden/example tests, docs warnings-as-errors, diff hygiene, and generated-host Playwright smoke.

## Key Decisions

- Prefer a structured token profile over raw CSS strings as the default white-label contract.
- Keep generated auth styling scoped under `.sigra-auth` so Sigra improves the installed default without owning the host application theme.
- Resolve branding from code/config first and admin-saved global profile when available, with missing-table fallback for pre-migration/pre-auth paths.
- Preserve full control through generated components and CSS instead of hiding the implementation behind a black-box hosted theme system.
- Treat email branding and form branding as one profile so product identity is consistent across the authentication journey.

## Issues Resolved

- Generated auth forms no longer ship as plain, unbranded white defaults.
- Admin operators can tune auth/email branding without editing code.
- Backend-leaning Phoenix adopters get safe defaults without needing design-system expertise.
- Generated-host smoke caught and fixed an Elixir boolean footgun in the generated component template.
- Generated-host smoke caught and fixed runtime auth-prefix resolution for generated schemas.

## Issues Deferred

- Per-organization branding remains out of scope; this milestone shipped a global profile.
- Arbitrary runtime CSS/HTML editing is intentionally not part of the default admin surface.
- Uploaded asset storage is not implemented; `logo_url` points at host-served or remote assets.

## Technical Debt Incurred

- Visual checkpoint coverage for auth branding is structural/browser-smoke based, not pixel-baselined.
- The admin branding preview is intentionally representative, not a full router-level render of every auth template.
