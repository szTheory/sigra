<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Generated host -> Sigra.Auth | Host code supplies repo, user schema, token/session schemas, scope, and audit context into the library contract. |
| Sigra.Account.Deletion -> Oban | Library code serializes worker args and schedules asynchronous deletion execution. |
| Oban worker -> Repo/User schema | Background job args are rehydrated into modules and IDs used to reload and mutate user lifecycle state. |
| Lifecycle state -> Export/status surfaces | Raw `deleted_at` and `scheduled_deletion_at` fields determine user-visible lifecycle truth through `Deletion.status/1`. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-128-01 | Repudiation | `Sigra.Account.Deletion.schedule/3` enqueue path | mitigate | Pin `repo.insert/1` Oban changeset fields in tests: worker `"Sigra.Workers.AccountDeletion"`, queue `"sigra_lifecycle"`, returned `scheduled_at`, replacement rule `[scheduled: [:scheduled_at, :args]]`, and serialized context args. |
| T-128-02 | Denial of Service | `maybe_enqueue_deletion_job/4` optional infrastructure | mitigate | Keep missing Oban or missing `:user_schema` as safe no-op degradation returning `:ok`; log unexpected enqueue failures without failing the schedule transaction. |
