<objective>
Let a documentation-only pull request stop paying for the full job matrix, without ever letting a
required check hang pending and without removing the coverage a docs change most needs.

Two constraints shape the whole design. First, D-06: a required workflow filtered at the trigger
never creates its check contexts, so all five ruleset-14941512 contexts would sit waiting for status
and the PR would be permanently unmergeable — the gating must live at the job and step level.
Second, a finding CONTEXT.md does not cover: `fast_checks` and `library_tests` are exactly the lanes
a docs-only PR most needs. `milestone-verification-gate.sh` walks `.planning/**`,
`getting-started-contract.sh` link-checks `guides/introduction/getting-started.md`, and 13 ExUnit
files under `test/sigra/planning/` and `test/sigra/*guides*` read those paths directly. Gating either
off would turn FAST-05 into a coverage hole in the one dimension the PR actually changes.

A third constraint shapes how this plan is *proven*, and it is structural rather than a matter of
effort. `ci.yml` triggers on `pull_request: branches: [main]`, so every pull request that runs this
workflow diffs against `origin/main`; and any pre-merge pull request that carries the `changes` job
at all necessarily carries this phase's own `.github/workflows/ci.yml`, `scripts/ci/*.sh`,
`test/example/priv/playwright/tests/admin-design.spec.ts` and `test/sigra/planning/*.exs` commits in
that same base-to-HEAD diff. The classifier therefore emits `false` on every pre-merge pull request,
including one whose own commit is Markdown-only. Re-cutting the probe branch does not help: from the
phase branch the diff is dominated by the phase's own non-Markdown changes, and from `main` the run
executes the *pre-change* workflow, in which the fast path does not exist. **An observed `docs_only=true`
run is impossible before this phase merges.**

That is not a reason to leave FAST-05 unproven. The rule itself is extracted into
`scripts/ci/docs-only-classify.sh` and pinned by a hermetic self-test wired into `fast_checks` — the
falsifiable in-phase evidence — the observed half is the AFTER-PR mixed-diff run emitting
`docs_only=false`, and the end-to-end `true` observation is recorded as an explicit **post-merge
obligation** (AFTER-DOCSONLY, `Status: pending`), exactly as AFTER-PUSH already is. A pending slot
stated honestly beats a pre-merge observation that cannot happen.

Purpose: collapse a docs-only PR from ~29.5m to roughly the cost of `fast_checks` plus `library_tests`.
Output: one `changes` job with a fail-open output consumed at step level by the four app-behaviour
required lanes and at job level by one non-required lane, plus the classifier script and self-test
that make its rule provable without a CI run.
</objective>
