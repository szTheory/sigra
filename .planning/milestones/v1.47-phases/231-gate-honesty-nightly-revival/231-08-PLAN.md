<objective>
GATE-03's logic half — the fourth link in D-24's locked chain, taken only after the stale `head_ref`
gate is gone (plan 231-07). Landing it earlier would have forced one of two bad outcomes: red every
PR on a lane the phase was about to fix, or make the manifest allowlist a gate already known to be
rotted, enshrining the rot inside the very oracle meant to detect it.

The defect GATE-03 closes is one line: `ci.yml:1831` counts `skipped` as a pass. That is correct for
a lane skipped because it was correctly gated for this event, and catastrophic for a lane skipped
because its gate rotted — which is exactly how generated-host parity reported green for months while
verifying nothing. The gate cannot tell the two apart because it has no enumeration of which skips
are legitimate.

Phase 230 already shipped that enumeration: `.github/ci-skip-manifest.tsv`, 16 data rows, whose own
header block instructs that Phase 231 GATE-03 should read this file rather than re-derive the set,
and that the file owns the enumeration while GATE-03 owns the consequence. **D-01 is honored to the
letter: this script builds no second list.**

One correction carried in from RESEARCH and already recorded in 231-07. **C-1:** the three-way parity
enforcer D-01 names, `honest-skip-parity.test.mjs`, does not exist. So the manifest's `gate` column
had never been read by anything. 231-07 made it load-bearing at lint time; this script makes it
load-bearing at verdict time. Together they are the assertion that would have caught GATE-02's defect.

This plan ships the script and its hermetic self-test. Plan 231-09 wires it into `ci-gate`, adds the
`force_rot_probe` dispatch input, and closes SC-3 with two real runs.

Purpose: `ci-gate` gains the ability to distinguish an honest skip from a rotted one.
Output: `scripts/ci/honest-skip-verdict.sh`, `scripts/ci/honest-skip-verdict.test.sh`, and one
`fast_checks` step.
</objective>
