<objective>
D-11's fourth and final step, taken only now that step 3 has been run and read. Plan 231-05 observed
the harness executing all six downstream guards to completion; this plan removes the mask that made
that observation optional.

The mask is not a mistake being corrected — it was Phase 230's deliberate D-11 decision, retained so
that demoting the lane could not be confused with fixing it. The guard `p05` exists to enforce that
retention, and it is written one-directionally on purpose: its header records that a self-retiring
form "writes part of Phase 231's exit condition into a Phase 230 guard and would red 231's own work
mid-flight." That is now this phase's work to finish, and the guard's own text says how — invert it
deliberately, in the same commit, not silently.

Two boundaries make this narrower than it sounds. **D-13:** only the four-space job-level
declaration goes. The eight-space step-level one under `id: admin_eval_harness` is retained
permanently, because it is what lets partial evidence bundles upload before the re-fail step turns
the job red. Delete both and an investigator loses the artifact precisely when the harness dies.
**C-3:** p05 also asserts that GATE-04's REQUIREMENTS.md coverage row does not read `Complete`, which
this phase's own bookkeeping would red. That assertion retires with the rest.

The inversion is chosen over deletion because deletion leaves nothing stopping a future re-mask. An
inverted guard is a forward-only ratchet: the thing that once demanded the mask now forbids it.

Purpose: make a red eval harness redden the run.
Output: an inverted `p05` and one deleted line, in one commit, plus SC-4's receipt.
</objective>
