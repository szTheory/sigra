a `scripts/ci/*.sh` guard, a hermetic `*.test.sh` beside it, a `fast_checks` wiring step, a

every one of those layers and proves it with a live invocation before any expansion task starts.

the locked GATE-0x chain (it touches only `release-please.yml` and `scripts/ci/`), and because D-21
already identifies the extraction as the only way to make a structurally-unobservable receipt
observable — the same move Phase 230 made with `docs-only-classify.sh`.

Two defects close here. **D-20:** `gate-ci-green` polls `max_attempts=60` at 30s = a 30-minute
ceiling, while post-230 push wall-clock measures 28m29s (run `30466318240`) with a 42.3m historical
max — so the gate is structurally below the run it waits for. Run `30379435985` concluded `success`
while `gate-ci-green` in run `30379435970` gave up at 17:16:37Z, about one minute before the run it
was waiting on finished. The same job declares no `timeout-minutes` at all and inherits 360 minutes.
**D-21:** the loop is 58 lines of inline `run:` shell that no test can reach, which is precisely why
nobody noticed. Extracting it is what converts SC-5 from a wait-for-the-next-release hope into a
runnable command.

D-23 is honored by omission: issue #118 and its three idempotent comments already prove both
branches of `notify-failure-issue.sh` against the real Issues API, so nothing here re-stages a probe.

DX-05's timeout half with a live receipt.
