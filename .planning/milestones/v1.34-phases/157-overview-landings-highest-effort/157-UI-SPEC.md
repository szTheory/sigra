# Phase 157 — UI Design Contract

> Visual and interaction contract for the two admin Overview LiveViews (Global + Org).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is a USAGE contract over a mature token layer, NOT a new design system.** The
> `sg-*` `@layer sg-components` layer (`test/example/priv/static/assets/css/app.css`) is the
> single source of truth for every value below. This spec specifies which existing tokens,
> classes, and shared components compose into the redesigned front-door archetype. **No new
> CSS class, token, or motion primitive may be invented** (STATE.md lock; CONTEXT.md D-03,
> hard-fail boundary). All values below are READ FROM the existing layer — they are not new
> declarations.

## Spacing Scale

Source of truth: `--sg-space-*` tokens in `app.css :root`. Sigra uses a 0.25rem (4px) base
unit. All values below are multiples of 4px. **Use the `sg-stack`/`sg-cluster`/`sg-grid`
utility classes — do NOT introduce inline spacing.**

| Token | Value | Class hook | Usage in this phase |
|-------|-------|-----------|----------------------|
| `--sg-space-1` | 4px | `sg-stack--1` | Kicker/title micro-gap; heading+copy pair inside a card |
| `--sg-space-2` | 8px | `sg-stack--2`, `sg-cluster` (default) | task_card title→body internal stack; pill clusters |
| `--sg-space-3` | 12px | `sg-stack--3`, `sg-cluster--3`, `sg-grid--3` gap | Within-card stacks; stat_link strip cluster; posture/roster card internals |
| `--sg-space-4` | 16px | grid/cluster default gap | Default element spacing |
| `--sg-space-6` | 24px | `sg-stack--6` | **Top-level Overview rhythm** — gap between archetype sections (header → alarm → cards → strip → matrix → Org tail) |

**Top-level page container is locked:** `<section class="sg-stack sg-stack--6">` — the 24px
rhythm between the five archetype sections is the visual spine of the front door. Do not change
the container class or its gap.

Exceptions: none. No 44px touch-target override needed — interactive elements are `sg-btn` /
`stat_link` / `notice` anchors that already meet target sizing via the token layer.

## Typography

Source of truth: `--sg-text-*` and `--sg-weight-*` tokens. **Apply via the existing semantic
classes only** (`sg-page-title`, `sg-page-kicker`, `sg-page-copy`, `sg-section-heading`,
`sg-section-copy`, `sg-text-sm`). Do not set `font-size`/`font-weight` inline. The four roles
below are the only type roles the Overview archetype uses.

| Role | Class | Size | Weight | Line Height |
|------|-------|------|--------|-------------|
| Display (page title) | `sg-page-title` | `--sg-text-2xl` = clamp(1.6rem, 2.3vw, 2.4rem); 1.5rem ≤480px | `--sg-weight-bold` (800) | `--sg-leading-tight` (1.1) |
| Heading (section / card) | `sg-section-heading` | `--sg-text-md` = 1.125rem (18px) | `--sg-weight-bold` (800) | `--sg-leading-snug` (1.3) |
| Label (kicker) | `sg-page-kicker` | `--sg-text-sm` = 0.875rem (14px), uppercase, `--sg-tracking-wide` | `--sg-weight-semibold` (700) | inherit |
| Body | `sg-page-copy` / `sg-section-copy` / `sg-text-sm` | base 1rem (16px) / sm 0.875rem (14px) | `--sg-weight-regular` (450) | `--sg-leading-normal` (1.5) |

**Notice body copy** (the LAND-01 alarm) renders inside `notice/1`'s own
`<p class="sg-text-sm">` wrapper at 14px — the executor passes INLINE content only (no nested
`<p>`; see Copywriting + D-07).

## Color

Source of truth: `--sg-color-*` tokens (`:root` light + dark override block). Both light and
dark are first-class — the redesign must be axe-green in chromium, mobile, AND dark. Tone
treatment is driven entirely by `data-tone` on `sg-notice` / `sg-status-pill`; **do not pick
hex values — set `tone={...}` / `data-tone={...}` and let the layer resolve color.**

| Role | Token (light → dark) | Usage |
|------|----------------------|-------|
| Dominant (60%) — surface | `--sg-color-subtle` #f6f5f2 → #171614 | Page background, posture-strip secondary surface |
| Secondary (30%) — panels | `--sg-color-panel` #ffffff → #1f1d1a; `--sg-color-panel-alt` #fbfaf7 → #25221e | `sg-card` task cards, posture strip, Org roster/invitations tail |
| Accent (10%) — brand | `--sg-color-brand` #c2410c → brand-soft tints | Reserved (see below) |
| Risk (semantic) | `--sg-color-risk` #b42318 → #f8a39c; `--sg-color-risk-soft` #fff1f0 → rgba | **The loud alarm** when `needs_review > 0`: `sg-notice[data-tone="risk"]` (inset risk bar + risk-soft fill, `app.css:960-967,972-978`) |
| OK (semantic) | `--sg-color-ok` #176b43 → #5dd1a0; `--sg-color-ok-soft` | "All clear" alarm state (`tone={:ok}`) |
| Warn / Info (semantic) | `--sg-color-warn` / `--sg-color-info` (+ soft) | Org roster/invitation status pills (unconfirmed=warn, role=info) — pre-existing, unchanged |

**Accent (`--sg-color-brand`) reserved for:** the primary CTA button only —
`<a class="sg-btn sg-btn--primary">` inside each `task_card` (the verb-first action), and the
brand-soft header wash already in the layout shell. Accent is NOT used for the alarm
(risk/ok semantic tones own that), NOT for stat_link values, NOT for status pills.

**The "loud" alarm gets NO color escalation beyond `data-tone="risk"`.** Prominence = position
(first child of `sg-stack--6`, above the task grid) + the existing risk treatment. Inventing a
new emphatic class (e.g. `sg-alarm`) is a hard-fail — escalate a milestone lock exception
instead (CONTEXT.md D-03 boundary).

## Copywriting Contract

Tone: operator-facing, verb-first, needs-led. Microcopy within tone+deep-link constraints is
Claude's discretion (CONTEXT.md); the values below are the prescribed contract for the executor.

| Element | Copy |
|---------|------|
| Page title (Global) | "What do you need to do?" (kicker: "Admin overview") — unchanged |
| Page title (Org) | `{@organization_name}` (kicker: "Organization overview") — unchanged |
| Primary CTA — Global task_cards | "Find a user" → `/admin/users`; "Investigate audit" → `/admin/audit`; "Review locked" → `/admin/users?locked=true` |
| Primary CTA — Org task_cards | "Open members" → `users_path(@admin_scope)`; "Open audit" → `audit_path(@admin_scope)` |
| **Alarm headline — risk** (`needs_review > 0`) | INLINE single message, e.g. `"{@needs_review} accounts need review"` with a deep-link anchor to `/admin/users?locked=true` (Org: `users_path(@admin_scope) <> "?locked=true"`). Content MUST be inline (text + inline `<span>`/`<a>`), never block `<p>` children. |
| **Alarm headline — ok** (`needs_review == 0`) | INLINE `"All clear"` (`tone={:ok}`), no deep-link required |
| Empty state — Org members | "No members yet — invite teammates to populate this organization." (existing `sg-section-copy`, demoted tail; keep) |
| Empty state — Org pending invitations | "No pending invitations." (existing `sg-section-copy`, demoted tail; keep) |
| Loading state | Render `<.skeleton>` shapes matching loaded footprint (NOT empty flash, NOT layout jump). No loading copy text — the skeleton communicates load visually; `aria-busy="true"` on the containing `<section>` communicates it to AT. |
| Error state | Not applicable — these are read-only aggregate landings; query failure is a server error, not a rendered notice. Do NOT add a risk `notice` error state (skeleton is loading only; out of scope). |
| Destructive confirmation | None — Overview screens contain no destructive actions. All anchors are read-only navigation into filtered lists. |

**Nested-`<p>` prohibition (D-07, folds `2026-06-04-org-notice-nested-p.md`):** Every
`<.notice>` slot is INLINE content. `notice/1` already wraps the slot in
`<p class="sg-text-sm">` (`components.ex:303-304`), so any block `<p>` child produces invalid
`<p><p>…</p></p>` and fails axe on the new `org-overview` checkpoint. The redesign removes the
old Org "Scoped attention" `<.notice>` (`organization_live.ex:73-78`) entirely; the new
top-of-page alarm carries single inline content.

## Interaction & Loading Contract (LAND-04)

**Deferred load via `connected?(socket)` gate (D-01, locked) — NOT `assign_async/3` (banned),
NOT `Task`/`send(self)`+`handle_info`.**

| State | Trigger | Render |
|-------|---------|--------|
| Skeleton | Disconnected / first-HTTP mount (`connected?(socket) == false`) | `loading: true`, no query data. Render `<.skeleton>` shapes for deferred regions: Global = posture strip stat values; Org = posture strip + members roster + pending invitations. Containing `<section>` gets `aria-busy="true"`. |
| Data | Connected mount (`connected?(socket) == true`) | Run real queries INLINE in `mount/3` (`Query.summary_counts/2`; Org also `Detail.member_roster/2` + `Detail.pending_invitations/2`), assign data, `loading: false`. Remove `aria-busy`. |

Exactly two render states (skeleton → data); no extra render frame. `mount/3` stays the single
load site. Precedent: `test/example/lib/example_web/live/confirmation_live.ex:103`.

- **Skeleton shapes (discretion, bounded):** each `<.skeleton>` must match the loaded content's
  footprint so there is genuinely no layout jump (the explicit LAND-04 intent) — not generic
  blocks. Skeleton CSS `app.css:1406-1428`; shimmer is `prefers-reduced-motion`-safe via the
  universal rule (`app.css:1463-1473`) — no extra motion handling.
- **Hard-fail boundary:** keeping the synchronous load and only flashing skeleton in a
  first-paint window violates the contract's "Do NOT use skeleton for content available
  synchronously" rule and makes LAND-04 a reviewable no-op.

**Alarm live-region (D-02):** the LAND-01 alarm count is now genuinely post-load-dynamic
(arrives on the connected mount), so a `role="status"` opt-in via `notice/1`'s `:rest` is
valid here. Do NOT add an always-on live-region role to load-present markup (inert per WAI-ARIA
APG; risks duplicate announcements on re-render — the exact failure `notice/1`'s doc warns
against, `components.ex:272-275`).

**Motion:** hover lift on `task_card` (`translateY(-1px)` + shadow, 140ms, pointer-fine only);
`var(--sg-transition-tone)` on notice (140ms). No load animation beyond the skeleton shimmer.
All `prefers-reduced-motion`-safe via the universal rule. No new motion primitives.
