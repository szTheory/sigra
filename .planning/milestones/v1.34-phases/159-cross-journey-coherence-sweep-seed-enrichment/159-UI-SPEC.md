## Spacing Scale

All layout values are owned by the `sg-*` token system. The 4px-base custom property scale
is the single source of truth. The template's named xs/sm/md/lg/xl aliases are mapped below
to the nearest `--sg-space-*` token.

| Alias | Token | Computed value | Usage |
|-------|-------|----------------|-------|
| xs | `--sg-space-1` | 4px (0.25rem) | Icon gaps, pill internal padding-y |
| sm | `--sg-space-2` | 8px (0.5rem) | Pill padding-x, cluster gaps, applied chip padding |
| md | `--sg-space-4` | 16px (1rem) | Card body padding, filter chip padding-x |
| lg | `--sg-space-6` | 24px (1.5rem) | Section stack gaps, page header spacing |
| xl | `--sg-space-8` | 32px (2rem) | Layout column gaps |
| 2xl | `--sg-space-10` | 40px (2.5rem) | Major section breaks |
| 3xl | `--sg-space-12` | 48px (3rem) | Page-level vertical rhythm |

Component sizing exceptions (named values with no spacing-scale fit, as defined in `:root`):
- `--sg-pill-h: 1.625rem` — pill height
- `--sg-pill-pad-y: 0.1875rem` — pill vertical padding
- `--sg-pill-pad-x: 0.625rem` — pill horizontal padding
- `--sg-control-md: 2.75rem` — filter chip min-height (touch target, 44px equivalent)
- Touch target minimum: `--sg-control-md` (2.75rem ≈ 44px). Applied to `.sg-filter-chip`.

Source: `app.css` `:root` spacing scale + component sizing tokens (lines 21-31, 151-156).

|------------|-----------|-------------|---------|-------------|

### Users-index security pills — users index (`/admin/users`)

Rendered via `users_index_live.ex:346-355` (`status_pills/1`). Source: `D-02`.

## Motion Contract (GATE-03 Verification Target)

This section codifies the existing motion budget that GATE-03 audits against. Sourced entirely
from `app.css`. No new motion rules are introduced in phase 159 (except the open fork below).

### Budget tokens

| Token | Value | Semantic |
|-------|-------|---------|
| `--sg-motion-press` | 120ms | Button/chip press feedback |
| `--sg-motion-pop` | 180ms | Toast + cmdk dialog enter |
| `--sg-motion-fast` | 140ms | Tone transitions (color, bg, shadow) |
| `--sg-motion-medium` | 220ms | Panel/overlay enter |
| `--sg-motion-slow` | 300ms | (reserved; not used by admin screens) |
| `--sg-ease-out` | `cubic-bezier(0.23, 1, 0.32, 1)` | All enters; flat destructive easing |
| `--sg-ease` | `cubic-bezier(0.2, 0, 0, 1)` | Tone transitions |
| `--sg-ease-spring` | `cubic-bezier(0.34, 1.4, 0.64, 1)` | Not used for destructive actions |

### Motion rules the audit verifies

| Interaction | Expected behavior | CSS location |
|-------------|-------------------|-------------|
| Toast enter | `sg-toast-enter` keyframe, `--sg-motion-pop`, `--sg-ease-out` | `app.css:1294-1296` |
| Toast leave | `sg-toast-leave` keyframe, `--sg-motion-press`, `--sg-ease-out` (flat, not spring) | `app.css:1297-1299` |
| Cmdk dialog enter | `sg-cmdk-enter` keyframe, `--sg-motion-pop`, `--sg-ease-out` | `app.css:1334-1336` |
| Cmdk active row highlight (keyboard nav) | NO transition — intentionally instant | `app.css:1368-1369` (no transition property) |
| Filter chip press | `--sg-transition-press` (transform 120ms) + `--sg-transition-tone` (color/bg/shadow 140ms) | `app.css:869` |
| Filter chip hover | translateY(-1px), brand-soft bg — hover-only (pointer: fine guard) | `app.css:871-877` |
| prefers-reduced-motion | strips transform + keyframes; retains color/opacity/shadow at `--sg-motion-fast` | `app.css:1458-1467` (documented `!important` exception) |

### Keyboard-frequent interactions: no-animation requirement

The motion audit must confirm these are NOT animated (transition-free or instant):
- Cmdk result list active row as keyboard moves up/down (`.sg-cmdk__item.is-active`, `.sg-cmdk__item[aria-selected]`)
- List row updates triggered by keyboard (`.sg-list-row` state changes)

Confirmed no transition on those selectors at `app.css:1368-1369`.

### Destructive easing rule

Destructive actions must use flat `--sg-ease-out` (NOT `--sg-ease-spring`). Verified in toast
leave animation (`app.css:1298`). Spring easing (`--sg-ease-spring`) is never used for
destructive confirmation flows.

### Open fork (planner's discretion — below escalation threshold)

`sg-filter-chip` currently carries `transition: var(--sg-transition-tone), var(--sg-transition-press)`
(line 869). If "filter apply" (toggling a chip by keyboard) counts as keyboard-frequent under
the gate's strict reading, the fix is to scope the press/tone transition to
`@media (hover: hover) and (pointer: fine)` inside `@layer sg-components`. This is a ~3-line
CSS-only change, no new tokens or deps. Planner adjudicates during task breakdown.

## Coherence Sweep Contract (D-07 Verification Targets)

Phase 159 verifies these contracts hold on all 6 admin screens via a Playwright journey
filmstrip extending `admin-checkpoints.spec.ts`. These contracts were established by prior
phases (154-158); phase 159 confirms they hold end-to-end.

### 6 screens

1. Global overview — `/admin`
2. Org overview — `/admin/organizations/:slug`
3. Users index — `/admin/users`
4. User audit/show — `/admin/users/:id/audit`
5. Audit explorer — `/admin/audit`
6. Org roster — roster section of `/admin/organizations/:slug` (or `/admin/organizations/:slug/users`)

### Per-screen checks

| Criterion | Component/token | Contract |
|-----------|----------------|---------|
| Scope ribbon present | `<.scope_ribbon>` | Renders on all list + leaf screens (screens 2-6); shows "Global" or org name |
| Back-nav present on detail screens | `<.page_back>` consuming `return_to` | Screens 4 (user audit), not overview screens |
| Empty-state spacing | `.sg-empty-state` | Consistent vertical padding using `--sg-space-8` (32px) top + bottom; centered layout; uses shared `<.empty_state>` component, not bespoke inline markup |
| Notice/flash unification | `<.notice>` component | All contextual alerts (summary alerts AND flash messages) render through the single shared `notice` component; no bespoke per-screen notice markup |
| Focus ring | `--sg-focus-ring` | `0 0 0 3px color-mix(in oklab, var(--sg-color-brand) 35%, transparent)` with `--sg-focus-ring-offset: 2px` on all interactive elements across all 6 screens |
| Hover state | `@media (hover: hover) and (pointer: fine)` guards | Hover transforms only fire on pointer devices, not keyboard/touch; no hover state on list rows when navigating by keyboard |

### Folded todo: `org-notice-nested-p`

The notice component on the org overview currently passes block `<p>` children into the
notice's `<p>` wrapper, producing invalid nested `<p>` HTML. Fix is in scope for phase 159
as it directly serves the notice/flash unification criterion. The `notice/1` component must
wrap slot content in a block element other than `<p>` (e.g. `<div>` or a `<span>`), or the
slot must accept inline content only. This is a single-component HTML fix with no visual
change, but it resolves a LiveView patch-desync hazard.

### Folded todo: `admin-format-date-naivedatetime`

`format_date/1` must handle non-DateTime host timestamps without silently rendering "—".
FIXT-01 adds invitation rows whose `expires_at` renders via `format_date` on a checkpoint
screen. The fix is a clause match in the presenter/helper — no visual contract change, but
it must not regress the "Expires {date}" / "Expired" pill display.
