## Resolution

root_cause: After Escape's closeAll(null) correctly closes the metric-help root, hiding the panel (panel.hidden=true) collapses layout under the stationary synthetic mouse cursor. Chromium then dispatches mouseout+mouseover; the mouseover handler (active because finePointer() / hover:hover+pointer:fine is true in headless Chrome) calls open(root) and re-opens the help. The help thus appears not to close on Escape. The metric root is itself the hover target, so it is uniquely vulnerable; field-help's separate trigger button is not.
fix: |
  Added a 400ms `escapeDismissedUntil` suppression window. Escape's keydown handler sets
  `escapeDismissedUntil = Date.now() + 400`; the mouseover handler returns early while
  `Date.now() < escapeDismissedUntil`, so the synthetic post-collapse mouseover cannot
  re-open the help. A capture-phase `mousemove` listener resets the window to 0 so a genuine
  pointer move still allows hover-to-reopen. Faithful to the focus-to-open + hover UX; does
  not change the test's intent. Propagated to all three copies for parity (build-free example
  has no auto-bundling; generated hosts use the installer template).
