## The Gap (BLOCKER) — RC-01 Threadline recipe config drift

**Three sources, contradictory config on the impl-specific keys:**

| Source | module: | id: | dispatch: | repo: | endpoint:/api_key: |
|--------|---------|-----|-----------|-------|--------------------|
| Forwarder consumer (`threadline.ex:241`) | ✓ | ✓ | ✓ | **reads** | never read |
| Recipe (`threadline.md:64-71`) | ✓ | ✓ | ✓ | **MISSING** | present (dead keys) |
| Example (`config.exs:55-63`) | ✓ | ✓ | ✓ | ✓ `Example.Repo` | absent (correct) |

The inline forwarder path (`call_threadline/2`, threadline.ex:238-309) does
`repo = Keyword.get(opts, :repo)` with no Application-env fallback. With the recipe's
config, `repo` is `nil` → `Threadline.record_action/2` returns `{:error, :missing_repo}`
(threadline dep line 233) → the forwarder fires `[:sigra,:audit,:forward,:error]` and
returns `:ok` (never rolls back the auth op). Every audit event silently fails to forward.

**Fix:** in `guides/recipes/companion-libs/threadline.md`, replace the
`endpoint:`/`api_key:` lines with `repo: MyApp.Repo` (matching `test/example/config/config.exs`),
and correct failure-mode #4 from "HTTP timeouts" to DB/transient framing. Then the frozen
contract / recipe / example agree byte-for-byte.

This is a one-file doc fix to the recipe + a failure-mode correction. No library code change.
