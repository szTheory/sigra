# v1.42 CI-Gate Remediation — Findings

**Date:** 2026-06-29
**Status:** Discovery complete; remediation phase to be planned.
**Trigger:** Attempting to ship the 294-commit v1.42 backlog to `origin/main` (paused Phase 208) revealed the admin Playwright gates were never actually run green in CI.

---

## Headline

The v1.42 milestone (phases 205–208) was marked "complete" in GSD, but the required
**"Example Playwright smoke (full lifecycle)"** CI check has **~15 real behavioral
failures** on the current HEAD that were never caught — because several phase audits
("cite-and-flip, gates already green") were **code-level reads that never executed the
specs**, and this code never reached a CI lane that runs the full Playwright suite.

The 294-commit backlog **cannot ship green** through branch protection until these are fixed.

## How this was discovered

1. `origin/main` is PR-protected (ruleset 14941512); 5 required checks; direct push rejected.
2. `admin_design_recapture` never runs on PRs (`if: github.event_name != 'pull_request'`),
   only on push-to-main / schedule / `workflow_dispatch` from a `v*` tag.
3. To bootstrap the missing board-cfg baselines we created a throwaway branch
   **`wip/recapture-trigger`** (= HEAD + a 7-line `release_ref_guard` relax allowing a
   branch-ref dispatch; commit `af75b127`; **never merged to main**) and dispatched recapture.
4. The recapture run (CI run 28401914980) **failed at the capture step** with 6 behavioral
   failures in `admin-design.spec.ts` → the commit/PR step was skipped → **no baselines produced.**
5. A local full-suite enumeration (boot example on :4011 against the Docker test PG, all 5
   required-check spec groups with `--update-snapshots` to suppress snapshot noise) surfaced
   the complete behavioral inventory below.

## Triage (real vs local-env)

### Definitively real, env-independent (DOM/geometry) — Phase 205/208 gallery scope
1. **`board-mg-1` metric count.** Test asserts `#board-mg-1 .sg-metric` `toHaveCount(7)`;
   markup renders **6** (3 in `mg-1-populated` + 3 in `mg-1-zero`, via `.summary_chip`).
   `design_gallery_live.ex:457–487`. NOTE: Phase 208-01's audit cited "mg-1 has 7 .sg-metric"
   straight from the test's expected value without counting the markup — this is the unsound-audit
   failure mode. Fix = decide correct count (markup→7 or test→6) per design intent.
2. **`board-cfg-audit` overflows 320px.** `overflowingChild: "table.sg-table"` — the audit
   composite renders the desktop table at mobile width instead of the content-equivalent
   mobile-card swap / overflow containment. Real responsive layout bug. (Phase 205 board-cfg.)

### Very likely real — introduced by the v1.36+ admin redesign, never reconciled
The recurring signature `strict mode violation: ... resolved to 2 elements` ("No active
sessions" ×2, "Passkeys" ×2) is the **desktop + mobile dual-DOM render** the admin redesign
introduced; the older Phase-31 behavioral specs don't scope to the visible variant. Also:
sudo "Confirm your password" heading not found; audit "Action prefix" textbox; revoke-session
button; org empty-state copy; demo-showcase persona stat ("9") / morgan visibility in the
admin users list (the `morgan@demo.tasklane.test` persona and all 9 non-admin personas **do
exist** in seed — so these are visibility/selector/pagination, not missing data).

These would fail in CI too. Exact final set must be confirmed by a real CI run (local
Playwright diverges from CI in known ways — see memory: font metrics, JS bundle drift,
compile-time PORT, disposable-PG), but local already proves the debt is real and non-trivial.

## Scope of the debt
- **Spans more than Phase 208:** board-cfg-audit is Phase 205; the behavioral-spec breakage
  traces to the v1.36+ admin redesign (pre-205). Phase 208's audit is the proximate trigger
  but not the only source.
- **Blocks everything downstream:** the 294-commit ship, Phase 208 completion, and the
  verification premise of phases 209–211 (all assume these gates are green).

## Recommended remediation approach
1. Fix the 2 env-independent `admin_design` bugs (board-mg-1 count, board-cfg-audit 320px).
2. Reconcile the redesign-broken behavioral specs (`admin_behavior`, `non_admin`,
   `demo_showcase`) — scope selectors to the visible desktop/mobile variant; fix any real UI
   regressions surfaced (sudo heading, org empty-state, etc.).
3. Use the **real CI required check as the arbiter** (not local) — iterate to green. Reuse the
   `wip/recapture-trigger` mechanism to capture board-cfg baselines once `admin-design` is green.
4. Re-validate the unsound "cite-and-flip" audits in 205/206/207/208 by actually running the
   specs, not re-reading code.
5. Then resume the backlog ship (one PR, get current) per the prior decision.
