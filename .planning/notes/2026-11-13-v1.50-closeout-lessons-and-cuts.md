# v1.50 closeout: what we kept, what we cut, what we learned

## Provenance

A long-running local branch carried the whole v1.50 effort (phases 252-258): 2,344 commits ahead of `main`, never pushed, with ~10.5k planning files and ~157k lines of CI-evidence machinery. It was triaged on 2026-11-13 by three independent reviews (shipped product code, CI machinery, planning docs). Nothing was deleted: the full branch, the untracked planning trees and the uncommitted closeout docs were preserved in a private offline backup (git bundle + tarball + patch + checksums, never pushed). Only the items below were folded into `main`.

## Decision: cut losses on the old automated UI/CI-proof process

The screenshot capture/compare, baseline-recapture, drift-guard, adversarial-LLM-panel and evidence-ledger chain was judged inefficient. About 97% of the branch's added lines were single-use evidence, canary or comparison machinery tied to attempts already spent. It never produced a comparable sample (valid pairs 0, median/p95 null). We keep the value already baked into the shipped UI and drop the machinery and its constraints. Admin/operator UI verification is expected to move toward a component catalog (Storybook-style), so Playwright baseline/measurement tooling is discounted.

Kept because it protects something independent: real-login and generated-host smoke, the axe a11y gate, golden install fixtures.

## Lessons (each is a rule we can apply next time)

1. **Terminal-plan counts are not verification.** Count verified outcomes, not plans with a SUMMARY. (v1.50: 157/164 plans terminal, 2/8 phases verified.)
2. **Change a proven-failed prerequisite before any rerun.** The 255.1 loop ended when source selection was fixed, not when more controllers were built. 2,166 artifacts did not buy one sample. Do not build a controller per attempt.
3. **Don't spend remaining samples on an impossible pass.** If a 20-pair comparison cannot be reached, record `insufficient_data` and stop; the honest state beats a staged proof.
4. **Any CI job duplicated for evidence needs a parity test** against the production job, or it goes stale and fails step-parity.
5. **A workflow job can skip while the run reports green.** Read the job, not the run. Required checks live in the ruleset, not classic branch protection; string "404" statuses broke a parser.
6. **Test the assembled candidate tree before publishing.** A publisher that swapped source `.planning` for main's made immutable inputs vanish.
7. **Persist per-test failure text and child stderr.** A driver that discarded collector stderr on non-zero exit hid the root cause; a halted plan must write a terminal record or the route repeats.
8. **Flaky browser tests were test-design bugs, not app bugs.** HTTP can answer before `app.js` exists (async asset build: build assets synchronously before boot, never weaken readiness selectors); a LiveView join wipes a filled field; a collision control asserted UI the app never renders.
9. **A negative result needs a positive control.** "No output" is ambiguous between absent and did-not-run.
10. **Hermetic fakes hide live-host differences.** Five consecutive halts came from fakes that differed from real GitHub (run-name format, redirect hosts, pagination links, stale parents). Prefer one real dry run early over more fixtures.
11. **Long-lived branches rot.** Never leave months of work unpushed. Push early, land small PRs, and keep planning receipts out of the public repo.
12. **Public repo hygiene.** Planning receipts leaked home-directory paths and a personal name into ~3,500 files. Sanitise text on the way in and add a guard (see todos).
13. **Pushing very large packs may fail (hypothesis, untested):** the publisher isolated git config so `http.postBuffer` was ignored; a 324 MiB pack plausibly caused HTTP 400.
14. **Reconciling a diverged branch:** real two-parent merge, per-path resolution, keep main's release fixes, retain only needed phase changes.
