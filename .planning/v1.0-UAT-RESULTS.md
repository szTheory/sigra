# Sigra v1.0 UAT Results

**Date:** 2026-04-10
**Method:** Playwright MCP (browser) + curl + psql + mix test
**Environment:** Docker Postgres 16, `test/example` Phoenix app, local dev
**Outcome:** **BLOCKED on example-app integration bugs — NOT ready for v1.0 release**

## Executive summary

The Sigra **library** (the code shipped to end users via hex) appears healthy: the `mix test --include example_app` suite runs 34/34 green, `mix docs` generates all 15 guides + 112 module docs, and the library modules called directly from `mix run` work correctly (registration, session creation, TOTP, audit logging at the API level).

The **example app** (`test/example/`) has **7 distinct integration bugs** that make it unusable as a browser demo — the first things any new user would try after cloning. Three of these blocked every browser-based UAT attempt I made. I fixed three in-session; four remain. Nothing in the runbook past UAT 4.1 was reachable in the browser.

**Recommendation:** Do NOT ship v1.0 until `test/example/` is fixed or replaced. The example app is what `mix sigra.install` on a fresh `mix phx.new` is supposed to produce, and if this one is broken, so is the generator output. Either (a) treat the 7 bugs below as a v1.0 hotfix phase, or (b) acknowledge the gap, ship v1.0 as "library works, bring your own example app", and file an explicit v1.0.1 for generator/example fixes.

## Bugs found in test/example (the highest-signal output of this UAT session)

| # | File | Bug | Status | Severity |
|---|------|-----|--------|----------|
| B1 | `priv/static/assets/js/app.js` | Was a stub ("copy phoenix_live_view.js here") — no JS bundle at all. `window.liveSocket` undefined, LiveView interactions impossible. | **FIXED in session** (concatenated phoenix_html + phoenix.min + phoenix_live_view.min + LiveSocket init) | Critical |
| B2 | `lib/example_web/endpoint.ex:14-16` | `socket "/live", Phoenix.LiveView.Socket` block was commented out. WebSocket and longpoll both 404 on `/live/websocket`. | **FIXED in session** | Critical |
| B3 | `lib/example_web/router.ex` `:browser` pipeline | Missing `plug :fetch_current_scope`. `conn.assigns.current_scope` was never set, so `require_authenticated_user` always redirected regardless of session cookie. Nobody could log in via browser. | **FIXED in session** (added `import ExampleWeb.UserAuth` at top of module + `plug :fetch_current_scope`) | Critical |
| B4 | `lib/example_web/router.ex` auth scope | Missing `live_session` blocks with `on_mount` callbacks. LiveViews under `:require_authenticated` pipeline crashed with `KeyError: key :current_scope not found` because on_mount hooks weren't wired. | **FIXED in session** (wrapped auth/unauth/mfa-challenge scopes with `live_session` blocks pointing at `UserAuth.ensure_authenticated`, `:redirect_if_user_is_authenticated`, `:mount_current_scope`) | Critical |
| B5 | `lib/example_web/live/registration_live.ex:82` | Comment says `# Phase 3 will send confirmation email here` — it's a stub. Registration never delivers the confirmation email. New users are unconfirmed but can still log in silently. | NOT FIXED | High (contradicts getting-started.md step 3, which describes clicking the confirmation link from `/dev/mailbox`) |
| B6 | `lib/example_web/live/login_live.ex:45` + `lib/example_web/user_auth.ex:58-67` | **Two parallel session systems wired in the same app.** `UserAuth.log_in_user` calls `Example.Accounts.generate_user_session_token` which writes to the `user_tokens` table (phx.gen.auth legacy store). But `Example.Accounts.list_sessions` (used by `Auth.SessionLive`) queries `user_sessions` (Sigra's store). So login writes to one table and the sessions LiveView reads from another. **The sessions page is permanently empty regardless of how many times you log in.** | NOT FIXED | Critical |
| B7 | `lib/example_web/controllers/auth/sudo_html.ex` (template) | `GET /users/sudo` crashes with `KeyError: key :value not found` — template references a form field that doesn't exist in the controller assigns. | NOT FIXED | High (sudo flow completely broken) |
| B8 | `priv/repo/migrations/*_create_audit_events.exs` | `audit_events.actor_id` is `uuid` but `users.id` is `bigint`. Type mismatch — audit log rows referencing users will fail on insert. Confirmed `audit_events` is empty despite successful logins. Either the audit writes are silently failing, or they're not wired at all in UserAuth. | NOT FIXED | Critical (audit log is unusable) |
| B9 | `lib/example_web/live/login_live.ex` (password login form) | The password login form inside LoginLive has `phx-update="ignore"` but is still inside a LiveView that intercepts form submit events. Both the Playwright `page.click()` and `form.submit()` calls are swallowed — no HTTP POST ever leaves the browser. Curl can POST to the endpoint fine. Only real-browser users are affected. | NOT FIXED | High (password login broken in Playwright; possibly real browsers too depending on LiveView submit event handling) |

**Also flagged during doc review** (not bugs per se, but drift):

- `guides/introduction/getting-started.md` uses `/users/log-in` (hyphen) throughout, router uses `/users/log_in` (underscore). Same for `/users/log-out` vs `/users/log_out`.
- Guide references `UserRegistrationLive`, actual module is `RegistrationLive`.
- Guide shows `plug :fetch_current_scope_for_user` + `on_mount :require_authenticated`, example app uses `plug :fetch_current_scope` + `on_mount :ensure_authenticated`.

## Environment / setup findings

- **Homebrew postgres@14** was already bound to `127.0.0.1:5432`, colliding with the Docker container. Had to `brew services stop postgresql@14` before `scripts/uat/up.sh` could make the example app connect. User needs to `brew services start postgresql@14` post-UAT. Runbook should mention this collision case.
- **`scripts/uat/RUNBOOK.md` estimates 90-150 min** — that assumes a working example app. With the bugs above, 0 minutes of manual UAT were actually reachable past item 4.1.
