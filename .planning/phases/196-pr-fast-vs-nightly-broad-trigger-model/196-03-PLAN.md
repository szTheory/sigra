<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `workflow_dispatch` input → CI job execution | The `force_fail_probe` input is attacker-reachable only by actors who can already dispatch the workflow (write access). It drives nothing but an `exit 1`; it grants no privilege, reads no secret, and cannot be set on `pull_request`/`schedule`/`push` events. |
| GitHub event → probe job `if:` | The probe host's `if: github.event_name != 'pull_request'` ensures the probe can never red a PR even if force_fail were somehow set on a PR-triggered run. |

## STRIDE Threat Register (ASVS L1, block-on high)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-196-03-01 | Elevation of Privilege | `force_fail_probe` workflow_dispatch input | mitigate | The input is a `type: boolean` that only triggers `exit 1` — no privileged effect, no secret access, no token scope change; cannot be set on PR/schedule events (dispatch-only). `permissions: contents: read` (ci.yml) preserved; the probe job adds no elevated permissions. |
| T-196-03-02 | Denial of Service | probe pre-empting a required lane / reding a PR | mitigate | Probe host is `if: github.event_name != 'pull_request'` (never runs on PRs) and is `needs`-free + NOT in ci-gate.needs, so it cannot block a PR, cannot be pre-empted by release_ref_guard, and cannot drag the aggregator. |
| T-196-03-SC | Tampering | npm/pip/cargo installs | accept | No package installs introduced this plan (edits ci.yml only); package legitimacy gate not applicable. |
</threat_model>
