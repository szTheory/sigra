<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| published Hex latest `0.3.x` -> tmp consumer app | Untrusted dependency-resolution and generator output cross into the proof harness |
| tmp consumer app -> local candidate source | Upgrade proof must not assume fresh-install equivalence |
| CI job -> release evidence | A misleading or incomplete smoke lane would tamper with release confidence |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-147-01 | Tampering | `scripts/ci/upgrade-smoke.sh` | mitigate | Resolve the semver-highest published `0.3.x` at runtime, log the selected version, honor only a validated explicit override, and fail if no `0.3.x` exists before switching the same tmp app to the local source. |
| T-147-02 | Repudiation | `.github/workflows/ci.yml` `upgrade_smoke` job | mitigate | Use a distinct job id and log surface so release evidence can prove the upgrade lane ran and failed or passed independently of `install_smoke`. |
| T-147-03 | Denial of service | tmp app boot/migration path | mitigate | Require `mix compile --warnings-as-errors`, `mix ecto.migrate`, and a boot route check to catch release-blocking regressions before publish. |
| T-147-SC | Tampering | package/dependency resolution | accept | No new npm/pip/cargo packages are added in this plan; the lane reuses existing Elixir/Phoenix toolchain setup. |
</threat_model>
