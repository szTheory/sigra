## Spacing Scale

The sg-* spacing scale is value-locked at Phase 186. Phase 189 consumes these values; it does not change them.

| Token | Value | Usage in L3 pages |
|-------|-------|-------------------|
| --sg-space-1 | 4px (0.25rem) | Icon gaps, inline padding within chips |
| --sg-space-2 | 8px (0.5rem) | Compact element spacing, button gaps |
| --sg-space-3 | 12px (0.75rem) | Intra-section padding (inside cards) |
| --sg-space-4 | 16px (1rem) | Default element spacing, dialog padding, scrim inset |
| --sg-space-6 | 24px (1.5rem) | Card internal stack (sg-stack--3 = --sg-space-6 via gap scale) |
| --sg-space-8 | 32px (2rem) | Major section gaps (sg-stack--6 = double that) |
| --sg-space-10 | 40px (2.5rem) | Page-level top/bottom padding |
| --sg-space-12 | 48px (3rem) | Between major page sections |

Stack class mapping (canonical — do not deviate):
- `sg-stack--3` = 12px gap between children (intra-card)
- `sg-stack--4` = 16px gap (inside cards per design contract)
- `sg-stack--6` = 24px gap (between major sections on a page)

No new spacing tokens. No raw pixel values in inline styles (the existing `style="margin-top: var(--sg-space-3);"` in user_show_live.ex and branding_live.ex is a documented exception from a prior phase; Phase 189 does not introduce additional inline-style spacing).

Exceptions: touch targets for destructive confirm buttons must be at least 44px tall. This is satisfied by `--sg-control-md: 2.75rem (44px)` on `.sg-btn`.

### Accent reserved-for list

Ember accent (`--sg-color-brand`, `--sg-color-brand-strong`) is reserved exclusively for:
1. Primary action buttons (`sg-btn--primary`) — e.g. "Manage users", "Customize branding"
2. Selected/active navigation states in `sg-admin-topbar`
3. Focus rings on brand-surface elements (`--sg-color-brand` ring at 3px)
4. Sigra logo mark and lockup (rail-block tittle, g-tail)

Accent is NOT used for: every heading, every icon, informational status badges, or hover-only states on non-primary elements.

## Page Archetypes — L3 Interaction Contracts

These are the scored surfaces for Phase 189. Each has its own interaction sub-contract.

### PAGE-01: Overview Archetype — index_live.ex + organization_live.ex

**IA order (GOV.UK derived — tasks-first / posture-second / capabilities-last):**

```
[1] Page header (h1 + kicker + copy)         — where am I / what is this page for
[2] Alarm notice (ok or risk tone)           — most urgent posture signal (posture)
[3] Task-card grid (primary CTAs)            — main actions (tasks-first)
[Org only] Member roster + invitations tail  — scoped capabilities (capabilities-last)
```

No `page_back` on Overview screens — enforced by archetype contract.
Breadcrumb: single crumb "Overview" on index_live; "Org Overview" (or equivalent) on organization_live.
Scope: visible in `sg-admin-topbar` (sg-scope-pill) and in page body via scope_ribbon on list/leaf screens (NOT on Overview — topbar pill is sufficient).

**Vertical rhythm:**
- `sg-stack--6` between header, alarm, task-card grid, and org tail sections
- No double-gap: do not wrap the page in an additional sg-stack outside the page-level section element
- No flush: no adjacent major sections without the sg-stack--6 gap

**Focus on LiveView navigate:** scroll reset to top; focus moves to `<h1>` (the page title).

### PAGE-02: List Archetype — users_index_live.ex

**IA order:**

```
[1] Page header (h1 + kicker + copy + summary_chip strip)  — context + posture
[2] Scope ribbon                                           — always visible
[3] Filter panel                                           — task entry point
[4] Applied chips row (conditional)                        — active filter state
[5] Results (table desktop / card mobile)                  — primary content
[6] Empty state (conditional)                              — zero-result feedback
[7] Pagination (conditional, honest)                       — navigation
```

Pagination honesty (D-09): `show_pagination?` guard must prevent phantom pagination controls when total results fit on one page. No fake "page 1 of 1" with disabled controls — if one page, hide the pagination nav entirely.

Sticky header behavior: if the filter panel or results header is sticky-positioned, it must use `position: sticky; top: <topbar-height>` without layout shift. No fixed positioning that causes reflow. The topbar is already sticky; page content scrolls beneath it.

**Focus on patch (filter apply):** focus stays on or returns to the filter input/submit that triggered the patch — do not reset to h1 on filter-apply patches.

### PAGE-03: Detail Archetype — user_show_live.ex

**IA order:**

```
[1] Scope ribbon (visible before header — context first)
[2] Page header (breadcrumbs + h1 + summary facts + status notice)
[3] Sessions card
[4] Detail grid (Security + Identities panels)
[5] Organizations card
[6] Recent Audit card
[7] Danger zone (destructive — last, secondary)
[8] Confirm dialog (portal-overlay — above all content when active)
```

**Danger zone placement:** last section on page, visually demoted (`sg-danger-panel`). Destructive action buttons inside danger zone only, never in header or primary content regions.

**Confirm dialog (PAGE-03 modal — net-new JS):**

The `sg-confirm-overlay` / `sg-confirm-dialog` markup already exists and is correctly centered by CSS. What is missing and must be added: a LiveView JS hook providing WAI-ARIA APG "Dialog (Modal)" behavioral compliance.

Hook attachment: add `phx-hook="ConfirmDialog"` (or equivalent name — planner decides the exact name) to the `.sg-confirm-overlay` element in both `user_show_live.ex` and `branding_live.ex`.

**Required behaviors (APG Dialog — hard gates for ratification):**

| Behavior | Requirement | Implementation guidance |
|----------|-------------|------------------------|
| Initial focus | On open: first focusable element inside `.sg-confirm-dialog`, or the Cancel button for destructive confirms | `mounted()`: query focusables inside dialog; `focus()` the first (or Cancel) |
| Focus containment | Tab/Shift-Tab cycles within dialog only; cannot Tab out to background | `trapFocus()` on keydown Tab — same pattern as CmdK.trapFocus |
| Escape closes | Keydown `Escape` within document closes the dialog and returns focus | document-level keydown listener while dialog is open; `pushEvent("cancel_confirm")` or equivalent |
| Cancel/close returns focus | On close (Escape or Cancel or confirm): focus returns to the element that triggered the dialog open | Store `document.activeElement` before open; `el.focus()` after server closes overlay via `:if` binding |
| role="dialog" | Present on `.sg-confirm-dialog` | Already in markup — do not remove |
| aria-modal="true" | Present on `.sg-confirm-dialog` | Already in markup — do not remove |
| aria-labelledby | Points to the confirm title `<p id="...">` | Already in markup — verify id matches |
| Background non-interactive | Background content must not receive keyboard or pointer focus while dialog is open | JS implementation: either `inert` attribute on `.sg-admin-shell` content, or JS focus-wrap that intercepts Tab at boundaries (APG-conformant either way — score the behavior, not the technique per D-07) |

**Optional enhancements (NOT hard-fail gates per D-08):**

| Enhancement | Notes |
|-------------|-------|
| Outside-click dismissal | The scrim `.sg-confirm-overlay` click triggers close (same as CmdK) — implement if it does not add risk; not required for ratification |
| Body scroll-lock / scroll-restore | Add `.sg-body-scroll-locked` class to `<body>` on open, remove on close; CSS: `body.sg-body-scroll-locked { overflow: hidden; }` — helpful for mobile but not a ratification gate |

**CmdK non-interference:** The new hook MUST be a separate named hook (e.g. `ConfirmDialog`), not a modification to `CmdK`. Planner decides whether to share a private `trapFocus` helper or duplicate-and-specialize. Do not risk the ratified CmdK behavior.

**Trigger element tracking:** The hook must capture `document.activeElement` at `mounted()` time (when the overlay becomes visible via `:if`) and restore focus to that element on destroy/close. Since the overlay is conditionally rendered via `:if`, `mounted()` fires on show and `destroyed()` fires on hide — use these lifecycle callbacks.

**CSS additions needed (lands in @layer sg-components):**

```css
/* Body scroll-lock (optional enhancement, commit regardless for completeness) */
body.sg-body-scroll-locked {
  overflow: hidden;
}
```

No other new CSS is needed for the modal — centering, backdrop, animation, and dialog sizing are already in sigra_admin.css lines 637–675.

### PAGE-04: Non-archetypal pages

**Branding customizer — branding_live.ex:**

Scored on bespoke IA for a settings/customizer page:
- Tabs (`sg-tabs`) for Light / Dark / Details sections — each tab is one thing per page
- Preview panel adjacent to controls (not overlapping)
- Destructive "Restore defaults" action last in the page, triggers the confirm dialog
- The confirm dialog in branding_live.ex gets the same ConfirmDialog hook (same behavior contract as above)

**Audit explorer — audit_index_live.ex + audit_user_live.ex:**

Scored on bespoke IA for a filter+export explorer:
- Filter panel first, results second, export/actions last
- Per-user audit (audit_user_live.ex) uses breadcrumbs for return context, not page_back
- Pagination honest (same `show_pagination?` guard pattern)
- Mobile: table-to-card swap at breakpoint, content-equivalent

### PAGE-05: Page-level a11y

Applies to all 6 LiveViews:

| Requirement | Pass criterion |
|-------------|----------------|
| Landmark regions | `<main>` wraps all page content; `<nav>` for breadcrumbs/tabs; `<header>` for page header |
| Heading order | `<h1>` = page title; `<h2>` = section headings; no skipped levels |
| Focus management on navigate | Full LiveView navigate: scroll reset, focus to `<h1>` |
| Focus management on patch | Patch (filter apply, etc.): focus stays in updated region or returns to trigger |
| Focus management on dialog open/close | See PAGE-03 above |
| axe wcag2a + wcag2aa | 0 violations on all 8 checkpoints × 3 projects |

## Animation Contract — Modal Entrance

The `sg-confirm-enter` keyframe is already defined (sigra_admin.css lines 666–675):

```
from: opacity 0, translateY(0.375rem) scale(0.98)
to:   opacity 1, translateY(0) scale(1)
```

Duration: `--sg-motion-pop` (180ms). Easing: `--sg-ease-out`. Both are Phase 186 locked values.

`prefers-reduced-motion: reduce` is handled by the global clamp at the bottom of sigra_admin.css — the animation strips to 0.01ms. No new reduced-motion rules needed for the dialog.

The ConfirmDialog JS hook does NOT add any additional animation. Open/close transitions are CSS-only.

**Modal interaction assertions (PAGE-03 evidence — required, deterministic):**

These must be deterministic, role-selector-based, no sleeps:

1. Open confirm dialog (click a destructive action trigger)
2. Assert: focus is inside `.sg-confirm-dialog` (e.g. `document.activeElement` is Cancel button)
3. Assert: Tab cycles within dialog (Tab from last focusable wraps to first)
4. Assert: Escape closes the dialog (overlay removed / hidden)
5. Assert: focus returns to the trigger element after close
6. Assert: aria attributes present (`role="dialog"`, `aria-modal="true"`, `aria-labelledby`)
7. axe scan while dialog is open (must pass wcag2a + wcag2aa with dialog visible)

**Snapshot recapture:** If the ConfirmDialog hook or scroll-lock CSS changes the visual output of any checkpoint (e.g. the overlay visible in a snapshot), that snapshot gets added to the allowlist and recaptured via `scripts/ci/snapshot-recapture-gate.sh`. The canary must remain green (canary slug untouched).

**Monotonic guard:** The 6 L3 ledger rows are already at Tier 1. Phase 189 must not decrease any tier. Evidence must be executable (Playwright + axe commands, not intent notes).
