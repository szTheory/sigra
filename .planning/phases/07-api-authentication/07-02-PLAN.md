    ```elixir
    defmodule Sigra.JWT.Signer do
      @moduledoc """
      JWT key loading and signer creation.

      Derives signing keys from the application's `secret_key_base` for HS256,
      or loads PEM keys for RS256/ES256.
      """

      @doc "Ensures Joken is available. Raises with clear message if not loaded."
      def ensure_joken! do
        unless Code.ensure_loaded?(Joken) do
          raise RuntimeError, """
          Joken is required for JWT support but is not available.

          Add {:joken, "~> 2.6"} to your mix.exs deps and run mix deps.get.
          """
        end
      end

      @doc "Creates a Joken.Signer for the configured algorithm."
      @spec create_signer(Sigra.Config.t()) :: struct()
      def create_signer(config) do
        ensure_joken!()
        jwt_config = config.jwt
        algorithm = Keyword.get(jwt_config, :algorithm, "HS256")

        case algorithm do
          "HS256" ->
            secret = config_secret_key_base(config)
            key = :crypto.mac(:hmac, :sha256, secret, "sigra-jwt-signing-key")
            Joken.Signer.create("HS256", key)

          "RS256" ->
            pem = Keyword.fetch!(jwt_config, :private_key)
            Joken.Signer.create("RS256", %{"pem" => pem})

          "ES256" ->
            pem = Keyword.fetch!(jwt_config, :private_key)
            Joken.Signer.create("ES256", %{"pem" => pem})
        end
      end

      defp config_secret_key_base(config) do
        # The host app must provide secret_key_base in config
        # This is typically available via endpoint config
        config.secret_key_base ||
          raise RuntimeError, "secret_key_base is required for JWT HS256 signing"
      end
    end
    ```

    NOTE: config.secret_key_base may not exist yet on Sigra.Config. The executor should add a `secret_key_base` field to the Config struct if not present, with type `{:or, [:string, nil]}` and default nil. Check config.ex first. If it doesn't exist, add it as a top-level config option.

    Refresh tokens are stored in the existing user_tokens table with `context: "api_refresh"`.

    The user_tokens table schema (from Phase 1) has: hashed_token, context, sent_to, inserted_at.
    For refresh tokens, repurpose `sent_to` to store JSON metadata: `{"family_id": "uuid", "scopes": [...], "superseded_at": null}`.

    Alternatively, if the token schema has flexible fields, use them. The executor should check the actual user_tokens schema. If it doesn't have family_id/superseded_at columns, store them as JSON in an available text/jsonb column OR add a separate `user_refresh_tokens` approach. The simplest approach per existing patterns: store `family_id` and `superseded_at` and `scopes` as JSON in `sent_to` field.

    Functions:

    `create(config, user, scopes)`:
    - Generate hashed token via `Sigra.Token.generate_hashed_token/0`
    - family_id = `Ecto.UUID.generate()`
    - Insert into user_tokens: context "api_refresh", user_id, hashed_token, sent_to = Jason.encode!(%{family_id: family_id, scopes: scopes, superseded_at: nil})
    - Return `{raw_token, token_record}`

    `rotate(config, raw_token)`:
    - Hash raw_token, look up in user_tokens where context = "api_refresh"
    - If not found: `{:error, :invalid_token}`
    - Decode sent_to JSON metadata
    - If superseded_at is not nil: REUSE DETECTED
      - Call `revoke_family(config, family_id)` to set superseded_at on ALL tokens in family
      - Emit `[:sigra, :jwt, :refresh_reuse_detected]` telemetry event
      - Return `{:error, :reuse_detected}`
    - If token expired (check inserted_at + refresh_ttl): `{:error, :token_expired}`
    - Mark current token as superseded: update sent_to JSON with superseded_at = now
    - Create new token in same family_id
    - Return `{:ok, raw_new_token, new_record, old_scopes}`

    `revoke(config, raw_token)`:
    - Hash, find, mark superseded

    `revoke_family(config, family_id)`:
    - `UPDATE user_tokens SET sent_to = jsonb_set(sent_to, ...) WHERE context = 'api_refresh' AND sent_to LIKE '%family_id%'`
    - Simpler approach: fetch all tokens with matching family_id in sent_to, update each
    - Return `{:ok, count}`

    `verify_access(config, jwt_string)`:
    - Create signer, verify via `Joken.verify_and_validate(%{}, signer, jwt_string)` -- verify Joken API
    - Check standard claims: exp not passed, signature valid

    - Wrap in telemetry span `[:sigra, :jwt, :verify]`

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API client -> JWT verify | Untrusted JWT from Authorization header; signature must be verified |
| Refresh token -> rotate | Untrusted opaque token; must detect reuse of superseded tokens |
| Claims -> application | JWT claims are signed but epoch must be verified against DB |
