<objective>
Let a documentation-only pull request stop paying for the full job matrix, without ever letting a
required check hang pending and without removing the coverage a docs change most needs.

Two constraints shape the whole design. First, D-06: a required workflow filtered at the trigger
never creates its check contexts, so all five ruleset-14941512 contexts would sit waiting for status
and the PR would be permanently unmergeable — the gating must live at the job and step level.
Second, a finding CONTEXT.md does not cover: `fast_checks` and `library_tests` are exactly the lanes
a docs-only PR most needs. `milestone-verification-gate.sh` walks `.planning/**`,
`getting-started-contract.sh` link-checks `guides/introduction/getting-started.md`, and 13 ExUnit
files under `test/sigra/planning/` and `test/sigra/*guides*` read those paths directly. Gating either
off would turn FAST-05 into a coverage hole in the one dimension the PR actually changes.

Purpose: collapse a docs-only PR from ~29.5m to roughly the cost of `fast_checks` plus `library_tests`.
Output: one `changes` job with a fail-open output, consumed at step level by the four app-behaviour
required lanes and at job level by one non-required lane.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PR head branch name / base ref → `run:` shell | An attacker-influenced context string reaching a shell body is a workflow-injection vector |
| `changes` job result → required lane execution | If a classifier failure can skip a required lane, the ruleset's guarantee is broken |
| `git diff` classification → coverage | A misclassified diff silently removes the matrix from a change that needed it |
