<objective>
Restore Playwright browser binaries from cache on the one PR-path job that still installs them, and
ship the guard that stops the hard-coded version in the cache key from silently rotting.

Two honesty constraints bind this plan. First, D-15: the install step measures 61s, but only ~14s is
the cacheable browser download — the ~33s system-dependency install lives in `/usr/lib` and is not
cacheable — and after FAST-03 only one PR job benefits. The honest expected win is ~15-25s, and on a
cache miss the post-job upload of the binaries is new cost. FAST-06 is a milestone requirement so it
lands, but the phase must not claim a ~62s win.

Second, a hazard CONTEXT.md does not cover: `package.json` declares `"@playwright/test": "^1.48.0"`
while the lockfile resolves 1.59.1. A literal version in the cache key means a future lockfile bump
leaves the key unchanged, an exact hit restores the *old* browser revision directory, the hit branch
runs only the dependency install, and Playwright fails at test time with a missing-executable error.
D-18 prefers the literal over a lockfile hash (which churns on unrelated dependency changes), so the
hole is closed with a guard rather than by changing the key strategy.

Third, an evidence constraint that shapes how FAST-06 is proven at all: a brand-new cache key can
only *miss* on the run that introduces it. There is no run in this phase that can log a hit on its
own — the key-introducing run misses by construction, intermediate phase-branch runs superseded by
plan 04's `cancel-in-progress` never reach the `actions/cache` post-step and so never save,
AFTER-DOCSONLY is a post-merge obligation rather than an in-phase run (and in any case gates the
whole Playwright lane off), and AFTER-NONPR and AFTER-PUSH each sit in a
different cache scope (`refs/heads/…`) from the pull request's (`refs/pull/<n>/merge`). The proof is
therefore a **miss-then-hit pair on the same pull request**, captured deliberately by plan 09 Task 1:
one run that misses and saves, then a second run on the same pull request that hits. That is
falsifiable in both directions; "a PR run logs a hit" is not.

Purpose: land FAST-06 with an honest measurement and no rot surface.
Output: a SHA-pinned cache step, a branched install, a summary line, and a guard-plus-self-test pair
wired into `fast_checks`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions cache → runner filesystem | Restored cache content becomes executable browser binaries on the runner |
| Third-party action → runner | `actions/cache` executes with the runner's token |
| Lockfile → cache key | A version mismatch silently substitutes the wrong binaries |
