<objective>
Move the 84 per-board PNG assertions off the PR critical path without moving the accessibility
signal, and without letting the baseline-recapture lane lose them.

The `design_gallery` step is 866s of a 28.5m job that is itself the sole PR critical path. Filtering
it to the untagged set leaves the WCAG scans and the L1-state behaviour tests on every PR, while a
second, event-gated step runs the pixels on push, schedule and dispatch — inside the same job, so a
push-to-main snapshot regression still reds a ruleset-required context (D-04).

Purpose: reclaim the largest single block of PR wall-clock in the phase.
Output: two complementary gallery steps whose executed-test counts are falsifiable, with the new
step's id wired into the aggregator that decides whether the job goes red (D-05).

Proof discipline for this plan is D-24: FAST-02 is proven by the run's own executed-test count, never
by reading YAML. The PR run must show the accessibility and behaviour tests executing and the tagged
tests absent; the non-PR run must show the tagged tests executing and hard-fail capable. Static reads
of `ci.yml` or the spec are necessary-but-not-sufficient pre-checks only.
