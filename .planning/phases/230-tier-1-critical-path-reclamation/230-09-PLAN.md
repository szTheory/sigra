<objective>
Capture the observed-run half of the phase — the half the phase is actually judged on.

Every success criterion here is a claim about what a run *did*.
`.planning/v1.42-CI-GATE-REMEDIATION-FINDINGS.md` records a milestone that passed audits which were
"code-level reads that never executed the specs" while the required Playwright check carried about 15
real failures. This plan is the correction: five real runs, each captured with a verbatim run ID
through the script committed in plan 01, plus one explicitly pending post-merge slot — and, where a
run could not be obtained at all, an evidence class that says so in the per-requirement table rather
than a substitute wearing an observation's clothes.

The fifth run is AFTER-PR-WARM, and it exists for a structural reason: a brand-new cache key can only
*miss* on the run that introduces it, so FAST-06's hit is unobservable from any single slot. It needs
a second run on the same pull request, in the same cache scope, after the first has completed and
saved.

Purpose: make the before/after pair real and re-fetchable.
Output: a completed `230-EVIDENCE.md`.

D-24 binds the FAST-02 evidence specifically: it is proven by each run's own executed-test count, not
by reading YAML. D-21 binds every duration: it is produced by the committed measurement script, so
the AFTER numbers are computed by the same method as the baseline.
</objective>
