> in the session that planned this phase.

- [ ] CONSTRAINT: **BSD `wc -l` false negative** — `… | wc -l | grep -qx "0"` can NEVER match on darwin (BSD `wc` pads to `"       0"`), so a verify built on it reds on a *correct* tree. The plan-checker caught this in four Phase 241 tasks. — Structural mitigation: every verify that counts a diff must use `test -z "$(git diff --name-only …)"`. Grep the plans for `wc -l` before executing and reject any survivor.
- [ ] CONSTRAINT: **A bare non-zero exit is not proof of RED** — a compile error or a broken parse also exits non-zero. — Structural mitigation: every RED proof must grep stderr/stdout for the guard's own assertion message, naming the specific failure token.

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| BSD `wc -l` \| `grep -qx "0"` | Padded output can never match; fails on a correct tree — a false negative in the reassuring direction | blocking | Use `test -z "$(git diff --name-only …)"`; grep plans for `wc -l` before executing |
| Unattributable RED | Non-zero exit taken as proof the guard fired, when a compile error produces the same exit | blocking | Grep for the guard's own failure token in output |
| Consistent-rename "mutation" | Renaming a token everywhere leaves the guard functional — the suite stays green and the test looks vacuous-proof | blocking | Mutate by neutering the guard's condition, not by renaming its label |
| Waiting on `gh pr checks` with `grep -qv pending` | Matches a joined string like `pass,pending` and exits while checks still run | advisory | `until [ "$(gh pr checks N --json bucket --jq '[.[]\|select(.bucket=="pending")]\|length')" = "0" ]` |
| §13a decision bullets in bare `##` prose | The coverage gate scans only frontmatter and specific headings/tags — a `D-NN:` in bare prose is invisible | advisory | Use `- **D-01:** text` with the bold closing on the same line; pass BOTH positional args to `check.decision-coverage-plan` |
