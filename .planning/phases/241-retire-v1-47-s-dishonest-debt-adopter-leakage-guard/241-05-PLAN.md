<objective>
Land the first two of `p18`'s three hard-fail classes — `.planning/` paths, and bookkeeping tokens in
`priv/templates/` — as sibling offline guards over a shared ported helper, each proven RED against
its own single-violation fixture.

Purpose: SURF-04. Phases 237 and 239 cleaned these surfaces by hand; nothing stops the next commit
from re-dirtying them. A guard is what converts a one-time sweep into a property.
Output: one shared helper, two guards, one ported allowlist, two known-bad fixtures.

### Decisions implemented by this plan

- **D-23:** the `.planning/` class is **literal-string** based and deliberately does **not** use the
  wide bookkeeping vocabulary. Running that vocabulary over the packaged-docs surface yields
  hundreds of matching lines at HEAD, overwhelmingly `CHANGELOG.md` legitimately citing phase
  numbers — the traceability the Out of Scope table protects.
- **D-24:** `guides/` is out of scope. The Hex `files:` list omits it, so guides never ship in the
  tarball; they reach HexDocs only at docs-build time via `extras:`. This closes the guides-scan
  todo **as a decision**, not as work.
- **D-25:** each hard-fail class gets its **own** fixture with exactly one violation, so each is
  independently reachable. Task 3 proves the independence explicitly rather than assuming it: each
  fixture must red its own guard **and** leave the sibling guard green.
- **D-26:** the `priv/templates/` clean-side assertion carries a real positive control, because with
  only one matching line in that surface at HEAD a zero is otherwise indistinguishable from an empty
  file list. The allowlist is ported along with the regex — the single HEAD hit is an allowlisted
  false positive inside a committed third-party brand mark, and a guard that hard-fails without the
  allowlist reds at HEAD on a logo.
- **D-27:** the guards are named `p18-*.test.mjs` under `scripts/ci/prohibitions/`, which is what
  earns zero-workflow-edit pickup. The glob's `run:` line is re-located **by content** at execution
  time; the `:393` the roadmap cites is stale (it was `:408` at research HEAD). The `mix ci` alias
  has no node leg, so a `.mjs` guard cannot enter `mix ci` by construction.
</objective>
