<objective>
Land `p18`'s third hard-fail class — planning-artifact tokens inside HexDocs-rendering doc ranges —
and the three-counter monotonic-decrease ratchet, each counter with its own committed baseline, its
own written definition, and its own independently reachable RED.

Purpose: SURF-04's second half. A ratchet is the only honest instrument for a surface where zero is
not the target; three counters are the only honest shape for three surfaces that move for unrelated
reasons.
Output: one hard-fail guard, one ratchet guard, one baseline file, four known-bad fixtures.

### Decisions implemented by this plan

- **D-22:** three separate monotonic counters, each with its own committed baseline and its own
  reproducible command, never one fused total. Baselines are **re-measured at execution HEAD** and
  the measured values committed; the research figures (R1 337 sites-and-files 254/69, R2 220, R3 58,
  all reproduced by the orchestrator at planning HEAD) are orientation, not values to paste.
- **D-25:** each counter's RED is independently reachable via its own committed known-bad baseline
  fixture. One fixture lowering all three counters would prove one assertion while declaring three —
  the short-circuit defect a pending todo already records against an earlier guard.
- **D-28:** the three counters do **not** share one vocabulary, and this plan states so in writing —
  see `## Settled: the three counter definitions` below — because a reader will otherwise assume the
  wide vocabulary throughout.
- **D-29:** the two proposed vocabulary widenings are **declined for v1.48**, decided here and
  recorded **before** any baseline is committed — see `## Settled: the two widenings` below.
- **D-30:** R1's committed Python scanner is reusable but is Python, and the job that owns the
  prohibitions glob declares no Python setup. The extractor is ported to JS inside the guard, and the
  Python run is kept as a one-time cross-check that the port reproduces the same total at the same
  commit.

### Settled: the three counter definitions (research open question 3)

Stated explicitly, because R1 and R2 come from **different** token sets and a reader who assumes one
vocabulary throughout will "fix" a discrepancy that is not one.

| Counter | Surface | Vocabulary | Reproducible command (recorded in the baseline file header) |
|---|---|---|---|
| **R1** | `@moduledoc` / `@doc` / `@shortdoc` / `@typedoc` heredoc ranges under `lib/` | the **narrower** committed Phase-237 scanner token set — this is where R1's number comes from | the committed Python scanner over `lib/`, and the JS port that reproduces it |
| **R2** | comment-only lines in tracked `lib/` Elixir sources | the **wide** committed Phase-239 vocabulary | the committed `git ls-files`-driven comment grep piped through the wide vocabulary |
| **R3** | the packaged-docs surface — the `docs/`, `README.md` and `CHANGELOG.md` files the Hex `files:` list actually packages | the **literal** planning-directory path string only (D-23) | the literal-string occurrence count over the packaged-docs file list |

R3 uses the literal string and not the wide vocabulary because the wide vocabulary over that surface
matches hundreds of lines at HEAD, overwhelmingly `CHANGELOG.md` legitimately citing phase numbers —
a ratchet nobody can move, on a file Phase 242 owns.

### Settled: the two widenings (research open question 2 / D-29)

**Decision: decline both for v1.48. Adopt neither before committing the baseline; record both, with
their measured cost, for a future phase.** This is a planner decision, not a checkpoint, because it
is fully determined by a locked decision rather than by preference: D-22 pins R2 at the value the
**unwidened** vocabulary measures, and adopting a widening would move R2 above it, contradicting a
locked decision the planner has no authority to overturn.

Three supporting reasons, recorded so the decline is auditable:

1. The wide vocabulary is a **committed, runnable spec**. A `p18` carrying a locally-widened variant
   would fork the definition and create a second source of truth — the defect class this phase exists
   to retire.
2. The cost of declining was **measured, not assumed**. Case-folding the whole vocabulary over the
   `lib/` comment surface at planning HEAD moves R2 from 220 to 221 — a delta of exactly one line,
   and that is an upper bound, since folding the entire vocabulary is broader than folding only the
   plan-reference alternations. The known lowercase miss is a single line in a Playwright spec under
   `test/example/`, which is outside every ratcheted surface.
3. Block-aware matching is a genuine unknown that cuts both ways: it would catch phrases split across
   two comment lines, and it would also raise false-positive risk across line boundaries. It is a
   widening no locked decision authorizes, and it cannot be costed without implementing it.

Task 3 records both widenings, the measured delta, and the surviving gap on the existing pending
todo rather than closing it.
