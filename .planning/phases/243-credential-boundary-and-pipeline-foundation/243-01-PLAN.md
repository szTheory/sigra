<threat_model>
## ASVS posture

Level 1; blocking threshold high.

## Trust Boundaries

| Boundary | Description |
|---|---|
| Authorization header → PAT verifier | Untrusted bearer input reaches the single selected verifier. |
| Verified identity → host Repo/Scope | A verifier-derived identity becomes a current-user lookup and host Scope. |
| Private facts → RequireScopes | Server-produced metadata controls route authorization. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-243-01 | Spoofing | `FetchAPIToken.call/2` | high | mitigate | Select only `APIToken.verify/2`, reload the live user, and assign nil on every failure. |
| T-243-02 | Elevation of Privilege | `RequireScopes.call/2` | high | mitigate | Ignore client/Scope-shaped authority and authorize only bounded private facts for scoped credential kinds. |
| T-243-03 | Information Disclosure | `CredentialAuth.put_verified_scope/5` | high | mitigate | Construct a fresh exact allowlist and test that raw request credentials never enter connection state. |
| T-243-04 | Tampering | Scope construction | medium | mitigate | Use canonical `Scope.build/3` for struct scopes and a bounded compatibility adapter only for existing non-struct modules. |
</threat_model>
