<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> SessionController passkey POST | Untrusted WebAuthn assertion and email params cross into auth completion. |
| SessionController -> Plug session | Controller verifies server-stored challenge and rotates or updates session state. |
| Auth wrapper -> Sigra.Passkeys | Generated app delegates security-sensitive verification to library code. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-01-01 | Spoofing | `complete_passkey/2` | mitigate | Look up user by submitted email, verify the server-stored authentication challenge through `Sigra.Plug.PasskeyChallenge.verify/5`, then call `UserAuth.log_in_user/3` only on `{:ok, conn, _credential}`. |
| T-21-01-02 | Tampering | passkey assertion payload | mitigate | Pass assertion params only into `Auth.authenticate_passkey/2`; do not read challenge from `clientDataJSON`. |
| T-21-01-03 | Repudiation | passkey registration | mitigate | `register_passkey/3` calls `Sigra.Passkeys.register/4`, which emits `passkey.register.success`, then sends a `:passkey_registration` delivery event. |
| T-21-01-04 | Information Disclosure | login failure copy | mitigate | Unknown email, invalid assertion, and missing challenge all use the same recovery copy and redirect to `/users/log_in`. |
| T-21-01-05 | Denial of Service | ceremony initiation | mitigate | Generated wrappers call `Sigra.Passkeys.rate_limit_ceremony/3` for `:registration` and `:authentication`. |
| T-21-01-06 | Elevation of Privilege | enrollment/delete sudo freshness | mitigate | Router injection adds `:require_sudo` and moves `/users/settings/mfa` plus registration options under `pipe_through [:browser, :require_authenticated, :require_sudo]`. |
</threat_model>
