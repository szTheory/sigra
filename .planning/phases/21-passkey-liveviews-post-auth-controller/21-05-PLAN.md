<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Generated templates -> example app modules | Template logic is instantiated into concrete app modules and can drift at compile time. |
| Example controller POST -> session cookie | Passkey completion routes can create or promote a session. |
| Example JS hooks -> controller completion routes | Browser ceremony output is serialized into `passkey[response]` and posted to Phoenix controllers. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-05-01 | Tampering | mirrored generated code | mitigate | Mirror generated template logic exactly; compile with warnings-as-errors to catch route/function drift. |
| T-21-05-02 | Elevation of Privilege | controller passkey completion routes | mitigate | Source mirror must keep terminal auth mutation in `SessionController`, not LiveView events, and expose `UserAuth.log_in_user/3` plus `put_user_session_token/2` wiring for Plan 21-06 tests. |
| T-21-05-03 | Information Disclosure | passkey settings source | mitigate | Source mirror must avoid rendering raw credential IDs, RP IDs, transports, or AAGUIDs by default. |
| T-21-05-04 | Denial of Service | hook/browser helper | mitigate | Mirror Plan 21-07 abort-safe helper/hook behavior without changing event names. |
| T-21-05-05 | Spoofing | test ceremony seam | mitigate | The seam is app-config scoped and defaults to the real verifier; Plan 21-06 uses it only in tests to avoid accepting fake WebAuthn data in production paths. |
</threat_model>
