<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser to passkey option/completion POST routes | Untrusted params and CSRF-protected POST requests reach controller actions. |
| stale authenticated session to sudo-gated enrollment/delete | Stolen or old sessions attempt sensitive passkey mutations. |
| runtime config to WebAuthn challenge creation | Missing or invalid RP ID/origin can produce unsafe ceremonies or runtime crashes. |
| database unique constraint to duplicate credential handling | Duplicate credential IDs must fail as friendly duplicate passkey errors, not 500s. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-08-01 | E | `test/example/lib/example_web/router.ex` settings passkey routes | mitigate | Put enrollment options/completion and delete routes in a `:require_sudo` pipeline using `Sigra.Plug.RequireSudo`. |
| T-21-08-02 | S | `test/example/lib/example_web/router.ex` primary login routes | mitigate | Keep passkey-primary completion in `SessionController.complete_passkey/2`, which verifies signed passkey challenge state before `UserAuth.log_in_user/3`. |
| T-21-08-03 | T | `test/example/config/config.exs` passkey runtime config | mitigate | Configure concrete `rp_id: "localhost"`, `origin: "http://localhost:4000"`, and bounded `timeout_ms: 60_000`; verification calls `Sigra.Passkeys.config/0`. |
| T-21-08-04 | D | passkey options routes | mitigate | Preserve existing `Sigra.Passkeys.rate_limit_ceremony/3` calls in `Example.Accounts`; config supplies `ceremony_rate_limit: [limit: 5, window_ms: 60_000]`. |
| T-21-08-05 | I | `test/example/lib/example/accounts/user_passkey.ex` | accept | Credential public key is encrypted by schema type; credential_id remains unencrypted by design for lookup and uniqueness. |
</threat_model>
