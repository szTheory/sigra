## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, inline status chips |
| sm | 8px | Row action gaps, label-to-helper spacing, inline confirm controls |
| md | 16px | Default control spacing, card inner gaps, form stack rhythm |
| lg | 24px | Card padding on auth and settings surfaces |
| xl | 32px | Inter-section spacing inside a screen |
| 2xl | 48px | Major state breaks between cards or recovery blocks |
| 3xl | 64px | Page-level top/bottom spacing on standalone auth screens |

Exceptions: 44px minimum touch target for icon-only or compact secondary controls; 40px minimum field/button height on desktop-auth surfaces; 56px minimum primary CTA height on mobile login/MFA screens. Defaults based on existing auth templates plus accessibility guardrails.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` / `base-100` | Page background, forms, controller-rendered auth shells |
| Secondary (30%) | `#F9FAFB` / `gray-50` / `base-200` | Settings cards, passkey list rows, recovery panels, inline confirmations |
| Accent (10%) | existing `brand` token (`text-brand`, `.btn-primary`) | Reserved for the primary passkey CTA, selected method state, inline action links, success-path deep links |
| Destructive | `#DC2626` / `red-600` | Delete passkey action, destructive warnings, danger text only |

Accent reserved for: `Continue with passkey`, `Use authenticator code instead`, `Use password instead`, `Email me a magic link`, selected verification-method indicator, passkey-section teaser link from `/users/settings`, and row-local rename affordances. Do not use accent on every border, helper message, or passive metadata line.

## Phase-Specific Interaction Contract

- Management surface: extend `/users/settings/mfa` with a prominent passkeys card. `/users/settings` may only link or tease; it is not the canonical management surface. Source: 21-CONTEXT D-01 to D-03.
- Page width: keep security-settings surfaces in `max-w-2xl`; keep standalone login/MFA/sudo screens in `max-w-sm`. Source: existing generated templates.
- Passkey list layout: use a stacked compact-card list. Each row shows resolved label order `nickname -> friendly AAGUID name -> device_hint -> "Passkey"`, plus one muted metadata line `Added …` and `Last used …` or `Never used`. Source: 21-CONTEXT D-12 to D-14.
- Rename behavior: row-local inline edit only. No separate route, no full modal, no page-level edit mode. Clearing the nickname reverts to the generated fallback label. Source: 21-CONTEXT D-14.
- Delete behavior: delete stays sudo-gated and only becomes available after reverification. After sudo succeeds, show inline secondary confirmation in the same row/card rather than a modal. Escalate warning copy if it is the last passkey. Source: 21-CONTEXT D-15 and PK-UX-04.
- MFA challenge behavior: replace the equal-weight tab model with a passkey-first layout when passkeys exist. Put `Continue with passkey` first, show `Use authenticator code instead` as an immediate visible secondary action, and keep `Use a backup code` visually tertiary. Do not auto-launch the browser prompt on mount. Source: 21-CONTEXT D-04 to D-07.
- MFA fallback behavior: if the user has no passkeys or the environment lacks support, render the existing TOTP-first experience with no passkey dead end. Source: 21-CONTEXT D-06.
- Primary login behavior: in `:passkey_primary_enabled` mode keep the controller-rendered identifier-first page, retain one email field with `autocomplete="username webauthn"`, and visually lead with `Continue with passkey`. Do not split into chooser-first or multi-screen auth. Source: 21-CONTEXT D-08 to D-11.
- Completion boundary: ceremony initiation and recoverable state can live in LiveView/hooks, but final session creation/rotation must complete through a plain controller POST. Source: ROADMAP Phase 21 success criteria and 21-CONTEXT D-11.
- Error posture: never expose raw `AbortError`, `NotAllowedError`, or browser exception strings. Map hook failures into four UI buckets: `canceled`, `timeout`, `unsupported`, and generic recoverable failure. Source: 21-CONTEXT D-16 to D-20 and Phase 20 hook contract.
- Abort behavior: when the LiveView is destroyed, disconnected, or superseded, the hook must leave the screen in a recoverable idle state with the primary CTA visible again and no stuck loading affordance. Source: Phase 20 `passkey_hooks.js`.
- Conditional UI: treat autofill/conditional mediation as progressive enhancement only. The screen must be understandable and actionable without it. Source: 21-CONTEXT D-22.
- Motion: no decorative animation. Limit motion to state swaps, loading labels, and inline row expansion/collapse. Browser passkey prompts are already the dominant interaction.

## Component Inventory

- `Passkeys card` on `MFASettingsLive`: heading, helper text, enrollment CTA, list, empty state, inline rename, delete affordance, recovery/help copy.
- `Passkey list row/card`: provider icon or generic key icon, primary label, muted metadata, inline actions.
- `Passkey enrollment state panel`: idle, enrolling/loading, success flash, duplicate-detected warning, generic recoverable error.
- `MFA passkey-first challenge block`: primary CTA, fallback actions, trust-browser checkbox only on TOTP path, recovery hint.
- `Primary login passkey block`: email field, primary passkey CTA, password fallback, magic-link fallback, conditional-ui enhancement affordance.
- `Inline recovery notice`: neutral/info/warning variants only; reserve red for destructive or truly blocking states.
