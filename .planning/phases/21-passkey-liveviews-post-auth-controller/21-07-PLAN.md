## Trust Boundaries

|----------|-------------|
| Browser conditional UI -> hook | Browser-generated autofill credentials and errors cross into hook code. |
| Hook -> controller POST | Successful browser ceremony leads to controller-owned session rotation. |
| Generated app.js -> controller page DOM | Static app.js binding attaches to controller-rendered markup created by Plan 21-04. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-07-01 | Tampering | conditional UI payload | mitigate | Browser helper serializes credential fields; server verification remains authoritative. |
| T-21-07-02 | Denial of Service | conditional mediation unsupported | mitigate | Helper throws normalized `ERROR_PASSKEY_UNSUPPORTED`; UI maps to fallback instead of stuck loading. |
| T-21-07-03 | Denial of Service | controller-page JS binding | mitigate | `attachPasskeyLogin({ enableConditionalUI: true })` feature-detects conditional mediation before auto-start, maps unsupported/abort/timeout to recoverable UI states, leaves password and magic-link fallback visible, and never shows raw browser exception strings. |
| T-21-07-04 | Elevation of Privilege | LiveView hook completion | mitigate | Hook success submits `passkey[response]` to controller completion URLs; no hook creates sessions directly. |
| T-21-07-05 | Information Disclosure | browser exception handling | mitigate | Node-stub tests assert abort/timeout/unsupported paths use safe copy and never expose `AbortError`, `NotAllowedError`, raw exception messages, or stacks. |
