<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser hook -> LiveView | Untrusted hook success/error payloads reach the management LiveView. |
| LiveView -> Auth wrappers | UI actions call generated wrappers for security-sensitive mutations. |
| User -> delete action | Destructive passkey deletion requires route-level sudo freshness from the existing settings route posture. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-02-01 | Spoofing | enrollment UI | mitigate | Enrollment entry remains on `/users/settings/mfa` and uses `Auth.register_passkey/3`; do not create a non-sudo standalone page. |
| T-21-02-02 | Tampering | rename/delete credential id | mitigate | `Auth.rename_passkey/3` and `Auth.delete_passkey/2` call library functions that resolve by `{user_id, credential_id}` and collapse cross-user access to `:not_found`. |
| T-21-02-03 | Information Disclosure | passkey rows | mitigate | Default row rendering excludes raw `credential_id`, `aaguid`, `transports`, and `rp_id`. |
| T-21-02-04 | Denial of Service | repeated ceremony attempts | mitigate | Enrollment handler routes through `Auth.register_passkey/3`, which calls `Sigra.Passkeys.rate_limit_ceremony/3`. |
| T-21-02-05 | Elevation of Privilege | stolen-session enrollment/delete | mitigate | Use Plan 01's sudo-protected `/users/settings/mfa` route and options endpoint; this LiveView must not introduce a second non-sudo passkey management route. |
| T-21-02-06 | Repudiation | delete/rename events | mitigate | Mutations delegate to `Sigra.Passkeys.rename/delete`, preserving `passkey.rename` and `passkey.delete` audit events. |
</threat_model>
