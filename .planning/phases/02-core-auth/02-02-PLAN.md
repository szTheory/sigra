    ```elixir
    defmodule Sigra.Auth do
      @moduledoc """
      Core authentication orchestrator.

      All security-critical auth operations live here. The generated
      `MyApp.Auth` context delegates to these functions for registration,
      authentication, session management, and magic link flows.

      ## Usage

          Sigra.Auth.register(MyApp.Repo, attrs, user_schema: MyApp.User)
          Sigra.Auth.authenticate(MyApp.Repo, params, user_schema: MyApp.User)
      """

      alias Sigra.{Crypto, Token, Telemetry}

      @doc "Registers a user. Returns {:ok, user} | {:error, changeset} | {:error, :email_taken}."
      @spec register(module(), map(), keyword()) :: {:ok, struct()} | {:error, Ecto.Changeset.t()} | {:error, :email_taken}
      def register(repo, attrs, opts \\ [])

      @doc "Authenticates by email+password. Returns {:ok, user} | {:error, :invalid_credentials | :unconfirmed}."
      @spec authenticate(module(), map(), keyword()) :: {:ok, struct()} | {:error, :invalid_credentials | :unconfirmed}
      def authenticate(repo, params, opts \\ [])

      @doc "Creates a session token for a user."
      @spec create_session(module(), struct()) :: {binary(), struct()}
      def create_session(repo, user)

      @doc "Verifies a session token. Returns {:ok, user} | {:error, :invalid}."
      @spec verify_session(module(), binary()) :: {:ok, struct()} | {:error, :invalid}
      def verify_session(repo, token)

      @doc "Deletes a session token."
      @spec delete_session(module(), binary()) :: :ok
      def delete_session(repo, token)

      @doc "Requests a magic link for the given email. Returns {:ok, {token, url}} | {:ok, :sent} | {:error, :rate_limited}."
      @spec request_magic_link(module(), String.t(), keyword()) :: {:ok, {String.t(), String.t()}} | {:ok, :sent} | {:error, :rate_limited}
      def request_magic_link(repo, email, opts \\ [])

      @doc "Verifies a magic link token. Confirms user if unconfirmed per D-02."
      @spec verify_magic_link(module(), String.t()) :: {:ok, struct()} | {:error, :invalid | :expired}
      def verify_magic_link(repo, token)
    end
    ```

    **Implementation details for each function:**

    `register/3`:
    - Get `user_schema` from `Keyword.fetch!(opts, :user_schema)` per D-49
    - Build changeset via `user_schema.registration_changeset(%user_schema{}, attrs)`
    - Call `repo.insert()` per D-48
    - On `{:error, changeset}`, check if only error is email uniqueness → return `{:error, :email_taken}` per D-29
    - Wrap in `Telemetry.span([:sigra, :auth, :register], ...)` per D-26
    - On success, emit `[:sigra, :auth, :register, :stop]` with `%{user_id: user.id}`

    `authenticate/3`:
    - Get `user_schema` from opts
    - Normalize email via `Sigra.Email.normalize/1`
    - Query user: `repo.get_by(user_schema, email: email)`
    - Call `Crypto.verify_with_upgrade(password, user && user.hashed_password)`
    - On `{:ok, :valid}`: reset `failed_login_attempts` to 0 via `repo.update(changeset)`
    - On `{:ok, :valid, new_hash}`: update `hashed_password` + reset attempts per D-10
    - On `{:error, :invalid}` with existing user: increment `failed_login_attempts` per D-31
    - On `{:error, :invalid}` with nil user: no DB write per D-33 (dummy hash already ran)
    - If `Keyword.get(opts, :require_confirmation, false)` and `user.confirmed_at` is nil: return `{:error, :unconfirmed}` per D-25
    - Emit `[:sigra, :auth, :hash_upgraded]` telemetry when hash changes per D-12
    - Emit `[:sigra, :auth, :login, :stop]` with `%{user_id: user.id, failed_attempts_before: user.failed_login_attempts}` per D-34

    `create_session/2`:
    - Use the pattern from existing `UserToken.build_session_token/1` template but call `Sigra.Token.generate_hashed_token()` for the raw+hashed pair
    - Actually, session tokens use raw bytes stored directly (not hashed) per existing template pattern — keep this consistent. Use `:crypto.strong_rand_bytes(32)` per D-35

    `verify_session/2`:
    - The session verification logic lives in the generated UserToken template (DB query). `Sigra.Auth.verify_session/2` delegates the query pattern. Since this needs the UserToken schema, accept it via opts or derive from config. Given the generated code pattern, this function may need `user_token_schema` in opts.
    - Alternative (recommended): Keep `verify_session` as a thin wrapper that the generated Auth context implements directly using its UserToken module. `Sigra.Auth` focuses on `register`, `authenticate`, `request_magic_link`, `verify_magic_link`. Session create/verify/delete stay in generated context since they need UserToken schema.
    - DECISION: `Sigra.Auth` implements `register/3`, `authenticate/3`, `request_magic_link/3`, `verify_magic_link/3`. Session CRUD stays in generated auth.ex context (it already works and needs UserToken schema). This is cleaner per the hybrid lib+generator boundary.

    `request_magic_link/3`:
    - Normalize email, look up user
    - If user exists: check rate limit via `RateLimiter` behaviour (key: `"magic_link:#{email}"`, limit: 3, window: 900_000ms per D-05). If rate limited, return `{:error, :rate_limited}`.
    - Generate token via `Sigra.Token.generate_hashed_token()`, store in user_tokens with context "magic_link" and `sent_to: user.email`
    - Return `{:ok, {encoded_token, url}}` where url is built from opts[:url_fun] per D-04 (stubbed — no email sent)
    - If user does NOT exist: return `{:ok, :sent}` (generic, enumeration-safe) — no token created, no DB write

    `verify_magic_link/3`:
    - Decode token, hash it, look up in user_tokens where context = "magic_link"
    - Check TTL: 10 minutes per D-03 (600 seconds)
    - Check `sent_to == user.email`
    - If valid: delete token (single-use per D-03), confirm user if `confirmed_at` is nil per D-02
    - Return `{:ok, user}` or `{:error, :invalid | :expired}`
