## Summary

The smallest correct implementation is to keep the current job graph and instrument the two test legs that already exist inside `mix ci`. The current alias contains the ordered values `"test --exclude scaffold"` and `"ci.install_golden"`, and the latter names exactly six test paths. The current workflow has one direct command, `"MIX_ENV=test mix ci"`, under `library_tests_shard`; the required `Library tests` aggregate depends only on that owner. [VERIFIED: mix.exs:143-168; .github/workflows/ci.yml:497-576]

Reuse `Sigra.CI.ExUnitTimingFormatter` unchanged if possible. It already consumes `{:test_finished, %ExUnit.Test{}}`, sorts by descending `time_us` with lexical tie-breaks, writes atomically, and accepts the fixed path `"/tmp/sigra-library-1-timings.json"`. Set `MIX_TEST_PARTITION=ordinary` and `SIGRA_EXUNIT_TIMING_PATH=/tmp/sigra-library-1-timings.json` on the sole owner, and make the ordinary command include both `ExUnit.CLIFormatter` and `Sigra.CI.ExUnitTimingFormatter`. [VERIFIED: test/support/ci/ex_unit_timing_formatter.ex:6-10,21-63,80-87]

Instrument the two existing test commands with a project-local, fixed-command Bash harness invoked once by the `ci` alias. This matches the repository's established nested-Mix harness pattern: `scripts/ci/sigra-dep-off.sh` runs fixed `mix` commands from a `cmd bash` alias while preserving failure status and cleanup. The new harness must emit a raw work-class receipt even on a failed leg, then return the failing child status; a separate verifier must recompute all ratio and dominance predicates instead of trusting booleans stored in the receipt. [VERIFIED: mix.exs:164-168; scripts/ci/sigra-dep-off.sh:1-64]

**Primary recommendation:** add one fail-closed `library-economics` harness plus verifier, reconnect the existing same-run formatter, retain two separately uploaded receipts, and use a fresh retry-free PR run to authorize traceability changes only after `ratio <= 2.0` and `install_scaffold_ms <= ordinary_ms` both pass. The factor-of-two comparability ceiling is a prescriptive phase recommendation, not a discovered ecosystem standard. [ASSUMED]

### Pattern 1: Same-run lifecycle receipt

Configure the ordinary test child exactly once with the existing formatter and no serializing flag:

```bash
MIX_TEST_PARTITION=ordinary \
SIGRA_EXUNIT_TIMING_PATH=/tmp/sigra-library-1-timings.json \
mix test --exclude scaffold \
  --formatter ExUnit.CLIFormatter \
  --formatter Sigra.CI.ExUnitTimingFormatter
```

The fixed path above is quoted verbatim from the formatter allowlist; `ordinary` is a recommended receipt identity. [VERIFIED: test/support/ci/ex_unit_timing_formatter.ex:6-10,23-30] [ASSUMED]

Official ExUnit documentation says formatter processes receive `test_finished` events and that `ExUnit.Test.time` is the test runtime in microseconds; official Mix documentation says the normal test runner supports async concurrency while `--slowest` enables serializing trace mode. [CITED: https://hexdocs.pm/ex_unit/main/ExUnit.Formatter.html] [CITED: https://hexdocs.pm/ex_unit/main/ExUnit.Test.html] [CITED: https://mix.hexdocs.pm/Mix.Tasks.Test.html]

### Pattern 2: Raw receipt, independent verdict

The runner should record only measured integer durations, exact fixed commands, exact outcomes, and whether the second leg ran. The verifier should require the exact key set and recompute:

```text
both conclusions == "success"
ordinary_ms > 0
install_scaffold_ms > 0
max(ordinary_ms, install_scaffold_ms) * 1000
  <= min(ordinary_ms, install_scaffold_ms) * 2000
install_scaffold_ms <= ordinary_ms
```

The `2.0` ratio and `50%` non-dominance boundary are the recommended operational definitions for this phase. The first is an agent-selected comparability bound; the second directly encodes D-06's “not the dominant leg.” Do not loosen either after seeing a failing final receipt; remediate and collect a new run. [ASSUMED]

### Pattern 3: Fail-closed artifact production

Run receipt validation and upload under `if: always()` so failures retain diagnostics, but use separate uploads with `if-no-files-found: error` so absence of either receipt is itself red. The official action defaults missing files to a warning, so the explicit error mode is load-bearing. [CITED: https://github.com/actions/upload-artifact/blob/main/README.md]

### Pattern 4: Two-stage evidence closure

First land instrumentation and deterministic contracts on an evidence branch, observe one retry-free `pull_request` run, fetch its structured summary once, download the two named artifacts, and commit a digest-bound `235.1-EVIDENCE.json`. Then run the focused contract against that committed evidence and allow REQUIREMENTS/verification prose updates only after it passes. [VERIFIED: AGENTS.md; .planning/phases/233-library-suite-economics/233-EVIDENCE.json]

## Common Pitfalls

### Pitfall 1: Formatter configured globally for both ExUnit legs
**What goes wrong:** `ci.install_golden` starts a second ExUnit run and overwrites the ordinary per-test receipt. [VERIFIED: mix.exs:149-163]
**Why it happens:** a job-wide formatter configuration applies to both child commands. [ASSUMED]
**How to avoid:** pass formatter flags only to the ordinary `mix test`; keep the install alias unchanged and measure it only at the harness boundary. [ASSUMED]
**Warning signs:** receipt identity says `scaffold`, test count equals only the six receiver files, or the file modification time follows the second leg. [VERIFIED: test/support/ci/ex_unit_timing_formatter.ex:23-30; mix.exs:161-163]

### Pitfall 2: Receipt loss hides a failed producer
**What goes wrong:** the main test step fails and later upload warns about a missing file while the evidence path appears green. [CITED: https://github.com/actions/upload-artifact/blob/main/README.md]
**How to avoid:** write a failure receipt before exiting, validate each receipt independently under `if: always()`, and use `if-no-files-found: error`. [ASSUMED]
**Warning signs:** no artifact ID, no digest, or a successful summary with an absent file. [CITED: https://github.com/actions/upload-artifact/blob/main/README.md]

### Pitfall 3: Ratio math accepts zero or rounded values
**What goes wrong:** integer-second measurements can produce zero in hermetic runs or floating rounding can move a boundary. [ASSUMED]
**How to avoid:** record monotonic integer milliseconds, require both values positive, and compare with integer cross-products. [ASSUMED]
**Warning signs:** division in shell/jq, decimal ratios stored as the authority, or zero-duration “passing” fixtures. [ASSUMED]

### Pitfall 4: Exact-once coverage drifts during wrapper insertion
**What goes wrong:** the wrapper calls a shortened path set or leaves the original alias call in place, creating omission or duplication. [VERIFIED: test/sigra/planning/phase_233_library_economics_contract_test.exs:50-75]
**How to avoid:** keep `ci.install_golden` as the sole six-path list; assert the `ci` alias invokes the harness once and the harness invokes `ci.install_golden` once. [ASSUMED]
**Warning signs:** more than one `mix ci.install_golden`, direct install file paths in the harness, or receiver/live scaffold set inequality. [VERIFIED: mix.exs:161-163; test/sigra/planning/phase_233_library_economics_contract_test.exs:50-75]

### Pitfall 5: Reconciliation precedes proof
**What goes wrong:** checked boxes and “Complete” rows advertise success before a real receipt passes. The current file already illustrates this split: TEST checkboxes are checked while traceability says `Gaps Found`. [VERIFIED: .planning/REQUIREMENTS.md:47-49,83-91]
**How to avoid:** make docs reconciliation the last plan after the evidence contract and protected verifiers pass. [VERIFIED: 235.1-CONTEXT.md]
