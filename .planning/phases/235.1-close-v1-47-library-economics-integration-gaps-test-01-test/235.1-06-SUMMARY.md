## Decisions Made

- Generated variants carry their own partition and port identities even when consumed read-only; mutating receivers additionally receive unique checkout identities and private build paths.
- Each private checkout points Mix at its checkout-owned copy of the compatible prepared `_build/dev`; no empty rebuild tree or shared writable build is introduced.
- Copy-on-write is attempted with platform-native copy cloning, with a measured ordinary-copy fallback. Both modes dereference source links and are rejected if writable hardlink or symlink state remains.
- The fixture receipt intentionally contains no verdict. Its exact phase keys and raw bound explain install cost, while `verify-library-economics.sh` remains the only admission authority.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Failure precedence] Preserved clock failures without masking child status**

- **Found during:** Task 3 runner hardening
- **Issue:** A failed post-child clock could otherwise return zero after a successful child or obscure an earlier nonzero child.
- **Fix:** Return the original child status when nonzero; otherwise fail the runner on clock failure.
- **Files modified:** `scripts/ci/install-golden.sh`
- **Verification:** Hermetic child/signal suite and ShellCheck pass.
- **Committed in:** `320c8675`

**2. [Rule 2 - Trust boundary] Dereferenced copied links and constrained every copy target to the validated graph root**

- **Found during:** Task 3 fixture integrity review
- **Issue:** Platform clone commands could preserve a source symlink, and the reusable cache-copy API needed the same root containment guarantee as cleanup.
- **Fix:** Clone with link dereferencing, reject residual links/shared inodes, and validate every target beneath a direct temporary graph root.
- **Files modified:** `test/support/install_fixture.ex`
- **Verification:** Focused isolation/cache/cleanup tests pass.
- **Committed in:** `dedae565`

**3. [Rule 1 - Portability] Materialized links after cloning so dangling generated links cannot abort macOS copies**

- **Found during:** Plan 07's first prepared-mode integration run
- **Issue:** macOS `cp -cRL` tried to dereference a dangling generated `_build/dev/phoenix-colocated/.../node_modules` link and aborted the entire private fixture copy.
- **Fix:** Preserve links during the clone, then materialize only safe in-graph targets into private bytes while omitting dangling and out-of-graph links. The source graph remains unchanged and the output is still link-free.
- **Files modified:** `test/support/install_fixture.ex`, `test/support/install_fixture_performance_test.exs`
- **Verification:** The macOS-compatible dangling-link regression and all focused Plan 06 checks pass.
- **Committed in:** `713ee2da`

**4. [Rule 1 - Build seeding] Pointed each checkout at its copied compatible prepared build**

- **Found during:** Plan 07's prepared receiver compile/rerun integration
- **Issue:** The checkout already contained a private clone of the compatible prepared `_build/dev`, but `MIX_BUILD_PATH` pointed to a newly created empty `_build/private-N`. Mix rebuilt dependencies there and `phoenix_live_reload` failed because Phoenix's generated static asset was absent.
- **Fix:** Use the checkout-owned `_build/dev` as the unique private build path, fail closed if it is absent, and regression-test Phoenix static asset presence plus mutation isolation across two checkouts and the immutable variant.
- **Files modified:** `test/support/install_fixture.ex`, `test/support/install_fixture_performance_test.exs`
- **Verification:** Focused Plan 06 ExUnit, shell, ShellCheck, and formatting gates pass.
- **Committed in:** `c1dd0162`

**5. [Rule 1 - Runtime assets] Materialized allowlisted Sigra `priv` bytes into link-free fixture builds**

- **Found during:** Plan 07's idempotent prepared-install rerun
- **Issue:** Mix represents the path dependency's `_build/dev/lib/sigra/priv` as a link to the repository. The isolation copier correctly removed external links, but also omitted required installer templates such as `organizations/router_injection.ex`.
- **Fix:** Permit materialization only from the repository's fixed `priv/` subtree, copy those bytes into each immutable variant/private checkout, and continue rejecting every other out-of-graph target. Regression coverage proves the router template is a regular private file.
- **Files modified:** `test/support/install_fixture.ex`, `test/support/install_fixture_performance_test.exs`
- **Verification:** Focused Plan 06 ExUnit, shell, ShellCheck, and formatting gates pass.
- **Committed in:** `87e650a5`

**6. [Rule 1 - Checkout isolation] Preserved executable modes and assigned run-unique dev resources**

- **Found during:** Plan 07's full prepared Task 1 gate
- **Issue:** Read-only and writable permission normalization stripped the executable bit from `file_system`'s macOS listener, while VM-local partition numbers left separate prepared runs sharing the generated app's hardcoded dev database and endpoint port.
- **Fix:** Preserve existing execute bits while removing or restoring owner-write access, derive every checkout partition from its graph root plus monotonic token, and rewrite the private checkout's dev database and endpoint port before any receiver command runs. The immutable source remains unchanged and each writable checkout owns distinct config and build bytes.
- **Files modified:** `test/support/install_fixture.ex`, `test/support/install_fixture_performance_test.exs`
- **Verification:** Regression coverage proves executable retention, immutable write denial, run-unique partition syntax, distinct database names and endpoint ports; all focused Plan 06 gates pass.
- **Committed in:** `f85b5042`

**7. [Rule 1 - Phoenix compatibility] Injected private ports when generated dev config omits one**

- **Found during:** Plan 07's fresh prepared Task 1 gate after checkout isolation landed
- **Issue:** Phoenix 1.8.7 generates `http: [ip: {127, 0, 0, 1}]` without an explicit port, while the checkout patcher only replaced an existing `port:` entry and therefore rejected a canonical fresh application.
- **Fix:** Replace an existing endpoint port when present or inject the private checkout port into the canonical one-line `http` keyword list when absent; retain fail-closed behavior for unknown endpoint shapes.
- **Files modified:** `test/support/install_fixture.ex`, `test/support/install_fixture_performance_test.exs`
- **Verification:** The fixture builder now uses Phoenix's no-port form and proves both checkouts receive distinct private ports; all focused Plan 06 gates pass.
