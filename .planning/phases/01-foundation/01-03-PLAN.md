<threat_model>
## Threat Model

| Threat | Mitigation | Verification |
|--------|------------|--------------|
| Generated schema exposes password field | Generated User schema has `:password` as virtual field and `:hashed_password` as persisted; password is deleted from changeset after hashing | Template contains `field :password, :string, virtual: true, redact: true` |
| Weak token storage | Generated UserToken schema stores HMAC-hashed tokens, not plaintext; calls `Sigra.Token.hash_token/1` | Template contains `Sigra.Token.hash_token` |
| SQL injection via generator args | Generator validates context/schema/table args are valid Elixir module names and table identifiers | Mix task validates args format before template rendering |
| Missing citext extension on Postgres | Migration template includes `execute "CREATE EXTENSION IF NOT EXISTS citext"` for Postgres adapter | Template contains conditional citext creation |
| Duplicate code injection | Injector checks for marker strings before injecting | Injector uses `String.contains?` with `"# Sigra authentication"` marker |
| Generated code with hardcoded secrets | No secrets in templates; all key derivation uses host app's `secret_key_base` at runtime | Grep templates for hardcoded strings — no `secret`, `key`, `password` literals in generated runtime code |
</threat_model>
