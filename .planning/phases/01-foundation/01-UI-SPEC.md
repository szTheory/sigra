# Phase 1 -- UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Applicability: NOT APPLICABLE

Phase 1 (Foundation) is a **backend Elixir library phase** with zero UI surfaces. It produces:

- Elixir library modules (`Sigra.Auth`, `Sigra.Config`, `Sigra.Telemetry`, `Sigra.Crypto`, `Sigra.Token`)
- Mix generator task (`mix sigra.install`)
- EEx code-generation templates (templates that produce Elixir source files, not rendered HTML)
- Behaviour definitions and default implementations
- Plug modules for HTTP pipeline integration
- Testing helpers and CI configuration

No browser UI, no rendered HTML, no CSS, no design tokens, no component library, and no user-facing visual surfaces are produced in this phase.

### Why EEx Templates Do Not Count

The EEx templates in `priv/templates/sigra.install/` are **code generation templates** -- they produce `.ex` source files (schemas, context modules, plugs) that are compiled into the host application. They are not rendered UI templates. The optional LiveView pages mentioned in FOUND-09 are also generated source code; their visual design will be specified when those pages are actually built (Phase 2+ when login/registration forms are implemented).

### First Phase Requiring UI-SPEC

The roadmap marks the following phases with `UI hint: yes`:
- **Phase 5**: OAuth and Social Login (provider selection UI, account linking confirmation)
- **Phase 6**: Multi-Factor Authentication (QR code display, TOTP entry, backup code display)
- **Phase 8**: Account Lifecycle (email change, password change, account deletion confirmation)

Phase 2 (Core Auth) will also likely need a UI-SPEC for login and registration forms, even though it is not explicitly tagged.
