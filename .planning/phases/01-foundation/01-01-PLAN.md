<threat_model>
## Threat Model

| Threat | Mitigation | Verification |
|--------|------------|--------------|
| Timing attack on password verification | Use argon2_elixir which provides constant-time comparison internally; `no_user_verify/0` runs dummy hash for non-existent users | Test that `no_user_verify/0` returns `false` (not early-exit) |
| Weak token generation | Use `:crypto.strong_rand_bytes(32)` for random tokens; Plug.Crypto.sign for signed tokens | Test token entropy (32 bytes = 256 bits) |
| Token comparison timing leak | Use `Plug.Crypto.secure_compare/2` for all token comparisons | Grep for `==` on token/hash values; must not exist |
| Sensitive data in config | Config struct never stores plaintext passwords; `secret_key_base` derived at runtime not stored | Config struct has no `password` or `secret` fields |
| Key derivation from weak source | Derive per-purpose keys from host app's `secret_key_base` via `Plug.Crypto.KeyGenerator` with unique salts | Token module uses purpose-specific salt strings |
</threat_model>
