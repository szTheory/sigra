# Phase 3 — UI Design Contract

> Visual and interaction contract for email flows: transactional email templates and generated Phoenix pages for confirmation and password reset. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Elixir library -- no frontend build tooling) |
| Preset | not applicable |
| Component library | Phoenix core components (`.header`, `.form`, `.input`, `.button`, `.link`) |
| Icon library | none (Unicode arrows only, matching Phase 2 pattern) |
| Font | Host app default (Phoenix 1.8 ships Inter via Tailwind) |

**Context:** Sigra is an Elixir library. Generated HEEx templates use Phoenix core components and inherit the host app's Tailwind theme. Email HTML templates use inline CSS with no external dependencies.

## Interaction Contracts

### Confirmation Code Entry (D-49)

- Input: single text field, `inputmode="numeric"`, `autocomplete="one-time-code"`, `maxlength="6"`, `pattern="[0-9]{6}"`
- LiveView mode: `phx-change` fires on every keystroke. When `String.length(code) == 6`, auto-submit verification. No custom JS hook needed.
- Controller mode: JS hook submits form when input length reaches 6. Graceful degradation: manual submit button always visible.
- Error: flash message on invalid code, input cleared, focus returned to input.
- Resend link: "Didn't receive a code?" link below form, triggers resend with rate limiting.

### Password Reset Form (D-50)

- Fields: new password + confirm password
- LiveView mode: `phx-change` validates match + policy in real time. Strength meter reused from Phase 2 registration component.
- Controller mode: server-side validation on submit. No real-time feedback.
- Submit disabled until both fields populated (LiveView only).
- On success: auto-login, redirect to home with flash "Your password has been reset."

### Confirmation Link Click (D-06, D-09)

- `GET /users/confirm/:token` -- no form, auto-confirms on page load.
- Success: redirect to home (or login if not logged in) with flash "Your email has been confirmed."
- Already confirmed: render friendly page with "Log in" link (D-09).
- Expired/invalid: render error page with "Send new confirmation email" button (D-07).

### Expired Token Pages (D-07, D-30)

- Dedicated error template with clear heading, explanation, and action button.
- Button pre-fills email in resend form when possible (via query param or session).
- Never a dead end -- always an actionable next step.

### Unconfirmed User Banner (D-02)

- When `:unconfirmed_access` is `:allow_with_banner`: Phoenix flash `:info` persists until dismissed or email confirmed.
- Flash copy includes link to resend confirmation email.
- Implementation: set flash in `user_auth.ex` plug when `user.confirmed_at` is nil.

## Email Template Structure

### HTML Layout (D-12, D-15)

All emails share this structure via `base_layout/1`:

```
+--------------------------------------------------+
|          {app_name} (centered heading)            |  zinc-900, 24px bold
+--------------------------------------------------+
|                                                    |
|  [Opening paragraph]                               |  zinc-700, 16px
|                                                    |
|  [Optional: 6-digit code block]                    |  32px bold monospace, zinc-100 bg
|                                                    |
|  +--------------------------------------------+   |
|  |          [CTA Button]                       |   |  blue-600 bg, white text, 16px semibold
|  +--------------------------------------------+   |
|                                                    |
|  [Optional: fallback URL as text]                  |  14px, zinc-500
|                                                    |
+--------------------------------------------------+
|  [Footer text]                                     |  zinc-500, 14px
|  [Unsubscribe / ignore notice]                     |
+--------------------------------------------------+
```

- Outer background: `#f4f4f5` (zinc-100)
- Content card: `#ffffff` white, `1px solid #e4e4e7` border, `8px` border-radius
- CTA button: `#2563eb` background, `#ffffff` text, `8px` border-radius, centered
- Fallback URL: raw URL below button for clients that strip buttons

### Text Layout

Plain text fallback for every HTML email:

```
{app_name}

Hi,

{opening paragraph}

{optional: Your confirmation code: 123456}

{CTA action}: {full URL}

---
{footer text}
```

## Accessibility

- All form inputs have explicit `label` attributes (via Phoenix `.input` component)
- Confirmation code input: `aria-label="Confirmation code"`, `inputmode="numeric"`
- Flash messages use Phoenix's built-in `role="alert"` for screen reader announcement
- Email CTA buttons include `role="link"` and descriptive text (not "Click here")
- Email HTML uses semantic `<table>` layout for email client compatibility, with `role="presentation"` on layout tables
- Color contrast: all text/background combinations meet WCAG 2.1 AA (zinc-700 on white = 5.6:1, white on blue-600 = 4.6:1)
- Expired token pages provide clear next-step actions, not just error messages
