<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| T-3-01: Confirmation token reuse after confirmation | HIGH | Token deleted from DB in same transaction as user confirmation (Ecto.Multi). Single-use enforced. |
| T-3-02: Confirmation link token forgery | HIGH | HMAC-signed via Plug.Crypto.sign with purpose salt "sigra-confirm-token". DB lookup of SHA-256 hash as second factor. |
| T-3-03: Reset token reuse after password change | HIGH | Token deleted and all sessions invalidated in same Ecto.Multi transaction. |
| T-3-04: Email enumeration via reset/confirm timing | HIGH | Dummy Argon2 hash for non-existent emails (Sigra.Crypto.hash_password("dummy")) to match timing. Generic response always returned. |
| T-3-05: Confirmation code brute force | MEDIUM | Rate limited to 5 attempts per user per 15 minutes via RateLimiter behaviour. 6-digit = 1M combinations. |
| T-3-06: Confirmation resend spam | MEDIUM | Rate limited to 3 resends per email per 15 minutes. |
</threat_model>

Add the following functions to `lib/sigra/auth.ex` (per D-52, following existing patterns):

**1. generate_confirmation_token/3:**
```elixir
@doc """
Generates a confirmation link token AND a 6-digit code for the given user.

Returns `{encoded_token, code, confirmation_token_struct, code_token_struct}`.
The encoded_token is HMAC-signed for URL use. The code is a random 6-digit
numeric string. Both are stored as SHA-256 hashes in the DB.

Per D-01: link-first, code as fallback. Both generated together.
"""
@spec generate_confirmation_token(module(), struct(), keyword()) ::
        {String.t(), String.t(), struct(), struct()}
def generate_confirmation_token(repo, user, opts \\ [])
```

Implementation:
- Generate `{raw_bytes, hashed}` via `Token.generate_hashed_token()`
- HMAC sign raw_bytes: `signed = Plug.Crypto.sign(secret_key_base, "sigra-confirm-token", raw_bytes)` where secret_key_base comes from `opts[:secret_key_base]`
- Generate 6-digit code: `code = :rand.uniform(900_000) + 99_999 |> Integer.to_string()` (ensures 6 digits: 100000-999999)
- Hash code: `hashed_code = Token.hash_token(code)`
- Build token structs for context "confirm" (link) and "confirm_code" (code)
- Return `{Base.url_encode64(signed, padding: false), code, link_token_struct, code_token_struct}`

**2. confirm_user/3:**
```elixir
@doc """
Confirms a user by HMAC-signed link token.

Verifies the HMAC signature, decodes the raw token, hashes it,
looks up in DB. On success, sets confirmed_at and deletes all
confirm/confirm_code tokens for the user in a single transaction.

Returns {:ok, user}, {:error, :token_expired}, {:error, :token_invalid},
or {:error, :already_confirmed}.
"""
@spec confirm_user(module(), String.t(), keyword()) ::
        {:ok, struct()} | {:error, :token_expired | :token_invalid | :already_confirmed}
def confirm_user(repo, signed_token, opts \\ [])
```

Implementation:
- Extract `secret_key_base` from opts
- Verify HMAC: `Plug.Crypto.verify(secret_key_base, "sigra-confirm-token", signed_token, max_age: ttl)` where ttl = `opts[:confirmation_ttl] || 48 * 60 * 60`
- On `:ok` -> hash the decoded raw bytes -> DB lookup with context "confirm"
- Check user.confirmed_at -- if not nil, return `{:error, :already_confirmed}`
- Use `Ecto.Multi` to: update user (set confirmed_at), delete_all tokens with contexts ["confirm", "confirm_code"] for user
- Emit telemetry: `[:sigra, :confirmation, :verify, :stop]` with `%{user_id: user.id}`

**3. verify_confirmation_code/3:**
```elixir
@doc """
Confirms a user by 6-digit code.

SHA-256 hashes the submitted code, looks up in DB with context "confirm_code".
Rate-limited to 5 attempts per user per 15 minutes.
"""
@spec verify_confirmation_code(module(), String.t(), keyword()) ::
        {:ok, struct()} | {:error, :invalid_code | :rate_limited | :already_confirmed}
def verify_confirmation_code(repo, code, opts \\ [])
```

Implementation:
- Check rate limit: `rate_limiter.check_rate("sigra:confirm_code:#{user_id}", max_attempts, window_ms)`
- Hash code: `Token.hash_token(code)`
- DB lookup: context "confirm_code", joined with user
- Same Ecto.Multi as confirm_user for confirmation + token cleanup

**4. request_password_reset/3:**
```elixir
@doc """
Requests a password reset for the given email.

Enumeration-safe: always returns {:ok, :sent} for non-existent emails
with a dummy hash operation to match timing (per D-38).
"""
@spec request_password_reset(module(), String.t(), keyword()) ::
        {:ok, {String.t(), String.t()}} | {:ok, :sent} | {:error, :rate_limited}
def request_password_reset(repo, email, opts \\ [])
```

Implementation:
- Normalize email, look up user
- If no user: `Crypto.hash_password("dummy_password_for_timing")`, return `{:ok, :sent}`
- If rate limited: return `{:error, :rate_limited}`
- Generate HMAC-signed reset token (purpose: "sigra-reset-token", context: "reset_password")
- Store hashed token in DB
- Return `{:ok, {signed_token, url_fun.(signed_token)}}` where `url_fun` from opts
- Emit telemetry: `[:sigra, :reset, :requested]`

**5. reset_password/4:**
```elixir
@doc """
Resets a user's password using a valid reset token.

Verifies HMAC signature, looks up token in DB, changes password,
and invalidates ALL tokens (including sessions) in a single transaction.
Per D-29: auto-login after reset (caller creates new session).
"""
@spec reset_password(module(), String.t(), map(), keyword()) ::
        {:ok, struct()} | {:error, :token_expired | :token_invalid | Ecto.Changeset.t()}
def reset_password(repo, signed_token, password_attrs, opts \\ [])
```

Implementation:
- Verify HMAC with purpose "sigra-reset-token", max_age: `opts[:reset_ttl] || 60 * 60`
- Hash decoded token, DB lookup with context "reset_password"
- Use Ecto.Multi: update user password (via changeset_fn from opts), delete_all tokens for user (:all contexts)
- Emit telemetry: `[:sigra, :reset, :completed]`

All functions follow the existing pattern: `(repo, args, opts)`, use `Keyword.fetch!/2` for required opts, `Keyword.get/3` with defaults for optional opts. Wrap in `Telemetry.span` where appropriate.

@doc """
Asserts that an email was sent (via Swoosh test adapter).

Checks the Swoosh test mailbox for an email matching the given criteria.
Uses Swoosh.TestAssertions under the hood when available.

## Options

- `:to` - Expected recipient email
- `:subject` - Expected subject (substring match)
"""
@spec assert_email_sent(keyword()) :: true
def assert_email_sent(opts \\ []) do
  to = Keyword.get(opts, :to)
  subject = Keyword.get(opts, :subject)

  # Uses Swoosh.TestAssertions.assert_email_sent/1 when available
  if Code.ensure_loaded?(Swoosh.TestAssertions) do
    criteria = []
    criteria = if to, do: [{:to, [{nil, to}]} | criteria], else: criteria
    criteria = if subject, do: [{:subject, subject} | criteria], else: criteria
    apply(Swoosh.TestAssertions, :assert_email_sent, [criteria])
  else
    raise "Swoosh.TestAssertions not available. Add {:swoosh, \"~> 1.5\"} to test deps."
  end
end
