<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| reconciliation result -> callback success contract | Only safe, typed outcomes may cross into session creation. |
| callback metadata -> session store and audit log | Enterprise org and connection truth is persisted on the first successful session write. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-124-05 | S | `Sigra.OAuth.Callback` | mitigate | Fail closed on stale or mismatched enterprise context and only map success from Plan 124-01 reconciliation, preventing wrong-org session issuance. |
| T-124-06 | T | `Sigra.Auth.create_session/4` | mitigate | Keep reconciliation before session creation and preserve explicit `active_organization_id` precedence so first-session truth cannot be patched later or overwritten by selector fallback. |
| T-124-07 | E | enterprise refusal handling | mitigate | Reject unsafe fallback from enterprise flow into another auth mode by mapping refusals to bounded `OAuthError` codes and never returning link-confirmation or generic login continuations. |
| T-124-08 | R | session/audit metadata | mitigate | Stamp enterprise connection, routing source, and reconciliation outcome into the first session.create audit metadata so later incident review can distinguish safe success from denial branches. |
</threat_model>
