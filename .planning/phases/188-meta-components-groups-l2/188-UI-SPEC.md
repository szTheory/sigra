# Phase 188 - UI Design Contract

> Visual and interaction contract for Phase 188: Meta-Components / Groups (L2).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none - preserve the hand-authored `sg-*` cascade-layer/BEM admin design system |
| Preset | not applicable |

design contract, and in the quality ledger.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | `--sg-space-1` / 4px | Icon gaps, pill internals, compact inline controls |
| sm | `--sg-space-2` / 8px | Tight row details, status-pill clusters, table cell micro-gaps |
| md | `--sg-space-4` / 16px | Default group padding, list-row padding, form field rhythm |
| lg | `--sg-space-6` / 24px | Section-internal rhythm and group header-to-body spacing |
| xl | `--sg-space-8` / 32px | Major group gaps inside a page stack |
| 2xl | `--sg-space-12` / 48px | Page-level separation when a group creates a new task zone |
| 3xl | 64px | Reserved for future page-level spacing only; do not add a new token in this phase |

Exceptions: none for new Phase 188 group spacing. Existing L1 component internals remain outside
this phase's spacing declaration; do not modify or re-declare them as group spacing choices.

Group rhythm rule: each meta-component group uses one internal stack tier. Default to
`sg-stack--3` inside cards/panels and `sg-stack--4` for form/filter workbenches. Do not combine
nested stacks in a way that doubles vertical gaps.

## Typography

Phase 188 declares only four group-level sizes and two group-level weights. Existing L1 component
internals may keep their ratified local tokens, but new group wrappers and labels must stay inside
this table.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | `--sg-text-base` / 16px | `--sg-weight-regular` / 450 | `--sg-leading-normal` / 1.5 |
| Label | `--sg-text-sm` / 14px | `--sg-weight-bold` / 700 | `--sg-leading-snug` / 1.3 |
| Section Heading | `--sg-text-lg` / about 23px | `--sg-weight-bold` / 700 | `--sg-leading-tight` / 1.1 |
| Page Heading | `--sg-text-xl` / 30px | `--sg-weight-bold` / 700 | `--sg-leading-tight` / 1.1 |

Do not scale group font sizes with viewport width. Data-heavy values use tabular numerals through
existing `sg-tabular`/component styling. Long identifiers must wrap, truncate with `title`, or
scroll-contain at the table/card boundary; never shrink text below the declared scale to force fit.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--sg-color-subtle` light `#f6f5f2`, dark `#171614` | Admin canvas, page background, unframed section areas |
| Secondary (30%) | `--sg-color-panel` light `#ffffff`, dark `#1f1d1a`; `--sg-color-panel-alt` for rows | Group panels, list rows, tables, detail panels, preview rails |
| Accent (10%) | `--sg-color-brand` `#c2410c`; dark text-on-soft uses `--sg-color-brand-strong` `#fdba74` | Rail Accent identity, primary actions, selected states, focus rings, ownership/scope emphasis |
| Destructive | `--sg-color-risk` light `#b42318`, dark `#f8a39c` | Destructive actions, risk notices, error states, confirmation affordances |

Accent reserved for: Rail Accent assets in admin chrome, `.sg-btn--primary`, selected tabs/filters,
active scope emphasis, focus rings, inline notice actions, and brand-soft selected states. Do not
use ember on every group heading, icon, row border, or decorative divider.

Status tones must never rely on color alone. Pair `ok`, `warn`, `risk`, and `info` tones with
specific copy, a status pill label, an inset rule, an icon/text glyph, or row structure.

Light, Dark, and System are mandatory. Explicit choices use `data-sg-admin-theme`; System follows
`prefers-color-scheme`. No new group CSS may hard-code raw colors when a `--sg-*` token exists.

## Visual Hierarchy

Primary focal point: the first actionable or diagnostic group in each admin task zone.

| Context | Focal Point | Visual Priority |
|---------|-------------|-----------------|
| Overview pages | MG-4 alarm notice when present; otherwise MG-3 task grid | Notice first for risk, then task cards, then MG-1 metrics |
| List pages | MG-2 filter panel, then MG-5/MG-6 result set | Filters must be scannable without pushing results off mobile viewports |
| Detail pages | MG-9 identity header, then MG-10 session/details, then MG-11 destructive area | Identity and scope before action; destructive controls stay visually secondary |
| Branding page | Branding editor workbench inside Phase 189 page composition | Preserve this phase's group rules for form, preview, error, and confirmation groups |

Group boards in `/admin/_design` are audit instruments. If a group contains `.sg-card` children
(for example task cards), the board wrapper must not create a visual card-in-card result. Use an
unframed `sg-stack`/example-only board shell or explicitly exclude the wrapper from the group
scorecard. Production group markup must never nest `.sg-card` inside `.sg-card`.

## Group State Contract

Every MG board must show populated, zero, loading, and error states when the application can reach
that state. If a state is impossible for a group, document why in the board copy and verification
notes rather than omitting it silently.

| Group | Zero State | Loading State | Error State |
|-------|------------|---------------|-------------|
| MG-1 | Metric values render `0` with explanatory help where denominators are zero | Skeleton metric cards matching final card count | `notice tone={:risk}`: `Unable to load summary metrics. Refresh the page, then check admin logs if it happens again.` |
| MG-2 | No applied chips; filter panel remains usable | Filter controls stay stable; result region owns loading feedback | `notice tone={:risk}`: `Unable to apply filters. Refresh the page, then try again.` |
| MG-3 | No task-card zero state; overview tasks are static capability launchers | Not applicable unless task availability is loaded | `notice tone={:risk}`: `Unable to load admin tasks. Refresh the page, then use the sidebar if the issue continues.` |
| MG-4 | `All clear` in ok tone | Hidden until data resolves or skeleton row if layout would shift | `notice tone={:risk}`: `Unable to check review status. Refresh the page, then open users to inspect manually.` |
| MG-5 | `No users match this view` with filter-aware clear action | Table row skeletons and mobile card skeletons with equivalent shape | `notice tone={:risk}`: `Unable to load users. Refresh the page, then try again.` |
| MG-6 | `No audit events match this view` or `No audit events for this user` | Table row skeletons and mobile `audit_row` skeleton shapes | `notice tone={:risk}`: `Unable to load audit events. Refresh the page, then try again.` |
| MG-7 | `No members yet` with invitation-oriented next step | `skeleton.sg-list-row` rows | `notice tone={:risk}`: `Unable to load members. Refresh the page, then check the organization scope.` |
| MG-8 | `No pending invitations.` | `skeleton.sg-list-row` rows | `notice tone={:risk}`: `Unable to load pending invitations. Refresh the page, then check invitation settings.` |
| MG-9 | Missing optional fields collapse without leaving blank labels | Header skeleton only if the user detail route loads asynchronously | `notice tone={:risk}`: `Unable to load user identity. Return to users, then open the account again.` |
| MG-10 | Panel-local `empty_state` copy such as `No linked identities` or `No organization memberships` | Panel-local skeletons matching facts/rows | `notice tone={:risk}`: `Unable to load detail panels. Refresh the page, then check user detail logs.` |
| MG-11 | Dangerous actions hidden or disabled when unavailable with explanatory copy | Pending buttons preserve dimensions and indicate action progress | Confirmation copy names the action and consequence; failure copy says how to recover |

Loading skeletons must match the shape and count of the content they replace. They are decorative;
the containing region owns `aria-busy`. Empty states are not errors. Errors are contextual notices,
not flash-only evidence when the group remains visible.

## Desktop Table To Mobile Card Contract

MG-5 and MG-6 are the required desktop-table to mobile-card swap groups. The two representations
must be content-equivalent at the breakpoint.

| Data Element | MG-5 Users Desktop | MG-5 Users Mobile | MG-6 Audit Desktop | MG-6 Audit Mobile |
|--------------|--------------------|-------------------|--------------------|-------------------|
| Primary identity/event | User column name/email/id | Card header name/email/id | Event/action column | `audit_row` action pill/code |
| Status/outcome | Status pill cluster | Status pill cluster | Outcome cell/status pill | `audit_row` tone pill |
| Secondary facts | Organizations and activity columns | `dl.sg-kv` organizations/activity/registered | Actor and effective-user lines | `audit_row` actor/effective-user lines |
| Action | `Open user` button | Full-width `Open user` button | Pagination/export outside table | Pagination/export outside card stack |
| Identifiers | `sg-code` user id | `sg-code` user id | event id/action code | event id/action code when `show_codes` |

Breakpoint behavior: desktop table uses `sg-show-desktop`; mobile cards use `sg-show-mobile`.
At 320px and 375px, no group may hide data as the only overflow strategy. Use wrapping,
`sg-truncate` with `title`, or scroll-containment at the table panel boundary. Mobile cards must
remain readable without squished columns.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Apply filters` for filter panels; `Open user` for result cards; `Review accounts` for risk notices |
| Empty state heading | `No users match this view`; `No audit events match this view`; `No members yet`; `No pending invitations.` |
| Empty state body | `Clear one or more filters to widen the result set.` or group-specific next step from the state table |
| Error state | `Unable to load {group subject}. Refresh the page, then try again.` Add a concrete fallback when one exists |
| Destructive confirmation | `Revoke all sessions`: `Revoke every active session for {email} in {scope}? This signs them out everywhere.`; `Restore defaults`: `This removes the saved admin branding changes and uses the app's configured defaults.` |

All group copy is terse, operator-calibrated, and verb-first where action is expected. Avoid
generic one-word command labels and bare dismissive actions. For secondary exits, use specific
nouns where the context is not obvious, such as `Clear all filters`, `Discard changes`,
`Keep sessions`, `Keep saved profile`, or `Restore defaults`.

## Accessibility And Interaction

| Concern | Contract |
|---------|----------|
| Headings | Each group has one reachable section heading. Do not skip heading levels inside group boards. |
| Scope | Preserve `scope_ribbon` in page body; group content must not hide global vs organization context. |
| Forms | Labels are explicit. `field_help` remains outside wrapping labels and uses `aria-controls`, `aria-describedby`, and `role="tooltip"`. |
| Tables/cards | Desktop and mobile result groups expose equivalent content and stable hooks: `data-testid` on result containers plus role selectors in tests. |
| Pagination | Icon-only previous/next controls require `aria-label` plus hidden text. Disabled controls use `aria-disabled` and inert styling. |
| Notices | Load-present notices have no live-region role; post-load dynamic notices may opt into `role="status"`; actual failures may use `role="alert"`. |
| Confirmations | Use `sg-confirm-overlay` / `sg-confirm-dialog`, not generic `.modal` for new admin confirmation UI. Dialogs declare `role="dialog"`, `aria-modal="true"`, and `aria-labelledby`. |
| Motion | Use exact-property transitions only. Pointer hover is gated with `@media (hover: hover) and (pointer: fine)`. Keyboard-frequent table/filter changes are not animated. Reduced motion strips movement. |
