**Why this cannot be shifted left.** A `workflow_run` lane only ever executes the default-branch
copy of its own file, so the job's first execution is necessarily post-merge — no in-phase command
can trigger it. 238-03 and 238-06 both carry an explicit prohibition against claiming it proven
in-phase, and the phase correctly did not claim it.

**What is already covered without this.** The offline half of the paired guard (`p19`) is 19/19
with a recorded RED proof and reads the committed snapshot. Code review IN-03 records two latent
defects in the drift job — an unpaginated ruleset list, and a `set -euo pipefail` abort at
`ID=$(…)` that pre-empts the job's own named `ABSENT` message on a transient API failure — deferred
to `.planning/todos/pending/2026-09-17-tag-ruleset-drift-observer-has-never-run-and-has-two-latent-defects.md`.
Both fail **closed** (false red or unlabelled red, never false green), so a deleted ruleset would
still be caught. This is a trust-and-noise item, not a silent hole.

**How to run it:** after this phase's commits reach `main`, let one push complete a `CI` run, then
`gh run list --workflow "CI (observe)" --limit 1` and open the `Tag namespace ruleset drift` job.
