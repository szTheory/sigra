parse it with the repo's manifest-parser discipline — skip blank and comment lines, require the

one literal tag name, taken from the row's first field, to a single-ref delete. No wildcard is ever
expanded into a delete invocation: a two-component name and its three-component neighbour share a
prefix, both exist in this repository today, and the three-component one backs a published release.
A tag already absent is reported and skipped without failing — that is what makes a re-run a clean
no-op. Any other non-zero status from a delete aborts the pass with a named reason and a non-zero
exit; do not suppress it, because a suppressed status would also hide a genuine server-side
rejection.

remote ref one literal name at a time. If 238-02 recorded that ref deletion is governed by the
ruleset, the remote pass prints the enforcement-flip instruction and refuses to proceed until the
window is open, rather than silently failing per row.

Each verify pass does a per-side set comparison. Build the side's current listing, build the keep
expression for that side, extract the keep-set, and compare the two sorted sets — sort both
operands at compare time, in the same pass, so the verdict cannot depend on enumeration order.

the release expression union the archive prefix, while the remote keep-set is the release
expression alone, because the archive namespace never reached the remote. A shared expression would
fail.

hyphen or a plus. The optional suffix is not decoration: D-05 records that the release automation
may mint a release-candidate tag during this phase's window, and a bare three-component expression
would classify such a tag as drift and fail the pass for an entirely benign reason. The delete set
is unaffected by the widening, because every allowlist row is a two-component name or a phase-proof
name and neither shape can match a three-component expression however it is suffixed.

non-empty, and abort with the repo's broken-parse message otherwise — two empty files compare
equal, and that green would mean nothing. Derive both sides of every comparison from the same
expression at compare time; do not encode an expected cardinality anywhere.

In reporting mode, print for each row what the pass would do and why, and print the comparison the
verify pass would make, without touching a ref.
