<planner_decisions_closed_here>
**The ledger is validated by calling the slot parser directly, not by running the shared run-id
provenance guard.** That guard was measured, in the immediately-preceding phase, to be hard-pinned
to an earlier phase's ledger path — running it green would say nothing about this file. There is
already a pending todo recording the pinning; this plan does not fix it.

**Most of this phase's evidence is local, not a CI run.** The status grammar the parser enforces
expects a run identifier inside a captured status. Local artifacts therefore use the pending form
with a one-line reason naming the command and the commit, following the preceding phase's
precedent. The Pages observation is the exception: it carries a real build identifier from the
GitHub API and uses the captured form.

**Every diff-based check in this plan compares against `git merge-base origin/main HEAD`, not the
live branch tip, and uses repo-root-anchored pathspecs.** The tip moves — this phase runs in
parallel with Phase 236 — so a tip-based comparison can attribute a sibling's merge to this phase.
Root-anchored pathspecs (`:/…`) keep every check independent of the directory it is invoked from.

**The residual documentation surface is recorded as a number plus its command, not as prose.** The
later ratchet phase is defined as a monotonic decrease where zero is explicitly not the target; a
ratchet needs a starting integer and a reproducible way to recompute it, or it cannot detect
anything.
</planner_decisions_closed_here>
