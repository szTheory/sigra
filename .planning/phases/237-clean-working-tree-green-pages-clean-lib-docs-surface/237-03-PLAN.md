<planner_decisions_closed_here>
**This plan was rewritten after a safety review; D-09 supersedes SC-3's stash clauses and the
earlier drafts of this plan.** Everything that existed to make the drop safe is deleted, not
disabled: the archive-ref push, the ARCHIVE TABLE row grammar, the SHA-for-SHA remote assertions,
the pre-drop/post-drop bracket, and the `checkpoint:decision`. There is no drop, so there is nothing
for that apparatus to protect, and leaving it in place as dead scaffolding would invite a later
reader to re-enable it.

**`autonomous` is now `true`, and the checkpoint is gone for a stated reason rather than by
inheritance.** The checkpoint existed solely to gate an irreversible step. With no push and no drop,
what remains is `git worktree prune` behind four prohibitions, which retires admin records and
deletes no objects. Keeping a checkpoint whose justification had been deleted would be ceremony.

**Why pruning the worktrees is safe while the stashes stay untouched — the specific mechanism.**
`refs/stash` lives in the shared main ref store (it is in `.git/packed-refs`), not in any
per-worktree ref store. `git worktree prune` removes admin records under `.git/worktrees/` and the
per-worktree refs belonging to them; it deletes no objects and cannot reach `refs/stash`. This is
the finding that lets the two halves of SC-3 be separated at all, so it is recorded here rather than
left implicit.

**The structural rule this plan now follows, stated because its absence is what let the hazard
through twice.** An earlier round removed an "authorized path with no green route" from this plan (a
sanctioned namespace fallback under which every assertion went permanently red). The same shape came
straight back in a more consequential place: the threat model instructed a halt if a stash carried
identity-shaped content, but that halt had no `<prohibition>` and no automated gate — and halting on
all six would have made the plan's own `6/6` assertions unsatisfiable, so a faithful executor was
pushed toward publishing anyway. The fix did not generalise because it was applied as a one-off edit
rather than as a rule. The rule, applied here: **every halt a plan instructs must be backed by a
prohibition with an automated verification, and the plan's assertions must remain satisfiable on the
halt branch.** In this plan the halt branch IS the only branch — no assertion anywhere requires a
push, so the safe path and the green path are the same path by construction, not by discipline.

**REPO-03 is partially unmet on purpose and says so.** The stash half is recorded in the snapshot
and in the SUMMARY as an exercised authorized option with its rationale, citing D-09, so a verifier
reads a choice rather than a failure. The inverse assertion — six stashes still present at the end —
is what makes the choice checkable.
