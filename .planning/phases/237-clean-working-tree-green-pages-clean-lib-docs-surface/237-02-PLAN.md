At line 174 the example redirects to an SSO path and builds its query string by interpolating a map
literal directly inside the path sigil. The two-character sequence formed where the interpolation
opens immediately onto a map literal is read by the legacy site builder's templating engine as an
opening tag it never finds a terminator for — which aborts the entire site build.

Rewrite the snippet so that sequence does not occur, WITHOUT changing what the code does: bind the
query map to a local variable on its own line immediately above, then interpolate that variable
into the sigil. The redirect target, the query key and its value must be byte-identical to what is
there now; only the shape of the expression changes. Keep the surrounding indentation and the
fenced block's language tag as they are.

This is defence in depth. Under the fix in Task 1 the site builder never parses this file at all,
so GREEN-03 does not depend on this edit — say so in the summary rather than presenting it as the
cause of the green check.

Do not apply templating-engine escape wrappers. They would render as literal noise in the
published library documentation, which also renders this guide. Do not touch the other file that
carries three same-shaped non-fatal warnings; those are warnings only and are out of scope.
