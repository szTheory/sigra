<planner_decisions_closed_here>
**SC-1's `!doc/llms.txt` wording is shorthand, not the implementation.** Per D-06 the satisfying
form is the directory-glob pair `/doc/*` + `!/doc/llms.txt`. The bare form specified in the
roadmap's SC-1 text was empirically falsified: git never descends into an excluded *directory*, so
the negation is unreachable. The plan implements the working form and records the divergence by
decision ID so the verifier grades against D-06, not the stale roadmap sentence.

**SC-1's untracked inventory is stale in three places** (D-06 / RESEARCH §A): the workspace-arg
file it names does not exist; the package tarballs are already ignored; and the `.log`/`.png` it
calls untracked are in fact *tracked*, under the planning directory, and are KEPT under D-02. The
only genuinely untracked offender is the agent scratch directory. This plan therefore adds exactly
one new ignore rule, not four.

**SC-1's "under `mix ci`" clause is corrected here (D-08).** Two of the three consumers are ExUnit
modules that do run under `mix ci`. `scripts/ci/launch-pack-contract.sh` has no workflow caller at
all (known as FUT-04). It is run manually and recorded as manual. Claiming `mix ci` covered it
would be exactly the kind of unverified green this milestone exists to retire.

**SC-1 is verified by a literal clone, not by a new CI job (D-08).** No whole-repo clean-tree check
exists in CI today, and the honest reading of "a fresh `git clone` reports a clean `git status`" is
to perform the clone. A CI approximation would be a proxy.
</planner_decisions_closed_here>
