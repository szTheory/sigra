## Summary

The new continuation flow correctly uses a one-time database claim and re-resolves the host session, but it serializes all correlation secrets into a same-origin callback URL without suppressing the subsequent same-origin `Referer`. The CI receipt also attests to a committed SHA while allowing uncommitted behavior outside its hand-maintained path list. ## Critical Issues

### CR-01: Callback correlation secrets leak in the same-origin Referer

**File:** `test/example/lib/example_web/controllers/crosswake_controller.ex:11-19`

**Issue:** `start/2` puts the continuation handle, OAuth state, and PKCE verifier in the redirect URL. The browser pipeline's default `Referrer-Policy` is `strict-origin-when-cross-origin`, which retains the full URL for the next same-origin request. Consequently, the `303` from `GET /crosswake/return?...` to `/app` sends those values in the `Referer` header to `/app`; application middleware, reverse proxies, traces, and access-log integrations can retain them even though Phoenix parameter filtering redacts only its own parameter logging. An observer can also use the leaked values to consume the one-time continuation and deny the legitimate return.

**Fix:** Keep the values out of URLs (for example, place the opaque continuation and correlation data in a server-side/signed session and submit the return with a POST). If the fixed GET transport is unavoidable, set `Referrer-Policy: no-referrer` on the callback response before its redirect and add an integration test that asserts the `/app` request has no secret-bearing Referer. Do not rely on `:filter_parameters` for HTTP header or proxy-log redaction.

## Warnings

### WR-01: Evidence can attest to a SHA that was not the code tested

**File:** `scripts/ci/hosted-session-interop-proof.sh:183-205`

**Issue:** `verify_scoped_paths_are_committed/0` checks only a manually maintained subset of Phase 240.3 paths, then `write_evidence/0` records `git rev-parse HEAD` as the tested revision. Uncommitted changes to any dependency of the flow (for example `test/example/lib/example/accounts/crosswake_session_adapter.ex`, session lookup code, configuration, or a dependency fixture) are not rejected, so the runner can produce a green receipt for behavior that does not exist at the recorded SHA. This defeats the receipt's stated immutable-coordinate guarantee.

**Fix:** Before running the suites or writing evidence, require a clean tracked worktree for the repository (or construct and record an explicit complete source manifest/diff hash, including all runtime dependencies). Continue to allow only the evidence file itself to be created after that verification.
