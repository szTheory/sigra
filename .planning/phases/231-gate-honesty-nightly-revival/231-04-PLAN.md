<objective>
GATE-04's second link in D-24's locked chain, and the first two steps of D-11's own locked order:
**install the browsers, then fix the probe, then run and READ, and only then delete the mask.** This
plan does steps 1 and 2. It does not touch `ci.yml:2450`.

Two defects are already diagnosed from push run `30472016250` (job `90644402928`), which reported
`Running 192 tests using 1 worker` then `76 failed, 116 passed (16.2m)` and exited 1 inside harness
phase (a). **Bug 1:** every `admin-eval-mobile` test failed, because that project is
`devices['iPhone 13']` — WebKit — while the install step provides chromium only, and the step's own
`name:` asserts that chromium is all the job needs. **Bug 2:** the chromium/dark failures cluster on
`board-mg-2` in all four states plus `board-summary_chip` and `board-field_help`, matching
`probes.ts:380`'s `el.className.includes('ember')`, which throws on any SVG element because
`className` is an `SVGAnimatedString` there.

Planning turned up a third, unrecorded obligation. D-11 step 1 requires re-tokening the Phase-230
browser-set cache key, and `scripts/ci/playwright-cache-key-guard.sh` extracts the version with a
regex that hard-codes the `-v1` suffix and fails closed when it matches nothing. Changing the key to
`-v2` without generalizing that regex reds `fast_checks` with a message about a missing cache key —
exactly the "cause that looks unrelated" pattern D-10 warns about, arriving from a direction nobody
recorded. Call it **C-6** and land it in the same commit.

Purpose: give the eval harness the browsers and the crash-free probe it needs, so its b1-b6 phases
can execute for the first time.
Output: two `ci.yml` edits, a generalized cache-key guard, a one-expression probe fix, and a new
prohibition that makes the crash class non-reintroducible.
