<objective>
The phase's terminal plan, and GATE-01's observation half. D-24 puts it last for a reason RESEARCH
confirmed against a live run: nightly `30425416933` ran 25 jobs, 23 of them green, and its only three
non-success jobs were GATE-02's 320px assertion, GATE-04's two bugs, and `ci-gate` propagating from
the first. Every one of those is fixed by plans 231-02 through 231-07. GATE-01 is an observation of
the other requirements, plus the two structural fixes plan 231-10 landed.

What is genuinely left is the part this milestone exists to enforce. Eleven plans have each produced
receipts inside their own summaries; nothing yet gathers them into one place a reader can check
against the five success criteria. D-25 is explicit that every criterion closes on a named run id
plus a named command — and the precedent failure being corrected is a milestone that passed audits
which were code-level reads that never executed the specs. A ledger is the form that makes that
impossible to repeat.

The format is not invented here. Phase 230's evidence-ledger parser is deliberately generic across
every phase's ledger, with no opt-in marker — because an opt-in is an opt-out and opt-outs rot. So
this ledger inherits the whole contract: `BEFORE-` / `AFTER-` slots, a status line in the
captured-with-run-id or pending-with-reason grammar, a fenced producing command in every captured
slot, and the status run id corroborated inside the slot body. Two shipped prohibition guards can be
pointed at this file to check every one of those mechanically, so the ledger's own honesty is not a
matter of care.

One criterion cannot close in phase. SC-1 needs a `schedule` event, the cron cannot be forced forward,
and no dispatch produces a scheduled run. It is booked as pending with its exact capture command and
with D-16's fallback criteria written down IN ADVANCE — so that if the first nightly is not literally
green, the response is a pre-agreed procedure rather than a negotiation about how green is green
enough.

Purpose: the phase's five criteria become one re-derivable record instead of eleven scattered claims.
Output: `231-EVIDENCE.md`, and a clean pre-merge hygiene check that protects SC-1's future receipt.
</objective>
