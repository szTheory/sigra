<objective>
GATE-02's enable half — the third link in D-24's locked chain, taken only after the lane is green
(plan 231-02) and after GATE-04's fix (plans 231-04 through 231-06).

The defect is one line. `ci.yml:1674` reads
`if: github.event_name != 'pull_request' || github.head_ref == 'ship/v1.42-ci-gate-remediation'`.
That branch was merged months ago. Since then the condition has evaluated false on every pull
request, the job has concluded `skipped`, and `ci-gate` has counted `skipped` as a pass — so
generated-host parity has reported green while verifying nothing, on every PR, for months. D-06
deletes the clause outright rather than replacing it with the house non-PR pattern, because a job
that runs on no PR at all is GATE-02's defect restated, not fixed.

Two corrections from RESEARCH change what "same-commit" means here, and both are recorded in this
plan rather than quietly applied. **C-1:** the parity enforcer D-01 and D-10 both name,
`honest-skip-parity.test.mjs`, does not exist; `git log -S` finds no trace of it. The real coverage
is split across `p10` (manifest versus ci.yml) and `p07` (MAINTAINING.md versus manifest, tier B
only), and neither has ever read the manifest's `gate` column. **C-2:** consequently D-10's boundary
is inverted. Leaving the stale row is silently accepted, because p10 only checks that the id resolves
and the display name matches — both still true. Deleting the row, which is the correct edit for a job
that can no longer skip, drops tier A to eight rows and reds p10's floor of nine with a message about
a broken parse when the parse is fine.

So the same-commit set is larger than D-10 says: the workflow line, the manifest row, p10's two
floors with their reasons, and three separate places in `MAINTAINING.md` — including `:152-153`,
which D-10 does not mention and which also names the job.

This plan also adopts RESEARCH's Open Question 2 recommendation and gives p10 a `gate`-column
assertion. That is the check that would have caught this defect, it is roughly fifteen lines, and it
makes the manifest's `gate` column load-bearing for the first time — directly serving GATE-03's
mandate that a condition which reads plausibly and verifies nothing must fail.

Purpose: generated-host parity is verified on a lane that actually executes on a PR.
Output: one deleted condition, one deleted manifest row, two lowered floors with recorded reasons,
two new p10 assertions, and three reconciled `MAINTAINING.md` passages.
</objective>
