<objective>
GATE-03's enforcement half. Plan 231-08 built a verdict that can tell a correctly-gated skip from a
rotted one; nothing consumes it yet. This plan makes `ci-gate` consume it, and closes SC-3 with two
real dispatched runs.

Three structural obstacles stand between the script and the gate, and RESEARCH found all three by
reading the job rather than assuming it. **`ci-gate` has no checkout** — it is a pure aggregation job
with exactly one step, so the script cannot read the manifest at all until a checkout is added.
**`changes` is not among `ci-gate`'s nine `needs:`** — so `needs.changes.outputs.docs_only` resolves
to empty rather than erroring, which would make `library_tests_dep_off`'s legitimate docs-only skip
look illegitimate on every docs-only PR and red the gate. And **`nightly_probe`'s shape is the wrong
model for SC-3** — it sits deliberately outside `ci-gate.needs`, whereas the rot probe must reach
`ci-gate`'s verdict, so the probe becomes a verdict-script flag threaded through the step env rather
than a new job. The DAG does not change.

The wiring is deliberately two steps, not one. The new verdict runs first and the existing
`Verify required release CI lanes` loop stays byte-unchanged behind it. That costs one duplicated
condition and buys a reviewable diff plus a provable non-regression at the exact gate this milestone
exists to make trustworthy.

D-25 binds the proof: SC-3 closes on two named run IDs and a named command. A clean dispatched run
whose `ci-gate` concludes `success`, and a rot-probe run whose `ci-gate` concludes `failure` and whose
log names the lane. A YAML condition that reads plausibly is exactly the failure mode being removed.

Purpose: `ci-gate` fails when a needed lane is skipped by a rotted condition and passes when it is
skipped by a correct event gate.
Output: a rewired `ci-gate`, the `force_rot_probe` input, self-test case T, two probe receipts, and
one filed todo.
</objective>
