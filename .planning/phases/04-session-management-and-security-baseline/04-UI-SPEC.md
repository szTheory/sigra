# Phase 4 -- UI Design Contract

> Visual and interaction contract for generated UI templates. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Elixir library -- not a JS frontend) |
| Preset | not applicable |
| Component library | Phoenix core components (`.header`, `.form`, `.input`, `.button`, `.link`, `.table`, `.flash`, `.modal`) |
| Icon library | Heroicons via Phoenix core components (`<.icon name="hero-*" />`) |
| Font | System font stack (inherited from host app's Tailwind config) |

**Note:** Sigra is an Elixir library that generates Phoenix LiveView templates and controller views into the host application. All UI is server-rendered HEEx using Phoenix core components and Tailwind CSS utility classes. There is no client-side JS framework. The shadcn gate does not apply.

| Role | Tailwind Class | Effective Size | Weight | Line Height |
|------|---------------|----------------|--------|-------------|
| Body | `text-sm` | 14px | 400 (normal) | 1.5 (`leading-normal`) |
| Label | `text-sm` | 14px | 600 (`font-semibold`) | 1.5 |
| Heading | `text-lg` | 20px (via `.header` component) | 600 (`font-semibold`) | 1.2 |
| Display | `text-2xl` | 28px (email subject lines in preview) | 700 (`font-bold`) | 1.2 |

Source: Matches existing template patterns (`.header` component uses `text-lg font-semibold`, body text uses `text-sm`).

## Color

All colors reference Tailwind classes and Phoenix's default color tokens. Generated templates do not hardcode hex values -- they use the host app's Tailwind theme.

| Role | Tailwind Token | Usage |
|------|---------------|-------|
| Dominant (60%) | `bg-white` / page background | Page surfaces, form backgrounds |
| Secondary (30%) | `bg-gray-50`, `border-gray-200` | Session list cards, table rows, dividers |
| Accent (10%) | `text-brand` | Primary CTA buttons, active links, "This device" badge |
| Destructive | `text-red-600`, `bg-red-50` | Revoke session button, "Log out everywhere" button, lockout warning |
| Warning | `text-yellow-700`, `bg-yellow-50` | Rate limit flash message |
| Muted | `text-gray-500` | Timestamps, IP addresses, secondary text in session list |

Accent reserved for:
- Primary action buttons ("Confirm password" on sudo page)
- "This device" badge/indicator on current session
- Navigation links (back to settings)

Destructive reserved for:
- "Revoke" button on individual sessions
- "Log out of all devices" button
- Lockout notification banner text

Source: Matches existing template patterns (`text-brand`, `text-gray-500`, `hover:underline`).

## UI Surfaces

### Surface 1: Session Listing LiveView (`session_live.ex`)

**Route:** `/users/sessions`
**Requirement:** SESS-06, D-17, D-19
**Layout:** `mx-auto max-w-2xl` (wider than auth forms to accommodate session metadata)

**Components used:**
- `.header` with subtitle
- `.table` or custom list (each session as a row/card)
- `.button` for revoke actions
- `.icon` for device type indicators
- `.flash` for success/error feedback after revocation

**Session row displays:**
| Field | Format | Example |
|-------|--------|---------|
| Device | `{browser} on {os}` from UA parser | "Chrome 120 on macOS" |
| IP address | Raw IP string, muted text | "192.168.1.1" |
| Location | City, Country (if GeoIP configured) or "Unknown location" | "San Francisco, US" |
| Last active | Relative time | "Active 5 minutes ago" |
| Current indicator | Badge with "This device" | Green badge: "This device" |
| Revoke action | Button per row | "Revoke" (destructive style) |

**States:**
| State | What User Sees |
|-------|---------------|
| Default | List of all active sessions for the current user |
| Single session | Only one session (current), no revoke button shown, "Log out of all devices" hidden |
| After revoke | Flash: "Session revoked." Session removed from list |
| Revoke current | Confirmation modal: "This is your current session. Revoking it will log you out. Continue?" |
| After revoke all | User is logged out, redirected to login with flash: "All sessions ended." |
| Empty (edge) | Should not occur (user must be logged in), but if it does: "No active sessions found." |

**Interactions:**
- "Revoke" button on non-current sessions: immediate revocation, no confirmation
- "Revoke" on current session: confirmation required (modal or inline confirm)
- "Log out of all devices" button at bottom: confirmation required, then redirect to login
- Page auto-refreshes session list via LiveView (no manual refresh needed)

### Surface 2: Sudo Re-Authentication Page (`sudo_controller.ex` + `sudo_html.ex`)

**Route:** `/users/sudo`
**Requirement:** SESS-09, D-20-D-23
**Layout:** `mx-auto max-w-sm` (matches login form width)

**Components used:**
- `.header` with subtitle
- `.form` with password input
- `.button` for confirmation
- `.input` for password field

**Fields:**
| Field | Type | Label | Autocomplete |
|-------|------|-------|-------------|
| Password | `password` | "Password" | `current-password` |

**States:**
| State | What User Sees |
|-------|---------------|
| Default | Header: "Confirm your password" / Subtitle: "For your security, please re-enter your password to continue." / Password field + "Confirm password" button |
| Wrong password | Flash error: "Incorrect password. Please try again." |
| Locked out | Flash error: "Too many attempts. Try again in a few minutes." (reuses lockout messaging) |
| Success | Redirect back to `return_to` URL |

**Interactions:**
- Form submits via HTTP POST (not LiveView event -- follows D-21 pattern)
- `return_to` param preserved in hidden field
- Pressing Enter submits the form
- Cancel link: "Go back" link returns to previous page without re-auth

### Surface 3: Lockout Notification Email (`lockout_notification_email/2`)

**Requirement:** D-28, D-62
**Delivery:** Async via Oban (Phase 3 infrastructure)
**Format:** HTML + text multipart

**Email content:**
| Element | Value |
|---------|-------|
| Subject | "Your account has been temporarily locked" |
| Heading | "Account Locked" |
| Body paragraph 1 | "We detected multiple failed login attempts on your account. For your security, your account has been temporarily locked for 15 minutes." |
| Body paragraph 2 | "If this was you, you can try again after the lockout period." |
| CTA | "Change your password" -- links to `/users/reset_password` |
| Body paragraph 3 | "If you did not attempt to log in, we recommend changing your password immediately." |
| Footer | "You received this email because your {app_name} account experienced a security event." |

### Surface 4: Suspicious Login Email (`suspicious_login_email/2`)

**Requirement:** SEC-07, D-44-D-46, D-62
**Delivery:** Async via Oban (Phase 3 infrastructure)
**Format:** HTML + text multipart

**Email content:**
| Element | Value |
|---------|-------|
| Subject | "New sign-in to your account" |
| Heading | "New Sign-In Detected" |
| Body paragraph 1 | "We noticed a new sign-in to your account from an unrecognized device or location." |
| Detail: IP | "IP address: {ip}" |
| Detail: Location | "Location: {city}, {country}" (or "Location: Unknown" if no GeoIP) |
| Detail: Device | "Device: {browser} on {os}" |
| Detail: Time | "Time: {formatted_datetime} UTC" |
| Body paragraph 2 | "If this was you, you can safely ignore this email." |
| CTA | "Not you? Secure your account" -- links to `/users/reset_password` |
| Footer | "You received this email because your {app_name} account experienced a security event." |

### Surface 5: Rate Limit 429 Response (Browser)

**Requirement:** SEC-02, D-39
**Format:** Flash redirect for browser, JSON for API

**Browser response:**
- Redirect back to the form page
- Flash warning: "Too many requests. Please try again in {retry_after} seconds."
- Flash style: warning (yellow)

**API response:**
```json
{"error": "rate_limited", "retry_after": 45}
```
- HTTP status: 429
- `Retry-After` header: seconds until window resets

### Surface 6: Lockout Flash Messages

**Requirement:** SEC-01, D-30
**Format:** Flash messages on login form

| Scenario | Flash Type | Message |
|----------|-----------|---------|
| Failed login (not locked) | error | "Invalid email or password" |
| Failed login (now locked) | error | "Invalid email or password. Too many attempts. Try again in a few minutes." |
| Failed login (already locked) | error | "Too many attempts. Try again in a few minutes." |

All messages are enumeration-safe: identical whether the email exists or not.

## Interaction Patterns

### Session Listing

1. User navigates to `/users/sessions` from settings
2. LiveView loads and displays all active sessions via `Sigra.Auth.list_sessions/2`
3. Current session is identified by matching token from conn and tagged with "This device" badge
4. User clicks "Revoke" on a non-current session -- session is deleted, list updates via LiveView
5. User clicks "Revoke" on current session -- confirmation appears, on confirm user is logged out
6. User clicks "Log out of all devices" -- confirmation appears, on confirm all sessions deleted + PubSub broadcast, user redirected to login

### Sudo Re-Authentication

1. User attempts to access a sudo-protected route
2. `RequireSudo` plug checks `sudo_at` on session -- if expired, redirects to `/users/sudo?return_to={original_path}`
3. User enters password, submits form via POST
4. On success: `sudo_at` updated on session record, user redirected to `return_to`
5. On failure: flash error, form re-rendered
6. On lockout: flash lockout message, form re-rendered

### Rate Limiting

1. User submits a rate-limited form (login, register, reset, magic link)
2. `Sigra.Plug.RateLimit` checks IP against Hammer
3. If allowed: request proceeds normally
4. If denied: 429 response -- browser gets redirect + flash, API gets JSON + Retry-After header

## Accessibility Requirements

| Requirement | Implementation |
|-------------|---------------|
| Form labels | All inputs use `.input` component with explicit `label` prop |
| Error messages | Associated with inputs via `aria-describedby` (Phoenix core component default) |
| Focus management | After revocation, focus returns to session list |
| Button labels | All buttons have descriptive text (no icon-only buttons without aria-label) |
| Flash announcements | Flash messages use `role="alert"` for screen reader announcement |
| Color contrast | All text meets WCAG 2.1 AA (4.5:1 for body text, 3:1 for large text) -- verified by Tailwind defaults |
| Keyboard navigation | All interactive elements reachable via Tab; forms submit on Enter |
