<objective>
Build `Example.Demo.Seeds` — the idempotent upsert orchestrator that turns the `Personas` data (plan 02) and the `UserIdentity` schema (plan 01) into a fully-populated demo database. For each persona it: (1) registers through `Example.Accounts.register_user/1` to fire real audit events and produce a real Argon2id hash, deduping on `{:error, :email_taken}`; (2) patches state-only lifecycle fields (`confirmed_at`, `locked_at`, `failed_login_attempts`, `deleted_at`, `scheduled_deletion_at`, Dave's `hashed_password` clear) via direct `Repo.update!` (the context API does not expose these); (3) inserts association rows (TOTP credentials, passkey display row, orgs, memberships, pending invitation, EnterpriseConnection, UserIdentity, audit events) with `on_conflict:` keyed on existing unique indexes. No hard-coded UUIDs — let Postgres generate PKs and fetch generated IDs for cross-references (D-02).

Purpose: This is the substance of the phase — the orchestrator that makes all six auth states and the rich audit trail observable in the library admin UI. It is consumed by `seeds.exs` (plan 04) as the final integration step.
Output: `seeds.ex` (`Example.Demo.Seeds.run/0`).

TWO load-bearing corrections from PATTERNS.md MUST be encoded (see the audit + identity tasks):
1. Reserved-prefix audit actions (`auth.*`, `session.*`, `mfa.*`, plus `oauth./api./account./sigra.`) RAISE unless `AuditEvent.changeset/3` is called with `allow_reserved: true` as the 3rd arg.
2. Admin detail filters a user's audit by `effective_user_id == id OR target_id == id`; `actor_id` alone will NOT surface rows. Admin-visible audit rows MUST set `effective_user_id` (or `target_id`) to admin's id. `audit_events` has NO unique index — idempotency uses a count/threshold guard, NOT `on_conflict`.
</objective>
