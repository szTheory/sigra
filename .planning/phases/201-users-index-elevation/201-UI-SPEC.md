## Design System

| Property | Value |
|----------|-------|
| Tool | none — hand-authored `sg-*` cascade-layer BEM system |
| Preset | not applicable |
| Component library | Sigra.Admin.Components (HEEx function components) |
| Icon library | none — CSS glyphs and text labels only |
| Font | Space Grotesk (self-hosted in `test/example/priv/static/assets/fonts/`; `--font-sans` on admin shell) |

**Design system rules (binding for this phase):**

- All layout, spacing, color, and motion must use existing `--sg-*` CSS custom properties. No one-off hex values, no Tailwind utilities, no inline style overrides.
- New CSS classes require the `sg-` prefix and must be written byte-identically across all three CSS copies (CONTEXT D-11):
  - `priv/templates/sigra.install/admin/sigra_admin.css`
  - `test/example/priv/static/assets/sigra_admin.css`
  - `test/fixtures/install_golden/tree/priv/static/assets/sigra_admin.css`
- Reuse existing primitives first. Introduce a new function component or CSS class only when a pattern is genuinely reused in more than one place.
- Never `transition: all`. Use exact-property transitions only (color, background-color, box-shadow, opacity, transform). (admin-ui-principles.md)
- `sg-chevron` currently has zero CSS rules in all three copies — either add rules or drop the class during consolidation (CONTEXT D-11).

1. `sg-btn--primary` fill — the "Search" submit button inside the filter panel

**Color rules:**

- The slimmed metric strip shows risk/warn tones only when counts are non-zero. At zero, use default/ok tone.
- `--sg-color-brand` is NOT for every heading, icon, or highlighted value. Use `--sg-color-ink` for emphasis on non-brand elements.

## Reduced Pill Vocabulary (D-04)

The `status_pills/1` function is reduced from the current set to decision-bearing signals only.

| Signal | Tone | Keep? | Rationale |
|--------|------|-------|-----------|
| Unconfirmed | warn | YES | Operator action may be needed — user cannot complete sign-in |
| Locked | risk | YES | Operator action needed — unlocking is an admin task |
| Deletion scheduled | warn | YES | Contextual awareness — account access disabled |
| Confirmed | ok | NO (DROPPED) | Green pills on nearly every row are noise; absence of Unconfirmed implies confirmed |
| MFA + passkeys | ok | NO (COLLAPSED) | Always-ok rows create visual noise in exception-scanning |
| MFA only | ok | NO (COLLAPSED) | As above |
| Passkeys only | ok | NO (COLLAPSED) | As above |
| No MFA | warn | YES (SURFACED) | Actionable — operator may want to follow up; no-security rows are the exception |

**Fully-secured rows (MFA or passkeys, no warn/risk flags):** show zero security pills. No quiet marker — absence of a "No MFA" pill is the signal.

## Interaction Contract

### Filter Form (D-02)

The filter form uses `method="get"` with `action={index_path(@admin_scope)}`. All filter state is URL-driven.

| Rule | Detail |
|------|--------|
| Form submission contract | `<form method="get">` — do NOT convert quick-filter chips to `phx-click` |
| Applied-chip clear | Navigation via `<a href={remove_chip_path(...)}>` — pure GET, no LiveView event |
| Clear all | `<a href={index_path(@admin_scope)}>` — plain navigation link |
| "More filters" toggle | `phx-click="toggle_filters"` stays a LiveView event (not in form submission) |
| Inputs outside form | NONE — every named input must remain inside `<form>`. Applied-chip row relocation must stay inside form boundary or be a sibling with navigation-only anchors (no named inputs). |
| Return-to round-trip | `open_user_path/3` encodes current filters for back navigation; pagination URLs from `page_path/3`; both depend on URL state — must remain intact |

### Applied-Chip Panel Placement (D-01)

The applied-chip row (currently a `<div>` sibling after `</form>`) moves up to sit directly below the search row, inside or visually contiguous with the filter panel. The exact placement is at Claude's discretion but:
- Must not break the GET form — if chips move inside the form, they must be navigation-only `<a>` tags (no named inputs).
- Must render only when `any_filter_active?(@current_params)` is true.
- The "Clear all" link remains.

### Desktop Table Column Order (D-06 — FROZEN CONTRACT)

```
td:nth-child(1) — User (primary_name / email / id)
td:nth-child(2) — Status (status_pills + extra_badges)
td:nth-child(3) — Organizations (organization_summary + count)
td:nth-child(4) — Activity (activity_label + registered_label + extra_columns)
td:nth-child(5) — Action (Open user button)
```

Any reorder, insertion, or removal of a column MUST update `assertUserResultEquivalence` selectors at `admin-design.spec.ts:151-164` in the same change.

### Host-Seam Preservation (D-07)

`extra_badges` and `extra_columns` from `decorate_rows/2` must appear in BOTH the desktop table (td for status/activity columns) and the mobile card stack. The shared `<.user_row_fields>` component must preserve both seams. The example's `sigra_admin_users.ex` (`:20,23`) should be updated to emit one non-empty badge + column to give the equivalence spec real coverage.

### Keyboard Navigation

- All interactive controls reachable by Tab in logical DOM order.
- Quick-filter checkboxes: each is independently focusable; GET form submission on Enter.
- Applied-chip remove links: each `<a>` is independently focusable; aria-label carries full context.
- "More filters" toggle: button, keyboard-activated via Enter/Space.
- "Open user" row action: focusable per row.
- Pagination prev/next links: native `<a>` elements.
- Search input: receives initial focus on mobile (viewport-appropriate, if implemented).

### Progressive Disclosure

- "More filters" uses the existing `phx-click="toggle_filters"` + `aria-expanded` pattern — do not convert to `<details>`.
- `aria-expanded={to_string(@filters_open?)}` must remain on the toggle button.
- The hidden advanced filter grid renders with `:if={@filters_open?}` (existing behavior).

### Responsive Behavior

| Viewport | Behavior |
|----------|---------|
| 320px–639px | `sg-show-mobile` card stack visible; `sg-show-desktop` table hidden. Applied chips wrap within `sg-cluster`. Search row stacks vertically if needed. Metric strip chips wrap within `sg-metric-grid`. |
| 640px–1023px | Same mobile/desktop split at the `sg-show-*` breakpoint. Filter panel may use two-column grid for advanced filters (`sg-form-grid--cols`). |
| 1024px+ | Desktop table visible. All five columns rendered. Full filter panel visible. |

### Reduced Motion

- The `@media (prefers-reduced-motion: reduce)` universal clamp at `sigra_admin.css:1467-1478` handles all components automatically. No per-component reduced-motion overrides needed.
- No new animations introduced in this phase. Quick-filter checkbox state changes are not animated (keyboard-frequent path per admin-ui-principles.md).
- Applied-chip `sg-applied-chip__remove` hover transition (`var(--sg-transition-tone)` at 140ms) is existing behavior — do not change.

### Theme Behavior

All components must render correctly in Light / Dark / System themes by using `--sg-color-*` tokens throughout. No hard-coded color values.

- The metric strip `summary_chip` components already use tone tokens — preserve.
- Status pills use `data-tone` attribute + `sg-status-pill[data-tone=risk/warn]` selectors — these already respond to `--sg-color-risk-*` / `--sg-color-warn-*` tokens in both themes.
