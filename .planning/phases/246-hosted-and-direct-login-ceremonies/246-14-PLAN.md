<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| factor result → persisted browser session | A successful second factor must upgrade the authoritative database session, not merely Plug flags. |
| LiveView event → Plug session | LiveView cannot self-assert completed assurance; token rotation must cross through the generated server session seam. |
| renewed session → hosted continuation | Only the bounded signed handle survives renewal and approval remains a separate CSRF-protected decision. |

## STRIDE Threat Register (ASVS L1; block high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-246-41 | Elevation of Privilege | controller/LiveView MFA completion | high | mitigate | Require a trusted `:mfa_pending` row, call `complete_mfa_verification`, rotate through `put_user_session_token`, and prove the old row cannot authorize approval. |
| T-246-42 | Tampering | LiveView completion transport | high | mitigate | Carry only CSRF-protected server state and reject missing/mismatched pending-session context. |
| T-246-43 | Information Disclosure | continuation preservation | medium | mitigate | Preserve only the signed handle; keep callback, state, factor, and credentials out of flash, logs, and rendered markup. |
</threat_model>
