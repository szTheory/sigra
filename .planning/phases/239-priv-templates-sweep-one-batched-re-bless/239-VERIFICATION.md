### Gaps Summary

This phase did real, unusually honest work. It killed the `.planning/` path leak on the bytes that
actually reach adopters, it caught its own instrument certifying a false clean and replaced it with
a measurably wider one carrying live per-alternation controls, it recorded a gate RED with a

re-derivation, and it left the tarball's 475-line `lib/` bookkeeping baseline measured rather than
hidden. The D-26 amendment is a legitimate response to a real constraint.

It does not achieve its stated goal. Two sentences of Sigra-internal bookkeeping ship into every
generated app at HEAD, one of them in a file plan 239-06 opened and edited and the code review
flagged as WR-02 before this verification ran. They survive because V2 matches plan identifiers and
these are plan vocabulary — structurally the same blind spot as V1's, one class up. And the Hex
tarball an adopter downloads carries 58 `.planning/` path references in its packaged `docs/`,
`README.md`, and `CHANGELOG.md`; SC-2 says "the tarball", and the tarball is not clean.

The right closure is small: strip the two sentences, fix WR-01/WR-03 while in the file, re-mirror,
re-bless (a third batch, which D-26 as amended permits), and then either clean the packaged docs
surface or narrow SC-2's wording to `lib/`+`priv/` and route `docs/` to Phase 241's SURF-04 ratchet.
What should not happen is accepting a V2 zero as proof of the goal — that is the instrument this
phase itself put on trial.
