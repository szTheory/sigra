## The Central Question, Answered

**Every declared success criterion substantially passes. The goal does not hold.**

SC-1 and SC-2 assert "greps clean", and the greps did come back clean — against a regex frozen in
`239-EVIDENCE.md`. That regex cannot match the bookkeeping that is still shipping. Running a wider
net over the literal bytes an adopter generates:

```
$ grep -rnE '\b[0-9]{3}-[0-9]{2}\b|\bround[s]?[ -][0-9]|\bwave [0-9]|actions/runs/[0-9]+|\bruns? [0-9]{9,}' \
    test/fixtures/install_golden/tree
.../priv/static/assets/sigra_auth.css:524:  initial round-3 draft that used `overflow-wrap: break-word` here silently
.../priv/static/assets/sigra_auth.css:531:  runs 30518012012 and 30518015684 immediately after the round-3 commit, never
.../priv/static/assets/sigra_auth.css:696:  automatic minimum width (min-content) even though 231-02's min-width: 0 already

$ grep -rnw UAT test/fixtures/install_golden/tree
.../lib/sigra_install_golden_tmp_web/controllers/session_html.ex:8:  submit during UAT. With no LiveView process on the page, the browser
```

That tree is not a proxy. I re-ran `MIX_ENV=test mix sigra.fixture.rebless_golden --check`, which
scaffolds a fresh app through `mix sigra.install` and byte-compares — it printed
`OK: fixture is up-to-date (check mode.)` and exited 0. So those four lines are, verbatim, in the
app every adopter generates today. Live GitHub Actions run IDs, a Sigra plan ID (`231-02`), Sigra's
own review-round history, and Sigra's QA-process vocabulary.

**The instrument gap is itself the deeper finding.** The frozen union regex requires a trailing
`.md` on plan-ID matches (`[0-9]{3}-[A-Z0-9-]+\.md`), so a bare `231-02` is unmatchable; it has no
pattern at all for `round N`, for CI run IDs, or for `UAT`. This is not a near-miss — it is a
category of bookkeeping the gate was never able to see. Phase 241's SURF-04 `p18-*.test.mjs` guard
is scheduled to be built on this same definition, and Phase 241 explicitly "Depends on: … Phase 239
(the surface must be clean before it is gated)". Gating a surface that is not clean, with a
definition that cannot see why, freezes the leak in place permanently.

**The overcorrection guard, applied.** I did not take the review's word for it. I re-ran the
frozen regex (0 on `priv/templates`, 0 on the golden tree, 0 on `STDOUT.txt`) with two positive
controls (97 files match `defmodule` in `priv/templates`; the same regex fires 366 times on
`test/example`), so the zeros are real negatives, not dead greps. I then cast a deliberately
wider net for `SEED-`/`FUT-`/`PR #`/`ROADMAP`/`commit <sha>`/`CI run`/`plan N` across both
surfaces: apart from the four lines above, every hit was a false positive (`verification`,
`gap-2`, an SVG `d=` path). The leak is exactly four lines plus their two surrounding sentences —
no more, and no less.

## Gaps Summary

The phase did the hard, careful work well. The commit topology is exactly as specified: one sweep,
one mirror, one re-bless, each provably confined to its own surface. The SC-3 classifier is
genuinely falsifiable — I proved it red against a committed known-bad fixture rather than trusting
its green. `.github/` is untouched, no security rationale was deleted, the tarball and the
freshly-generated app are both free of `.planning/` paths, and the named dead path in
`organizations.ex` is gone. SURF-01 is met.

What it did not do is achieve its own goal sentence. Four lines of Sigra-internal bookkeeping — two
live GitHub Actions run IDs, a plan ID, the phase's own review-round history, and its QA
vocabulary — are still copied verbatim into every adopter's `priv/static/assets/sigra_auth.css` and
`SessionHTML` moduledoc. They survived because the gate was built to a narrower definition than the
goal, and once the gate went green the surface stopped being looked at. That is the failure mode
worth naming: the phase certified the instrument, and the instrument was mistaken for the outcome.

Three fixes close this, and they are small: rewrite two CSS comment blocks and one moduledoc
sentence; widen the bookkeeping definition by five alternations and re-measure; re-run the single
batched re-bless. The mirror and prose gaps (SC-4, WR-03…WR-07) are lower-severity and can ride the
same closure plan, since the router/layouts mirror and the degraded template wordings both touch
text an adopter or a future maintainer reads.

One thing makes this urgent rather than cosmetic: Phase 241 depends on Phase 239 with the stated
rationale *"the surface must be clean before it is gated"*, and Phase 241's SURF-04 `p18` guard
inherits this exact definition of "bookkeeping". Shipping 239 as-is bakes a blind spot into the
permanent guard — after which the remaining leak becomes invisible by construction.
