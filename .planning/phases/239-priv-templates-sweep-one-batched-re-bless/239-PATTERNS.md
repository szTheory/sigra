**Analog:** `.planning/phases/237-clean-working-tree-green-pages-clean-lib-docs-surface/237-security-comment-diff-check.sh`

**(a) Header block declaring it is a phase artifact, not repo tooling** (`:1-26`):

```bash
#         nothing is mechanically impossible to mistake for a real pass.

# This script is deliberately NOT wired into any workflow or prohibitions glob — the durable
# bookkeeping ratchet is Phase 241's `p18` slot. This is an in-plan phase artifact, committed so

```

Copy this framing verbatim in shape: (1) filename + "phase artifact, not repository tooling" +
decision id anchor; (2) rationale paragraph; (3) `Usage:` block; (4) **per-exit-code contract
documented in the header before any code**; (5) an explicit "NOT wired into any workflow" sentence
(Standing Constraint 5 — 239 builds no guard; `p18` is Phase 241's).

**(b) Strict mode + argv contract** (`:28-45`):

```bash
set -euo pipefail

if [ "$#" -ne 1 ]; then
  echo "usage: $0 <diff-file>|-" >&2
  exit 2
fi

input_arg="$1"

if [ "$input_arg" = "-" ]; then
  content="$(cat)"
else
  if [ ! -r "$input_arg" ]; then
    echo "FAIL: cannot read input file: $input_arg" >&2
    exit 1
  fi
  content="$(cat "$input_arg")"
fi
```

Exactly one positional argument; `-` means stdin; unreadable file → exit 1; wrong arity → exit 2.

**(c) The fail-closed-on-empty guard — the line the research cites** (`:47-50`):

```bash
if [ -z "$content" ]; then
  echo "FAIL: empty diff input — refusing to report success on no input (fail-closed guard)" >&2
  exit 1
fi
```

This is the single most important line to copy. For 239 the guard must be *stronger* than 237's,
because an empty `git diff -- test/fixtures/install_golden/` is a realistic vacuous-pass path
(re-bless run before commit 1, or wrong path). Extend it with the non-vacuity thresholds from
RESEARCH §5.1: `changed_lines >= 200` and `files >= 30`, both **printed**, both failing closed.

**(d) Line-class filtering pipeline, `|| true`-guarded under `set -e`** (`:52-65`):

```bash
removed="$(printf '%s\n' "$content" | grep -E '^-' | grep -vE '^--- ' || true)"

examined=0
if [ -n "$removed" ]; then
  examined="$(printf '%s\n' "$removed" | grep -c '.' || true)"
fi

class_hits="$(printf '%s\n' "$removed" | grep -iE '\b(security|CSRF|…)\b' || true)"
survivors="$(printf '%s\n' "$class_hits" | grep -vE '\b(D-[0-9]{2}|SC-[0-9]+|Phase [0-9]{1,3})\b|\.planning/' | sed '/^$/d' || true)"
```

Note the idiom: every `grep` in a pipeline under `set -e` carries `|| true`; results are held in
shell vars and tested with `[ -n … ]` rather than relying on grep exit status. Copy this.
For 239 the analogous body is the **expected-removed-set containment** check (RESEARCH §5.1 option
1): `removed_set ⊆ expected_set`, where `expected_set` is the pre-sweep snapshot file. `comm -23`
on two sorted files is the natural implementation and keeps the same "hold in a var, test with
`-n`" shape.

**(e) Verdict block — failures to stderr, counters to stdout** (`:67-74`):

```bash
if [ -n "$survivors" ]; then
  echo "FAIL: removed line(s) carry security/design rationale with no bookkeeping token:" >&2
  printf '%s\n' "$survivors" >&2
  exit 1
fi

echo "examined_removed_lines=${examined}"
exit 0
```

`FAIL: …` prefix + offending lines to **stderr**; the observable counter to **stdout**; explicit
`exit 0`. 239's counters per RESEARCH §5.4 are `changed_lines=<N>`, `files=<N>`, `nonconforming=<N>`
— print **all three** on success *and* on failure.

### Editing conventions inside `priv/templates/` (generator template, transform)

**Analog: the corpus itself.** Key facts a plan must not violate:

**1. `priv/templates/` is NOT in the formatter inputs.** `.formatter.exs:3-13` lists
`"{config,lib}/**/*.{ex,exs}"`, `test/{sigra,support,mix}/**`, `test/example/{lib,config,test,priv}/**`
— `priv/templates` is absent (templates contain `<%= @module %>` interpolations that are not valid
Elixir). So `mix format --check-formatted` will **not** police template edits, but it **will**
police the `test/example/` mirror edits in commit 2. Removing a comment line from a mirrored
`.ex` file can change the formatter's preferred wrapping of the following expression — run
`mix format` on the touched example files, and expect that to be the only non-comment change there.

**2. The `<%%` / `<%%=` escape idiom** (the D-12 / RESEARCH §2.4 subset, 17 lines / 7 files).
Inside a template, `<%%` is EEx's escape for a literal `<%`. Live example,
`priv/templates/sigra.install/core/settings_live.ex:66` and `:77`:

```heex
      <%%= # Force password change banner (D-58) %>
      <div
        :if={@force_password_change?}
        class="sigra-auth-notice sigra-auth-notice--warning"
      >
```

and `priv/templates/sigra.install/core/mfa_challenge_live.ex:290,297`:

```heex
      <%% # Remaining attempts hint (D-38) %>
      <div :if={@active_method != "passkey"} aria-live="polite">
```

These render into the generated app as `<%= # … %>` / `<% # … %>` — verified present in the golden
tree at `tree/…_web/live/settings_live.ex:66` and `tree/…_web/live/mfa_challenge_live.ex:288`
(RESEARCH §2.4). Line numbers shift between template and golden (EEx header offset of 2) — map by
**content, never by line number**.

**A safe edit vs an unsafe one:**

| Safe | Unsafe |
|---|---|
| Delete the **entire** `<%%= # … %>` line, leaving the surrounding markup untouched | Deleting only the `<%%=` opener and leaving a stray `%>` |
| Rewrite the text *inside* the comment, keeping `<%%`/`<%%=` … `%>` intact | Changing `<%%=` to `<%%` (or vice versa) — changes the emitted tag in the generated file |
| Edit a `#`-comment line in plain Elixir template body | Touching any line that is markup or an `:if={…}` attribute |
| Edit `@moduledoc`/`@doc` heredoc prose | Editing a `@doc "…"` one-liner *without noting it is adopter-facing API doc text* (see below) |

**3. `@doc "…"` one-liners are adopter-facing API documentation, not comments.**
`priv/templates/sigra.install/organizations/organizations.ex:65,75,85,99`:

```elixir
  @doc "Rename an organization (D-10 — inline, no password required)."
  @doc "Update an organization's slug (D-11 — requires inline password + typed confirm)."
  @doc "Soft-delete an organization (D-11 — requires inline password + typed confirm)."
  @doc "Change a member's role with last-owner guard (D-18)."
```

Rewriting these changes text the adopter reads in their own IEx/ExDoc. That is desirable, but it is
a **content** change, not a comment strip — call it out so a reviewer expects it.

**4. The one `.planning/` path, in context** (`organizations/organizations.ex:55-62`) — a
multi-line comment where the token spans two physical lines, so a per-line strip is wrong:

```elixir
  # `use Sigra.Organizations` above already injects thin delegators for
  # `list_organizations_for_user/1`, `remove_member/2`, and a 3-arg
  # `change_role/3`. The wrappers below route the Phase 16 LiveView callers
  # (settings page + members list) through Sigra.Organizations with the
  # configured @sigra_org_config. See .planning/phases/16-org-liveviews-switcher/
  # 16-CONTEXT.md D-10 / D-11 / D-16 for signatures.
```

The `.planning/` URL wraps across `:59-60`; `:62` carries a separate `Phase 16 Plan 01` token. Treat
comment **blocks**, not lines, as the edit unit.

### The golden fixture / re-bless lane (mix task + contract test, batch regeneration)

**Analog / the thing itself:** `lib/mix/tasks/sigra.fixture.rebless_golden.ex` (246 lines).

**Invocation + "does not commit" contract** (`:10-21`, moduledoc):

```
      MIX_ENV=test mix sigra.fixture.rebless_golden
      MIX_ENV=test mix sigra.fixture.rebless_golden --check

  `--check` writes to a tmp dir and diffs against the committed fixture without
  modifying `test/fixtures/install_golden/`. Exits 2 if drift is detected. …

  The task does NOT stage, commit, or amend. After a normal (non-check) run,
  review `git diff test/fixtures/install_golden/` before committing.
```

**Replace-not-merge write** (`:92-103`) — why the fixture cannot carry stale leaves:

```elixir
  defp write_tree!(target_tree_dir, tree) do
    # Replace — not merge — so stale leaf files from a prior rebless cannot
    # linger. The fixture layout mirrors the normalized tree exactly.
    File.rm_rf!(target_tree_dir)
    File.mkdir_p!(target_tree_dir)
    for {rel_path, content} <- tree do …
```

**How `--check` signals drift** (`:115-140`) — the exact exit semantics the plan's verifications
must assert:

```elixir
    {tree_diff, _tree_code} =
      System.cmd("diff", ["-qr", @fixture_tree_dir, target_tree_dir], stderr_to_stdout: true)

    stdout_equal? = File.read!(@fixture_stdout) == File.read!(target_stdout)

    cond do
      tree_diff == "" and stdout_equal? ->
        Mix.shell().info("OK: fixture is up-to-date (check mode).")
        :ok

      true ->
        Mix.shell().error("DRIFT DETECTED:")
        if tree_diff != "", do: Mix.shell().error(tree_diff)
        unless stdout_equal?,
          do: Mix.shell().error("  STDOUT.txt differs from regenerated output")
        exit({:shutdown, 2})
    end
```

Observable PASS = literal stdout `OK: fixture is up-to-date (check mode).` and `$? = 0`.
Observable FAIL = `DRIFT DETECTED:` + `$? = 2`. `STDOUT.txt` is compared **separately by byte
equality**, so `--check` exit 0 independently covers the D-13 hazard.

**The delta report a non-check run prints** (`:142-179`) — counts by bucket plus a 4-step "Next
steps" block ending with `MIX_ENV=test mix test test/sigra/install/golden_diff_test.exs`. Capture

### Multi-commit, path-restricted change conventions

**Honest finding: there is no exact precedent in this repo for a commit that asserts its own path
scope.** `grep -rln "show --name-only" .planning/phases .planning/milestones` returns only
`239-RESEARCH.md` itself. `main` is squash-only (repo policy), so per-phase commit topology is not
visible in `git log` on main — `git log --oneline -- test/fixtures/install_golden/` shows only
squashed PR commits (`fb11c8d3`, `59e68096`, `4bba9c71`, …), each mixing the golden tree with
planning files and source.

**What that means for the plan:** the D-19 three-commit topology and the per-commit scope assertion
are a **new convention this phase introduces**. Build it from RESEARCH §5.3 rather than from a
precedent:

```bash
git show --name-only --format= HEAD | grep -vE '^priv/templates/' && echo "FAIL: commit 1 escaped scope"
```

**Nearest partial analogs that do exist:**

| Convention | Precedent |
