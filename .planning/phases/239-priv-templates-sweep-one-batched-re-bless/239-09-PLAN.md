Exit semantics:

  * exit 0 when `hits_outside_allowlist=0` **and** `control_defmodule` is non-zero **and** every

  * exit 2 on usage error.

Fail-closed gets its own exit code deliberately. If a dead instrument exited 1, a broken script
would be indistinguishable from a demonstrated RED — the same failure shape this closure is
repairing everywhere else. Exit 1 means "the surface is dirty"; exit 3 means "the instrument cannot
answer". State that distinction in the script's header contract.

**Allowlist matching and its per-entry non-vacuity control.** An entry suppresses a hit only when
the hit's path equals the entry's `path` **and** the hit's line contains the entry's `literal`.

from silently starting to cover something new when lines shift. Before reporting any result, the
script runs one control per entry: the entry's `path` must still exist in the tier file list, the
`literal` must still be found in that file, and that line must still match V3. Any entry failing
that control is a fail-closed exit 1 with `refusing to report success on a vacuous allowlist entry`
naming the entry (exit 3) — an allowlist row that has quietly stopped covering anything is exactly
the dead instrument this phase is about.
