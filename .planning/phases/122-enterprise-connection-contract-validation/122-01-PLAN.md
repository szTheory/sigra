<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| org admin input -> enterprise connection context | Untrusted operator-entered issuer, client, and domain metadata crosses into persisted auth configuration. |
| enterprise connection context -> external OIDC discovery endpoint | Sigra consumes remote discovery metadata before declaring a connection usable. |
| generated host schema -> later routing/login phases | Later phases will trust this persisted contract, so bad state here cascades into auth failures. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-122-01 | E | `Sigra.EnterpriseConnections` org-scoped CRUD | mitigate | Require explicit `organization_id` ownership checks on fetch/update/activate APIs and prove them in context tests so one org cannot mutate another org’s connection. |
| T-122-02 | T | OIDC validation lifecycle | mitigate | Gate `active` behind `validate_oidc/2`, persist `validation_failed` on bad discovery/client config, and reject unsupported auth methods or missing `openid` scope before activation. |
| T-122-03 | I | Validation diagnostics and persisted settings | mitigate | Store redacted failure codes/messages only, never audit or persist plaintext secret echoes in error metadata, and assert this in activation/validation tests. |
</threat_model>
