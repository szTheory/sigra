<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| global oauth config -> org-scoped enterprise state | If the phase reuses `config.oauth[:providers]`, generated-host enterprise setup becomes fake and non-tenant-safe. |
| saved config -> active config | If lifecycle state is only a boolean or derived from field presence, invalid connections can masquerade as active. |
| operator-entered secrets -> logs/audit/diagnostics | If validation paths log raw client secrets or token-shaped values, the setup-truth wedge creates a new disclosure bug. |
| OIDC-first delivery -> future protocol seam | If the schema is OIDC-only at the top level, future SAML support will require a different operator model. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-122-01 | E | org-scoped connection persistence | mitigate | Require `organization_id` ownership and scope-aware CRUD in the Sigra context; test reject paths for cross-org writes. |
| T-122-02 | T | activation lifecycle | mitigate | Use explicit status transitions `draft`, `validation_failed`, `active`, `disabled`; only `active` after successful preflight validation. |
| T-122-03 | I | validation diagnostics | mitigate | Persist safe failure reasons only; forbid client secret/token values in returned errors or audit metadata. |
| T-122-04 | T | future protocol compatibility | mitigate | Store top-level `protocol` / `provider_type` and keep OIDC-specific settings inside a typed config layer. |
</threat_model>
