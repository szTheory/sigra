(1) `pin_wall_clock!/0`, idempotent and rank-preserving, run through `Example.Repo` SQL immediately before every request (so rows created by earlier capture requests are pinned too; the rank recomputation is deterministic because the request sequence is). For each displayed wall-clock column it maps the current values to a fixed base plus one second per row rank, ranking by (current value, ctid) so list ordering (the explorers sort by inserted_at) is preserved. Values that are in the past at pin time map to the base 2026-01-01 00:00:00 UTC; values that are in the future at pin time (an invitation `expires_at`) map to the base 2099-01-01 00:00:00 UTC, so each row keeps its relation to "now" (`expired?` flags keep their meaning). Initial column set, found by reading the render paths: `users.inserted_at` (the "Registered:" label in users_index_live.ex), `audit_events.inserted_at` (audit_table_row timestamp and audit_row date in components.ex) and `organization_invitations.expires_at` (the "Expires" label in organization_live.ex), all in the `auth` schema; extend the set with any column the clock control below flags. (2) `dump(slug, html, ctx)`: (a) replace every seeded persona user id found in the HTML with `{{PERSONA:<key>}}` (look the ids up from the seeded users so no database UUID is committed later); (b) replace the capturing admin session's own activity stamp: read that session row's `last_active_at` from the database both before and after the request and replace each occurrence of its two renderings (`%Y-%m-%d %H:%M` and `%Y-%m-%d %H:%M:%S`) by exact string, never by pattern, with `{{CAPTURE_SESSION_ACTIVITY}}`; this is the only wall-clock value normalized anywhere in the catalog, because it is the capture session's own activity and cannot be pinned (the throttled activity update sets it back to now); (c) when `System.get_env("SIGRA_CATALOG_RAW_DIR")` is non-empty write `tier2-example-admin/<slug>.html` under it (create directories; this env read is allowed here because the RegenGuardTest scan covers only root brand tests). Non-persona UUIDs (session, organization, audit-event ids) are deliberately left raw: the root normalizer (plan 02) maps every UUID to `{{UUID}}` and plan 05 asserts the normalized output is UUID-free.

(3) `assert_clock_pinned!/2` (the clock control): scan every date token of the shape `YYYY-MM-DD` in the page; each must be on or before 2026-05-15 (the seeds' reference date) or start with 2099-01-01, and none may equal the UTC date of the run; a failure names the slug and the token and means another displayed column must be added to the pin set.

Tracer path: `build_conn |> log_in_user(admin)`, pin, `get("/admin/users")`, `html_response(conn, 200)`, assert no seeded persona id remains and the HTML contains a persona display name, run `assert_clock_pinned!/2`, then dump. Planted controls in the same file (pure, in memory): an HTML string holding the capture-session stamp next to a seeded stamp comes back with only the former replaced; a page string holding a token dated today makes `assert_clock_pinned!/2` fail. Do not normalize csrf, phx ids or relative time here: that is the root normalizer's job. Do not compare anything to a committed file.
