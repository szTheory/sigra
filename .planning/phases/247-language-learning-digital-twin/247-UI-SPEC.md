| Destructive | `--vt-color-danger` (`#b42318`) | Never a general accent; only an irreversible account/action failure if one is introduced later. This phase has no destructive learner action. |

Use the existing semantic status-pill treatment, not color alone: available/accepted uses explicit positive text, download-needed/unavailable is neutral, expired is caution, rejected is risk, and conflict is caution plus a clear next step. Every status includes visible text; no status is communicated only by color, icon, or audio.

## Page and Interaction Contract

### Composition

Render the lesson as one `vt-page-intro` in the inherited authenticated `Layouts.app` shell, with `data-testid="twin-lesson"` and a non-secret `data-twin-ready="true"` only after LiveView and the lesson bootstrap state are ready.

1. Header: `vt-kicker` “Language practice”, `<h1>` “Market morning”, and one `vt-copy` sentence stating this lesson can be prepared for bounded offline study.
2. Lesson panel: structured vocabulary/prompt content, then the one image in an `<img>` with meaningful alt text and fixed intrinsic dimensions to avoid layout shift.
3. Audio panel: a visible transcript/description plus the native `<audio controls>` element. The browser control must retain its accessible native label; it is never autoplayed and no custom seek UI is added.
4. Offline panel: one primary button labelled “Make available offline”, a text status row, and a compact lease sentence. The button is disabled with an explanatory status while verification is active or no valid account lease exists.
5. Progress/replay panel: a learner action form with explicit checkpoint context, then a receipt list showing queued and terminal actions. It is present even when empty so offline/replay state has a predictable location.

At desktop widths, the image and audio panels may form a two-column `vt-card-grid`; below 768px all panels are one column in the sequence above. No card may be nested inside another card. Image and audio controls must remain usable at 320px viewport width without horizontal page scrolling.

### Offline and replay states

| State | Required presentation and interaction |
|-------|----------------------------------------|
| Online, not installed | Show “Not available offline” and enabled “Make available offline”. Do not imply download completion before verification and cache write succeed. |
| Verifying | Disable the CTA, set the offline panel `aria-busy="true"`, show “Checking lesson media…” with no percentage invented from unknown work. |
| Available | Show “Available offline” and “Offline until {localized date/time}”. The downloaded marker is displayed only after both media have verified and the account-partitioned ready marker exists. |
| Media unavailable / failed | Show “Lesson media could not be prepared. Connect to the internet and try again.” Provide one “Try again” control. Do not show a ready badge. |
| Offline with valid lease | Keep the structured lesson, image, audio, and action form usable; show “Offline study mode — available until {localized date/time}”. Queued action copy must state it will be checked when reconnected. |
| Lease expired / missing / partition changed | Suppress prior lesson content and prior receipts, show “Offline study has expired. Connect and sign in to continue.” No offline action control or replay may be activated. |
| Logged out or account switched | Immediately replace the prior account’s lesson/replay area with the authenticated redirect or fresh account bootstrap state. Never reveal the former account’s title, answer, lease, receipt, or readiness status during transition. |
| Queued | Add one receipt row: “Practice update queued — it will be checked when you reconnect.” Include its local timestamp; do not expose credentials or raw account partition. |
| Accepted | Replace/update the same receipt row with “Practice update accepted” and its terminal timestamp. |
| Rejected | Replace/update the same receipt row with “Practice update rejected. Review the lesson and try again online.” |
| Conflict | Replace/update the same receipt row with “Practice update needs review. Your saved checkpoint has changed.” Provide “Review lesson” as a local navigation/focus action, not automatic overwrite. |

The receipt list uses an ordered semantic list with each item keyed by the stable client mutation ID but never displays that ID as learner-facing copy. Do not provide a “sync now” control that bypasses reconnect/host reauthorization. A repeated replay request must visibly retain its original terminal result rather than adding a duplicate row or optimistic second success.

### Accessibility and motion

- Use one `<h1>` and meaningful `<h2>` headings for lesson, audio, offline availability, and progress/replay sections. The offline/replay status region uses `role="status"` only for post-load changes; load-present content has no live-region role.
- Associate the status line with its action using `aria-describedby`; disable rather than hide an unavailable primary action when its reason is actionable. Native controls, image alt, visible transcript, and text status make the lesson usable without sound, color perception, pointer input, or JavaScript animation.
- Keep keyboard focus on the invoking control after an in-place status update; when account/lease failure replaces the lesson, focus the replacement heading. Focus is the inherited visible Tasklane focus ring.
- Reuse existing hover/focus transitions only. No autoplay, looping progress animation, artificial download animation, or timer-driven countdown. Respect existing `prefers-reduced-motion` behavior.

### Deterministic automation contract

Use role selectors first and stable, non-secret hooks only where browser storage/worker proof cannot be expressed by roles:

| Hook | Contract |
|------|----------|
| `data-testid="twin-lesson"` | Authenticated lesson root; present only for the current account bootstrap. |
| `data-twin-ready="true"` | Bootstrap completed; tests may inspect storage or start interaction without elapsed-time waits. |
| `data-testid="twin-offline-status"` | Textual readiness/lease state; no credential, raw partition, checksum, or cookie value. |
| `data-testid="twin-replay-receipts"` | Ordered receipt container for queued/accepted/rejected/conflict assertions. |
| bounded worker message protocol | Provides only test-safe readiness, verification outcome, and controlled failure acknowledgements; never returns cached bytes, account partition, cookies, tokens, or raw media digests. |

Playwright proof waits on `[data-phx-session].phx-connected`, the readiness hook, and pre-armed worker/event or response waits. It uses browser-context offline control and direct Cache Storage/IndexedDB inspection. It must use no sleeps, timing guesses, raw-cookie inspection, or visual-only assertions.
