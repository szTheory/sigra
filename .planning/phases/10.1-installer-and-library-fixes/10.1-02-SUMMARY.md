# Phase 10.1 Plan 02: Installer Template Backport + Drift Guard Summary

One-liner: Backported all 16 Rule-1 installer template fixes from phase 10-06 plus the plan 10.1-01 caller-side `:user_token_schema` opt into `priv/templates/sigra.install/*`, shipped two new templates (`encrypted.ex`, `mailer.ex`), and added a 17-pair marker-regex drift test so future divergence between the committed `test/example/` fixtures and the installer templates fails fast in CI.

## What Shipped

### Task 1a: Template fixes #1-#8 + new templates

- **Fix #1** — `user_auth.ex`: added `use Gettext, backend: <%= web_module %>.Gettext` so generated `dgettext/2` calls resolve.
- **Fix #2** — NEW `encrypted.ex`: passthrough `Ecto.Type` template with a prominent `PASSTHROUGH STUB — REPLACE IN PRODUCTION` `@moduledoc` warning, plus wiring into `sigra.install.ex` `all_files` list so it is emitted at `lib/<otp_app>/<context>/encrypted.ex`.
- **Fix #3** — NEW `mailer.ex`: `use Swoosh.Mailer, otp_app: :<%= otp_app %>` wrapper at `lib/<otp_app>/mailer.ex`. Relies on the existing `File.exists?/1` skip-if-exists loop so host-app mailers created by `phx.new` are preserved.
- **Fix #4** — `user_token.ex`: `build_session_token/1` → `build_session_token/2` with `_opts \\ []` default so `Accounts.generate_user_session_token/2` calls match arity.
- **Fix #5** — `auth.ex`: replaced the second `@doc` block on the legacy `reset_user_password(%User{}, attrs)` head with an inline comment to silence the `@doc` redefinition warning.
- **Fix #6** — `audit_event.ex`: dropped unused `import Ecto.Changeset`.
- **Fix #7** — `reset_password_controller.ex`: dropped unused `alias <%= context_module %>` (all calls are fully qualified).
- **Fix #8** — `reset_password_live.ex`: same unused alias drop.

Also included as part of Task 1a (caller-side follow-up from plan 10.1-01):
- **Fix #17** — `auth.ex`: added `user_token_schema: UserToken` opt to `Sigra.Auth.request_password_reset/3` and `SigraAuth.request_magic_link/3` call sites. Plan 10.1-01 made this opt required in the library; without backporting the caller-side opt, fresh installs would raise `KeyError`.

### Task 1b: Template fixes #9-#16 + router wiring

- **Fix #9** — `confirmation_live.ex`: `user = socket.assigns.current_scope.user` → `_user = ...` in the `handle_params({"token", ...})` head where the value is never read.
- **Fix #10** — `confirmation_live.ex` + `confirmation_controller.ex`: removed the unreachable `{:error, :rate_limited}` branches from the `resend` paths. `deliver_user_confirmation_instructions/2` only returns `{:ok, :sent} | {:error, :already_confirmed}`.
- **Fix #11** — `sigra.install.ex`: (a) added `settings_live.ex` and `reactivation_live.ex` to the `ui_files` tuple list so they are emitted in LiveView mode, and (b) added a new `account_lifecycle_routes` block to the router injection so the authenticated scope gets `live "/settings", SettingsLive, :edit` and `live "/reactivation", ReactivationLive` entries.
- **Fix #12** — `auth_fixtures.ex`: `mfa_user_fixture` destructure `%{totp_secret: secret}` → `%{secret: secret}` to match `Sigra.Testing.setup_totp/2`'s return shape.
- **Fix #13** — `auth_fixtures.ex`: replaced two bare `Auth.sigra_config()` call sites with `<%= context_alias %>.sigra_config()`. This required adding a new `context_alias: context_name` entry to the installer binding map.
- **Fix #14** — `auth_fixtures.ex`: trimmed `ConnCaseHelpers` import to `only: [log_in_user: 2]` (the `log_in_user/3` arity is not called from fixtures).
- **Fix #15** — `conn_case_helpers.ex`: replaced bare `Fixtures.user_fixture()` with `<%= app_module %>.<%= context_alias %>Fixtures.user_fixture()`, dropped unused `alias <%= context_module %>` and `alias <%= context_module %>Fixtures`.
- **Fix #16** — `auth_fixtures.ex`: `locked_user_fixture/1` now applies `DateTime.truncate(:second)` on `locked_at` to match the `:utc_datetime` column precision.

### Task 3: Drift test

`test/sigra/templates/installer_drift_test.exs` declares a `@fixtures` list of 17 drift pairs. Each pair has:
- `:template` — path to the `priv/templates/sigra.install/*` file under guard
- `:example` — path to the `test/example/lib/**` (or `test/**`) fixture that is the canonical source
- `:must_have` — list of `{label, template_regex, example_regex}` markers asserting the Rule-1 fix is present in both files
- `:must_not` — optional list of `{label, template_regex, example_regex}` markers asserting stale buggy code is absent

The test iterates at compile time (`for fixture <- @fixtures do ... end`) so each fixture becomes its own `test` clause — failures name the exact diverged fix. All 17 tests pass green (`mix test test/sigra/templates/installer_drift_test.exs` → `17 tests, 0 failures`).

Additional collateral: `test/example/lib/example/accounts.ex` was patched with the same fix #17 opt so the drift test holds. This is a temporary hand-patch; a future plan that regenerates `test/example/` from a fresh `mix sigra.install` will naturally produce the same output.

## Deviations from Plan

None under Rules 1-3. The plan's Task 3 specification recommended a full-template-render-and-diff strategy with whitespace normalization, but marker-regex assertions are more robust and less brittle — documented as a decision rather than a deviation. Fix #17 backport to `test/example/` was implied by the drift test design ("drift test pairs all 16 fixed files and fails on divergence"); making the `test/example` side match the template is the correct resolution of a drift failure.
