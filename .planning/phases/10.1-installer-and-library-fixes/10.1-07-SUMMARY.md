# Phase 10.1 Plan 07: Mark test/example stub LiveViews Summary

## One-liner

Added triple-layer STUB — NOT FOR PRODUCTION warnings (prominent @moduledoc, visible render-body text, and runtime `Logger.warning` outside `:test`) to `test/example/lib/example_web/live/settings_live.ex` and `reactivation_live.ex`, preventing developers from copy-pasting the scaffold placeholders into a real application.

## Objective

Phase 10 plan 10-06 created these two files as minimal stubs so that the example app could compile and smoke-test happy-path register/login/logout flows without wiring the full settings and reactivation LiveViews. The risk: a developer consulting `test/example/` as a reference could copy the stubs into a real app and ship pages that do nothing.

Per locked decision (option b from the 10.1 context), this plan adds highly visible warnings without replacing the stubs with functional LiveViews (which would require wiring email change, password change, MFA management, session listing, and the full account-deletion undo flow — a scope explosion).

## What Was Done

### Task 1: Mark stub LiveViews with visible warnings

Rewrote both stub modules so each carries three independent warning layers:

1. **@moduledoc warning block** — opens with `⚠️  STUB — NOT FOR PRODUCTION ⚠️`, explicitly says `DO NOT COPY THIS FILE INTO A REAL APPLICATION`, points to the real installer template at `priv/templates/sigra.install/{settings,reactivation}_live.ex`, and explains the stub's narrow purpose.
2. **Visible render-body warning** — the rendered HTML now contains an `h1` labelled "(stub)" plus a `<strong>STUB — NOT FOR PRODUCTION.</strong>` paragraph pointing at module docs.
3. **Runtime `Logger.warning` in mount/3** — fires on every mount outside `:test` env, using a release-safe `function_exported?(Mix, :env, 0)` guard that mirrors the `Sigra.Env.current/0` pattern from plan 10.1-04.

Both files kept their `use ExampleWeb, :live_view` signature so route wiring and existing compile expectations are unchanged.

### Installer template cross-check

- `priv/templates/sigra.install/settings_live.ex` — 324 lines (real LiveView)
- `priv/templates/sigra.install/reactivation_live.ex` — 80 lines (real LiveView)

The installer templates are meaningfully richer than the test/example stubs, confirming the intentional delta documented in the plan: the installer ships functional LiveViews, while `test/example/` carries scaffold placeholders for compilation only. No drift to flag.
