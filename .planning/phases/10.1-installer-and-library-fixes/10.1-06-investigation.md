## Failure 1: test/mix/tasks/sigra.install_test.exs — "renders fixtures template"

**Line:** test/mix/tasks/sigra.install_test.exs:179


**Root cause classification:** stale-assertion

**Analysis:**
The test supplies `binding = [context_module, schema_alias, repo_module]`. Plan 10.1-02 modified `priv/templates/sigra.install/auth_fixtures.ex` line 10 (fix #14) to add `import <%= web_module %>.ConnCaseHelpers, only: [log_in_user: 2]` and lines 102/133 (fix #13) to use `<%= context_alias %>.sigra_config()`. The test binding is missing both `web_module` and `context_alias`. This is not a library bug — `lib/mix/tasks/sigra.install.ex:83-103` correctly populates the binding map in the real install path. The test fixture is simply stale.

**Fix location:** test file (test/mix/tasks/sigra.install_test.exs)

**Fix description:** Add `web_module: "MyAppWeb"` and `context_alias: "Accounts"` to the test binding. Matches how the real installer constructs the binding.

**git blame:** Line introduced at 8d04f093 (2026-04-05, Phase 5 installer). Predates plan 10.1-02 template changes — test was correct before templates acquired new interpolations.

## Failure 4: test/sigra/audit/cursor_portability_test.exs — "paginates deterministically across cursor boundary on this adapter"

**Line:** test/sigra/audit/cursor_portability_test.exs:31 (assertion at line 52)

**Captured output:**
```
Assertion with == failed
code:  assert length(page1.entries) == 2
left:  0
right: 2
stacktrace: test/sigra/audit/cursor_portability_test.exs:52: (test)
```

**Root cause classification:** aspirational

**Analysis:**
The test's inline `StubRepo` module (lines 15-29) is self-contradictory:

```elixir
def all(_query), do: []
def aggregate(_q, :count, _f), do: 0
```

`all/1` returns `[]` unconditionally — the "in-memory ordered store" comment is a TODO, not an implementation. The test inserts 5 changesets but `Audit.list/2` calls `StubRepo.all(query)` which always returns `[]`, so `page1.entries == []` and `length == 0`. The test cannot pass in its current form regardless of the cursor pagination logic in `Sigra.Audit`.

Confirming evidence:
- The moduledoc says "the real adapter check happens on PG/SQLite once Plan 02 wires a sandbox" — Plan 02 (phase 9) never wired the sandbox for this test.
- deferred-items.md entry (2026-04-09 10-03) lists it as pre-existing.
- Introduced at commit 43e4a11 (2026-04-09) as a "Wave 0 scaffold" — it was placeholder code from day one.

The test is aspirational: the REAL pagination logic is already covered by `test/sigra/audit/cursor_test.exs` (which uses Ecto directly). This portability smoke test was scaffolded against a stub that was never completed, and the real portability signal comes from CI running the full `cursor_test.exs` against PG/SQLite adapters.

**Fix location:** delete test (and `@moduletag :cursor_portability` does not appear in any other file — it's a singleton)

**Fix description:** Delete `test/sigra/audit/cursor_portability_test.exs`. The portability signal is already covered by `cursor_test.exs` and `query_test.exs` in the same directory. Alternative would be to implement a working StubRepo with an in-memory ordered store, but that duplicates Ecto integration-test coverage without adding signal. Deleting is the minimum-scope fix.

**git blame:** 43e4a115 (szTheory 2026-04-09) — entire file added in one commit as "Wave 0 scaffold." Never worked.
