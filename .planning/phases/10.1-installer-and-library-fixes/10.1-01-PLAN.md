<objective>
Fix the two latent DoS bugs in `Sigra.Auth` (password reset + magic link) where a plain map is passed to `repo.insert!/1`, raising `Protocol.UndefinedError` at runtime. Add a shared live-repo regression test using `Ecto.Adapters.SQL.Sandbox` that exercises BOTH call sites so the bug cannot regress silently.

Purpose: Password reset and magic link token issuance are fundamentally broken in the library today; the example-app smoke tests route around the delivery path. This plan closes AR-10-01 and AR-10-02 from the phase 10 security audit.

Output: `lib/sigra/auth.ex` with proper %UserToken{} struct construction at both call sites, plus `test/sigra/auth_plain_map_regression_test.exs` covering both paths.
</objective>

```elixir
def request_password_reset(repo, email, opts \\ []) do
  user_schema = Keyword.fetch!(opts, :user_schema)
  secret_key_base = Keyword.fetch!(opts, :secret_key_base)
  # ...
  true ->
    {raw_token, hashed_token} = Token.generate_hashed_token()
    signed = Plug.Crypto.sign(secret_key_base, "sigra-reset-token", raw_token)
    encoded_token = Base.url_encode64(signed, padding: false)

    token_struct = %{    # <-- BUG: plain map
      token: hashed_token,
      context: "reset_password",
      sent_to: user.email,
      user_id: user.id
    }

    repo.insert!(token_struct)
```

IMPORTANT: `request_password_reset/3` currently does NOT fetch a `:user_token_schema` from opts — callers pass `:user_schema` but not `:user_token_schema`. This plan MUST add `:user_token_schema` as a required option to both functions. The installer-generated `Accounts` context already knows the token schema module and must be updated in a follow-on plan (or grep-verified here) to pass it.
