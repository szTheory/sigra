<domain>
## Phase Boundary

This is a **remediation phase**, not a new-capability phase. It closes 12 deferred items surfaced during the phase 10 audit chain (code review, security audit, Nyquist validation) plus pre-existing library bugs that pre-date phase 10 but were discovered while auditing it.

**What this phase delivers:**
- Two latent DoS bugs in `Sigra.Auth` fixed (password reset + magic link paths) with live-repo regression tests
- Fresh-install correctness: 16 installer template bugs backported from the committed `test/example/` fixes into `priv/templates/sigra.install/*`
- MFA API surface canonicalized (`verify_backup/4`, `enabled?/2`) so guides/flows/mfa.md references are not drift
- `mix docs --warnings-as-errors` passes cleanly in CI (27 pre-existing `@doc` reference warnings eliminated)
- Supply-chain hardening: GitHub Actions SHA-pinned, Dependabot `github-actions` config added
- Five code-review deferrals (IN-01..IN-05) resolved
- Three pre-existing failing tests fixed
- test/example stub LiveViews replaced or documented so they don't mislead users

**What this phase does NOT deliver:**
- No new user-facing features
- No new requirement IDs — this is remediation against existing DX-01..DX-04 + AUDIT-* + the library's baseline correctness
- No changes to Phase 11+ scope or roadmap sequence

</domain>

## Implementation Decisions (locked from audit findings)

Every item below is a locked decision because it's a bug, a regression, or a one-way consequence of a prior audit. The planner's job is to sequence these into plans with proper dependencies, not to re-open them.

### Library bug fixes (critical)

- **D-10.1-01 (AR-10-01):** Fix `Sigra.Auth.request_password_reset/3` at `lib/sigra/auth.ex:828-835`. Current code builds a plain map and passes to `repo.insert!/1`, which raises `Protocol.UndefinedError`. Fix: build a proper `%UserToken{}` struct via the schema module resolved from `config.token_schema`.
- **D-10.1-02 (AR-10-02):** Fix the twin bug at `lib/sigra/auth.ex:425-432` in the magic-link token write path. Same plain-map pattern, same fix shape. Discovered during phase 10 security audit, not phase 10 code review.
- **D-10.1-03:** Add a shared live-repo regression test that exercises BOTH call sites with actual `Repo.insert!/1` so the plain-map regression cannot recur silently.

### Installer template backport

- **D-10.1-04:** Backport the 16 Rule-1 installer template fixes from `test/example/lib/example_web/*` and `test/example/lib/example/accounts/*` into `priv/templates/sigra.install/*`. Enumerated list lives in `.planning/phases/10-developer-experience/10-06-SUMMARY.md § Deviations > Rule 1`. After backport, fresh `mix sigra.install` runs must not require manual patching to compile.
- **D-10.1-05:** Add a test that diffs each fixed `test/example/` file against the corresponding `priv/templates/sigra.install/` template (with generator substitutions) so future drift is caught.

### MFA API canonicalization

- **D-10.1-06:** Verify `Sigra.MFA.verify_backup/4` and `Sigra.MFA.enabled?/2` exist as the canonical public surface. If they do, remove the corresponding entries from `test/sigra/guides_dx02_test.exs` `@known_library_drift` allow-list (they are no longer drift, they are correct — already done in the phase 10 WR-01 fix, verify). If they don't exist, ship them with specs, docs, and unit tests.

### Docs strictness

- **D-10.1-07:** Eliminate the 27 pre-existing `mix docs --warnings-as-errors` `@doc` reference warnings enumerated in `.planning/phases/10-developer-experience/deferred-items.md`. Affected modules per phase 10 SUMMARY: OAuth strategy wrappers, `Sigra.Session`, `Sigra.Audit.Changeset`, `Sigra.RateLimiters.Hammer`. Fix = correct the broken `@doc` refs or convert to inline backticks where the referenced function does not exist.
- **D-10.1-08:** After D-10.1-07, add `mix docs --warnings-as-errors` as a CI gate in `.github/workflows/ci.yml` so these cannot regress.

### Supply chain (IN-03)

- **D-10.1-09:** SHA-pin third-party GitHub Actions in `.github/workflows/ci.yml`: `actions/checkout`, `erlef/setup-beam`, `actions/cache`, and any others discovered during the fix. Pin to full 40-char commit SHAs with `# v4.2.2` style comments so Dependabot can update them.
- **D-10.1-10:** Add `.github/dependabot.yml` with a `github-actions` entry (weekly schedule) so SHA pins stay current automatically.

### Code review deferrals (IN-01..IN-05)

- **D-10.1-11 (IN-01):** Extract `Sigra.Env.current/0` (or similar) helper that encapsulates the release-safe `function_exported?(Mix, :env, 0)` guard used in `lib/sigra/application.ex:30` and `priv/templates/sigra.install/user_auth.ex:32`. Both call sites switch to the helper. Helper has a doctest.
- **D-10.1-12 (IN-02):** Add a concrete example comment above the `test_load_filters: [~r"^test/(?!example/)"]` line in `mix.exs` explaining what the regex excludes and why.
- **D-10.1-13 (IN-04):** `AuthFixtures.scenario/2` currently raises `FunctionClauseError` on unknown scenario atoms. Change to raise `ArgumentError` with a formatted list of valid atoms in the message. Update existing tests that grep for `FunctionClauseError`.
- **D-10.1-14 (IN-05):** Either strip interior whitespace in `Sigra.Auth.normalize_email/1` OR add a `@doc` that states explicitly "does not strip interior whitespace; use `String.trim/1` + regex for that case". Pick one (research the RFC 5321 expectation) and ship.

### Pre-existing failing tests

- **D-10.1-15:** Fix the 2 failures in `test/mix/tasks/sigra.install_test.exs`. Investigate root cause before touching — these have been failing since before phase 10 and may indicate a genuine installer bug worth surfacing.
- **D-10.1-16:** Fix the failure in `test/sigra/audit/cursor_portability_test.exs`. Same — investigate first. Phase 9 carryover.

### test/example stub cleanup

- **D-10.1-17:** The `test/example/lib/example_web/live/settings_live.ex` and `reactivation_live.ex` stubs exist to unblock compilation of the installer-emitted router. Either: (a) replace with minimal but functional LiveViews that match what real apps need, OR (b) add a very visible `@moduledoc` + runtime log warning that these are scaffolding placeholders to prevent copy-paste into production. Decide based on what keeps `test/example/` useful as a reference.

<specifics>
## Specific Ideas / Known Constraints

- **Argon2 + test speed:** existing tests use `Argon2` at default cost; new live-repo tests should match existing patterns (no need to tweak cost).
- **`config.token_schema`:** the UserToken schema module is resolved at runtime via `Sigra.Config`. The fix for D-10.1-01 and D-10.1-02 must call `config.token_schema.build_hashed_token(...)` (or whatever the actual factory is — verify during planning) rather than hardcode `Sigra.UserToken`.
- **Installer test isolation:** `test/mix/tasks/sigra.install_test.exs` runs the installer in a tmp dir. The 2 failing tests are likely assertion drift after phase 10 template changes. Check git blame on the assertions.
- **Docs CI gate placement:** `mix docs --warnings-as-errors` should go in the existing `library_tests` job, not a new job, to keep CI fast.
- **Backport diff test pattern:** the D-10.1-05 drift test can use a simple content comparison — read both files, apply known template substitutions (e.g., `Example.` → `<%= inspect(@web_module) %>.`), assert equal. Or: check that every `# sigra.install:` marker in the template has a corresponding fix in `test/example/`.

</specifics>
