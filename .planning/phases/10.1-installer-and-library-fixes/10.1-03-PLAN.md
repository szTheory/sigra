<!-- The fix pattern for @doc reference warnings in ExDoc -->

When a @doc string contains `` `Module.function/arity` `` and ExDoc cannot resolve
the target (because the function is `@doc false`, hidden, or nonexistent), it
emits a warning like:

    warning: documentation references function Module.function/arity but it is hidden or does not exist

Fix options (pick per-reference):
1. If the target is INTENTIONALLY hidden → use an EXPLICIT backtick code span
   that ExDoc will NOT auto-link. The canonical way in ExDoc is to use the
   code-span WITHOUT the function reference shape — i.e., drop the `/arity`:

      before: "See `Sigra.Audit.__log_internal__/3` for details."
      after:  "See `Sigra.Audit.__log_internal__` (internal, not public API) for details."

   OR use a markdown code fence that isn't a reference at all.

2. If the reference is to a function that EXISTS under a DIFFERENT name → fix
   to the real name:

      before: "Uses `Sigra.Audit.log_safe/3`"
      after:  "Uses `Sigra.Audit.log/2` with safe metadata"

3. If the reference is to a function that SHOULD exist but doesn't → either
   ship the function (out of scope for this plan) OR remove the reference
   and inline-describe what would be there.
</interfaces>
</context>
