# Phase 10.1 Plan 04: Env Helper + CI Supply-Chain Hardening Summary

Extracted `Sigra.Env.current/0` as a release-safe `Mix.env` guard with a doctest, replaced both call sites (library + installer template + lockstep test/example copy), SHA-pinned every third-party GitHub Action in `ci.yml` (actions/checkout v4.3.1, actions/cache v4.3.0, erlef/setup-beam v1.24.0) with version comments, added `.github/dependabot.yml` on a weekly github-actions schedule, and wired `mix docs --warnings-as-errors` as a CI gate in the `library_tests` job so the plan 10.1-03 clean-docs baseline cannot regress silently.

## What Shipped

### Task 1: Sigra.Env.current/0 helper (TDD: red → green)

- **New module `lib/sigra/env.ex`** — single-function module with a `@moduledoc` explaining the `:mix` exclusion in releases, a `@spec`, and a doctest asserting `Sigra.Env.current() in [:dev, :test, :prod]`.
- **New test `test/sigra/env_test.exs`** — async `ExUnit.Case` with `doctest Sigra.Env` plus two simple tests (returns `:test` in the test env, always an atom). RED confirmed: module-not-loaded compile error on first run. GREEN after adding `env.ex`: 1 doctest + 2 tests pass.
- **`lib/sigra/application.ex:30`** — replaced `env = if function_exported?(Mix, :env, 0), do: Mix.env(), else: :prod` with `env = Sigra.Env.current()`.
- **`priv/templates/sigra.install/user_auth.ex`** — `remember_me_options/0` body replaced the same inline guard with `env = Sigra.Env.current()`. Updated the preceding comment block to reference `Sigra.Env.current/0` instead of `function_exported?/3` so the rationale still reads.
- **`test/example/lib/example_web/user_auth.ex`** — applied the SAME change in lockstep so the 17-pair drift test from plan 10.1-02 continues to pass. (The specific drift fixture for this pair only asserts `use Gettext` presence, so the Mix.env change did not require a drift-test update.)

### Task 2: SHA-pinning, Dependabot, mix docs CI gate

- **`.github/workflows/ci.yml`** — every `uses:` line is now SHA-pinned with a `# vX.Y.Z` comment. Pinned versions:
  - `actions/checkout@34e114876b0b11c390a56381ad16ebd13914f8d5  # v4.3.1`
  - `erlef/setup-beam@fc68ffb90438ef2936bbb3251622353b3dcb2f93  # v1.24.0` (annotated tag dereferenced to commit SHA via `gh api repos/erlef/setup-beam/git/tags/<tag-sha>`)
  - `actions/cache@0057852bfaa89a56745cba8c7296529d2fc39830  # v4.3.0`
  - Applied to BOTH `library_tests` and `example_app_smoke` jobs — 6 `uses:` lines total, all pinned.
- **`mix docs --warnings-as-errors` CI gate** — added as a new step in `library_tests` after `mix test`. Locally verified `mix docs --warnings-as-errors` exits 0 (plan 10.1-03 cleared all the prior warnings).
- **NEW `.github/dependabot.yml`** — `version: 2`, a single `github-actions` ecosystem entry rooted at `/`, weekly schedule, commit-message prefix `ci`, labels `dependencies` + `ci`. This keeps the pinned SHAs fresh as upstream actions release security patches without forcing manual refresh.

## Deviations from Plan

None under Rules 1-3. Two minor decisions worth noting (documented as decisions rather than deviations):

1. **Version selection within majors** — The plan listed `v4.2.2` / `v4.1.2` / `v1.18.2` as example placeholders. Latest patch levels as of 2026-04-10 are v4.3.1 / v4.3.0 / v1.24.0 within the existing major ranges used by ci.yml. I intentionally did NOT jump to checkout v6 / cache v5 (both breaking), leaving that for Dependabot to propose.
2. **Comment rewording in user_auth templates** — the original comment block referenced `function_exported?/3` as the release-safety technique. After the refactor, that technique is one level of indirection away (inside `Sigra.Env.current/0`). Rewrote the comment to reference `Sigra.Env.current/0` instead so the rationale still lands for a developer reading the template output. This was applied to both the template and the test/example lockstep copy.

No authentication gates or blockers encountered.
