## Ordering constraint (D-13 — this is why this plan is a separate wave)

`workflow_dispatch` is only offered once the workflow file is on the default branch, and the
capture must observe the **final committed HEAD on a clean tree**. Phase 216's SC-5 precedent is
the inverted lesson: a harness green at a *pre-commit* SHA is invalid. So the order is fixed —
merge, then dispatch, then capture, and the ledger flip is explicitly a *post-evidence
documentation commit* whose own SHA is not the subject of any claim. The collector records
`head_sha` and `clean_tree` into the receipt at capture time, which is what makes that separation
legible to a reviewer.
