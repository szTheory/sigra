  <action>
Create lib/sigra/doctor.ex as a pure library module — no Mix.Task, no IO calls, no side effects.

Module: Sigra.Doctor

Primary public entrypoint: diagnose/1 accepts a keyword list of injected inputs. Supported injection keys are:
- predicates: a map of predicate_name atom → boolean, overriding individual OptionalDeps calls. Keys: :oban, :bcrypt, :eqrcode, :threadline, :assent, :swoosh, :joken, :hammer, :req, :encryption_active
- host_sigra: the raw keyword config list (same shape as what the two-hop config read in application.ex produces)
- oban_running: a boolean override for both the async-email and audit-forwarder Oban supervision checks (injected into Sigra.Audit.Forwarders.oban_running?/1 via the :oban key in forwarder_opts)

When predicates or oban_running are NOT injected, call the real functions:
- Sigra.OptionalDeps.oban_available?(), Sigra.OptionalDeps.bcrypt_available?(), etc. for each of the nine predicates
- Sigra.OptionalDeps.encryption_active?(host_sigra) for encryption posture
- Sigra.Audit.Forwarders.oban_running?([]) for the supervised-Oban check (the production path; the :oban injection key is only used in tests via Forwarders.oban_running?([oban: override_name]))

When host_sigra is NOT injected, perform the two-hop config read from application.ex lines 34-37:
  otp_app = Application.get_env(:sigra, :otp_app)
  host_sigra = case otp_app && Application.get_env(otp_app, :sigra_config) do
    opts when is_list(opts) -> opts
    _ -> []
  end

Per D-06, NEVER call Code.ensure_loaded? directly in this module; always call Sigra.OptionalDeps predicates.

Build nine feature rows using the Feature→Predicate Matrix from 138-PATTERNS.md. Each row is a map with:
- :feature — atom key (e.g. :totp_mfa, :password_migration, :oauth, :rate_limiting, :jwt, :async_email, :audit_forwarding, :encryption, :enterprise_connections)
- :deps — list of dep name strings (e.g. ["eqrcode"])
- :state — one of :missing | :available | :loaded_active | :configured_but_missing
- :hint — non-empty actionable string (what to add to deps or config to improve state)

State determination rules per D-07:
- :missing — all availability predicates for the feature return false AND feature is not configured
- :available — all/some availability predicates return true AND feature is not configured (dep present, not in use)
- :loaded_active — availability predicates true AND feature IS configured AND wiring check passes
- :configured_but_missing — feature IS configured but a required availability predicate returns false (dep absent while configured); OR wiring check fails per D-09

"Configured" per feature (read from host_sigra keyword list):
- totp_mfa: mfa sub-key enabled (default true when mfa key present); treat as configured if host_sigra[:mfa] is non-empty list
- password_migration: bcrypt_available? doubles as configured indicator (bcrypt in use implies migration configured); no explicit config flag
- oauth: host_sigra[:oauth][:providers] is non-empty
- rate_limiting: host_sigra[:rate_limiting][:limiter] is set to a non-default value
- jwt: host_sigra[:jwt][:enabled] is true
- async_email: host_sigra[:email][:delivery_mode] == :async
- audit_forwarding: host_sigra[:audit][:forwarders] is non-empty list
- encryption: passkeys_enabled? (host_sigra[:passkeys][:enabled] is true, default true when passkeys key present) OR oauth token storage configured
- enterprise_connections: host_sigra[:enterprise_connections] is non-empty

D-09 hard-fail conditions (set verdict to :fail, mark row as :configured_but_missing):
1. audit_forwarding: any configured forwarder has dispatch: :async and Sigra.Audit.Forwarders.oban_running?/1 returns false
2. async_email: delivery_mode == :async and Sigra.Audit.Forwarders.oban_running?([]) returns false
3. encryption: passkeys enabled (or OAuth token storage configured) and Sigra.OptionalDeps.encryption_active?(host_sigra) returns false
4. audit_forwarding: any configured forwarder module where Code.ensure_loaded?(module) is false — check this via calling Code.ensure_loaded?(module) directly for the module atom read from forwarder_opts (this is the one narrow exception where direct ensure_loaded? is correct — checking a host-provided dynamic module atom that cannot be listed in OptionalDeps)

For multi-dep features (async_email needs swoosh + oban; audit_forwarding needs threadline + oban):
- :missing — ALL deps absent AND not configured
- :available — ANY dep present AND not configured
- :loaded_active — deps present AND configured AND no wiring failure
- :configured_but_missing — configured AND any dep absent OR wiring failure

Return value from diagnose/1: a map with keys:
- :rows — list of nine row maps in a stable order matching the D-05 feature set
- :wiring — list of wiring check result strings (plain text; may be empty if all wiring OK)
- :verdict — :ok or :fail

Secondary public function: run/1 accepts the same keyword injection opts as diagnose/1, then additionally accepts :quiet boolean. Calls diagnose/1 and returns the same structured map. This is the entrypoint the Mix task calls; all IO formatting and exit logic lives in the task, NOT here.

@moduledoc: explain the diagnostic module, its pure/injectable nature, and that it consumes Sigra.OptionalDeps per D-06. Include a note that it deliberately does not call Sigra.Application.verify_vault!/1 or attach_forwarders (per D-08, those raise and would abort the report before it prints).

@spec annotations for diagnose/1 and run/1.
