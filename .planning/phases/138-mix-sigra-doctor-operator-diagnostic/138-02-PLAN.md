Module: Mix.Tasks.Sigra.Doctor

@shortdoc: "Diagnoses optional-dependency wiring and prints a per-feature status matrix"

@moduledoc: include usage section, flags (--quiet), examples showing invocation with and without CI usage note, and the "delegates to Sigra.Doctor.run/1 — all diagnostic logic ships via mix deps.update" sentence per D-03. Note the CI-gate behavior (non-zero exit on misconfiguration, green on dep-off installs).

use Mix.Task

@options_schema (NimbleOptions):
- quiet: [type: :boolean, default: false, doc: "Suppress per-row hints; print only the summary verdict. Does not suppress the error report on misconfiguration."]

@switches: [quiet: :boolean]

run/1 body structure (per D-02 precedent from 138-PATTERNS.md):
1. OptionParser.parse(args, switches: @switches) — collect {opts, _parsed, _invalid}
2. NimbleOptions.validate!(opts, @options_schema) — raises Mix.Error on invalid options (D-10: Mix.raise is only for usage errors)
3. Mix.Task.run("app.start") — D-02: must run before delegating to Sigra.Doctor.run/1 so OptionalDeps live checks and host config reads see a booted app
4. Call Sigra.Doctor.run(validated_opts) — receives the structured result map
5. Format and output the result (see below)
6. If result.verdict == :fail: call exit({:shutdown, 1}) after printing full report via Mix.shell().error/1

Output formatting rules (D-01, D-10):
- Print a header line: Mix.shell().info([:bright, "==> sigra.doctor", :reset])
- For each row in result.rows, print one line via Mix.shell().info/1 using ANSI IO-data:
  - :missing → [:faint, "  [ ] ", :reset, feature_label, " — ", :faint, hint_if_not_quiet, :reset]
  - :available → [:yellow, "  [~] ", :reset, feature_label, " (available, not configured)", " — ", hint_if_not_quiet]
  - :loaded_active → [:green, "  [✓] ", :reset, feature_label]
  - :configured_but_missing → [:red, "  [!] ", :reset, feature_label, " — ", :red, hint, :reset]
  (Exact color choices and bracket glyphs are Claude's discretion per 138-CONTEXT.md; the above is the intended shape — adjust for readability)
- Print a blank separator line between feature rows and the verdict
- Print the verdict line: Mix.shell().info/1 with green "OK: all configured features are properly wired." for :ok, or (on :fail) print via Mix.shell().error/1 with red "ERROR: misconfigured features detected (see above). Fix the issues above before deploying."
- If result.wiring is non-empty, print each wiring check string via Mix.shell().error/1 before the verdict
- On :fail verdict: full report (all rows + wiring + error verdict line) is already printed; then call exit({:shutdown, 1}) — NEVER System.halt/1 (D-10)
- When --quiet: omit per-row hint text from :missing and :available rows; still print :configured_but_missing hints and the error verdict (D-10: --quiet does not suppress the gate)

NEVER call Mix.raise/1 for app misconfiguration — only for bad flags (e.g. unknown switch). The NimbleOptions.validate! call already handles bad opts via Mix.Error (which IS the Mix.raise path, so no explicit Mix.raise needed unless a usage check beyond NimbleOptions is required).

The task passes validated_opts (including quiet: boolean and the injection seam keys if present) directly to Sigra.Doctor.run/1 so tests can inject predicates/host_sigra through the task.

No raw IO.puts anywhere (D-01).

## Trust Boundaries

| Boundary | Description |

| Mix.shell() output channel | Writes to stdout/stderr; no network, no file writes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-138-03 | Information Disclosure | Mix.shell().info/1 and .error/1 output | mitigate | Task formats Sigra.Doctor structured result — prints dep names and state labels, not config values. No encryption keys, OAuth secrets, API tokens, or host app configuration values are printed. :hint strings contain only "add {:dep, ~> X.Y} to mix.exs" instructions. Accepted: dep load status (loaded vs not) is not a secret. |
| T-138-04 | Tampering (correctness) | exit({:shutdown, 1}) gate | mitigate | D-10: gate is always-on, not tunable by --quiet. Test 6 (misconfig exits) + Test 1 (ok does not exit) form the correctness contract. If exit/1 were omitted or called conditionally on a quiet flag, a broken deploy could slip through CI silently. The gate fires after the full report is printed, ensuring operators see the reason before the process exits. |
| T-138-05 | Denial of Service | System.halt/1 usage | mitigate | Forbidden per D-10 — kills the VM, bypasses on_exit hooks, and breaks CaptureIO testing. Use exit({:shutdown, 1}) only. Static grep gate in acceptance criteria enforces this. |
| T-138-SC | Tampering | No package installs in this plan | accept | No new deps added; no package manager install operations. N/A. |
