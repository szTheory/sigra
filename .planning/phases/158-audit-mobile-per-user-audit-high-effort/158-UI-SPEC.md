## Spacing Scale

All spacing uses the existing `--sg-space-*` token set. Tokens map to a 4px base (1rem = 16px assumed):

| Token | CSS Var | Value | Grid alignment | Usage in this phase |
|-------|---------|-------|----------------|---------------------|
| xs | `--sg-space-1` | 4px (0.25rem) | 1×4px | Intra-row text stack gap (`sg-stack--1`) |
| sm | `--sg-space-2` | 8px (0.5rem) | 2×4px | Pill cluster gap (`sg-stack--2`, `sg-cluster--2`); filter chip padding-y |
| md-sm | `--sg-space-3` | 12px (0.75rem) | 3×4px — pre-existing `app.css` token (lines 22–30), reused not introduced | Card/row vertical stack gap (`sg-stack--3`); filter chip padding-x |
| md | `--sg-space-4` | 16px (1rem) | 4×4px | Default `sg-stack` gap; container padding-inline |
| lg | `--sg-space-6` | 24px (1.5rem) | 6×4px | Admin content padding-block |
| xl | `--sg-space-8` | 32px (2rem) | 8×4px | Major layout gap |
| 2xl | `--sg-space-12` | 48px (3rem) | 12×4px | Page-level bottom padding |

**Spacing scale note:** All declared tokens are multiples of 4px and are pre-existing tokens defined in `app.css` lines 22–30. This phase documents and reuses them — no new tokens are introduced (CONTEXT.md: "no new design tokens"). `--sg-space-3` (12px = 3×4px) sits between the 8px and 16px steps of the standard set and is intentionally present in the project's token scale; it is not an arbitrary off-grid value.

**Touch target exception:** `sg-filter-chip` has `min-height: var(--sg-control-md)` = 2.75rem (44px). This meets WCAG 2.5.5 touch target minimum for mobile. No additional exception needed.

**Mobile breakpoint:** `sg-show-desktop` / `sg-show-mobile` flip at 1024px (`app.css:247-255`). The dual-layout card/table split for `AuditIndexLive` and `AuditUserLive` is keyed on this breakpoint.

*Source: `app.css` token declarations lines 22-30; CONTEXT.md D-02; existing `UsersIndexLive` dual-layout idiom*

## Color

All colors use the existing `--sg-color-*` token set. No new color tokens are introduced.

| Role | CSS Token | Light-mode value | Usage |
|------|-----------|-----------------|-------|
| Dominant (60%) — surface | `--sg-color-subtle` | #f6f5f2 | Page background (`html`); fills the space around panels |
| Secondary (30%) — panels | `--sg-color-panel` | #ffffff | `sg-list-row` card background; `sg-filter-chip` background; `sg-table-panel` background |
| Secondary alt | `--sg-color-panel-alt` | #fbfaf7 | Alternating table row tint (`sg-table-panel tbody tr:nth-child(even)`) |
| Accent (10%) — brand | `--sg-color-brand` | #c2410c | Reserved for: active `sg-filter-chip` checked state; `sg-btn--primary` CTA; focus rings |
| Semantic — risk | `--sg-color-risk` | #b42318 | `sg-list-row[data-tone="risk"]` and `sg-status-pill[data-tone="risk"]` — failure/error audit rows; `sg-notice[data-tone="risk"]` |
| Semantic — info | `--sg-color-info` | #1d4ed8 | `sg-list-row[data-tone="info"]` and `sg-status-pill[data-tone="info"]` — impersonation/elevated-action audit rows |
| Semantic — ok | `--sg-color-ok` | #176b43 | `sg-status-pill[data-tone="ok"]` — success outcomes |
| Semantic — warn | `--sg-color-warn` | #a15c00 | `sg-status-pill[data-tone="warn"]` — warning states |
| Muted text | `--sg-color-muted` | #686868 | `sg-muted` class — secondary/metadata text in audit rows |
| Ink text | `--sg-color-ink` | #151515 | Primary body text |

**Accent reserved for specifically:**
1. The active (`:has(input:checked)`) state of `sg-filter-chip` — brand-soft background, brand-strong text
2. The hover state of `sg-filter-chip` — brand-soft background tint
3. Primary CTA buttons (`sg-btn--primary`)
4. Focus rings (`--sg-focus-ring`)

**Tone derivation (single source of truth — `audit_tone/1` in `audit_row/1`):**
- `outcome` not in `["success", nil, ""]` → `"risk"`
- `action_badge` present (impersonation/elevated) → `"info"`
- Otherwise → `nil` (neutral, no data-tone attribute)

This retires the divergent `row_tone/1` in `audit_index_live.ex:206-208`, `row_tone/1` in `audit_user_live.ex:246-248`, and the old `audit_tone/1` in `user_show_live.ex:437-440`.

## Component Inventory

### New component: `audit_row/1`

**Location:** `lib/sigra/admin/components.ex` (11th component)

**House style:** Flat, stateless Phoenix.Component function component. Emits only existing `sg-*` CSS classes. No `variant={:table|:card}` polymorphism.

**Markup shape (card form):**

```heex
<article class="sg-list-row sg-stack sg-stack--2" data-tone={audit_tone(@row)}>
  <div class="sg-cluster sg-cluster--2">
    <span class="sg-status-pill" data-tone={audit_tone(@row)}>{@row.action_label}</span>
    <span :if={@row.action_badge} class="sg-status-pill" data-tone="info">{@row.action_badge}</span>
  </div>
  <span class="sg-muted sg-text-sm">{@row.actor_summary}</span>
  <!-- explorer-only lines (gated by optional attr): -->
  <span :if={@show_detail} class="sg-muted sg-text-sm">Actor: {@row.actor_label}</span>
  <span :if={@show_detail and @row.action_badge} class="sg-muted sg-text-sm">
    Effective user: {@row.effective_user_label}
  </span>
  <!-- timestamp line: -->
  <span class="sg-muted sg-text-xs">{format_date(@row.inserted_at)}</span>
  <!-- id/action code lines (gated by optional attr): -->
  <code :if={@show_codes} class="sg-code">{@row.id}</code>
  <code :if={@show_codes} class="sg-code">{@row.action}</code>
</article>
```

**Attrs:**

| Attr | Type | Required | Default | Purpose |
|------|------|----------|---------|---------|
| `row` | `:map` | yes | — | Presenter row struct (from Audit Explorer / AuditUser / UserShow) |
| `show_detail` | `:boolean` | no | `false` | Renders "Actor:" / "Effective user:" lines — on in explorers, off in UserShowLive compact block |
| `show_codes` | `:boolean` | no | `false` | Renders `row.id` and `row.action` code lines — on in explorers, off in compact block |

**Consumed by:**
1. `audit_index_live.ex` — mobile card list (`sg-show-mobile` wrapper), `show_detail: true`, `show_codes: true`
2. `audit_user_live.ex` — mobile card list (`sg-show-mobile` wrapper), `show_detail: true`, `show_codes: true`
3. `user_show_live.ex` — "Recent Audit" block, `show_detail: false`, `show_codes: false` (compact variant)

**Desktop `<tr>` rows stay inline** in both explorers — the `<tr>` and `<article>` shapes cannot share markup. This mirrors the `UsersIndexLive` idiom exactly.

### Quick-filter chips: AuditIndexLive

Rendered on **all viewports** (no `sg-show-*` gate). Placed above the detailed filter form, below the `applied_chip` row.

| Chip label | Param set | Param value |
|-----------|-----------|------------|
| "Failures" | `outcome` | `failure` |
| "Impersonation" | `action_prefix` | `admin.impersonation` |

**Implementation:** Value-setting links/setters (NOT boolean checkboxes). Chips populate the existing `@allowed_params` via the existing `QueryParams` contract. Chips must NOT use `impersonation=true` (not a real param — silently dropped by `QueryParams`).

## Interaction Contract

### Mobile card layout (AUDX-01, AUDX-03)

- At < 1024px: desktop `sg-table-panel` is hidden (`sg-show-desktop`), mobile `sg-stack sg-stack--3` card list is shown (`sg-show-mobile`).
- At >= 1024px: desktop table is shown, mobile card list is hidden.
- Cards are `<article class="sg-list-row sg-stack sg-stack--2">` with `data-tone` from `audit_tone/1`.
- No horizontal table scroll. No CSS-only responsive reflow of table columns.

### Quick-filter chips (AUDX-02)

- Chips render above the detailed filter form on all viewports.
- Chips are interactive: clicking a chip sets the corresponding query param and navigates (LiveView `push_patch` or equivalent link).
- Active chip: renders with brand-soft background + brand-strong text (`:has(input:checked)` equivalent visual state via `sg-filter-chip` checked CSS).
- Chip removal: user removes via the `<.applied_chip>` remove link (existing pattern) — chips do not have a dedicated inline remove. Alternatively, clicking an active chip deactivates the param.
- Both chips use the `sg-filter-chip` class. Minimum touch target: 2.75rem (44px) height via `min-height: var(--sg-control-md)`.

### Tone derivation (`audit_tone/1`) — single source of truth

```elixir
defp audit_tone(%{outcome: outcome}) when outcome not in ["success", nil, ""], do: "risk"
defp audit_tone(%{action_badge: badge}) when not is_nil(badge), do: "info"
defp audit_tone(_row), do: nil
```

This unified helper replaces `row_tone/1` (×2) and the prior `audit_tone/1`.

### `format_date/1` — NaiveDateTime handling (D-09 fold)

The `format_date/1` helper must handle:
- `%DateTime{}` → format as `"YYYY-MM-DD HH:MM"`
- `%NaiveDateTime{}` → format as `"YYYY-MM-DD HH:MM"`
- `nil` → `"—"`
- Any other value → raise `ArgumentError` (no silent catch-all absorbing a wrong-typed value)
