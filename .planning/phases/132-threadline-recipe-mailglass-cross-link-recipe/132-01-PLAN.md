<interfaces>
<!-- Phase-131 contracts the recipes pin against. Recipes reference these by prose, not by copying code. -->

From `lib/sigra/audit/forwarders/threadline.ex:290-307`:
- Sigra invokes `Threadline.record_action/2` with `[repo: repo, status: status, correlation_id: metadata[:id]]` plus an actor opt derived from the audit row.
- Error taxonomy returned to the dispatcher: `:schema_mismatch` (Ecto.Changeset error from Threadline), `:missing_actor`, `:invalid_actor_ref`, `:missing_repo`, or a passthrough term.

From `lib/sigra/audit/forwarders.ex` moduledoc:
- Dispatch modes: `:auto` (Oban-present → async, else sync), `:async` (raises at boot if Oban absent — see `Sigra.Application.attach_forwarders/0`, D-26), `:sync` (always inline).
- The dispatcher reads the per-forwarder `:dispatch` key (NOT top-level `:delivery_mode`).

From `lib/sigra/audit/forwarder.ex`:
- `Sigra.Audit.Forwarder` behaviour, single `@callback attach(keyword) :: :ok | {:error, term}` — host custom forwarders implement this and can be mocked via `Mox.defmock(MyForwarder, for: Sigra.Audit.Forwarder)`.

From `lib/sigra/mailer.ex:1-31`:
- `Sigra.Mailer` behaviour, single `@callback deliver(to :: String.t(), subject :: String.t(), body :: body()) :: {:ok, term()} | {:error, term()}`.
- `body :: String.t() | %{html: String.t(), text: String.t()} | %{text: String.t()}`.

From `deps/mailglass/lib/mailglass/mailable.ex:30-33`:
- `use Mailglass.Mailable, stream: :transactional` invokes the `NoTrackingOnAuthStream` compile-time guard. Using `stream: :bulk` for auth mail is a privacy regression and the guard rejects it.

From `deps/mailglass/lib/mailglass.ex:7-11`:
- Mailglass sits ABOVE Swoosh (it is NOT a Swoosh adapter). Recipes must frame it that way to avoid the v1.25 EMAIL-RAILS narrative confusion that Phase 136 DOC-01 corrects.
</interfaces>
