<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Feature manifest -> generated host files | Installer-owned fragments decide which passkey code and dependencies land in the host app. |
| Generated browser templates -> host asset dependency graph | Browser-side imports must match the package inserted into `assets/package.json` or omission semantics become dishonest. |
| Injector edits -> host asset/dependency files | Automatic edits to `mix.exs`, `assets/package.json`, and router/config files can silently fail if anchors drift. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-02-01 | I | Passkey route/config ownership | mitigate | Move passkey-only router and config fragments into `Features.Passkeys` and remove duplicate Core emission so `--no-passkeys` cannot leak partial routes or config. |
| T-22-02-02 | T | `mix.exs` / `assets/package.json` edits | mitigate | Use deterministic injector anchors with exact manual-action fallback text so dependency rewrites fail loudly instead of silently leaving a half-wired install. |
| T-22-02-03 | I | `passkey_browser.js` / `passkey_hooks.js` | mitigate | Align generated browser imports with `@simplewebauthn/browser` so enabled installs depend on the same package the feature injects, making omission coverage meaningful. |
</threat_model>
