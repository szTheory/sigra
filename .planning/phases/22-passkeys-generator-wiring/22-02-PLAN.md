<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Feature manifest -> generated host files | Installer-owned fragments decide which passkey code and dependencies land in the host app. |
| Shared template guards -> generated controller/UI surface | Conditional template regions must fully remove passkey mutation endpoints and helper references on opt-out. |
| Injector edits -> host asset/dependency files | Automatic edits to `mix.exs`, `assets/package.json`, and router/config files can silently fail if anchors drift. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-02-01 | I | Core router/config/template ownership | mitigate | Move passkey-only router and config fragments into `Features.Passkeys` and remove duplicate Core emission so `--no-passkeys` cannot leak partial routes or config. |
| T-22-02-02 | E | `session_controller.ex` and shared auth templates | mitigate | Guard every passkey session mutation and passkey-primary branch with `passkeys?`, and omit them entirely instead of emitting stubs, closing the session-mutation surface when opted out. |
| T-22-02-03 | T | `mix.exs` / `assets/package.json` / `app.js` edits | mitigate | Use deterministic injector anchors with exact manual-action fallback text so dependency or asset rewrites fail loudly instead of silently leaving a half-wired install. |
| T-22-02-04 | R | omission regression tests | mitigate | Add generated-app omission assertions that directly grep for forbidden residue strings, files, routes, and dependency lines on the disabled path. |
</threat_model>
