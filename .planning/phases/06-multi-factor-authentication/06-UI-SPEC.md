# Phase 6 -- UI Design Contract

> Visual and interaction contract for MFA generated templates. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Phoenix 1.8 built-in components + Tailwind CSS) |
| Preset | not applicable |
| Component library | Phoenix core components (`<.header>`, `<.form>`, `<.input>`, `<.button>`, `<.link>`, `<.flash>`) |
| Icon library | Heroicons via Phoenix core components (`<.icon name="hero-*" />`); inline SVG for QR code |
| Font | System font stack (Phoenix 1.8 default via Tailwind) |

**Note:** Sigra is an Elixir library generating Phoenix HEEx templates. All UI is server-rendered using Phoenix core components and Tailwind CSS utility classes. The shadcn gate does not apply.

**Source:** Consistent with Phase 4 and Phase 5 UI-SPECs.

## Spacing Scale

Declared values (Tailwind utility classes, multiples of 4):

| Token | Tailwind Class | Value | Usage |
|-------|---------------|-------|-------|
| xs | `gap-1`, `p-1` | 4px | Icon gaps, inline element spacing |
| sm | `gap-2`, `p-2` | 8px | Compact element padding, tab gaps, checkbox-to-label gap |
| md | `gap-4`, `p-4`, `space-y-4` | 16px | Default form field spacing, card padding, backup code grid gap |
| lg | `gap-6`, `p-6`, `space-y-6` | 24px | Section padding, space between QR code and form inputs |
| xl | `gap-8`, `p-8` | 32px | Page content padding |
| 2xl | `mt-12`, `mb-12` | 48px | Major section separation |
| 3xl | `mt-16` | 64px | Page-level vertical spacing |

Exceptions: QR code rendered at 200x200px (50 Tailwind units, `w-[200px] h-[200px]`). Backup code grid uses `grid-cols-2 gap-3` (12px gap) for two-column layout on desktop, single column on mobile.

**Source:** Matches Phase 4/5 spacing conventions.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (normal) | 1.5 (`leading-normal`) |
| Label | 14px (`text-sm`) | 600 (`font-semibold`) | 1.5 (`leading-normal`) |
| Heading | 20px (`text-xl` via `.header` component) | 600 (`font-semibold`) | 1.2 |
| Code | 16px (`text-base font-mono`) | 400 (normal) | 1.5 (`leading-normal`) |

**Code role** is new to Phase 6: used for TOTP 6-digit input display, backup codes, and manual TOTP secret key. Uses `font-mono` for fixed-width character alignment. 16px for readability of security-critical codes.

Weights used: 400 (body text, inputs, code) and 600 (labels, headings, emphasis text).

**Source:** Extends Phase 4/5 typography with monospace role for security codes.

## Color

| Role | Tailwind Token | Usage |
|------|---------------|-------|
| Dominant (60%) | `bg-white` | Page background, form surfaces |
| Secondary (30%) | `bg-gray-50`, `border-gray-200` | Backup code grid container, enrollment card, MFA settings card |
| Accent (10%) | `text-brand` | "Enable two-factor authentication" button, "Verify" button on challenge page |
| Destructive | `text-red-600`, `bg-red-50` | "Disable two-factor authentication" button, low backup code warning |
| Warning | `text-yellow-700`, `bg-yellow-50` | Backup code low-count banner (<= 2 remaining), all-codes-exhausted banner |
| Success | `text-green-700`, `bg-green-50` | MFA enabled success flash, backup codes saved confirmation |

Accent reserved for:
- "Enable two-factor authentication" CTA on enrollment page
- "Verify" button on MFA challenge page
- "Regenerate codes" link in MFA settings

Destructive reserved for:
- "Disable two-factor authentication" button in MFA settings
- Low backup code warning text/banner

**Source:** Matches Phase 4/5 color conventions.

## Visual Focal Points

| Surface | Primary Visual Anchor | Why |
|---------|----------------------|-----|
| MFA Challenge (`/users/mfa`) | The 6-digit monospace input field, centered in a narrow `max-w-sm` card. Auto-submit JS enhancement fires when 6 digits entered. | Single-purpose page: enter code, proceed. The input field receives autofocus; nothing else competes for attention. |
| TOTP Enrollment (settings) | The QR code SVG, centered above the confirmation code input. 200x200px black-on-white, high contrast. | Users need to scan the QR code first; the visual hierarchy guides: scan, then type code below. |
| Backup Code Display (enrollment) | The 2-column grid of 8 codes in monospace font on a `bg-gray-50` container. "Copy all" and "Download" buttons immediately below. | Users must record these codes. The grid format with clear monospace type and action buttons makes this unmistakable. |

## UI Surfaces

### Surface 1: MFA Challenge Page (`mfa_challenge_live.ex` / `mfa_challenge_controller.ex`)

**Route:** `/users/mfa`
**Requirement:** MFA-02, MFA-03, D-21, D-22--D-36, D-98
**Layout:** `mx-auto max-w-sm` centered card, GitHub-style focused page

**Components used:**
- `.header` with subtitle (partial email)
- `.form` with code input
- `.button` for verify
- `.input` for code entry
- `.flash` for error/success feedback
- Custom tabs for TOTP / backup code switching

**Page anatomy:**
```
[mx-auto max-w-sm]
  .header "Two-factor authentication"
  Subtitle: "Enter the code for j***@example.com"
  
  [Tab bar]                          <-- D-21
    [Authenticator code] (default, active)
    [Backup code]
  
  [TOTP Tab Content]
    [6-digit input]                  <-- text-base font-mono, autofocus
      inputmode="numeric" pattern="[0-9]*" maxlength="6" autocomplete="one-time-code"
    [Trust checkbox]                 <-- D-51, unchecked by default
      "Trust this browser for 30 days"
    [Verify button]                  <-- accent style
  
  [Backup Code Tab Content]
    [Backup code input]              <-- text-base font-mono
      placeholder="XXXX-XXXX"
    [Verify button]                  <-- accent style
  
  [Remaining attempts hint]          <-- D-38, muted text below form
    "3 attempts remaining"
  
  [Cancel link]                      <-- D-34
    "Cancel and sign out" (logs out)
```

**States:**

| State | What User Sees |
|-------|---------------|
| Default | TOTP tab active, 6-digit input with autofocus, trust checkbox (if enabled), verify button |
| Backup code tab | Input switches to XXXX-XXXX format, trust checkbox hidden |
| Invalid code | Flash error: "Invalid verification code. 3 attempts remaining." (D-38, D-90) |
| Lockout | Flash error: "Too many failed attempts. Try again in 12 minutes." (D-91) |
| Success | Session upgraded, redirect to originally requested page |
| Trust checked | On success, trust cookie set; next login skips MFA (D-46--D-47) |
| Session expired | Redirect to login with flash: "Your session has expired. Please sign in again." (D-26) |

**Interactions:**
- TOTP input: `inputmode="numeric"` for mobile numeric keyboard. Auto-submit JS fires when 6 digits entered (D-36). User can also press Enter or click Verify.
- Backup code input: User types or pastes code. Dashes/spaces stripped on server (D-12). Submit via Enter or Verify button.
- Tab switching: Client-side tab switch, no page reload. Both tab contents are rendered; CSS toggles visibility.
- Cancel link: Destroys `mfa_pending` session, redirects to login page (D-34).
- Trust checkbox: Only shown on TOTP tab (not backup code tab). Only shown if `mfa: [show_trust_option: true]` (D-50--D-51).

### Surface 2: TOTP Enrollment Page (settings, LiveView)

**Route:** Settings page section (not a standalone route)
**Requirement:** MFA-01, D-01, D-03--D-11, D-96--D-97
**Layout:** `mx-auto max-w-2xl` (matches settings page width from Phase 4/5)

**Enrollment flow (single page, D-01):**

```
[mx-auto max-w-2xl]
  .header "Two-Factor Authentication"
  Subtitle: "Add an extra layer of security to your account."
  
  [Step 1: QR Code + Manual Key]
    "Scan this QR code with your authenticator app"
    [QR Code SVG]                    <-- 200x200px, centered
    
    [Manual key section]             <-- collapsible
      "Can't scan? Enter this key manually:"
      [Secret key]                   <-- font-mono text-sm, select-all on click
        "JBSWY3DPEHPK3PXP"
    
    [Confirmation form]
      "Enter the 6-digit code from your app to verify setup:"
      [6-digit input]                <-- same styling as challenge page
      [Enable two-factor authentication]  <-- accent button
  
  [Step 2: Backup Codes (revealed after confirmation)]  <-- D-08
    .header "Save your backup codes"
    "Store these codes in a safe place. Each code can only be used once."
    
    [Backup code grid]               <-- bg-gray-50 p-4 rounded-lg
      [grid-cols-2 gap-3]
        1234-5678
        2345-6789
        ... (8 codes total)
    
    [Action buttons]                 <-- flex gap-2
      [Copy all]                     <-- secondary button
      [Download .txt]                <-- secondary button
    
    [Acknowledgment checkbox]        <-- D-11
      "I have saved these backup codes in a safe place"
    
    [Done]                           <-- accent button, disabled until checkbox checked
```

**States:**

| State | What User Sees |
|-------|---------------|
| MFA not enrolled | Full enrollment UI: QR code + confirmation form |
| MFA already enrolled | MFA status card (see Surface 3) instead of enrollment form (D-07) |
| Invalid confirmation code | Flash error: "Invalid verification code. Please try again." |
| Confirmation success | Backup codes section revealed; enrollment form hidden |
| Codes not acknowledged | "Done" button disabled (D-11) |
| Codes acknowledged | "Done" button enabled; clicking completes enrollment |
| Enrollment complete | Flash success: "Two-factor authentication has been enabled." |

**Interactions:**
- QR code: Static SVG rendered server-side (D-04). No JS required.
- Manual key: Click/tap to select all text for easy copying. `user-select: all` CSS.
- Confirmation code input: Same `inputmode="numeric"` and auto-submit behavior as challenge page (D-36).
- Copy all: JS copies all 8 codes newline-separated to clipboard. Button text changes to "Copied!" for 2 seconds.
- Download .txt: Triggers browser download of `backup-codes.txt` containing all 8 codes.
- Acknowledgment checkbox: Must be checked before "Done" button enables.

**Backup code warning states:**

| Remaining | Visual |
|-----------|--------|
| 3--8 | "X of 8 backup codes remaining" in `text-gray-500` |
| 1--2 | "X of 8 backup codes remaining" in `text-yellow-700 bg-yellow-50 p-2 rounded` banner (D-15) |

**Interactions:**

- Regenerate codes: Requires current TOTP code (D-14). Shows confirmation, then new codes with same copy/download/acknowledge flow as enrollment.
- Revoke trusted browsers: Requires sudo mode (D-55). Browser `data-confirm`: "This will require two-factor authentication on all your browsers. Continue?"

## Interaction Patterns

### MFA Challenge Flow

1. User logs in with password or OAuth.
2. If user has MFA enabled, session created as `:mfa_pending` (D-22).
3. User redirected to `/users/mfa`. All other routes redirect here (D-24).
4. User enters 6-digit TOTP code (auto-submits at 6 digits via JS, D-36) or switches to backup code tab.
5. On valid code: session upgraded to `:standard` or `:remember_me` (D-25, D-27). Token rotated. Redirect to originally requested page.
6. On invalid code: flash error with remaining attempts (D-38). Input cleared, autofocus restored.
7. After 5 failures: lockout for 15 minutes (D-19). Flash shows remaining time. Input disabled during lockout.
8. On cancel: session destroyed, redirect to login (D-34).
9. If `mfa_pending` session expires (5 min, D-26): redirect to login with expiry flash.

### TOTP Enrollment Flow

1. User navigates to settings, sees MFA section with enrollment UI.
2. User must be in sudo mode (D-06). If sudo expired, redirect to sudo page first.
3. Server generates TOTP secret, renders QR code SVG and manual key (D-04, D-68).
4. Secret held in encrypted Plug session (D-03). Not in database yet.
5. User scans QR code, enters 6-digit confirmation code.
6. On valid code: MFA credential created in DB, backup codes generated and hashed (D-08).
7. Backup codes displayed in grid with copy/download actions.
8. User checks acknowledgment checkbox (D-11), clicks "Done".
9. Enrollment complete. MFA enabled notification email sent (D-81).

### Disable MFA Flow

1. User clicks "Disable" on MFA settings card.
2. Sudo mode required (D-59). If expired, redirect to sudo page.
3. Disable confirmation form shown with warning and code input (D-62).
4. User enters current TOTP code or backup code.
5. On valid code: MFA credential deleted, backup codes deleted, trust_epoch incremented (D-60).
6. Flash success + post-disable suggestion (D-63).
7. MFA disabled notification email sent (D-61).

### Backup Code Regeneration Flow

1. User clicks "Regenerate codes" in MFA settings.
2. Prompt for current TOTP code (D-14).
3. On valid code: old codes deleted, 8 new codes generated.
4. Same code display UI as enrollment: grid + copy + download + acknowledge.
5. Telemetry event emitted (D-64).

## Accessibility Requirements

| Requirement | Implementation |
|-------------|----------------|
| TOTP input | `inputmode="numeric"` for mobile keyboard, `autocomplete="one-time-code"` for browser autofill, explicit `<label>` |
| Tab switching | Tabs use `role="tablist"`, `role="tab"`, `role="tabpanel"`, `aria-selected`, keyboard arrow navigation |
| Auto-submit | JS enhancement only; form remains fully functional without JS (manual submit via Enter/button) |
| QR code | `role="img"` with `aria-label="QR code for TOTP setup"`. Manual key fallback always visible (D-04) |
| Backup code grid | Semantic `<ol>` list for screen readers. Each code in `<li>` with `<code>` element |
| Remaining attempts | Announced via `aria-live="polite"` region when count changes |
| Lockout state | Verify button gets `disabled` attribute. Input gets `disabled`. Screen reader announcement via `role="alert"` flash |
| Focus management | After tab switch: focus moves to input in new tab panel. After error: focus returns to input. After enrollment step: focus moves to next interactive element |
| Color contrast | All text meets WCAG 2.1 AA (4.5:1 body, 3:1 large). Warning banners use icon + text (not color alone) |
| Checkbox labels | Explicit `<label>` associated with trust and acknowledgment checkboxes |
| Cancel link | Visible, keyboard-accessible. Not hidden behind menu or icon-only control |
