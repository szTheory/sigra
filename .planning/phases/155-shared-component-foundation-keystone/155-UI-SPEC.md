# Phase 155 — UI Design Contract

> Visual and interaction contract for the `Sigra.Admin.Components` keystone phase.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

> **Phase nature — read first.** This is NOT a screen-design phase. It builds a
> lib-owned Phoenix function-component module (`lib/sigra/admin/components.ex`)
> by extracting markup that already ships in the admin LiveViews. The governing
> visual authority is the **mature `sg-*` token + CSS layer** and the committed
> `guides/reference/admin-design-contract.md` (COMP-03). This phase invents **no**
> new tokens, **no** new CSS, **no** new screen copy, and **no** registry components.
> The "design contract" for this phase is **markup / class-string / ARIA fidelity**:
> each extracted component must be a byte-faithful (or, for `notice`, pixel-neutral)
> drop-in for the markup it replaces. A Playwright baseline re-record in this phase
> is a bug, not permission to proceed (STATE.md keystone lock).
>
> All token tables below document the **existing** system that the components emit
> against (source: `test/example/priv/static/assets/css/app.css`). They are recorded
> so the checker can confirm the components reuse — never reinvent — these values.

## Spacing Scale

Components do **not** emit raw px/rem — they emit `sg-stack--N` / `sg-space-N` /
`sg-cluster` utilities that resolve to the existing token scale below. The scale is
a 4px (0.25rem) base; values are recorded for checker verification. Components must
reuse these utility classes, never inline new spacing.

| Token | Value | px @16 root | Usage |
|-------|-------|-------------|-------|
| `--sg-space-1` | 0.25rem | 4px | Icon gaps, tightest inline padding |
| `--sg-space-2` | 0.5rem | 8px | Compact element spacing (`sg-stack--2`) |
| `--sg-space-3` | 0.75rem | 12px | Default intra-card spacing (`sg-stack--3`) |
| `--sg-space-4` | 1rem | 16px | Default element spacing |
| `--sg-space-5` | 1.25rem | 20px | — |
| `--sg-space-6` | 1.5rem | 24px | Section / page-stack rhythm (`sg-stack--6`) |
| `--sg-space-7` | 1.75rem | 28px | — |
| `--sg-space-8` | 2rem | 32px | Layout gaps |
| `--sg-space-10` | 2.5rem | 40px | — |
| `--sg-space-12` | 3rem | 48px | Major section breaks |

Exceptions: 12px (`--sg-space-3`), 20px (`--sg-space-5`), 28px (`--sg-space-7`),
40px (`--sg-space-10`) are part of the **pre-existing, mature** Sigra scale and are
not multiples of 8. This is intentional and locked — the milestone audits *usage* of
this scale, not the scale itself (REQUIREMENTS.md "Out of Scope": no new tokens).
Components in this phase emit only existing utilities; they introduce zero new spacing.

## Typography

Components emit `sg-text-*` / `sg-section-heading` / `sg-page-title` utilities that
resolve to the existing type scale below. Recorded for checker verification; no new
type sizes or weights are introduced this phase.

| Role | Token | Size | Weight (token) | Line Height (token) |
|------|-------|------|----------------|---------------------|
| Body / copy | `--sg-text-sm` | 0.875rem (14px) | `--sg-weight-regular` (450) | `--sg-leading-normal` (1.5) |
| Base body | `--sg-text-base` | 1rem (16px) | `--sg-weight-regular` (450) | `--sg-leading-normal` (1.5) |
| Section heading | `--sg-text-md` / `--sg-text-lg` | 1.125rem / 1.45rem | `--sg-weight-medium` (600) | `--sg-leading-snug` (1.3) |
| Page title | `--sg-text-xl` / `--sg-text-2xl` | 1.875rem / clamp(1.6–2.4rem) | `--sg-weight-semibold` (700) | `--sg-leading-tight` (1.1) |

Component-relevant defaults (what these components actually emit):

- `notice`, `empty_state` body copy → `sg-text-sm` (14px, weight 450, line-height 1.5).
- `task_card` title → `sg-section-heading`; body → `sg-section-copy`.
- `summary_chip` → `<dt>`/`<dd>` inside `sg-metric` (inherits metric-grid type).
- `page_back` / `scope_ribbon` scope copy → `sg-text-sm` / `sg-muted`.

Weights are an existing 4-step ramp (450 / 600 / 700 / 800). This phase touches only
regular (450), medium (600), and semibold (700) via existing utilities. No new weights.

## Color

Components emit semantic `sg-color-*` tokens and `data-tone` attributes; they never
hardcode hex. The 60/30/10 split below describes the existing admin surface system
(light values; dark-mode equivalents exist at `app.css:160–180` and are unaffected).

| Role | Token | Light value | Usage |
|------|-------|-------------|-------|
| Dominant (60%) | `--sg-color-subtle` / `--sg-color-ink` | `#f6f5f2` bg / `#151515` ink | Page background + body text |
| Secondary (30%) | `--sg-color-panel` / `--sg-color-panel-alt` | `#ffffff` / `#fbfaf7` | Cards (`sg-card`), panels, table surfaces |
| Accent (10%) | `--sg-color-brand` | `#c2410c` | See reserved-for list below |
| Destructive | `--sg-color-risk` | `#b42318` | Risk-tone notices, danger zone, error copy |

Accent (`--sg-color-brand`) reserved for, in this phase:

- The primary CTA link inside `task_card` (`sg-btn sg-btn--primary`).
- `stat_link` hover/focus affordance (brand-tinted focus ring via `--sg-focus-ring`).
- Nothing else. `stat`, `summary_chip`, `scope_ribbon`, `page_back` (ghost),
  `empty_state`, and `skeleton` carry **no** accent — they use ink/muted/line tokens.

Semantic tone tokens for `notice` (`data-tone`), all pre-existing, conveyed visually
**and** textually (never color-alone):

| Tone | Soft bg token | Foreground token |
|------|---------------|------------------|
| `ok` | `--sg-color-ok-soft` `#ecfdf3` | `--sg-color-ok` `#176b43` |
| `warn` | `--sg-color-warn-soft` `#fff7e6` | `--sg-color-warn` `#a15c00` |
| `risk` | `--sg-color-risk-soft` `#fff1f0` | `--sg-color-risk` `#b42318` |
| `info` | `--sg-color-info-soft` `#eef2ff` | `--sg-color-info` `#1d4ed8` |
| `nil` (no tone) | inherits `sg-notice` base | `--sg-color-ink` |

## Component Contract Inventory

The real deliverable of this phase. Each component is a flat, stateless
`Phoenix.Component` function (D-01) emitting the exact `sg-*` classes pinned by the
design contract (D-03). `attr :class, :any, default: nil` is merged as
`class={["sg-…", @class]}` and `attr :rest, :global` spreads on the outer element (D-02).

| Component | Job (one line) | Required attrs | Slots | Emitted root class | ARIA |
|-----------|----------------|----------------|-------|--------------------|------|
| `stat_link` | Numeric KPI with a nav destination (always `<a>`) | `href`, `label`, `value` | — | `sg-metric-link` (+ `__label`/`__value`) | native `<a>` |
| `stat` | Read-only numeric KPI, no nav | `label`, `value` | — | reuse `sg-metric*` utilities; **no `<a>`, no `.sg-stat`** | static text |
| `task_card` | Verb-first action prompt with CTA | `title`, `body`, `action`, `href` | — | `sg-card sg-card-hover sg-stack sg-stack--3` | `<article>` + `<h2>`; CTA `<a>` |
| `summary_chip` | Non-interactive aggregate posture badge | `label`, `value` | — | `sg-metric-grid` › `sg-metric` (`<dl>`/`<dt>`/`<dd>`) | definition-list semantics |
| `applied_chip` | Active filter indicator with remove affordance | `label`, remove `href` | — | `sg-applied-chip` (+ `__remove`) | `aria-label="Remove filter …"`; glyph `aria-hidden`; `.sr-only` fallback |
| `empty_state` | Dashed centred zero-rows placeholder | (title via slot/attr) | `inner_block` | `sg-empty-state sg-stack sg-stack--3` | `sg-empty-state__title` as region heading |
| `page_back` | Single-step back to list (consumes `return_to`) | `return_to` | — | `sg-btn sg-btn--ghost sg-btn--sm`; **no dedicated class** | native `<a>`; `&larr;` `aria-hidden`; descriptive text |
| `scope_ribbon` | Persistent in-body scope indicator | scope/copy assigns | — | reuse `sg-muted sg-text-sm`; **no dedicated class** | decorative span, read inline |
| `notice` | Block-level toned contextual alert | `tone` (`values: [:ok,:warn,:risk,:info,nil]`) | `inner_block` (required) | `sg-notice` + `data-tone={@tone}` (**not** `sg-list-row`) | **no live-region role by default** (D-08); opt-in via `:rest` |
| `skeleton` | Loading-shape placeholder | — | — | `sg-skeleton` | none on element; `aria-busy` is a caller concern (Phase 157) |

### Notice — the one deliberate fork (D-07 / D-08 / D-09)

`<.notice>` ships its **final** form against `sg-notice` (a byte-for-byte property
clone of `sg-list-row` at `app.css:971–993`), making the class swap **pixel-neutral**:

```heex
<div class="sg-notice" data-tone={@tone} {@rest}>
  <p class="sg-text-sm">{render_slot(@inner_block)}</p>
</div>
```

- **No `role="alert"` / `role="status" aria-live` by default.** Load-present content
  makes `role="alert"` inert (WAI-ARIA APG) and `role="status"` risks duplicate
  announcements on LiveView re-render (MDN). Phoenix `flash/1` uses `role="alert"`
  only because it is dynamically injected with focus-management JS — not Sigra's
  render model. A live-region role is opt-in per call site via `:rest`, only for
  genuinely post-load dynamic notices (future Phase 157 / LAND-01).
- The design contract's notice ARIA cell (~lines 112–113) is amended in this phase
  with this one-line correction-of-fact (D-09); the markup-cell target becomes the
  `sg-notice` div above.

## Motion Contract

Motion is owned entirely by the existing CSS layer; components add no inline motion.
Recorded for the GATE-03 motion-usage audit (owned at Phase 159; referenced here so
checker can confirm components don't violate it).

| Component | Motion |
|-----------|--------|
| `stat_link` | Hover `box-shadow` lift, 140ms `--sg-ease`; not animated on focus/load |
| `task_card` | Hover `translateY(-1px)` + shadow, 140ms, pointer-fine only; not on focus/load |
| `applied_chip` | `--sg-transition-tone` on remove hover; **not** animated on filter-apply (keyboard-frequent, GATE-03) |
| `notice` | `--sg-transition-tone` on base rule; not animated on initial render |
| `stat`, `summary_chip`, `empty_state`, `page_back`, `scope_ribbon` | Not animated (static) |
| `skeleton` | `translateX` shimmer; stripped by universal `prefers-reduced-motion` rule (`app.css:1463–1473`) |
