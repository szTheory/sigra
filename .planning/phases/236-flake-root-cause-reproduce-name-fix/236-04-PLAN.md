## SC-5 — the dated quarantine, SPECIFIED not BUILT

This is the design of record for the contingency. It is implemented ONLY if the plan 236-01 branch
call came out (c) — no keydown reached the document, pure harness actionability, no `lib/` change
warranted. On branches (a) and (b) nothing here is built. Rationale for specify-only: the amendment
below is a real schema change to `.github/ci-skip-manifest.tsv`, a file Phase 241 explicitly depends
on ("the honest-skip-parity guard pins `ci.yml` job ids; writing it before 236's `ci.yml` edits pins
a moving target"). Building it speculatively is exactly the moving target the ROADMAP ordering
exists to prevent.

**Why the naive version is structurally impossible.** `.github/ci-skip-manifest.tsv` is not a
general quarantine ledger — it is an enumeration of `ci.yml` constructs, enforced in four directions
by `scripts/ci/prohibitions/p10-no-undocumented-demotion.test.mjs`: `:72-89` asserts every manifest
`id` resolves to a real `ci.yml` job block or step `id:`; `:101-116` asserts `display_name`
byte-matches what `ci.yml` declares; `:118-175` asserts the `gate` column equals `ci.yml`'s actual
normalized `if:` expression; `:211-226` asserts the reverse set-equality. A Playwright *test name*
satisfies none of those, so a `kind=job` row naming the flaking test hard-fails `p10` and therefore
hard-fails `fast_checks` for every subsequent run.

Nor can the date and owner go in the `observer` cell: `scripts/ci/ci-demotion-observer.sh:83` keys on
`$8 == "assert"` and enforces a ≥2-assert floor at `:88`, so `observer` is a closed enum consumed by
shell, not free text. And `_lib.mjs:212` throws on any row with fewer than 8 cells, so an
under-filled row poisons every later parse.

**The amendment, in three parts:**

1. **Append two columns, making 10:** `quarantined_on` (`$9`, ISO date) and `owner` (`$10`). This is
   parser-safe — `_lib.mjs:212` rejects only `cells.length < 8` and the destructure at `:215` ignores
   extras — and observer-safe, because `$8` is unchanged. Every existing row gets `-` / `-`. Note the
   header cell is `parent_job_id` (snake_case); `parentJobId` is only the JS destructuring alias at
   `_lib.mjs:215`.
2. **Add `kind=spec` and exempt it** from `p10:72-89`'s id-resolution branch and `p10:101-116`'s
   display-name branch, with an explicit in-file comment stating why: a Playwright test is not a
   `ci.yml` construct, so the four-direction parity assertions do not apply to it.
3. **Add the matching `MAINTAINING.md` entry**, because the manifest's own header documents
   `MAINTAINING.md` as a renderer of this file and the parity checks assert in both directions.

**Validation if built:** add the row, then `node --test scripts/ci/prohibitions/p10-no-undocumented-demotion.test.mjs`,
`bash scripts/ci/ci-demotion-observer.test.sh` and `bash scripts/ci/honest-skip-verdict.test.sh` must
all stay green. Claiming SC-5 without running all three is claiming an untested schema change.

**What is NOT the fallback:** retry-wrapping, in any form (D-33). The `p17` guard from plan 236-03
makes that mechanical.

**Related, deliberately out of scope:** the manifest's comment block cites
`scripts/ci/prohibitions/honest-skip-parity.test.mjs`, which does not exist. That is already tracked
twice — as requirement DEBT-03, owned by Phase 241, and as the pending todo
`.planning/todos/pending/2026-09-15-honest-skip-parity-guard-does-not-exist.md`. Not ignored, not
fixed here; fixing it would be a found-while-cleaning in-phase fix, which standing constraint 4
forbids (the single pre-authorized exception is the `lib/` product race).
