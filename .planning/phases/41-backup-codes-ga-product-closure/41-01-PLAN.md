<objective>
Implement **library-side** backup-code **rotation**: TOTP-gated **`Sigra.MFA.regenerate_backup_codes/4`**, **transactional** delete+insert, and **atomic** audit when `:audit_schema` is set — superseding non-transactional **`BackupCodes.regenerate/4`** + post-hoc **`audit_backup_codes_regenerate/3`** for this path.
</objective>

<threat_model>
| ID | STRIDE | Finding | Severity | Mitigation in plan |
|----|--------|---------|----------|-------------------|
| T-41-01 | Tampering | Attacker rotates codes with only a stolen backup sheet | high | Require `{:totp, _}` verification before Multi; never accept backup code as rotation proof in this API (D-41-01). |
| T-41-02 | Elevation / integrity | Partial DB writes leave user with zero backup codes | high | Single `Repo.transaction` wrapping delete, insert, audit insert. |
| T-41-03 | Repudiation | Success returned but audit row missing when audit enabled | medium | `log_multi_safe` on same Multi + `emit_telemetry_from_changes/1` after `{:ok, changes}`. |
</threat_model>

Keep **`Sigra.MFA.BackupCodes.generate/1`** and **`hash/1`** unchanged; **`BackupCodes.regenerate/4`** may delegate to the new Multi-based path **or** wrap its body in **`repo.transaction`** for backward compatibility — **must not** leave a public code path that does delete+insert without a transaction.
    5. Document in **`@moduledoc`** or function doc that **`audit_backup_codes_regenerate/3`** is **not** the authoritative path when audit is enabled for rotation (callers use **`regenerate_backup_codes/4`**).
