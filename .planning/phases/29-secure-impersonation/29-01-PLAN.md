<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| resolved admin scope -> impersonation runtime | Untrusted callers may try to impersonate out-of-scope users or start nested sessions |
| impersonation scope -> audit writer | Dual-actor attribution crosses from web/runtime scope state into durable evidence |
| timeout evaluation -> web restoration | Expired impersonation state must not leave the user in a partially restored session |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-29-01 | E | `Sigra.Impersonation.start/4` | mitigate | Per D-07, authorize target reachability through `Sigra.Admin.Authorizer` before session creation, with denied-attempt audit events. |
| T-29-02 | T | `Sigra.Session` impersonation metadata | mitigate | Extend the existing session struct additively and keep all state changes in library-owned runtime functions instead of ad hoc controller maps. |
| T-29-03 | R | `Sigra.Audit.scope_fields/1` | mitigate | Per D-16 and D-17, keep actor/effective-user composition in canonical columns and cover it with `log_safe_scope` tests. |
| T-29-04 | D | timeout/restore path | mitigate | Per D-18, return explicit restore-versus-login-fallback outcomes so the web layer can fail closed instead of silently dropping session state. |
</threat_model>
