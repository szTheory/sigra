<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user detail UI -> controller start route | High-risk action entry must preserve scope and target identity clearly |
| current scope -> host-owned banner chrome | Host-owned display code must not be allowed to hide or weaken the impersonation state contract |
| generated layout injection -> host layout | Installer-owned layout updates must stay additive and consistent with existing admin-shell conventions |
| host-owned banner chrome -> app-wide stop route | The visible stop control must remain reachable from app and admin layouts without depending on admin-only routing |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-29-09 | S | `UserShowLive` impersonation entry | mitigate | Per D-08 and D-11, render start only on user detail with explicit target and return context instead of list-row shortcuts. |
| T-29-10 | I | banner chrome | mitigate | Per D-09 and D-10, render both real and effective identities plus a stop action in persistent chrome so operators cannot mistake the active actor. |
| T-29-11 | T | host-owned shell seam | mitigate | Keep the security contract in controller and runtime code; the shell only renders state and stop links, and tests pin the required copy. |
| T-29-12 | D | stop-link reachability | mitigate | Point the persistent stop control at the app-wide impersonation stop path from Plan 29-02 so operators can always end the session outside admin-only routes. |
</threat_model>
