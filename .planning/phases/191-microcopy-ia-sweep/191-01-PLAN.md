  Create `test/sigra/admin/glossary_test.exs`. Follow the existing ExUnit test module pattern in `test/sigra/admin/components_test.exs`.

  The test reads each of the 8 in-scope source files directly via `File.read!/1` with paths relative to the project root. Use `File.cwd!/0` or hard-coded relative paths consistent with how `components_test.exs` addresses source files.

  Module structure:
  - `defmodule Sigra.Admin.GlossaryTest do`
  - `use ExUnit.Case, async: true`
  - `@moduledoc false`
  - `@in_scope_files` — the 8 files as a list of relative paths
  - `describe "admin glossary drift guard"` block with one test per concept cluster, or a single parametrized test that iterates all files

  Core private functions:

  `strip_carve_outs(lines, filename)` — implement using DOM-marker anchoring, NOT a hardcoded line range. For `"lib/sigra/admin/live/branding_live.ex"`, scan through lines and use a two-state machine:
  - Carve-out is INACTIVE until a line is seen containing `"sigra-auth sigra-auth--preview"` (this is the class attribute on the opening `<div>` of the auth-replica block, currently line 584). When that marker is found, mark carve-out as ACTIVE and begin skipping lines (including the marker line itself).
  - While carve-out is ACTIVE, track `<div>` open/close nesting depth (increment on lines containing `<div`, decrement on lines containing `</div>`). When depth returns to 0 after the opening marker was consumed, the closing `</div>` has been reached — emit it as skipped and mark carve-out INACTIVE.
  - Lines that appear BEFORE the opening marker (e.g. line 583 `<h2>Login preview</h2>`) and AFTER the closing `</div>` are kept in the output and remain subject to scanning.
  - All other filenames return lines unchanged.

  This ensures: (a) future line-number shifts from edits above or below the block do not break the carve-out; (b) line 583 (`<h2>Login preview</h2>`) is never skipped and the "Login" banned term there is caught; (c) lines 601 (`<h1>Log in</h1>`), 602, 605 inside the auth-replica are always skipped.

  `strip_non_copy_lines(lines)` — reject lines matching any of the strip patterns from RESEARCH.md §Source-Extraction Regexes. Patterns: `^\s*(defmodule|def\s|defp\s)`, `^\s*(alias|import|use|require)\s`, `^\s*@`, `^\s*#`, `data-testid=`, `data-sg-`, `class=`, `(href|action|phx-\w+|name=|input.*name=)`, `\|\>`, `~r\/`, `(%\{|%Ecto|__struct__)`, `inspect\(`, `raise\s+[A-Z]`, `^\s+(attr|slot)\s+:`.

  `banned_terms()` — returns a list of `{pattern_string, canonical, description}` triples exactly matching RESEARCH.md §banned_terms. Include: log in, log out, logout, signin, sign off, login (noun), logins (plural), org (not-organization), teammates, collaborators, seat (as person).

  `check_file(file_path)` — reads the file, splits into lines, calls `strip_carve_outs/2` with the relative file path (matching the string used in `@in_scope_files`), calls `strip_non_copy_lines/1`, then for each remaining line checks all `banned_terms()` patterns using `Regex.scan/3` with case-insensitive flag. On any match, accumulates `"#{file_path}:#{line_num} — found '#{matched}' — use '#{canonical}' instead (#{description})"`. Note: after carve-out stripping, the accumulated line numbers must still reference the original line numbers in the source file, not the post-strip offsets — track original 1-based line numbers alongside lines through the strip pipeline.

  The test assertion: `assert violations == []` with a message that prints all violations joined by `\n`.

  Note: On the pre-edit source, this test WILL FAIL (RED). That is the intended state entering Wave 2. The RESEARCH.md confirms ~15–20 violations across 5 files. Wave 2 edits will turn it green.

  Do NOT add a broad `\baccount\b` ban — per RESEARCH §Pitfall 1. The 6 account-as-person-noun violations are fixed by per-line edits in Wave 2.
  Do NOT add `inspect(` to the banned_terms regex list — it is already in the strip patterns (inspect calls in function heads are stripped). The WR-04 `inspect` leak at branding_live.ex:731 is in a string interpolation context that will remain after stripping and IS separately caught by the guard via the string `"Could not save auth branding: #{inspect(reason)}"` — but since the strip pattern removes lines containing `inspect(`, this line IS stripped. The WR-04 fix is made by the copy edit in Wave 2 regardless; the guard is not the primary catch mechanism for it.

  Keep the test self-contained — no external dependencies, no DB, runs in `mix test` like other unit tests.
