## Warnings

### WR-01: Refresh-response proof accepts extra or duplicate credential fields

**File:** `scripts/ci/generated-app-login-runtime-proof.sh:399`
**Issue:** The check counts the number of *distinct expected key names* found by `grep`, so it passes whenever all four expected names appear at least once. It does not reject duplicate expected keys or any additional JSON keys (including an accidentally exposed secret). Consequently, a response such as `{"access_token":"…","refresh_token":"…","family_id":"…","expires_in":900,"password":"leaked"}` still satisfies the check even though the nearby diagnostic says it is the “exact credential shape.” This weakens the generated-host evidence lane’s ability to detect an API-contract or sensitive-data regression.
**Fix:** Parse the response as JSON and compare its complete key set (and types) to the expected schema. For example:

```bash
python3 - "$response" <<'PY'
import json, sys
value = json.load(open(sys.argv[1]))
assert set(value) == {"access_token", "refresh_token", "family_id", "expires_in"}
assert all(isinstance(value[key], str) and value[key] for key in ("access_token", "refresh_token", "family_id"))
assert isinstance(value["expires_in"], int)
PY
```
