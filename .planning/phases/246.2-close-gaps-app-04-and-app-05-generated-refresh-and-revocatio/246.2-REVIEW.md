# Phase 246.2: Code Review Report

**Reviewed:** 2026-08-18T15:40:07Z
**Depth:** standard
**Files Reviewed:** 7

## Summary

The generated APP-04/APP-05 controller, router, proof harness, CI receipt check, and source-contract tests were reviewed in context with the session and rate-limit implementations. The new limiter prevents the required refresh-reuse revocation path from being reached after unrelated direct-login traffic, and the retained-evidence parser does not fail closed for several fields it represents as provenance.

## Critical Issues

### CR-01: Direct-login traffic can prevent refresh-reuse family revocation

**File:** `priv/templates/sigra.install/app_sessions/router_injection.ex:49-54`
**Issue:** The `:app_login_refresh` limiter is IP-keyed (`app_login_refresh:ip:<remote_ip>`) and is shared by `/refresh`, `/direct`, and `/direct/mfa`. Four direct-login requests from the same IP (including a shared NAT or an attacker able to send requests from the victim's IP) return 429 before `AppLoginController.refresh/2` runs. A replayed consumed refresh token therefore cannot reach `AppSessions.refresh/1` to revoke its family, violating the required refresh-reuse lifecycle. The proof only exercises refresh in a host where no direct requests have consumed that limiter, so it misses this production path.

**Fix:** Keep `/refresh` in its own pipeline and put direct start/MFA routes behind a separate `:app_login_direct` limiter/key prefix (or another limiter that cannot consume the refresh budget). Add a generated-route/runtime test that exhausts the direct budget and proves a consumed refresh token still reaches the refresh handler and revokes its family.

### CR-02: Receipt provenance accepts forged run location, artifact, and implementation reference

**File:** `test/sigra/planning/phase_246_runtime_evidence_contract_test.exs:166-188`
**Issue:** `valid_provenance?/2` requires these fields to be present but never validates `run_url`, `implementation_ref`, or `artifact_name`. Thus a provenance map with a correct historical `head_sha` and recomputed receipt hash but an arbitrary run URL/artifact/ref is accepted as `:ok`; the test named “fail closed for every evidence mutation” does not mutate any of these fields. This makes the claimed CI provenance and immutable implementation binding forgeable within the retained-evidence contract.

**Fix:** Validate `run_url` equals `https://github.com/szTheory/sigra/actions/runs/#{run_id}`, require the exact artifact name, and bind the implementation reference to an immutable expected SHA (or validate the recorded ref resolves to `head_sha` using trusted GitHub metadata). Add rejection tests for mutations of all three fields.

## Warnings

### WR-01: Contract-stage test does not test each declared contract

**File:** `test/sigra/planning/phase_246_generated_app_login_runtime_test.exs:617-621`
**Issue:** The loop variable `contract` is unused (and emits a compiler warning). Each iteration checks the same literal `${mode}_post_ceremony_${contract}` text, so deleting one of the concrete stage names from the harness would still pass as long as that generic interpolation string remains. This weakens failure-stage coverage precisely where the proof is meant to give deterministic diagnostics.

**Fix:** Interpolate the Elixir loop variable into the expected string, for example `assert harness =~ "${mode}_post_ceremony_#{contract}"`, and retain a test for every listed contract.
