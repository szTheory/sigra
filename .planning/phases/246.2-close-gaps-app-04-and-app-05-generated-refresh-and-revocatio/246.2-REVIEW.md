# Phase 246.2: Code Review Report

**Reviewed:** 2026-08-16T00:00:00Z
**Depth:** standard
**Files Reviewed:** 7
**Status:** issues_found

## Summary

The reviewed changes add generated refresh/revocation endpoints and a CI runtime-proof lane. The retained-evidence test can explicitly accept an obsolete or malformed receipt, so the claimed fail-closed evidence gate does not actually enforce the v4 proof. The runtime harness also has a process/port handoff race, and callback construction corrupts valid configured callback URIs that contain a fragment.

## Critical Issues

### CR-01: BLOCKER — obsolete retained runtime proof is accepted

**File:** `test/sigra/planning/phase_246_runtime_evidence_contract_test.exs:90`
**Issue:** When a canonical receipt exists but its schema is not v4, the test takes the `else` branch and merely refutes that it is v4—the condition already known to be true. Thus a v3 receipt, arbitrary JSON receipt, or otherwise stale evidence passes without parsing its provenance or validating its source hashes. This contradicts the test's fail-closed contract and can let the phase retain unverified runtime evidence.
**Fix:** Require the current schema whenever a receipt is present, then always validate the receipt and provenance. For example:

```elixir
receipt = decode!(@receipt_path)
assert receipt["schema"] == "sigra.generated-app-login-runtime-proof/v4"
assert :ok = validate(receipt, decode!(@provenance_path))
```

## Warnings

### WR-01: WARNING — generated direct proof can race the prior server on the same port

**File:** `scripts/ci/generated-app-login-runtime-proof.sh:930`
**Issue:** `--all` runs the hosted and direct hosts sequentially on the fixed port, but `kill "$SERVER_PID"` is followed immediately by clearing the PID and starting the next host. `kill` only signals the process; it does not wait for it to release port 4019. The direct server can consequently fail to bind while readiness succeeds against the still-running hosted server, producing intermittent and misleading failures.
**Fix:** Wait for the process after signaling it, before clearing the PID and returning from `prove_host`:

```bash
kill "$SERVER_PID"
wait "$SERVER_PID" || true
SERVER_PID=""
```

### WR-02: WARNING — approval redirect appends query parameters after URI fragments

**File:** `priv/templates/sigra.install/app_sessions/app_login_controller.ex:160`
**Issue:** `callback_with_code/3` chooses `?` or `&` by searching the raw callback string and concatenates the query afterward. A configured exact callback URI such as `com.example.app:/login#complete` becomes `com.example.app:/login#complete?code=...`; the code and state are then fragment content rather than query parameters, so the receiving application does not receive the authorization response as intended. First-party profile validation allows any non-empty callback URI string, so this is a valid configurable input.
**Fix:** Parse the URI and merge encoded query parameters before preserving its fragment, or reject fragment-bearing callback URIs during profile validation. For example, build `URI.to_string(%{URI.parse(callback) | query: URI.encode_query(merged_query)})` after decoding and merging any existing query values.

### WR-03: WARNING — per-contract source assertions never inspect the loop variable

**File:** `test/sigra/planning/phase_246_generated_app_login_runtime_test.exs:523`
**Issue:** The loop binds `contract`, but its assertion uses the literal shell-style string `"${mode}_post_ceremony_${contract}"`, not Elixir interpolation. As the compiler warning confirms, `contract` is unused and all five iterations assert the identical text. Removing or misspelling an individual stage can therefore pass this source-contract test.
**Fix:** Use Elixir interpolation and assert the contract-specific string, for example:

```elixir
assert harness =~ "\${mode}_post_ceremony_#{contract}"
```
