<interfaces>
`Auth.AppSessions.refresh/1` delegates to `Sigra.AppSession.refresh/2`. Success is `{:ok, %{access_token: binary, refresh_token: binary, family_id: term, expires_in: integer}}`; invalid, expired, reused, unconfigured, and transaction-aborted outcomes are bounded error tuples. Replacement credentials become observable only after the repository transaction succeeds.

`Auth.AppSessions.revoke_family/2` delegates to owner-bound `Sigra.AppSession.revoke_family_for_user/3`, returning `{:ok, family}` or bounded `:not_found`, unconfigured, or aborted errors. `Auth.AppSessions.revoke_all/1` returns `{:ok, non_neg_integer}` or a bounded error. Controllers discard returned rows/counts and expose only outcome JSON.

The existing public app-login scope is `scope "/api/app-login"` through `[:api, :app_login_public]`. The established sensitive self-service boundary is `scope "/users"` through `[:browser, :require_authenticated, :require_sudo]`; the browser pipeline supplies CSRF protection.
</interfaces>

## Trust Boundaries

| Boundary | Description |
|---|---|
| Public refresh JSON → generated controller | An untrusted refresh credential and body shape cross into a rate-limited lifecycle exchange. |
| Generated controller → `Auth.AppSessions` | Thin delivery code must not duplicate transaction, digest, rotation, or revocation semantics. |
| Browser cookie/CSRF/sudo Scope → revocation actions | Only a recently authenticated browser session may mutate the current user's app-session families. |
| Request family selector → owner-bound library lookup | An opaque selector is untrusted and must never select or override its owner. |
| Raw response files → retained diagnostics | Runtime proof temporarily handles credentials but retained output must remain outcome-only. |
