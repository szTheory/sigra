# Phase 246.2 — Security

> Per-phase security contract for the generated refresh/revocation surface and its retained runtime evidence.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Untrusted public request → generated limiter/controller | Refresh and opt-in direct-login traffic enter independent bounded pipelines before strict input decoding. | Opaque credential material; password/MFA input |
| Browser session → revocation mutation | Authenticated, sudo-confirmed, CSRF-protected browser requests derive ownership only from current Scope. | Family selector; owner identity |
| Generated host → lifecycle transaction | Refresh rotation, replay-family revocation, owner isolation, and next-auth denial execute through host-owned app-session APIs. | Digest-only session state and bounded outcomes |
| Runtime proof → retained canonical evidence | A successful exact-head workflow run publishes a receipt last, then offline validation binds it to source hashes and provenance identity. | Credential-free flags, hashes, run metadata |
