## Summary

This phase closes two discrete cleanup items deferred from v1.31 DEMO-SHOWCASE. Both are purely mechanical with zero behavioral or functional impact.

**Change 1 — TypeScript unused-param rename:** The `assertDemoScreenshot()` function in `demo-showcase.spec.ts` accepts a `testInfo: TestInfo` parameter that the function body never references. TypeScript and Playwright convention is to prefix intentionally unused parameters with `_`. The rename to `_testInfo` is a single token change on line 51; callers on lines 115, 132, 148, and 160 pass `testInfo` from the outer test callback and require no change.

**Change 2 — ExDoc absolute URL fix:** `docs/ga-evidence.md` ends with a relative `../.planning/` link to `144-VERIFICATION.md`. ExDoc cannot resolve relative paths that step outside the `docs/` tree, which caused an undefined-reference warning suppressed by adding `"docs/ga-evidence.md"` to `skip_undefined_reference_warnings_on` in `mix.exs`. The real fix is replacing the relative link with an absolute GitHub URL (`blob/main/...`), then removing the suppression entry so ExDoc's warning remains active for real future issues.

**Primary recommendation:** Execute the three edits in a single commit; verify with `mix docs --warnings-as-errors` passing cleanly.

### Pattern 1: TypeScript Unused Parameter Convention

**What:** Prefix unused function parameters with `_` to signal intentional non-use.
**When to use:** Any TypeScript function parameter that satisfies an interface or callback signature but is not referenced in the function body.
**Example:**
```typescript
// Before (triggers @typescript-eslint/no-unused-vars if lint is configured)
async function assertDemoScreenshot(
  page: Page,
  testInfo: TestInfo,
  slug: string,
) { ... }

// After (convention-compliant, no lint suppression needed)
async function assertDemoScreenshot(
  page: Page,
  _testInfo: TestInfo,
  slug: string,
) { ... }
```
[ASSUMED] — standard TypeScript/ESLint community convention; no official spec URL, but universally adopted.

Note: The Playwright project at `test/example/priv/playwright/` has no `tsconfig.json` and no ESLint config — `noUnusedParameters` is not enforced at compile time in this project. The rename is a style/documentation fix, not a compiler-error fix.

### Pattern 2: ExDoc Absolute URL for Out-of-Tree Links

**What:** Use absolute GitHub URLs for links to files outside the ExDoc extras tree (e.g., `.planning/` artifacts).
**When to use:** Any `docs/*.md` or `guides/**/*.md` file that links to a path ExDoc cannot serve as a rendered page.
**Example:**
```markdown
<!-- Before: relative path — ExDoc warns "unresolvable reference" -->
[v1.31 proof bundle](../.planning/phases/144-readme-evaluator-lane-docs-proof/144-VERIFICATION.md)

<!-- After: absolute GitHub URL — ExDoc treats as external link, no warning -->
[v1.31 DEMO-SHOWCASE proof bundle (planning-internal)](https://github.com/szTheory/sigra/blob/main/.planning/phases/144-readme-evaluator-lane-docs-proof/144-VERIFICATION.md)
```

**Established pattern in this codebase:** `docs/ga-evidence.md` lines 11–13 already use `https://github.com/sztheory/sigra/blob/v0.2.1/...` for tag-pinned `.planning/` links. The new link uses `blob/main/` (unpinned) per D-02 in CONTEXT.md. [VERIFIED: codebase inspection]

### Anti-Patterns to Avoid

- **Using `// eslint-disable-next-line` instead of `_` prefix:** The `_` prefix is the idiomatic solution; ESLint suppression comments are noisy and non-standard for this case.
- **Leaving the `skip_undefined_reference_warnings_on` entry after fixing the link:** The suppression exists only as a workaround. Once the link is absolute, the entry must be removed so the warning gate remains active for future docs.
- **Using a version-tagged URL (e.g., `blob/v0.2.1/`)** for the VERIFICATION.md link: This is a planning-internal artifact not versioned with releases; `blob/main/` is the correct ref.

## Common Pitfalls

### Pitfall 1: Callers Misidentified as Needing Change

**What goes wrong:** The `testInfo` argument in the four test call-sites (lines 115, 132, 148, 160) is passed from the outer `test(...)` callback parameter at line 102. Renaming the *function signature* parameter does not affect callers.
**Why it happens:** Confusion between call-site variable name and function parameter name.
**How to avoid:** Change only line 51 (`testInfo: TestInfo` → `_testInfo: TestInfo`). Lines 102, 115, 132, 148, 160 are untouched.
**Warning signs:** If a plan task includes edits to caller lines, it is wrong.

### Pitfall 2: Wrong URL Casing

**What goes wrong:** Using `sztheory` (all-lowercase) instead of `szTheory` (capital T) in the new GitHub URL.
**Why it happens:** GitHub repo URLs are case-insensitive for navigation but the existing links in `ga-evidence.md` use `sztheory` (lowercase). D-02 locks in `szTheory` (capital T) per Claude's Discretion.
**How to avoid:** Use exactly `https://github.com/szTheory/sigra/blob/main/...`
**Warning signs:** Capital-T consistency with CONTEXT.md D-02 is the arbiter.

### Pitfall 3: Removing the Wrong `mix.exs` Entry

**What goes wrong:** Removing `"docs/ga-evidence.md"` from the `extras:` list (line 220) instead of (or in addition to) the `skip_undefined_reference_warnings_on:` list (line 181).
**Why it happens:** `docs/ga-evidence.md` appears in both lists in `mix.exs`. The `extras:` entry must stay — it makes the file part of the rendered docs. Only the `skip_undefined_reference_warnings_on` entry and its `# Phase 144:` comment above it are removed.
**How to avoid:** Diff carefully. Line 181 (suppression) + line 179 (`# Phase 144:` comment) are removed. Line 220 (`extras:`) is untouched.
**Warning signs:** If `mix docs` no longer renders the ga-evidence page, the wrong entry was removed.

### Pitfall 4: Verification Omission

**What goes wrong:** Skipping `mix docs --warnings-as-errors` after removing the suppression entry — if the link fix was incomplete or the wrong entry removed, the warning fires silently.
**How to avoid:** Run `mix docs --warnings-as-errors` as the phase gate check.
