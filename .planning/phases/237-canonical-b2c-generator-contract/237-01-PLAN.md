## Executable assumptions for the spec-less edge

There is no standalone SPEC/UI-SPEC, so the previously unresolved/unclassified requirement edges are accepted only through these executable predicates:

- **B2C-01 predicate:** the exact D-01 install command succeeds in an assets-enabled PostgreSQL Phoenix app, then warning-free compile, `assets.deploy`, `ecto.create`, `ecto.migrate`, server start, and bounded `curl -sf /` all succeed on that same host.
- **B2C-02 predicate:** the same host adds direct `cloak_ecto`, runs the D-02 Google generator, and contains every named OAuth file and injection before compile/migration/boot is credited.
- **B2C-03 predicate:** feature-owned sentinels for admin, organizations, and passkeys are absent from the generated host across routes, files, migrations, assets/dependencies, and configuration; command flags alone do not satisfy the requirement.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| generator options → generated host | Fixed installer/provider inputs control which privileged, multi-tenant, passkey, and OAuth surfaces are emitted. |
| generated OAuth source → secret storage/config | Generated identity tokens must use the Cloak vault contract, while automation must not introduce or print real provider secrets. |
| shell harness → local filesystem/process/PostgreSQL | The smoke creates disposable applications/databases and starts a bounded local server process that must be cleaned up and must not collide with other runs. |
| local fixture evidence → CI evidence | Fast fixture proof cannot establish assets, PostgreSQL migrations, or root boot; exact-commit local/CI smoke evidence is required. |
