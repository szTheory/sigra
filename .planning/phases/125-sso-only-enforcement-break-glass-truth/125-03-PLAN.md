## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| typed library denial -> example controller/view | The host may translate denial outcomes into copy and redirects but must not weaken the policy decision. |
| generated-host login UI -> user recovery expectations | UI copy must not imply unsupported local-auth methods remain available under SSO-only. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-125-09 | S | `Example.Accounts` / `SessionController` | mitigate | Preserve typed `:sso_required`-style outcomes so the host can route denied users to enterprise sign-in rather than flattening every denial into generic invalid credentials. |
| T-125-10 | E | login/recovery UX | mitigate | Remove or narrow passkey and magic-link break-glass implications so unsupported local methods do not survive as accidental bypasses. |
| T-125-11 | I | reset guidance | mitigate | Use bounded enterprise guidance copy for denied local reset paths without leaking unnecessary account-state detail. |
| T-125-12 | R | example proof surface | mitigate | Add controller tests proving denied vs exempt behavior so future regressions in host translation fail visibly. |
</threat_model>
