<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| verified password -> login success path | A correct password must still be policy-denied before success/audit/session work if the org requires enterprise sign-in. |
| password-reset request/completion -> local recovery | Reset flows must not recreate a hidden local-auth bypass under SSO-only. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-125-05 | E | `Sigra.Auth.authenticate/2` | mitigate | Enforce SSO-only after credential verification but before `auth.login.success` and `session.create`, so valid local credentials cannot bypass org policy. |
| T-125-06 | T | audit/session truth | mitigate | Emit typed denial metadata and keep denied paths from reaching normal success audit/session writes. |
| T-125-07 | E | password-reset flow | mitigate | Gate reset issuance/completion through the same break-glass evaluator so local reset does not become an unintended second-factor bypass. |
| T-125-08 | R | denial semantics | mitigate | Use bounded result atoms rather than controller copy to preserve machine-readable evidence of policy denials. |
</threat_model>
