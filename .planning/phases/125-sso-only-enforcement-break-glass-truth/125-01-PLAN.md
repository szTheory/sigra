<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator settings form -> host policy persistence | Host-owned policy state must remain explicit and durable rather than inferred from UI-only toggles. |
| enterprise connection state -> auth policy state | Connection validity and SSO-only enforcement are adjacent but non-equivalent control planes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-125-01 | T | host auth-policy persistence | mitigate | Use dedicated org policy and exemption records so operators cannot accidentally flip SSO-only by mutating enterprise connection state. |
| T-125-02 | D | organization settings enablement flow | mitigate | Require explicit exempt members before enabling `:sso_required` so the UI cannot create an avoidable operator lockout. |
| T-125-03 | E | break-glass representation | mitigate | Model break-glass as explicit org-user exemptions, not owner role or password-presence heuristics that can silently widen local auth. |
| T-125-04 | R | operator truth | mitigate | Add tests and explicit copy that distinguish connection state, policy state, and password-only break-glass posture so later incidents can reconstruct intent. |
</threat_model>
