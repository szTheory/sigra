<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Workflow evidence -> maintainer decisions | The runbook must translate workflow logs into publish/no-publish decisions without ambiguity. |
| Public registry/docs state -> recovery actions | Recovery decisions depend on current Hex and HexDocs behavior and timing windows, not maintainer memory. |
| Maintainer index pages -> canonical runbook | Router docs must not contradict or duplicate the release matrix, or evidence becomes fragmented. |
| Hotfix reports -> patch/revert/replace decisions | The first-14-day policy must separate release blockers from deferred feature requests under pressure. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-146-06 | Repudiation | `docs/release-runbook-v1-0.md` evidence checklist | mitigate | Require `Gate`, `Release ref`, `Evidence URL or log`, `Reviewer`, `Waiver?`, and `Notes` for every gate row before publish. |
| T-146-07 | Tampering | recovery decision tree | mitigate | Encode `dry-run failure`, `publish failure`, `Hex visibility`, `replace`, `revert`, and `follow-up patch` branches with explicit timing windows and commands. |
| T-146-08 | Information Disclosure | local trusted-machine fallback guidance | mitigate | Keep local publish as fallback only, route default recovery to GitHub Actions, and avoid documenting any token-copying shortcuts. |
| T-146-09 | Repudiation | stale router docs | mitigate | Update `MAINTAINING.md`, `docs/NEXT-STEPS-MANUAL.md`, and `docs/ga-evidence.md` to point at one canonical runbook and remove stale `main`-linked proof routes. |
| T-146-10 | Denial of Service | hotfix triage process | mitigate | Define `P0` through `P3` triage timing and keep deferred feature requests out of the first-14-day release window. |

ASVS Level 1 applies. This plan directly addresses high-severity release-operation threats: incomplete release evidence, recovery mistakes after failed dry-run/publish, and manual-only publish/hotfix sign-offs that would otherwise rely on tribal knowledge.
