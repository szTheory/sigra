# Phase 261 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**What this phase is.** A value-only re-skin of an existing, build-free design system. Token *names*, `sg-*` classes, `data-testid`s, routes and `Sigra.Branding.Profile` defaults are frozen (ADR 005); only token *values*, the logo and favicon bytes, and the font tokens change, and names are only added. Copy and layout belong to Phase 262; `mix.exs`/ExDoc/README favicon wiring belongs to Phase 263.

**Provenance tags used below.** `[L]` locked in 261-CONTEXT.md. `[B]` dictated by the brand book (`brand/BRAND.md`, `brand/tokens.json`, `brand/brand.json`). `[D]` derived or forced by measurement during this research; the planner may confirm or adjust these, and each is listed again under "Derived decisions to confirm".

**Sources read.** `brand/tokens.json`, `brand/brand.json` (`color.contrastPairs`), `brand/BRAND.md`, `priv/templates/sigra.install/admin/sigra_admin.css` (1723 lines), `priv/templates/sigra.install/admin/components/admin_shell.ex`, `test/example/priv/static/assets/css/app.css`, `scripts/ci/admin-css-conformance.sh`, `test/sigra/install/features/admin_test.exs`, `test/example/priv/playwright/tests/admin-design.spec.ts`, ADR 005. Every contrast figure below was computed with the WCAG 2.x formula from the hex values (the same formula `Sigra.Branding.Contrast.contrast_ratio/2` implements); all 30 ratios recorded in `brand/brand.json` reproduce to within 0.01.

### Where the tokens live (four places) [L]

| # | Block | Selector | Rule |
|---|-------|----------|------|
| P1 | light `:root` | `:root` | Every token. Light values. Theme-invariant tokens (fonts, spacing, radii, motion) live only here. |
| P2 | System dark | `@media (prefers-color-scheme: dark) { :root {...} }` | Every token whose dark value differs from P1. |
| P3 | Explicit Light | `.sg-admin-shell[data-theme="light"], html[data-sg-admin-theme="light"] .sg-admin-shell` | Restates, with the P1 value, every token P2 overrides, so Light wins over a dark OS scheme. |
| P4 | Explicit Dark | `.sg-admin-shell[data-theme="dark"], html[data-sg-admin-theme="dark"] .sg-admin-shell` | Byte-identical declarations to P2 (existing parity assertion in `admin_test.exs`). |

Three invariants the tests must hold (the first exists; the other two are new and cheap) [D]:

1. P2 declarations equal P4 declarations (existing).
2. Every token in P2 is also declared in P3, with the P1 value. Today P3 omits `--sg-color-brand` and `--sg-color-on-brand` because they never varied; they vary after this phase, so P3 must gain them. Without them, an OS-dark machine with the admin set to Light would render Kiln Bright with a white label (2.48:1).
3. A custom property whose value uses `var()` of a theme-variant token must be declared in all four blocks. A `var()` is resolved where it is declared, so a `:root` alias of a theme-variant token stays light inside an explicit-Dark shell. This is why `--sg-elev-inset` is already restated in every block, and why `--sg-focus-ring` (below) must be too.

### Font tokens (additive) [L]

| Token | Default (in `:root`, P1 only) | Opt-in value (documented, not shipped) |
|-------|-------------------------------|----------------------------------------|
| `--sg-font-sans` | `inherit` (the host's typeface) | `'Instrument Sans', system-ui, -apple-system, 'Segoe UI', sans-serif` |
| `--sg-font-mono` | `ui-monospace, 'SF Mono', Consolas, monospace` | `'Red Hat Mono', ui-monospace, 'SF Mono', Consolas, monospace` |

Rules:

- `sigra_admin.css` ships no `@font-face` and the installer ships no binary (the installer has only the `{:eex, src, target}` file kind). [L]
- Application selectors, in the existing `sg-components` layer, no new classes [D]:
  - `.sg-admin-shell { font-family: var(--sg-font-sans, inherit); }`
  - `.sg-admin-shell :is(button, input, select, textarea) { font-family: inherit; }` so controls do not fall back to the UA font.
  - `.sg-code, .sg-admin-shell code { font-family: var(--sg-font-mono); font-variant-ligatures: none; font-feature-settings: "zero"; }` (book: slashed zero, ligatures off). `font-feature-settings: "zero"` is ignored by system mono faces that lack the feature.
  - `font-variant-numeric: tabular-nums` on `.sg-table td, .sg-table th` (book: dense lists always use tabular numerals). `.sg-code` and `.sg-metric__number` already set it.
- Footgun [D]: `--sg-font-sans: inherit` on `:root` is a CSS-wide keyword on a custom property, so the token is effectively "unset", and the usage-site fallback `var(--sg-font-sans, inherit)` supplies the inheritance. The reasoning is subtle, so the oracle is a computed-style probe in a real browser, not the reasoning: with default tokens, the computed `font-family` of `.sg-admin-shell`, of a `.sg-btn`, an `input`, and `code.sg-code` (mono) must equal the host body font (sans) and the system mono stack. If the probe fails, drop the `, inherit` fallback and use `font-family: var(--sg-font-sans)`; both forms are expected to inherit.
- Glyph coverage (measured on `brand/assets/fonts/web/*.woff2`, Latin subsets): Instrument Sans covers `←`, `→`, `×`, em/en dash, ellipsis, curly quotes, bullet; it lacks U+00B7 (middle dot, 2 uses in admin markup), which falls back per glyph to the next stack family. Red Hat Mono has no arrows (U+2190, U+2192), so no `←` or `→` may appear inside `.sg-code` or `code`; a grep test over admin markup asserts this. Instrument Sans ships `tnum`, `liga`, `case`; Red Hat Mono ships `zero`.

### Split

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Paper `#F7F3EE` / Char `#17120F` (`--sg-color-subtle`) | Page background |
| Secondary (about 22-30%) | White `#FFFFFF` / Char Surface `#221B17` (`--sg-color-panel`) | Panels, table surface, form fields |
| Accent (5-10%) | Kiln `#C2410C` / Kiln Bright `#F08A55` (`--sg-color-brand`); Kiln Deep `#9A3412` light / Kiln Bright dark (`--sg-color-brand-strong`) for text-grade accent | See reserved list |
| Destructive | `--sg-color-risk` kept: `#B42318` light / `#F8A39C` dark | Destructive actions and risk notices only |

Book proportions are 60 / 22 / 9 (text) / 5 (Kiln) / 4 (lines); the template's three-way split is mapped onto them. [B]

Accent reserved for [B]:

1. The one primary button per screen (`.sg-btn--primary`).
2. The logo square (inside the SVG files).
3. The 8px square before the current tab's name and the 2px rule on the selected row (`--sg-color-selected-edge`).
4. Text-grade accent: links, the focus ring and the current tab label use `--sg-color-brand-strong` (Kiln Deep light, Kiln Bright dark), never raw Kiln as small text on Char.

Never: Kiln as small text on Char; Paper Line as the only edge of a control (use Control Edge); a status color as the only way to tell a status. [B]

Legacy accent uses retained this phase (layout is Phase 262): `.sg-nav-link.active` fill in `app.css`, the theme-switch active segment (`--sg-logo-rail-accent`). Both are re-measured by the contrast test (see "Derived and state pairs").
