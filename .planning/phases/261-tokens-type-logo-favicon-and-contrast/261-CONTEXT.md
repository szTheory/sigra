# Phase 261: Tokens, Type, Logo, Favicon and Contrast - Context

**Gathered:** 2026-11-15
**Status:** Ready for planning

<domain>
## Phase Boundary

Sigra's own surfaces carry the Kiln visual identity (token values, type, logo, favicon) in Light and Dark. Every `--sg-*` token name, class, `data-testid`, route and `Profile` default stays unchanged (frozen list, ADR 005). Values change, names are only added. Contrast is proven over the implemented CSS (ExUnit) and the real DOM (axe plus a non-text helper). Requirements BTOK-01 to BTOK-08. Out of scope: `mix.exs`/ExDoc favicon wiring, README and the `architecture_guides_contract_test` favicon pin (Phase 263), `Profile`/`Config` defaults, `--sigra-auth-*` and `sigra_auth.css` host-default fallbacks, copy and layout changes (Phase 262).

</domain>

<decisions>
## Implementation Decisions

### Token value migration (BTOK-01, BTOK-08)
- One reviewed old-to-new table, light and dark, committed in the phase directory and applied by hand to `priv/templates/sigra.install/admin/sigra_admin.css`, mapping each existing `--sg-*` color token to the nearest `brand/tokens.json` value (neutrals: subtle to Paper/Char, ink to Soot/Chalk, muted to Muted Soot/Muted Chalk, line to Paper Line/Char Line, panel dark to Char Surface). Tokens with no book equivalent (`risk`, `info`, `brand-soft`, `brand-fill-*`, `panel-alt`) keep their current value unless a contrast pair forces a change; each such row says "kept, no book equivalent". — **Reversibility:** costly — a visible change reaching every adopter's admin on `mix deps.update`, covered by the minor-release policy (ADR 005 decision 3).
- Dark `--sg-color-brand`, `--sg-color-brand-strong` and `--sg-color-brand-solid` become Kiln Bright (#F08A55); dark `--sg-color-on-brand` becomes Char (#17120F), because white on Kiln Bright is 2.48:1. Every color change is made in all four places (light `:root`, `@media (prefers-color-scheme: dark)`, explicit light, explicit dark) and the existing admin_test parity assertion stays green. The armed danger button and `app.css` `.sg-nav-link.active`, which also read `on-brand`, are re-checked by the contrast test. — **Reversibility:** costly — same blast radius as the row above.
- Weight tokens map regular 450 to 400, medium 600 and semibold 700 unchanged, bold 800 to 700 (book allows 400/600/700 only); names unchanged.
- Additive tokens (names are new, so the ratchet passes): `--sg-status-active|unconfirmed|locked|deleting|suspended` (text color, light/dark), `--sg-color-selected` and `--sg-color-selected-edge` (selected-row ground and 2 px edge), `--sg-color-current-tab`, `--sg-color-sunken` (table header), `--sg-color-control-edge`. Each gets a row in `guides/reference/admin-token-reference.md` (the completeness script counts documented against `:root` names). No new `sg-*` classes unless CSS defines them (css-undefined-classes shrink-only baseline).
- `sigra_auth.css` is not edited. Rail/Ember vocabulary retires in docs only; `--sg-logo-rail-*` names stay.
- The template CSS is copied by hand to `test/example/priv/static/assets/sigra_admin.css`, and the golden tree copy is regenerated by exactly one `MIX_ENV=test mix sigra.fixture.rebless_golden` under pinned `phx_new 1.8.8`, run after the template, example copy, logo SVGs and docs are final. Rebless output is reviewed per directory.
- No raw hex outside token blocks and no raw px (admin-css-conformance CHECK 2/3): hover/focus/disabled colors are tokens or `var()` expressions.

### Fonts (BTOK-06)
- `--sg-font-sans` defaults to `inherit` (the host's typeface); `--sg-font-mono` defaults to a system mono stack. The book stack (Instrument Sans, Red Hat Mono) is documented as opt-in. `sigra_admin.css` gets no `@font-face` and the installer ships no binary (installer has only the `:eex` file kind). — **Reversibility:** costly — a token name and its documented default become public once released.
- Sigra-owned surfaces (the example app admin and design gallery) self-host `brand/assets/fonts/web/{sans,mono}.woff2` plus the two OFL texts, copied (never edited in `brand/`) into `test/example/priv/static/assets/fonts/`, with `@font-face` in a Sigra-owned example stylesheet scoped to the admin shell, not in the demo's `vt-*` `app.css`. The Tasklane demo keeps its own Fraunces/Inter on host-facing pages (ADR 005 decision 15). The Playwright guard that asserts `"Space Grotesk"` (`admin-design.spec.ts`) is rewritten to the new admin face. Never a CDN, never base64.

### Logo and favicon (BTOK-04, BTOK-05)
- The v2 lockup replaces the SVG bytes under the frozen filenames `admin/sigra-logo-primary.svg` and `-dark.svg` (installer targets unchanged), each with an inline `<title>`. The shell `<img>` elements keep `alt=""` inside the labelled link (`aria-label="Sigra admin overview"`), which is the accessible name and avoids a duplicate announcement; the name is carried by SVG `<title>` and the link label. The new lockup is about 2.47:1, so the image width/height and the `.sg-brand-mark__lockup` box are resized to respect the book's 96 px minimum width (current box is 84 px). The template and example `admin_shell.ex` stay in parity.
- Tests pinning the old logo (`admin_shell_test.exs` viewBox and "Space Grotesk v2.0", `catalog.ex`, `before/MANIFEST.json` sha256, golden `STDOUT.txt`, `admin-theme.spec.ts`) are updated in the same change set as the SVGs. The `before/` catalog snapshot is the pinned "before" and is not regenerated; the catalog diff test is updated to expect the known after-state.
- Rail files in `test/example/priv/static/images/`: `logo.svg` (Phoenix glyph) is removed if grep proves it unreferenced; `rail-accent-mark{,-dark}.svg` are used by the demo brand preset (`Example.Demo.Branding`) and a Playwright spec, so the planner must verify each by grep and either repoint the demo preset to the demo's own mark and delete them, or keep and document them as demo-owned. Do not delete anything referenced. `tasklane-mark.svg` stays.
- Favicon: the book's `icon/favicon.svg` and `favicon.ico` (copied, unchanged) are served from the example for Sigra-owned pages (admin and design gallery) only, via an admin-scoped head link and `favicon.svg` added to `static_paths`; host-facing Tasklane pages keep the demo identity. No `mix.exs` or ExDoc wiring.
- A 16/32 px render check is automated (render the favicon at both sizes and assert it is non-blank and distinct from the old mark). The single human gate (logo distinctness, 16-24 px legibility) is satisfied by one contact sheet handed to the owner at phase end; all automation proceeds without waiting for it.

### Contrast proof (BTOK-02, BTOK-03)
- A new shared test helper under `test/support/brand/` parses the implemented CSS (follows `var()` chains, covers the `@media` dark block and both explicit theme blocks, composites `rgba()` over its ground, resolves simple `color-mix(in srgb, ...)`), reusing and consolidating the private extractors in `admin_test.exs`. `test/sigra/brand/` gets an ExUnit test evaluating the 30 pairs from `brand/brand.json` (15 ids x light/dark) with `Sigra.Branding.Contrast.contrast_ratio/2` plus hover/focus/disabled states, a printout of the thinnest margins, and a planted bad color that must fail (positive control). It runs in `mix test`; no new script, workflow or CI job (process budget).
- axe: the existing gate (`assertNoAxeViolations`, design gallery, light/mobile/dark projects) stays and additionally records the `incomplete` count from the same `analyze()` result as a test annotation; `incomplete` is never counted as a pass. A ~20-line non-text helper checks focus ring, control edge and logo square at 3:1 in both themes.
- Known first red: the dark primary button label; resolved by the on-brand decision above.

### Pinned assertions (BTOK-07)
- The ~10 pinned token/hex assertions (`admin_test.exs` :429, :482-484 and neighbors; `admin-generated.spec.ts` :393 and :165-182; `admin-theme.spec.ts` :1418-1446) are rewritten to read expected values from the template CSS or `brand/tokens.json` rather than literals. `architecture_guides_contract_test` lines 221-222 (favicon hex pin) are left alone: Phase 263 owns them. `admin-token-reference.md` is re-pointed at `brand/tokens.json` names and old values/ember raw-token names are corrected.

### Gates
- Frozen-surface ratchet, privacy grep (pushed diff incl. SVG metadata, planted-failure control) and process budget (no new workflow/job/receipt; no `.github` edits) hold. The PNG-compare lanes remain parked; never recapture on darwin; the `impersonation-banner` canary is never allowlisted. `ci-gate` must be green on the first token PR, so CSS, example copy, pins, docs and the single rebless land as one coherent change set. The fresh-host run (`phx_new 1.8.8`, `mix sigra.install`, boot, real login, admin in Light/Dark/System) is automated through `scripts/ci/admin-acceptance-smoke.sh` and its screenshots are looked at. `MIX_ENV=test mix ci` is green before any push.
