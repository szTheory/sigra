# Phase 10.1.1 Plan 02: Example App Bug Fixes (B5 + B7) Summary

**Wired confirmation email delivery into RegistrationLive (B5/D-05) and fixed /users/sudo KeyError by form-ifying the password input (B7/D-08), with installer templates mirrored.**

## Performance

- **Duration:** ~12 min
- **Tasks:** 2
- **Files modified:** 6

## Accomplishments

- **B5 fix:** Registration success branch now calls `Example.Accounts.deliver_user_confirmation_instructions/2` with a `fn token -> url(socket, ~p"/users/confirm/#{token}") end` builder. Both `{:ok, :sent}` and `{:error, :already_confirmed}` are swallowed to preserve enumeration safety. The Phase 3 stub comment is gone.
- **B7 fix:** `sudo_controller.new/2` now assigns `form: Phoenix.Component.to_form(%{"password" => ""}, as: "sudo")`. `sudo_html.ex` switches `<.form for={%{}}>` to `<.form :let={f} for={@form}>` and drives the password input via `field={f[:password]}` instead of a naked `name="sudo[password]"`. Root cause: `core_components.ex` declares `attr :value, :any` with no default, so rendering `<.input>` without `:field` or `:value` raised `KeyError` at render.
- **Installer template sync:** The same two edits landed verbatim (modulo EEx bindings) in `priv/templates/sigra.install/registration_live.ex`, `sudo_html.ex`, and `sudo_controller.ex`, so `mix sigra.install` on a fresh host app produces identical behavior. The phase 10.1.1-08 drift-guard test continues to enforce this going forward.
