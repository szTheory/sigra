# Summary

Plan 10.1.1-08 closes Phase 10.1.1 by renaming the existing example app smoke
job for naming consistency (`example_app_smoke` → `example_unit_smoke`), adding
a branch protection runbook section, and completing the human-verify checkpoint
by landing live branch protection on `main` in the szTheory/sigra repo.

The literal plan scope (rename + docs) was finished in two commits (`40b6d2f`,
`a47ccec`) but the **real work** of this plan happened during the first cold
CI run after push to a new remote, which uncovered ~15 latent bugs across the
example app, installer templates, and library. All fixes landed together in
PR #5 (squash-merged as `3d24be8`).

## What verified

All five CI jobs ran green on PR #5's final push and are now the required
status checks on `main`:

| Job | Purpose |
|-----|---------|
| `Library tests` | ExUnit + doctests for the library itself |
| `Example unit smoke (ExUnit + ConnTest)` | Example app unit suite (was `example_app_smoke`, renamed in this plan) |
| `Install smoke (fresh phx.new + sigra.install)` | Clean install drill: fresh Phoenix app → `mix sigra.install` → compile clean |
| `Example HTTP smoke (boot + curl critical routes)` | Six-route curl harness against a running example app |
| `Example Playwright smoke (full lifecycle)` | Browser golden-path: register → confirm → login → sessions → sudo → MFA enroll |

## What's NOT done (deliberately)

- The Playwright spec does not exercise MFA-as-login-challenge — the example
  uses step-up auth (sudo mode) instead, and rewriting the login flow to
  require TOTP on every password login is out of scope for this phase. The
  current spec verifies MFA state persistence across logout/login, which is
  the correct end-state for the step-up pattern.
- The 17-hour `sigra-uat-postgres` container from earlier UAT work was stopped
  during `act` setup (port 5432 collision) and not automatically restarted.
  If you need UAT again, `docker start sigra-uat-postgres` brings it back.
- The PR branch has merged so the `--reuse` act issue with ETXTBSY on the
  OTP binary is moot until the next iteration. Next time `act -j <job> --reuse`
  is run, kill any leftover beam.smp processes in the container first (or
  drop --reuse and accept cold-start cost).

## Followups to consider

- Bump `actions/cache` and `actions/checkout` when they publish Node.js 24
  variants — current pins are on Node 20 which GitHub deprecates Sept 2026.
- Add a Playwright browser cache step (keyed on
  `test/example/priv/playwright/package-lock.json`) so `npx playwright install`
  can skip the ~8-minute chromium download on cache hits.
- Sigra.MFA could grow an `is_enrolled?/3` that reflects on schema fields so
  the consumer's schema doesn't have to include `updated_at` AT the library
  level.
