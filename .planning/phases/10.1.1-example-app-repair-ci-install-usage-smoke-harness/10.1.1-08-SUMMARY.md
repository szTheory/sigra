## Decisions Made

- **Display names, not job keys, in required-status-checks.** Discovered during the Task 3 checkpoint: a second ruleset had been created by the operator using job keys (`library_tests`, `example_unit_smoke`, etc.), but those would never match because GitHub Actions reports check contexts using the `name:` field. The original ruleset (using display names like `"Example unit smoke (ExUnit + ConnTest)"`) was the correct one and was kept.
- **Deleted the duplicate ruleset.** Rather than edit the new ruleset to use display names, deleting it was cleaner — two rulesets on the same branch layer additively and create confusion.

## Deviations from Plan

None — plan executed as written. The checkpoint in Task 3 surfaced a real configuration issue (duplicate ruleset with wrong contexts) which is exactly what the checkpoint was designed to catch.

## Issues Encountered

- **Duplicate rulesets at checkpoint time.** When the operator went to add required checks, they created a new ruleset alongside the pre-existing `main` ruleset. Both were set to `enforcement: active`, which would have layered. Resolved by `gh api` introspection → confirming the old ruleset used correct display names → deleting the new one.
