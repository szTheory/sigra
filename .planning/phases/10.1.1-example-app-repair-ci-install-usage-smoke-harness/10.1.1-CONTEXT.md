# Phase 10.1.1: example-app repair + CI install/usage smoke harness — Context

**Gathered:** 2026-04-10
**Status:** Ready for planning

<domain>
## Phase Boundary

Close the gap between "library tests green" and "app actually works in a browser." Two deliverables:

1. **Repair `test/example/`** — fix the 5 remaining integration bugs from the v1.0 UAT session (B5–B9), the getting-started.md doc drift, the missing `doc/llms.txt`, and the RUNBOOK brew-postgres collision note.
2. **Add a CI install/usage smoke harness** — four parallel CI jobs that would have caught the B1–B9 class of bugs automatically, so the next UAT session doesn't re-discover the same failures.

B1–B4 were fixed in-session and committed as `58b7122` (JS bundle, LiveView socket, `fetch_current_scope`, `live_session` wiring) — not in scope here.

**Out of scope:** library-layer behavior changes beyond what's needed to unblock the example app and the generator templates. Human UAT items in phases 04/05/06/08 (MFA backup codes, real Google OAuth, etc.) remain their own follow-up except where the Playwright smoke naturally exercises them.

</domain>

<decisions>
## Implementation Decisions

### Bug fix scope (all in-scope)

- **D-01:** Fix all 5 remaining UAT bugs: B5 (registration confirmation email stub), B6 (dual session stores), B7 (`/users/sudo` `KeyError`), B8 (audit `actor_id` type mismatch), B9 (LiveView login form submit swallowed).
- **D-02:** Fix getting-started.md doc drift in the same phase: `/users/log-in` → `/users/log_in` and `/users/log-out` → `/users/log_out`; `UserRegistrationLive` → `RegistrationLive`; `plug :fetch_current_scope_for_user` → `plug :fetch_current_scope`; `on_mount :require_authenticated` → `on_mount :ensure_authenticated`.
- **D-03:** Investigate and fix missing `doc/llms.txt` from `mix docs`. Per stack notes, ex_doc 0.40.1 is supposed to generate it automatically. Either wire the missing config or document the workaround.
- **D-04:** Update `scripts/uat/RUNBOOK.md` with the brew `postgresql@14` port-5432 collision case discovered during UAT (stop brew service before `scripts/uat/up.sh`, restart after).

### B5 — confirmation email wiring

- **D-05:** Wire `Sigra.Auth.request_confirmation/2` (already exists from phase 3) into the success branch of `RegistrationLive.handle_event("save", ...)`. Remove the `# Phase 3 will send confirmation email here` stub comment. Confirmation link lands in `/dev/mailbox`, restoring the getting-started.md step 3 flow. Library-level change (auto-sending from `Sigra.Auth.register_user/2`) is rejected — host apps should keep the wire explicit.

### B6 — session store unification

- **D-06:** Rip out phx.gen.auth's `user_tokens` store from `test/example/` end-to-end. `ExampleWeb.UserAuth.log_in_user` must call `Sigra.Auth.create_session/4` (not `Example.Accounts.generate_user_session_token`), and `Example.Accounts.list_sessions/1` + `Auth.SessionLive` already read from `user_sessions`. Drop the legacy `Example.Accounts.generate_user_session_token`, `delete_user_session_token`, and the `user_tokens` schema/migration if no other call sites remain.
- **D-07:** If `mix sigra.install` templates (`lib/mix/tasks/sigra.install.ex`) still emit phx.gen.auth-shaped session code, update the templates so fresh installs land on Sigra's session store by default. This is the real DX bug B6 is surfacing.

### B7 — sudo template

- **D-08:** Fix the assign/field mismatch in `test/example/lib/example_web/controllers/auth/sudo_html.ex`. Template references a form field that isn't in controller assigns — either add the missing assign in the controller or switch the template to the correct field name. Must route through `Sigra.Auth.sudo_*` API, not re-implement.

### B8 — audit/user PK type mismatch

- **D-09:** Switch `test/example/` `users.id` (and every FK referencing it) from `bigint` to `uuid`. This requires updating the Sigra-generated migrations (`20260410125242_create_sigra_auth_tables.exs`, `20260410125244_create_audit_events.exs`), the user schema, MFA/session/identity FK columns, and seed data.
- **D-10 (SCOPE EXPANSION — planner must split cleanly):** Flip the **library default** to uuid. Update `lib/mix/tasks/sigra.install.ex` and `lib/mix/tasks/sigra.gen.oauth.ex` migration templates so fresh `mix sigra.install` runs emit uuid FKs by default. Update all guides (`guides/introduction/getting-started.md`, `guides/introduction/installation.md`, any recipes that show migrations) to reflect the uuid default.
- **D-11:** This phase does NOT add a `--primary-key bigint` installer flag. If a host app still needs bigint, document the manual migration edit. A real installer flag is deferred to its own phase.

### B9 — password login form

- **D-12:** Use the **hybrid pattern**: `LoginLive` renders the password form, but the form's `action` points at a plain Phoenix controller (`POST /users/log_in`) that runs `Sigra.Auth.authenticate_user/2` + `UserAuth.log_in_user/2`. This matches what Phoenix 1.8 `phx.gen.auth` actually generates and dodges the LiveView form-submit interception entirely. `phx-update="ignore"` becomes unnecessary.

### CI smoke harness — four parallel jobs

- **D-13:** Four separate GitHub Actions jobs in `.github/workflows/ci.yml`, **all required for PR merge**:
  1. **`install_smoke`** — fresh `mix phx.new tmp_app --no-dashboard`, then `mix sigra.install` inside it, then `mix compile --warnings-as-errors`. Catches generator output regressions (template drift, wrong migration types, missing files).
  2. **`example_http_smoke`** — boot `test/example` against the services Postgres, curl the critical routes (`/`, `/users/register`, `/users/log_in`, `/users/sudo`, `/dev/mailbox`, `/users/sessions`) and assert non-500. Fast, no browser deps.
  3. **`example_playwright_smoke`** — headless browser runs the full lifecycle (see D-14). Requires Node + Playwright install step.
  4. **`example_unit_smoke`** — keep the existing `mix test --include example_app` job as-is. ConnTest coverage stays.
- **D-14:** Playwright golden path (full lifecycle): **register → confirm via /dev/mailbox → login → sudo re-auth → session list → MFA enrollment (TOTP) → MFA challenge → logout**. This catches B1, B2, B5, B6, B7, B9 simultaneously and exercises phase 6 MFA enrollment (partial credit toward that phase's UAT backlog). TOTP code generation happens inside the harness via a node otp library.
- **D-15:** No `continue-on-error` — playwright is required. If flakes emerge, fix them at the root cause, not by masking the signal.

### Claude's Discretion

- Exact `doc/llms.txt` fix (config change vs `mix docs.llms` step) — investigate, pick the simpler path.
- Sudo template fix (rename assign vs add field) — whichever keeps the controller API cleaner.
- Playwright test framework choice (Playwright Test vs a thin custom runner) — Playwright Test is the default; no reason to deviate unless a real blocker appears.
- How the `install_smoke` job caches the fresh `mix phx.new` app between runs to keep wall-clock acceptable.
- Playwright TOTP library (`otplib`, `otpauth`, etc.) — any maintained npm package is fine.

</decisions>

<code_context>
## Existing Code Insights

### Reusable assets
- `Sigra.Auth.create_session/4`, `Sigra.Auth.request_confirmation/2`, `Sigra.Auth.authenticate_user/2` — all exist from phases 2–4. The repair work is wiring, not new library code.
- `.github/workflows/ci.yml` already has a `services: postgres` block and the `erlef/setup-beam` step pinned to OTP 27.3 / Elixir 1.18.4. The three new jobs reuse this pattern.
- `scripts/uat/up.sh` / `scripts/uat/RUNBOOK.md` — already boot the example app against docker postgres. Some logic is reusable for the `example_http_smoke` job's local boot.

### Established patterns
- Library functions take the host's `user` struct or id and return `{:ok, ...}` / `{:error, ...}`. Example app's `UserAuth` module is the integration seam — repairs stay inside this module where possible.
- Phoenix 1.8 `phx.gen.auth` uses a LiveView for the login *page* but the login *form action* is a plain controller POST. D-12 realigns `test/example` to this convention.
- `erlef/setup-beam` actions are pinned to full commit SHAs with Dependabot updating — new CI jobs must follow the same pinning discipline.

### Integration points
- `ExampleWeb.UserAuth` is the single module where phx.gen.auth legacy code touches Sigra code — D-06 unification happens here.
- `mix sigra.install` template output is what the repair work is ultimately proving out — every fix in `test/example` should have a matching template fix if the template is also broken (D-07, D-10).
- The Playwright harness needs a way to read from `/dev/mailbox` to extract the confirmation link — Swoosh's dev mailbox exposes HTML pages; scrape or use the JSON endpoint.

</code_context>

<specifics>
## Specific Ideas

- "The example app is what `mix sigra.install` on a fresh `mix phx.new` is supposed to produce, and if this one is broken, so is the generator output." — UAT-RESULTS.md §Executive summary. This is the load-bearing principle: every `test/example` fix must be checked against the installer templates.
- The library default PK flip to uuid is the user's call and represents a meaningful v1.0 posture change. Planner must treat this as its own plan within the phase (not a one-line edit) and consider migration guidance for any beta users who ran `mix sigra.install` before the flip.
- Playwright flow specifically includes MFA enrollment end-to-end so phase 6 partially clears its human-UAT backlog for free. If MFA flow is brittle, do not downgrade — fix the brittleness.
- `install_smoke` is expensive (fresh hex fetch every run); caching strategy is Claude's discretion, but the job stays on PR (not nightly-only).

</specifics>
