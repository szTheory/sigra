## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous user → `/users/register` | Untrusted POST, Phoenix CSRF token on form; registration creates a user row |
| authenticated user → `/users/sudo` | Authenticated session, Phoenix CSRF, re-auth gate before sensitive ops |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10.1.1-02-01 | Information disclosure | deliver_user_confirmation_instructions enumeration | accept | The existing helper already returns `{:ok, :sent}` or `{:error, :already_confirmed}` — both are swallowed by this plan so the LiveView flow never leaks "already registered" vs "new user" to the caller. Enumeration safety is preserved (UAT-RESULTS confirms the handle_event branch always flows through `trigger_submit: true` regardless). |
| T-10.1.1-02-02 | Spoofing | Confirmation token generation | mitigate | Unchanged from phase 3 — `Sigra.Auth.generate_confirmation_token/3` is HMAC-signed and expires per config (default 48h). This plan only wires a call, no crypto changes. |
| T-10.1.1-02-03 | Tampering | `/users/sudo` POST CSRF | mitigate | The `:browser` pipeline includes `plug :protect_from_forgery`; the `<.form>` component emits a `_csrf_token` hidden input. Changing `for={%{}}` → `for={@form}` does not remove this — `<.form>` always injects the CSRF field when used under a controlled connection. Verified by reading Phoenix.Component.form/1 docs. |
| T-10.1.1-02-04 | Denial of service | Sudo page 500 crash (B7) | mitigate | Fixing the KeyError removes a trivial crash-on-GET DoS. No rate-limiting change needed. |
| T-10.1.1-02-05 | Information disclosure | Sudo form password field echoed in value | mitigate | The controller builds `to_form(%{"password" => ""}, as: "sudo")` — empty string, not a real password. The type=password input is never re-rendered with a value from a server round-trip. Verified by the controller new/2 only being GET-serving; errors re-render new with fresh empty form. |
</threat_model>
