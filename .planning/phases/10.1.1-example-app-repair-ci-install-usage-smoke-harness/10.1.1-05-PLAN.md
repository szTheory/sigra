<objective>
Flip test/example/ to uuid primary keys end-to-end (D-09), flip the library installer default to uuid (D-10), and update guides to reflect the new default (D-10 + D-02 residual). This is the biggest plan in the phase — it spans migrations, schemas, seeds, installer task code, every EEx schema template, and guide copy. It explicitly does NOT add a `--primary-key bigint` flag (D-11 — deferred).

Purpose: B8 is a concrete type mismatch — `users.id` is bigint but `audit_events.actor_id` is binary_id, causing every audit insert referencing a user to silently fail. The root fix is unifying on uuid. The example app has no production data, so the migration is a clean drop-and-recreate. The library default flip makes every new `mix sigra.install` run emit uuid by default — the real DX fix that stops future users from hitting B8.

This plan DEPENDS on plan 03 (B6 session store unification) because the `audit_events` row is emitted as a side effect of `Sigra.Auth.create_session`. Without the B6 fix, logins don't go through Sigra's create_session and no audit row is written at all — the B8 "assert count > 0" test would fail for the wrong reason.
Output: uuid everywhere in test/example and the installer default; audit_events receives rows on login; fresh mix sigra.install output compiles against a binary_id-default schema; guides describe uuid as the default.
</objective>
