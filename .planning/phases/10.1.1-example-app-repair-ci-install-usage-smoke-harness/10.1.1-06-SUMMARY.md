## Decisions Made

- **`--yes` as documented no-op (vs adding real prompt plumbing).** `rg 'Mix\.shell\(\)\.yes\?|IO\.gets|Mix\.shell\(\)\.prompt|:interactive' lib/mix/tasks/sigra.install.ex` returned zero matches, so the installer is already non-interactive. The cleanest move is: accept the flag, document it, discard it. Future prompt sites will need to honor `opts[:yes]` but none exist today.
- **Parallel jobs (no `needs:`).** Keeps wall clock bounded at `max(library_tests, example_app_smoke, install_smoke, example_http_smoke)` rather than serialising. install_smoke is the slowest of the four (~3-5 min first run, 1-2 min cached) so adding a `needs:` would dominate PR feedback time.
- **MIX_ENV=dev for example_http_smoke.** `/dev/mailbox` in `test/example/lib/example_web/router.ex` is gated on `Application.compile_env(:example, :dev_routes)` which is only true in dev/test. Using dev matches the "developer running `mix phx.server` locally" scenario and keeps the router identical to what a human sees during manual UAT.
- **Anchor-based mix.exs patch over Elixir AST rewrite.** A targeted `String.replace(content, "      {:phoenix,", ..., global: false)` is ~5 lines and has no dependencies; an AST-based patch would pull in `Sourceror` or similar. The tradeoff is fragility if `mix phx.new` reshapes the deps list — mitigated by a loud `System.halt(1)` when the anchor is not found.
- **5xx-only failure criterion for http-smoke.** Routes like `/users/sudo` and `/users/sessions` are behind `:require_authenticated` and will 302 to `/users/log_in` for an unauthenticated curl. Those 302s are the expected success path at the HTTP layer (Playwright in plan 07 covers actual authenticated navigation). Gating on `code >= 500` avoids false positives.
