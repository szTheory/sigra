<objective>
Fix B9 (LiveView login form submit swallowed) by replacing `ExampleWeb.LoginLive` with a plain Phoenix controller + HEEx template (`SessionController.new/2` + `SessionHTML.new/1`). This is the canonical Phoenix 1.8 `phx.gen.auth` shape — the login *page* is not a LiveView, so there is no `phx-submit` interception and the browser issues a real HTTP POST to the controller action.

Purpose: LiveView's `<.form>` component registers `phx-submit` by default. Even with `phx-update="ignore"`, the submit event is intercepted and no HTTP POST leaves the browser — confirmed in UAT as B9. The fix is structural: move the login page out of LiveView entirely. The `priv/templates/sigra.install/login_html.ex` template already exists and maps almost 1:1 to the replacement; the installer just needs to emit it by default.
Output: `GET /users/log_in` renders via SessionController.new/2 + SessionHTML.new/1; LoginLive module deleted; router updated; ConnTest locks the behavior; installer templates default to plain-controller login.
</objective>

```elixir
defmodule ExampleWeb.SessionHTML do
  @moduledoc """
  Controller-mode login templates (non-LiveView).

  Per D-12, the login page is a plain controller + HEEx template rather than
  a LiveView. This dodges Phoenix.Component.form/1's default phx-submit
  registration which was swallowing the browser form submit (B9).
  """
  use ExampleWeb, :html

  def new(assigns) do
    ~H"""
    <div class="mx-auto max-w-sm">
      <.header>
        Log in
        <:subtitle>
          Don't have an account?
          <.link navigate={~p"/users/register"} class="font-semibold text-brand hover:underline">
            Sign up
          </.link>
          for an account now.
        </:subtitle>
      </.header>

      <%!-- Magic link section --%>
      <.form :let={f} for={@magic_link_form} id="magic_link_form" action={~p"/users/log_in"} method="post">
        <input type="hidden" name="_action" value="magic_link" />
        <.input field={f[:email]} type="email" label="Email" autocomplete="username" required />
        <.button class="btn btn-primary w-full">
          Send magic link <span aria-hidden="true">&rarr;</span>
        </.button>
      </.form>

      <div class="relative my-6">
        <div class="absolute inset-0 flex items-center"><hr class="w-full" /></div>
        <div class="relative flex justify-center text-sm">
          <span class="bg-white px-2 text-gray-500">or sign in with password</span>
        </div>
      </div>

      <%!-- Password section --%>
      <.form :let={f} for={@form} id="login_form" action={~p"/users/log_in"} method="post">
        <.input field={f[:email]} type="email" label="Email" autocomplete="username" required />
        <.input field={f[:password]} type="password" label="Password" autocomplete="current-password" required />
        <div class="flex items-center justify-between">
          <label class="flex items-center gap-2 text-sm">
            <input type="checkbox" name="user[remember_me]" value="true" class="checkbox" />
            Keep me logged in
          </label>
        </div>
        <.button class="btn btn-primary w-full">
          Log in <span aria-hidden="true">&rarr;</span>
        </.button>
      </.form>
    </div>
    """
  end
end
```

Note: this is a plain HTML page, so the `<.form>` component is still rendered but it is NOT inside a LiveView process. When `<.form>` is used in a dead render (controller render), it does not register `phx-submit` — the form submits normally via the browser. Verified: this is exactly what `phx.gen.auth` generates on Phoenix 1.8. The template produces `<form action="/users/log_in" method="post">` with a CSRF token input but no phx-* attributes.
