2. Create `lib/sigra/oauth.ex` -- the orchestrator (per D-20):

Public API:
- `authorize_url(config, provider, opts \\ [])` -- Resolves strategy via `Strategies.resolve/2`, calls strategy's `authorize_url/1`, overrides state with HMAC-signed version using `Sigra.Token.generate(config.secret_key_base, "sigra-oauth-state", %{provider: provider, nonce: random}, max_age: 900)` per D-16. Returns `{:ok, url, session_params}` where session_params includes `:sigra_state` and any PKCE `:code_verifier`.
- `handle_callback(config, provider, params, session_params)` -- Verifies HMAC state via `Sigra.Token.verify(config.secret_key_base, "sigra-oauth-state", params["state"], max_age: 900)`. If state invalid, returns `{:error, %OAuthError{error_code: :state_mismatch}}`. Then calls strategy's `callback/3`, checks email presence (D-08), delegates to `Callback.process_callback/4`.
- `get_tokens(config, identity_or_id)` -- Fetches identity, checks `token_expires_at`. If expired and `encrypted_refresh_token` exists, calls strategy's token refresh, persists new tokens, returns updated tokens. If no refresh token or refresh fails, returns `{:error, :token_expired}` (per D-27).
- `link_provider(config, user, provider_info, opts)` -- Creates new identity for user. Emits `[:sigra, :oauth, :link, :stop]` telemetry. Sends link notification email (D-07).
- `unlink_provider(config, user, provider, opts)` -- Checks user has alternative auth method (password or other provider) per D-03. If last provider and no password, returns `{:error, :last_provider}`. Otherwise deletes identity. Emits `[:sigra, :oauth, :unlink, :stop]`. Sends unlink notification email (D-07).

State HMAC implementation:
```elixir
defp generate_state(secret_key_base, provider) do
  nonce = :crypto.strong_rand_bytes(16) |> Base.url_encode64(padding: false)
  Sigra.Token.generate(secret_key_base, "sigra-oauth-state", %{
    provider: to_string(provider),
    nonce: nonce
  }, max_age: 900)
end

defp verify_state(params, session_params, secret_key_base) do
  state = params["state"] || params[:state]
  case Sigra.Token.verify(secret_key_base, "sigra-oauth-state", state, max_age: 900) do
    {:ok, _data} -> :ok
    {:error, _} -> {:error, %Sigra.Error.OAuthError{provider: nil, error_code: :state_mismatch}}
  end
end
```

3. Create `lib/sigra/oauth/callback.ex` (per D-20):

`process_callback(config, provider, user_info, token)`:
- Step 1: Look up identity by `(provider, user_info["sub"])` via `config.repo.get_by(identity_schema, provider: provider, provider_uid: uid)` (D-32)
- Step 2a: If identity found, check if identity's user matches the email. If provider_uid maps to identity A but user_info email matches different user B, return `{:error, %OAuthError{error_code: :email_mismatch}}` (D-09). Otherwise update identity fields (D-31: provider_email, provider_name, provider_avatar_url, tokens, last_used_at), log in user, return `{:ok, :logged_in, user, session}`.
- Step 2b: If no identity, look up user by email `config.repo.get_by(user_schema, email: user_info["email"])`.
  - If user found: return `{:link_confirmation_required, %{provider: provider, provider_uid: uid, email: email}}` (D-01, D-02).
  - If no user: register new user with `confirmed_at: DateTime.utc_now()` if `trust_provider_email` is true and `user_info["email_verified"]` is true (D-42). Create identity. Create session with `type: config.oauth.session_type` and metadata `%{auth_method: :oauth, provider: provider}` (D-48). Return `{:ok, :registered, user, session}`.
- Handle no-email case: if `user_info["email"]` is nil or empty, return `{:error, %OAuthError{error_code: :no_email}}` before any lookup (D-08).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OAuth callback params | URL params from provider redirect -- untrusted, may be tampered |
| OAuth state param | HMAC-signed by Sigra, verified before processing |
| Provider user info | Data from provider API -- semi-trusted but validated |
| Session store | Database -- trusted internal boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-06 | Spoofing | OAuth state | mitigate | HMAC-signed state param with 15-min TTL via Sigra.Token (D-16); state_mismatch error on invalid |
| T-05-07 | Spoofing | Account takeover via email match | mitigate | Email-match linking always requires login confirmation (D-01); no auto-linking |
| T-05-08 | Spoofing | UID/email cross-account | mitigate | Block login when provider_uid maps to identity A but email matches user B (D-09); generic error |
| T-05-09 | Tampering | Identity lookup | mitigate | Match by (provider, provider_uid) only, never email alone (D-32); unique indexes enforce |
| T-05-10 | Denial of Service | Token refresh race | accept | First refresh wins; subsequent attempts use newly stored token (Pitfall 7). Acceptable for v1. |
| T-05-11 | Information Disclosure | Callback errors | mitigate | Generic user-facing messages via safe_message/1 (D-55); detailed logging at :error level |
| T-05-12 | Elevation of Privilege | Link/unlink without sudo | mitigate | Both operations require sudo mode (D-05); check enforced in Sigra.OAuth |
| T-05-13 | Spoofing | Unverified Facebook email | mitigate | Facebook strategy sets email_verified=false; registration with unverified email triggers confirmation flow |
| T-05-14 | Denial of Service | Race on registration | mitigate | Ecto.Multi transaction + unique email index catches concurrent registration attempts (Pitfall 6) |
</threat_model>
