# Phase 5 -- UI Design Contract

> Visual and interaction contract for OAuth and Social Login generated templates. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Phoenix 1.8 built-in components + Tailwind CSS) |
| Preset | not applicable |
| Component library | Phoenix core components (`<.header>`, `<.form>`, `<.input>`, `<.button>`, `<.link>`) |
| Icon library | Inline SVG (tier 1-2 provider brand icons per D-38; Heroicons for generic fallback) |
| Font | System font stack (Phoenix 1.8 default via Tailwind) |

**Source:** Existing templates in `priv/templates/sigra.install/` establish these conventions.

---

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing, gap between icon and label in OAuth buttons |
| md | 16px | Default element spacing, form field gaps, button internal padding |
| lg | 24px | Section padding, space between OAuth button group and divider |
| xl | 32px | Layout gaps, space between page header and content |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: OAuth provider buttons use 40px minimum touch target height (10 units) for accessibility. Settings page identity cards use 16px internal padding (p-4, matching Phase 4 session cards).

**Source:** Existing templates use Tailwind spacing: `my-6` (24px), `mt-8` (32px), `p-4` (16px), `gap-2` (8px), `space-y-4` (16px).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (text-sm) | 400 (normal) | 1.5 (leading-normal) |
| Label | 14px (text-sm) | 600 (font-semibold) | 1.5 (leading-normal) |
| Heading | 20px (text-xl via .header component) | 600 (font-semibold) | 1.2 |
| Hint | 12px (text-xs) | 400 (normal) | 1.5 (leading-normal) |

**Source:** Existing templates use `text-sm` for body/labels, `font-semibold` for emphasis, `text-xs` for badges. Phoenix 1.8 `.header` component controls heading size.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | white / bg-white | Page background, form surfaces |
| Secondary (30%) | gray-50 / bg-gray-50 | Identity cards, session cards, badge backgrounds |
| Accent (10%) | brand / text-brand | Navigation links ("Sign up", "Log in", "Go back"), "This device" badge |
| Destructive | red-600 / text-red-600 | Unlink button text, revoke session text |
| Success | green (via Phoenix flash) | Flash messages on successful link/login |
| Provider brand | Per-provider SVG fill | Google: #4285F4, GitHub: #24292f, Apple: #000000, Meta: #1877F2 |

Accent reserved for: navigation links between auth pages, "This device" badge, provider-linked status indicator on settings page.

**Source:** Existing templates use `text-brand`, `hover:underline` for links, `text-red-600 bg-red-50 hover:bg-red-100` for destructive actions, `bg-gray-50 border-gray-200` for cards.

## Component Inventory

### 1. OAuth Button Group (login + registration pages)

**Location:** Above password form on login page, above registration form on registration page.
**Layout:** Vertical stack of provider buttons, full width, `space-y-3` (12px gap between buttons).
**Button anatomy:**
- Container: `w-full h-10 flex items-center justify-center gap-2 rounded-lg border border-gray-300 bg-white hover:bg-gray-50 text-sm font-medium`
- Icon: 20x20px inline SVG, left of label
- Label: "Continue with {Provider}" (verb: "Continue with", not "Sign in with" -- matches Vercel/Linear pattern)
- No icon-only buttons. Always icon + label for clarity.

**Provider buttons rendered:**
- Dynamic from `Sigra.Config.oauth_providers()` list (D-37)
- Order: as configured in `config.exs`
- Tier 1-2 get brand SVG icons (D-38)
- Custom/generic providers get a generic globe icon (Heroicons `globe-alt`)

**Divider below OAuth buttons:**
```heex
<div class="relative my-6">
  <div class="absolute inset-0 flex items-center">
    <hr class="w-full" />
  </div>
  <div class="relative flex justify-center text-sm">
    <span class="bg-white px-2 text-gray-500">or</span>
  </div>
</div>
```
**Source:** Matches existing divider pattern in `login_html.ex` (line 36-42). Divider text shortened from "or sign in with password" to "or" since context is clear.

### 2. Account Linking Confirmation Banner (login page)

**When:** OAuth callback email matches an existing account (D-41).
**Implementation:** Phoenix flash message, `:info` level.
**Copy:** "An account with this email exists. Log in to link your {Provider} account."
**Visual:** Standard Phoenix info flash styling (blue/info bar at top of page).
**Behavior:** After successful login with link intent in session, auto-link provider and redirect to settings with success flash.

### 3. OAuth Settings Section (settings page)

**Location:** Dedicated settings page or section within user settings.
**Container:** `mx-auto max-w-2xl` (matches Phase 4 session listing width).
**Header:** `.header` component with title "Connected Accounts" and subtitle "Manage your linked sign-in providers."

**Identity card (per linked provider):**
```
Layout: flex items-start justify-between p-4 bg-gray-50 rounded-lg border border-gray-200
```
- Left side:
  - Row 1: Provider icon (20x20 SVG) + provider name (font-semibold text-sm) + provider email (text-sm text-gray-500)
  - Row 2: "Linked {relative_time}" (text-sm text-gray-500) + "Last used {relative_time}" (text-sm text-gray-500), separated by middot
- Right side: "Unlink" button (text-sm text-red-600 bg-red-50 hover:bg-red-100 rounded-md px-3 py-1.5)

**Source:** Card layout matches Phase 4 session listing pattern in `session_live.ex` (line 41-87).

**Unlink button states:**
- Default: enabled, red styling as above
- Last provider (no password set): disabled, tooltip/title "Set a password first to keep access to your account" (D-03)
- After click: browser `data-confirm` dialog (same pattern as session revoke)

**Add provider section (below linked providers):**
- Heading: "Add a sign-in method" (text-sm font-semibold, no `.header` component)
- Buttons: Same OAuth button group component as login page, filtered to exclude already-linked providers
- Empty state: When all configured providers are linked, show "All available providers are connected." (text-sm text-gray-500)

**OAuth-only user hint:**
- When user has no password set (D-52):
- Copy: "No password set. Set a password to enable email login and as a backup."
- Style: `text-sm text-gray-500 mt-4` -- subtle, not a banner. Placed below the provider list.
- Link: "Set a password" as `text-brand hover:underline`

### 4. Unlink Confirmation Dialog

**Trigger:** Click "Unlink" button on identity card.
**Implementation:** Browser native `data-confirm` attribute (same as Phase 4 session revoke).
**Copy:** "Unlink {Provider}? You'll still be able to log in with: {remaining_methods}." (D-53)
- Example: "Unlink Google? You'll still be able to log in with: Password, GitHub."
- If only one method remains: "Unlink Google? You'll still be able to log in with: Password."

### 5. Error Flash Messages (login page)

All errors redirect to login page with flash messages (D-39, D-40, D-55).

| Scenario | Flash Level | Copy |
|----------|-------------|------|
| Generic OAuth failure | :error | "Could not sign in with {Provider}. Please try again or use another method." |
| State/CSRF mismatch | :error | "Authentication expired. Please try again." |
| Provider denied/unavailable | :error | "Could not connect to {Provider}. Please try again." |
| No email from provider | :error | "We need your email to create an account. Please grant email permission and try again." |
| UID/email conflict | :error | "Could not complete sign in." |
| Successful link | :info | "{Provider} has been linked to your account." |
| Successful unlink | :info | "{Provider} has been removed from your account." |
| Link while authenticated | :info (redirect to sudo first) | Standard sudo flow, then link |

## Accessibility

| Requirement | Implementation |
|-------------|----------------|
| OAuth buttons keyboard accessible | Standard `<a>` or `<button>` elements, focusable by default |
| Provider icons decorative | `aria-hidden="true"` on all SVG icons; button label carries meaning |
| Unlink confirmation | Browser native `data-confirm` -- accessible by default |
| Disabled unlink state | `disabled` attribute + `title` attribute for screen readers |
| Flash messages | Phoenix LiveView flash component handles `role="alert"` |
| Color contrast | Gray-500 on white: 4.6:1 (passes AA). Red-600 on red-50: passes AA. Brand on white: verify >= 4.5:1 |
| Focus indicators | Tailwind default focus ring (focus:ring-2 focus:ring-offset-2) |
