<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Fixture helpers -> tests | Helpers can accidentally hide real auth/org/passkey boundaries if they overreach. |
| Assertion helpers -> test truthiness | Broad or vague assertions can let security regressions pass unnoticed. |
| Generated template -> downstream host apps | Fixture helper names and caveats become part of the generated API contract. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-02-01 | E | generated fixture helpers | mitigate | Keep helpers on the existing fixture surface and document exactly which controller/session boundaries they bypass per D-08. |
| T-23-02-02 | T | `Sigra.Testing` assertions | mitigate | Implement narrow explicit helpers instead of a generic matcher DSL so assertion scope stays obvious and reviewable. |
| T-23-02-03 | R | generated helper contract | mitigate | Mirror helper names in the example app and pin them in focused tests so the docs and generated API cannot silently drift. |
| T-23-02-04 | I | org-aware audit assertions | mitigate | Route `assert_audit_logged_for_org/2` through the existing audit query/assertion path so it checks real `organization_id` values instead of test-only bookkeeping. |
</threat_model>
