<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Playwright browser -> example app server | Browser smoke must observe the served app, not test-only route fulfillment or session fabrication. |
| Browser smoke lane -> CI release signal | The CI lane becomes part of the release gate for v1.1 regressions. |
| Browser smoke -> install/compile jobs | Playwright coverage must complement, not replace, the install matrix. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-03-01 | T | Playwright specs | mitigate | Forbid route fulfillment, hidden cookie/storage seeding, and keep the flows on real mailbox, route, and WebAuthn surfaces. |
| T-23-03-02 | R | CI browser signal | mitigate | Run the focused spec files explicitly in CI so regressions are attributable to the load-bearing journeys, not a sprawling matrix. |
| T-23-03-03 | E | invitation acceptance flows | mitigate | Exercise both new-signup and existing-user acceptance paths through the actual invitation email and accept route instead of direct DB state injection. |
| T-23-03-04 | D | CI scope explosion | accept | The browser suite intentionally covers only the five required journeys; long-tail permutations remain deferred by design. |
</threat_model>
