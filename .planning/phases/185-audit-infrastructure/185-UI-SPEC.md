# Phase 185 — UI Design Contract

> Visual and interaction contract for the `/admin/_design` gallery scaffold only.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.

---

## Scope Boundary

This contract covers EXACTLY ONE user-facing surface: the **example-only
`/admin/_design` gallery LiveView** (INFRA-01). The other five requirements
(INFRA-02..06) are CI and tooling artifacts with no visual surface — this
contract makes no design decisions for them.

The gallery introduces **zero net-new component visual contracts.** Every
rendered component's spacing, type, color, interaction states, and motion are
already locked by the existing `sg-*` design system and byte-golden-guarded by
`test/sigra/admin/components_test.exs`. This contract governs only:

1. The gallery's own **scaffold layout** (page structure, board grid, section headings).
2. The **board wrapper contract** — the structural/interaction element that Playwright uses as a snapshot anchor.
3. **Gallery-specific microcopy** (audit-tool labels, board captions, section headings).
4. The gallery's **theme and responsive behavior** — it must render correctly in chromium/mobile/dark to match the three snapshot projects (D-05).

All other dimensions (color tokens, type ramp, spacing scale, component states,
motion budget) are INHERITED from the locked system. They are not re-specified
here.

INHERITED — locked by the `sg-*` token layer (`--sg-space-*`, `sg-stack--N`,
`sg-cluster`, `sg-grid` primitives). Not re-specified here.

**Gallery scaffold exceptions (net-new decisions for this phase only):**

| Usage | Value | Rationale |
|-------|-------|-----------|
| Gap between boards in the gallery grid | `sg-stack--6` (equivalent to 48px on the `sg-stack` scale) | Matches the inter-section rhythm used on real admin list pages; gives each board visual separation for Playwright element-scoped capture |
| Gap between the L1/L2 section heading and its first board | `sg-stack--3` (equivalent to 24px) | Matches `sg-card sg-stack sg-stack--3` section padding used in real admin pages |
| Padding inside each board wrapper | `sg-stack--4` (equivalent to 32px) or `sg-card` base padding | Reuse `sg-card` so the board wrapper renders consistently in all three theme/viewport projects |

All other spacing is INHERITED.

## Gallery Scaffold Contract

This section specifies the structural design decisions unique to this phase.

### Page Structure

The gallery LiveView renders inside the real `{ExampleWeb.Layouts, :admin}` shell
(true chrome, breadcrumbs, theme toggle, topbar). The gallery body follows the
standard `sg-stack sg-stack--6` page stack:

```
<section class="sg-stack sg-stack--6">
  <header class="sg-page-header">
    <p class="sg-page-kicker">Design System</p>
    <h1 class="sg-page-title">Design Gallery</h1>
    <p class="sg-page-copy">
      Component and group state matrix. Dev only — compiles out of prod.
    </p>

  <section class="sg-stack sg-stack--4">           [L1: Components]
    <h2 class="sg-section-heading">Components</h2>
    <div class="sg-stack sg-stack--6">             [board stack]
      <div id="board-{component}" class="sg-card sg-stack sg-stack--4">  [board wrapper]
        <p class="sg-muted sg-text-sm">{component_name}</p>
        {state matrix rows}
      </div>
      ...repeat for each of 13 components
    </div>

  <section class="sg-stack sg-stack--4">           [L2: Meta-component groups]
    <h2 class="sg-section-heading">Component Groups</h2>
    <div class="sg-stack sg-stack--6">
      <div id="board-mg-{n}" class="sg-card sg-stack sg-stack--4">
        <p class="sg-muted sg-text-sm">MG-{N} {group_name}</p>
        {group composition}
      </div>
      ...
    </div>
```

### Board Wrapper Contract

Each component and group renders inside a board wrapper. This is the Playwright
snapshot anchor (D-03).

**Required attributes on every board wrapper:**
- `id="board-{component}"` for L1 component boards, e.g. `id="board-notice"`, `id="board-stat"`, `id="board-stat_link"`, `id="board-task_card"`, `id="board-summary_chip"`, `id="board-applied_chip"`, `id="board-empty_state"`, `id="board-page_back"`, `id="board-scope_ribbon"`, `id="board-notice_link"`, `id="board-field_help"`, `id="board-skeleton"`, `id="board-audit_row"`
- `id="board-mg-{n}"` for L2 group boards, e.g. `id="board-mg-1"`, `id="board-mg-2"`, etc.
- CSS: `class="sg-card sg-stack sg-stack--4"` — renders the board as a card with vertical rhythm, consistent with the real admin shell's card pattern

The board wrapper must NOT introduce any custom CSS class outside `sg-*`. It
must NOT use bespoke markup that could drift from the design system.

**Canary board:** The `id="board-notice"` board is designated as the design
canary (the "impersonation-banner" analog for this lane, per D-10). It must be
stable, present on every gallery render, and contain at minimum one `notice`
component in each of its four tones (`ok`, `warn`, `risk`, `info`).

### State Matrix Arrangement Inside Each Board

Each board shows a **single composite state-matrix** (one PNG captures all
states of that component). States are arranged vertically in a `sg-stack sg-stack--3`
stack inside the board, with a `<span class="sg-muted sg-text-xs">` state label
above each instance. This arrangement:

- Keeps each board's height bounded (viewport capture with `fullPage: false`).
- Places meaningful visual variation in the vertical axis so diffs are human-meaningful.
- Avoids horizontal overflow on mobile (iPhone 13 viewport).

State coverage per component — what "every state" means for each of the 13
functions:

| Component | States to show in the board |
|-----------|----------------------------|
| `stat` | one instance (read-only; no interactive states) |
| `stat_link` | default (hover/focus are CSS-only and not snapshot-captured) |
| `task_card` | one instance with real title/body/action copy |
| `summary_chip` | basic form (label+value only) + enhanced form (icon, value_unit, subvalue, help, tone: risk, tone: warn, tone: ok, tone: info) |
| `applied_chip` | one instance (interactive states CSS-only) |
| `empty_state` | one instance with inner_block copy |
| `page_back` | one instance |
| `scope_ribbon` | one instance (global scope) + one instance (org scope) |
| `notice` | tone: nil + tone: ok + tone: warn + tone: risk + tone: info |
| `notice_link` | notice with an embedded notice_link (combined board with the `notice` board is acceptable, or a separate `id="board-notice_link"`) |
| `field_help` | one instance (panel hidden/default state; JS-toggle not captured in static snapshot) |
| `skeleton` | one instance at a representative width |
| `audit_row` | show_detail: false + show_detail: true + show_codes: true + tone risk (non-success outcome) + tone info (action_badge present) |

### Responsive Behavior of the Gallery Scaffold

The gallery scaffold uses only `sg-*` layout primitives. No breakpoint-specific
gallery CSS is added. The existing `sg-stack`, `sg-card`, and `sg-grid`
primitives reflow correctly at 320/375px (mobile) and 768px+ (desktop).

The gallery must render without horizontal overflow at the iPhone 13 viewport
(390px × 844px) used by the `admin-design-mobile` Playwright project.

### Theme Behavior

The gallery inherits Light/Dark/System from the real `{ExampleWeb.Layouts, :admin}`
shell. No gallery-specific theme code is needed. The `admin-design-dark`
Playwright project sets `colorScheme: 'dark'` at the browser level, which
triggers `prefers-color-scheme: dark` and the CSS `:root[data-sg-admin-theme="dark"]`
rule already present in `sigra_admin.css`.

## Copywriting Contract

These are the gallery-specific audit-tool labels. They are not product-facing
copy and do not need to conform to the brand voice guide — they are developer
and operator tooling copy, calibrated to be precise and terse.

| Element | Copy |
|---------|------|
| Gallery page kicker | "Design System" |
| Gallery page title | "Design Gallery" |
| Gallery page body | "Component and group state matrix for audit and regression checking. Available in development only." |
| L1 section heading | "Components" |
| L2 section heading | "Component Groups" |
| Board label prefix for L1 boards | The component function name, e.g. "notice", "stat", "audit_row" — lowercase, matching the Elixir function name |
| Board label prefix for L2 boards | "MG-{N} {descriptive name}", e.g. "MG-1 Metric / Summary Strip", "MG-2 Filter Panel + Applied-chip Row" |
| In-board state labels | Terse key=value style, e.g. `tone: ok`, `tone: risk`, `show_detail: false`, `show_detail: true, show_codes: true`, `basic`, `enhanced` |
| DEV-only badge | "DEV ONLY" — rendered as a `<span>` near the gallery page header (mirrors `ExampleWeb.Demo.CredentialsLive` precedent, `data-testid="design-gallery-dev-only-badge"`) |

No primary CTA, empty state, error state, or destructive confirmation is needed.
The gallery is a read-only audit surface with no user-initiated actions or
data-mutation paths.
