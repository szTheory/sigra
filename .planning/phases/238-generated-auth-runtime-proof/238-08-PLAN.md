<objective>
Close the two final committed Phase 238 security review findings by atomically revoking canonical sessions on password reset, disconnecting their LiveViews, and enforcing authenticated-user ownership in every generated per-session revoke path.

Purpose: The current reset transaction updates the password and deletes only legacy user_tokens, while generated browsers authenticate through user_sessions; the generated revoke events also forward a client-selected hash without the ownership option already supported by Sigra.Auth. These gaps leave stolen sessions usable after reset and permit cross-account logout attempts.
Output: Hardened library/generated auth boundaries, deterministic unit/source/browser regressions, and a fresh exact-correction-SHA generated-host runtime receipt.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| signed reset credential → password/token/session transaction | A valid reset credential crosses into password mutation and must revoke all authentication state for exactly its user atomically. |
| persisted session hash → LiveView socket topic | Reset retains only hashed session identity, so open socket revocation depends on generated socket topics using that same non-secret identity. |
| client LiveView event → generated session context | The browser controls the submitted token value; ownership must come only from the authenticated socket scope. |
| GitHub workflow metadata → evidence receipt | Remote success must belong to the exact final correction commit and direct generated-host job. |
