## Decisions Made

- **admin-user-operations "No active sessions"**: Root cause was `getByText` default substring matching. `empty_state` component renders both a `<p class="sg-empty-state__title">No active sessions</p>` AND the inner slot `<p>This user has no active sessions in the current scope.</p>`. Playwright's `getByText` without `exact: true` matches both as substrings. Fix: `{ exact: true }` matches only the title element.
- **admin-modal-interaction "Revoke session"**: Phase 200 D-04 moved revoke off the user detail page to `UserSessionsLive`. The spec was written against the pre-Phase-200 detail page. Fix: navigate to the sessions page via the "Manage sessions" link before the APG gate assertions.
- **admin-audit "session.create"**: The raw action code lives inside a `<details>Event codes</details>` disclosure that is CLOSED by default — Playwright sees it as hidden. Fix: assert the visible `action_label` pill "Session Create" (from `presenter.ex:43-47` capitalization logic).
- **Sudo heading**: Drift confirmed — installer template and example were inconsistent. Reconciled all three (installer template, `impersonation.spec.ts`, `admin-generated.spec.ts`) to "Re-enter your password". The "Confirm password" button unchanged (it already matched).
