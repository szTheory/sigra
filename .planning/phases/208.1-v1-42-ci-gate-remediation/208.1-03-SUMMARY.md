## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Stale Vaultr-era dev DB rows blocking re-seed**
- **Found during:** Task 2 — re-seeding dev DB to create passkeys for admin/pat
- **Issue:** `auth.user_identities` had a row with `provider_uid=carol-gh-demo-uid` belonging to the old `carol@demo.vaultr.test` user. The seeds' `ON CONFLICT (user_id, provider) DO NOTHING` didn't cover the `(provider, provider_uid)` unique index, causing the insert to fail. Separately, old Vaultr-era `user_passkeys` rows held the same `credential_id` values as the new Tasklane passkeys, causing `ON CONFLICT (credential_id) DO NOTHING` to silently skip the new admin/pat passkeys.
- **Fix:** Manual DB cleanup — deleted the stale Vaultr-era `user_identities` and `user_passkeys` rows via SQL before re-seeding. No code changes.
- **Files modified:** (none — dev DB cleanup only)
- **Commit:** (dev DB state, not committed)
