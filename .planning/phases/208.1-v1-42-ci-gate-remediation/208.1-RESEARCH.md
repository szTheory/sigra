# Phase 208.1: v1.42 CI-Gate Remediation - Research

**Researched:** 2026-06-29
**Domain:** Playwright behavioral-spec remediation + responsive admin LiveView markup reconciliation (Elixir/Phoenix, sg-* design system) against an already-ratified design contract
**Confidence:** HIGH (all failures traced to file:line in source; the clean reference pattern is in-repo; CI lane structure read verbatim)

## Summary

This is a **debt-remediation** phase, not a design phase. The v1.42 backlog (294 commits) cannot ship green through branch protection because the required CI check **"Example Playwright smoke (full lifecycle)"** (`.github/workflows/ci.yml:878`) has ~15 real behavioral failures that were never CI-validated — several phase audits were "cite-and-flip" code reads that never executed the specs. The job is to make the suite green by **reconciling spec selectors and a small number of real markup gaps to the EXISTING ratified design contract** — never by redesigning the admin UI.

The failures cluster into four mechanically-distinct buckets, all with in-repo fixes:
1. **Two env-independent `admin_design` gallery bugs** — a stale test-vs-markup count (`board-mg-1 .sg-metric` asserts 7, markup renders 6) and a real responsive overflow (`board-cfg-audit` renders a desktop `<table>` at 320px with no mobile-card swap). Both are pure DOM/geometry, reproducible anywhere.
2. **Redesign-broken behavioral specs** — the admin redesign introduced a desktop+mobile **dual-DOM** render (`sg-show-desktop` / `sg-show-mobile`), and older Phase-31 specs use unscoped `getByText(...)` that now matches 2 elements → Playwright strict-mode violation. The repo **already contains the canonical fix idiom** (`helpers/adminUsersIndex.ts`) and the clean `admin_checkpoints` lane proves it.
3. **A handful of stale-text spec selectors** — e.g. a spec asserts the sudo heading `"Confirm your password"` but the template renders `"Re-enter your password"`; an audit textbox filter lives inside a collapsed `<details>`.
4. **CI-native baseline capture** — 12 net-new `board-cfg-*` PNGs (4 boards × 3 projects) must be captured on ubuntu via the existing `admin_design_recapture` job, **only after** the design lane is behaviorally green (else the capture step is skipped, exactly as run 28401914980 failed).

**Primary recommendation:** Fix in dependency order — (a) the 2 env-independent gallery bugs first (they gate both the design lane and the baseline capture), (b) the dual-DOM/stale-selector behavioral specs (mechanical, using the existing `adminUsersEmailLocator` idiom), (c) re-validate the cite-and-flip audits by running the enumeration harness, (d) capture the 12 board-cfg baselines CI-native, (e) confirm green via a real CI run on `wip/recapture-trigger` (the only branch-ref dispatch path; `admin_design_recapture` never runs on PRs). The **real required CI check is the sole arbiter of done** — local Playwright green is necessary but not sufficient (known CI divergences below).

### Pattern 1: Dual-DOM responsive scoping (THE canonical fix idiom)
**What:** The admin redesign renders BOTH a desktop table AND a mobile card stack in the DOM simultaneously. CSS hides the inactive one per viewport. A `getByText('X')` that is not scoped to the visible variant resolves to 2 elements → `strict mode violation: ... resolved to 2 elements`.

**Source of the substrate** — `sigra_admin.css:293-317` [VERIFIED: grep]:
```css
/* Responsive show/hide — the core substrate fix (kills duplicated content) */
.sg-show-desktop { display: none; }     /* hidden below 1024px */
.sg-show-mobile  { display: revert; }
@media (min-width: 1024px) {
  .sg-show-desktop { display: revert; }
  .sg-show-mobile  { display: none; }   /* hidden at/above 1024px */
}
```

**The clean idiom** — `helpers/adminUsersIndex.ts:10-21` [VERIFIED: Read]:
```ts
// Both desktop and mobile result nodes can exist in the DOM; CSS only shows
// one layout. `.filter({ visible: true }).first()` resolves the single match.
export function adminUsersEmailLocator(page: Page, email: string) {
  return page
    .locator('#admin-users-desktop-results tbody tr, #admin-users-mobile-results article')
    .filter({ hasText: email })
    .filter({ visible: true })
    .first();
}
```

**How the CLEAN `admin_checkpoints` lane scopes** — `admin-checkpoints.spec.ts:325-376` [VERIFIED: grep]: it targets `[data-testid="admin-audit-{user-}{desktop,mobile}-results"]` and asserts `.toBeVisible()` / `.toBeHidden()` per viewport, never an unscoped `getByText`. This is why it passes while the Phase-31 behavioral specs fail.

**When to use:** Any failing assertion that targets content rendered in both result panes (users list, audit list) or content that appears on both a bounded preview AND its dedicated full surface (sessions empty-state).

**The contract markers** (frozen — do not rename) — `users_index_live.ex:216-218,262-264` [VERIFIED: grep]:
```
id="admin-users-desktop-results" data-testid="admin-users-desktop-results" class="sg-table-panel sg-show-desktop"
id="admin-users-mobile-results"  data-testid="admin-users-mobile-results"  class="sg-stack sg-stack--3 sg-show-mobile"
```
Design contract documents this in the List Archetype and Audit Explorer Archetype [CITED: admin-design-contract.md:242-264, 368-391].

### Pattern 2: Responsive table — desktop table + mobile-card swap (the board-cfg-audit fix)
**What:** A wide table at mobile width overflows the viewport. The correct pattern wraps the `<table>` in `.sg-table-panel.sg-show-desktop` AND renders a content-equivalent `.sg-show-mobile` card stack.

**Correct reference** — MG-5/MG-6 in `design_gallery_live.ex:617/703, 811/841` [VERIFIED: grep]:
```
<div data-testid="mg-5-desktop-results" class="sg-table-panel sg-show-desktop"><table class="sg-table">…</table></div>
<div data-testid="mg-5-mobile-results"  class="sg-stack sg-stack--3 sg-show-mobile">…cards…</div>
```
At 320px the table is `display:none`, so it cannot overflow.

**The broken composite** — `board-cfg-audit` `design_gallery_live.ex:1324-1363` [VERIFIED: Read]: renders a bare `<div class="sg-table-panel"><table class="sg-table">` with NO `sg-show-desktop` wrapper and NO mobile swap. `.sg-table-panel { overflow: hidden }` (sigra_admin.css:750) clips visually but the table's intrinsic min-width (4 columns × `padding: space-3 space-4` + timestamp/email content) still pushes a child cell's `getBoundingClientRect().right` past 320px → the overflow test (`admin-design.spec.ts:269-306`) reports `overflowingChild: "table.sg-table"`.

### Anti-Patterns to Avoid
- **Widening the test to "expect overflow"** — do NOT relax `overflowingChild: null`. Fix the markup to match the ratified responsive contract.
- **Inventing new design** — do NOT add new components, copy, or layout. Every fix reconciles to `admin-design-contract.md`. (Phase planned `--skip-ui` for this reason.)
- **Recapturing admin-design baselines on darwin** — forbidden; font metrics diverge from ubuntu CI. CI-native only [CITED: memory `admin-design baselines are CI-native`].
- **Treating local Playwright green as "done"** — it is a pre-filter; the required CI check is the arbiter.
- **Capturing baselines before the design lane is behaviorally green** — `--update-snapshots` runs the spec; a behavioral failure aborts the run and skips the commit/PR step (run 28401914980).

## Common Pitfalls

### Pitfall 1: Capturing board-cfg baselines before the design lane is behaviorally green
**What goes wrong:** `admin_design_recapture` runs `npx playwright test admin-design.spec.ts … --update-snapshots`. If ANY behavioral test in that file fails (the overflow test :269, the catalog-states test :318 with its `board-mg-1 .sg-metric` count and `board-cfg-audit` overflow), the playwright process exits non-zero → the gate/commit/PR step is skipped → **no baselines produced**.
**Why it happens:** `--update-snapshots` updates snapshot assertions but does NOT make non-snapshot (behavioral) assertions pass.
**How to avoid:** Land the 2 env-independent design bugs FIRST and confirm `admin-design.spec.ts` is behaviorally green (all of `group boards expose catalog states`, the overflow test, content-equivalence) BEFORE dispatching the recapture. This is a hard ordering constraint.
**Warning signs:** Recapture run logs "capture step" failure with 6 behavioral failures (the literal run 28401914980 signature) [CITED: FINDINGS.md:27-28].

### Pitfall 2: Fixing `board-mg-1` count in the wrong direction
**What goes wrong:** `admin-design.spec.ts:331` asserts `#board-mg-1 .sg-metric` `toHaveCount(7)`; markup at `design_gallery_live.ex:462-475` renders **6** (mg-1-populated: 3 summary_chips + mg-1-zero: 3 summary_chips; each `summary_chip` emits one `<dl class="sg-metric">` — `components.ex:180`). Naively bumping the test to 6 or adding a 7th chip both "pass" but only one matches design intent.
**Why it happens:** The board has only two populated states (populated + zero), each a 3-chip strip mirroring the Phase-201 slim 3-chip User health strip (Total + Locked + Deletion scheduled) [CITED: design_gallery_live.ex:456 comment, admin-design-contract.md List Archetype D-03].
**Recommendation (grounded in the contract):** The design intent is a **3-chip strip** (the ratified slim User-health strip). The board renders two instances (populated + zero) = 6 `.sg-metric`. The number 7 has no design basis — it was lifted from a cite-and-flip audit, not counted [CITED: FINDINGS.md:48-51]. **Fix the TEST to `toHaveCount(6)`**, not the markup. Adding a 7th chip would violate the slim-strip contract. (Confirm during planning that no third state, e.g. a loading metric, is expected to count as `.sg-metric` — the loading state uses `.sg-skeleton`, not `.sg-metric`, so it does not contribute: `design_gallery_live.ex:476-480`.)
**Warning signs:** A proposed fix that adds a `summary_chip` to make 7, or that changes the slim-strip vocabulary.

### Pitfall 3: Stale heading text in the sudo flow
**What goes wrong:** `impersonation.spec.ts:62` asserts `getByRole('heading', { name: 'Confirm your password' })`, but the sudo template renders `<h1 class="vt-auth__title">Re-enter your password</h1>` (`sudo_html.ex:29`) [VERIFIED: Read]. The button "Confirm password" (sudo_html.ex:51) DOES match `confirmSudo`, so only the heading assertion is stale.
**Why it happens:** The sudo template copy drifted to "Re-enter your password" during a demo/branding pass; the spec was never updated. `admin-generated.spec.ts:48` carries the same stale string (verify whether the generated-host template differs).
**How to avoid:** Update the spec heading assertion to match the rendered text (`Re-enter your password`), OR reconcile the template heading to the spec — choose per which is the ratified copy. Recommendation: the template copy is the product reality (more recent); **update the spec**. Confirm the generated-host installer template's sudo heading so `admin-generated.spec.ts` stays consistent.
**Warning signs:** `heading "Confirm your password" not found` against a page whose `<h1>` reads "Re-enter your password".

### Pitfall 4: The "Action prefix" textbox is inside a collapsed `<details>`
**What goes wrong:** `admin-audit.spec.ts:135` does `getByRole('textbox', { name: 'Action prefix' }).fill('session')`. The textbox (`audit_index_live.ex:95-104`) lives inside `<details><summary>More filters</summary>…</details>` (line 82) which is **collapsed by default** → the input is not visible/interactable.
**Why it happens:** Phase 202 moved advanced filters into a CSS-only `<details>` disclosure [CITED: admin-design-contract.md Audit Explorer D-02]. The spec was written against the pre-disclosure flat form.
**Also note:** `name="action_prefix"` appears twice (the Impersonation checkbox at line 73 AND the textbox at line 99) — `getByRole('textbox')` disambiguates by role, so the role-based selector is correct; the only gap is the collapsed disclosure.
**How to avoid:** Have the spec open the disclosure first — `await page.getByText('More filters').click()` (or `page.locator('details').click()`) before targeting the textbox. Verify the `<span class="sg-field-label">Action prefix</span>` provides the accessible name via the wrapping `<label>` (it does — implicit label association).
**Warning signs:** `textbox "Action prefix" not found` or "element is not visible".

### Pitfall 5: "No active sessions" / "Passkeys" resolve to 2 elements
**What goes wrong:** `admin-user-operations.spec.ts:152` `page.getByText('No active sessions')` (unscoped). The string appears on the user-detail Sessions preview (`user_show_live.ex:115`) AND the dedicated sessions page (`user_sessions_live.ex:160`). Combined with dual-DOM rendering this trips strict mode [CITED: FINDINGS.md:57-59].
**How to avoid:** Scope to the visible page region. On the sessions page, scope to the sessions `<section>` (e.g. `page.locator('section').filter({ hasText: 'Sessions' })` or a `[data-testid]` if added) then `.getByText('No active sessions')`, or add a `data-testid` marker to the empty-state container and assert against it. Prefer the existing `.filter({ visible: true }).first()` idiom.
**Note:** `user_sessions_live.ex:125` ALSO renders a bare `.sg-table-panel`+`<table>` with no mobile swap — if a mobile/webkit project exercises this surface it can overflow like board-cfg-audit. Confirm whether the failing lane is desktop-only (admin_behavior runs `--project=chromium`, desktop) — if so the sessions table overflow is out of scope for THIS phase's failing set, but flag it as a latent debt.

### Pitfall 6: Local green ≠ CI green
**What goes wrong:** A spec passes locally on :4011 against Docker PG but fails on CI :4000.
**Why it happens:** Documented divergences — OS system-ui **font metrics** (macOS vs ubuntu; the SEED-006 root cause), **JS bundle drift** (served `app.js` lags source `admin_hooks.js` unless propagated), **compile-time PORT** baked into `_build`, and **disposable-PG** state differences [CITED: memory references; CLAUDE.md].
**How to avoid:** Use local enumeration as a fast filter only; gate "done" on a real CI run via `wip/recapture-trigger` dispatch.
