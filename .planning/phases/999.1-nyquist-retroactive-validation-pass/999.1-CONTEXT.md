- **D-01a:** Maintain **`999.1-CONTEXT.md`** (this file) as the **machine- and human-visible tombstone** that satisfies GSD’s discuss → **`*-CONTEXT.md`** contract, so greps and agents do not treat “missing CONTEXT” as “phase not started.”

Elixir/Hex uses `@deprecated`, CHANGELOG, and upgrade guides for **API** tombstones; Sigra adds **`.planning/`** tombstones for **work-tracking IDs**. GSD tooling is **CONTEXT-centric**; VALIDATION-only is weaker for agents that only look for `*-CONTEXT.md`.

### D-02 — `STATE.md` must not be a second roadmap

- **D-02a:** **`STATE.md` must not** list superseded **999.x** cards as **“current focus”** or **“ready to plan”** when **`999.1-VALIDATION.md`** declares supersession.
- **D-02b:** Prefer **narrative + session handoff** in STATE, or **generated** “next phase” lines later; until then, **canonical queue = `ROADMAP.md` + phase `*-VERIFICATION.md` / `*-VALIDATION.md`**.

**Rationale:** Duplicate “writable now” pointers (STATE vs ROADMAP) create the same class of **honesty risk** as contradictory verification claims — AI agents weight prominent “Current focus” heavily. Elixir OSS more often uses CHANGELOG + issues than a living STATE; where STATE exists, it must **not contradict** attested phase files.

### D-03 — Cross-links and information architecture

- **D-03a:** **Hub-and-spoke:** **`ROADMAP.md`** + milestone archives = hub; phase dirs = spokes. **One canonical link per factual claim**; elsewhere use **short summaries** with “canonical = …” (same pattern as **Nyquist matrix wins over `MAINTAINING.md` summary**).
- **D-03b:** Treat **999.x** as a **namespace**, not the execution ledger. When parking-lot IDs appear in old notes, readers should find a **forward link** (999.1 → Phase **36**) in this directory and in ROADMAP reader notes.
- **D-03c:** **Hex vs GitHub:** integrator truth stays in **published docs + CHANGELOG + upgrade guides**; evidence-heavy matrices stay on **GitHub `main`** with stable URLs — do not fork deep tables into the Hex tarball.

### D-04 — Policy for a *new* Nyquist / retro validation pass

- **D-04a:** **Default:** no standing “re-run 999.1” loop. **999.1** remains **closed as archaeology**; additional assurance is **event-driven** (material auth change, loud launch, incident, major Phoenix/Ecto jump that changes test meaning, or stale human UAT disposition).
- **D-04b:** **Preferred ladder:** (1) refresh links / evidence index if behavior unchanged; (2) **expand machine substitutes** (CI contracts, ceremony tests, installer golden) and move rows human → machine; (3) **waive with named substitute + honest residual risk**; (4) **new bounded phase** (not 999.x) with exit criteria and verification gate; (5) **promote 999.x** only with an **explicit** stakeholder driver.
- **D-04c:** **Avoid:** infinite re-validation, checkbox security theater, waivers without substitutes, “Phase 36 again” without new facts.

**Rationale:** SOC2/PCI-style **re-attestation** is **periodic or change-triggered**, not per-PR. OpenSSF Scorecard–style **continuous automation** covers regressions; **human matrices** supplement. Matches Sigra’s shipped pattern: **bounded SEED-002**, **SEED-001** evidence packaging, **NYQ** posture for **41–44** — trust work is **milestone-shaped**, not perpetual archaeology.

### D-05 — Cohesive project stance (single paragraph)

Ship **honest, legible disposition** (machine vs human, waivers, evidence pointers) over volume of re-checks. **Planning files** follow the same bar as verification: if two artifacts disagree, **fix the planning doc before greenfield work**. **DX:** contributors and agents should open **one** obvious file in `999.1-*` and immediately see **superseded → Phase 36** and **where truth lives**.
