## Design System

| Property | Value |
|----------|-------|
| Tool | none — hand-authored `sg-*` cascade-layer BEM system |
| Preset | not applicable |
| Component library | Sigra.Admin.Components (HEEx function components) |
| Icon library | none — CSS glyphs and text labels only |
| Font | Space Grotesk (self-hosted in `test/example/priv/static/assets/fonts/`; `--font-sans` on admin shell) |

**Design system rules (binding for this phase):**

- All layout, spacing, color, and motion must use existing `--sg-*` CSS custom properties. No one-off hex values, no Tailwind utilities, no inline style overrides.
- New CSS classes require the `sg-` prefix and must be written byte-identically across all three CSS copies (CONTEXT D-11, D-12):
  - `priv/templates/sigra.install/admin/sigra_admin.css`
  - `test/example/priv/static/assets/sigra_admin.css`
  - `test/fixtures/install_golden/tree/priv/static/assets/sigra_admin.css`
- Reuse existing primitives first. Introduce a new function component or CSS class only when a pattern is genuinely reused in more than one place. (CONTEXT D-01)
- Never `transition: all`. Use exact-property transitions only (color, background-color, box-shadow, opacity, transform). (admin-ui-principles.md)

## Page Composition Contract

### User Detail (user_show_live.ex) — Target JTBD-First Structure

```
<section class="sg-stack sg-stack--6">
  scope_ribbon

  <header class="sg-page-header">                [1] CALM IDENTITY BAR
    kicker ("User" or breadcrumb context)
    h1 — display_name or email (primary identity)
    email + id (secondary, muted, code for UUID)
    metrics strip — 3-4 key facts (sessions count / MFA / last seen)
    <.notice> — exactly one priority alert (locked > unconfirmed > no-MFA)
    status pills — compact cluster

  <section class="sg-card sg-stack--3">          [2] SESSIONS PREVIEW (link-out)
    heading "Sessions" + count badge
    bounded preview (max 3 rows — display only, no revoke actions here)
    <.empty_state> when sessions == []
    "Manage sessions →" link to /admin/users/:id/sessions

  <div class="sg-detail-grid">                   [3] SECURITY + IDENTITIES (paired)
    <section class="sg-detail-panel">            Security facts
    <section class="sg-detail-panel">            OAuth identities

  <section class="sg-card sg-stack--3">          [4] ORGANIZATIONS PREVIEW (bounded)
    heading "Organizations" + count
    bounded preview (max 3 orgs — org name + role)
    "View all" link to pivot_path when > 3

  <section class="sg-card sg-stack--3">          [5] RECENT AUDIT (link-out preserved)
    heading "Recent audit" + count
    preview rows (existing behavior)
    "View full audit →" link via full_audit_path/3

  [6] HOST-INJECTED EXTRA SECTIONS (preserved seam)
    extra_detail_sections/1 — rendered AFTER lib sections, BEFORE danger zone

  <section class="sg-danger-panel sg-stack">     [7] DANGER ZONE
    account lock / unlock actions

  [confirm overlay lives on UserSessionsLive, not here]
```

**North star:** An operator can orient in under 2 seconds. The identity bar answers "who + what state?" with exactly one priority alert. No stacked fact-dl under status pills.

### UserSessionsLive (new: /admin/users/:id/sessions)

```
<section class="sg-stack sg-stack--6">
  <.scope_ribbon>
  <header class="sg-page-header">
    breadcrumb (Overview / Users / email / Sessions)
    h1 "Sessions"
    session count

  <section class="sg-card sg-stack--3">
    cluster: heading + "Revoke all sessions" danger button
    full session table (Type / IP / Last activity / Revoke action per row)
    <.empty_state> when no sessions

  <div class="sg-confirm-overlay">              [APG confirm dialog — reused unchanged]
    <div class="sg-confirm-dialog" ...>
```

## Interaction Contract

### Progressive Disclosure

- Use `<details>` (native HTML) for any secondary panel that defaults closed. No JS-driven accordion.
- Do not hide content that an operator needs to assess the user's risk posture on first view.
- Sections that may start collapsed (Claude's discretion): Organizations list (when >3 rows already link-out), MFA recovery codes status (if added later), passkey credential details.

### APG Destructive Confirm Dialog (DETAIL-03)

This is the existing `ConfirmDialog` hook — reuse with zero changes to JS or hook selectors.

| Requirement | Implementation |
|-------------|---------------|
| Focus trap on open | Handled by existing `ConfirmDialog` hook (admin_hooks.js:376-480) |
| Initial focus on Cancel | Existing behavior — cancel gets focus on open (WCAG 2.4.3) |
| Escape closes | Existing behavior |
| Click-outside scrim closes | Existing scrim click handler |
| Scroll lock | Existing hook behavior |
| Focus restore on close | Existing behavior — returns to trigger element |
| No scrim-hidden modal | Dialog is un-nested; overlay is visible (not `display:none`) |
| Selector stability | Do NOT rename `.sg-confirm-dialog`, `[data-sg-confirm-cancel]`, `#user-session-confirm-title` — admin-modal-interaction.spec.ts depends on these |
| Dialog location | Lives on UserSessionsLive only (moved from user_show_live per D-04) |

### Keyboard Navigation

- All interactive controls reachable by Tab in logical DOM order.
- `sg-btn--danger` (Revoke) in the session table: each row's revoke button is independently focusable.
- The "Manage sessions" link-out from User Detail is a native `<a>` — no JS needed.
- The `<details>` progressive disclosure for any collapsible section is keyboard-accessible by default via native browser behavior.
- Breadcrumb links are native `<a>` elements.

### Responsive Behavior

| Viewport | Behavior |
|----------|---------|
| 320px–639px | Single-column. `sg-detail-grid` stacks to single column. Session table horizontally scrollable within `sg-table-panel`. Identity bar: name full-width, metrics strip wraps. `sg-card` padding reduces to `var(--sg-space-4)`. |
| 640px–1023px | Two-column detail grid (`sg-detail-grid`) active. Identity bar side-by-side layout possible. |
| 1024px+ | Full layout with `sg-admin-shell` max-width container. No layout shift. |

### Reduced Motion

- The `@media (prefers-reduced-motion: reduce)` universal clamp at `sigra_admin.css:1467-1478` handles all components automatically. No per-component reduced-motion overrides needed.
- `sg-confirm-dialog` entrance animation (`sg-confirm-enter` keyframe) is stripped to opacity-only under reduced-motion. This is existing behavior — do not change.
- No new animations introduced in this phase without a matching reduced-motion alternative.

### Theme Behavior

All components must render correctly in Light / Dark / System themes. This is guaranteed by using `--sg-color-*` tokens throughout — do not introduce hard-coded color values.

- `data-sg-admin-theme` on `html` root carries the explicit choice.
- `data-theme` on `.sg-admin-shell` mirrors it for component context.
- New UserSessionsLive must inherit the same shell structure as existing admin pages — no extra theme setup needed.

## State Matrix

Every state must be handled explicitly. Empty/loading/error/permission-denied must not show blank regions.

| State | User Detail behavior | Sessions page behavior |
|-------|---------------------|----------------------|
| Loading | `aria-busy="true"` on containing section; `sg-skeleton` placeholders for async-loaded sections | Same — skeleton for table body |
| Empty sessions | Identity bar metrics show `0 active`; Sessions preview shows `<.empty_state>` with message; no "Manage sessions" button (link still present) | Sessions page: full `<.empty_state>` |
| Empty orgs | Organizations preview shows `<.empty_state>` | n/a |
| Empty audit | Recent audit shows `<.empty_state>` | n/a |
| Permission denied | `notice` with `risk` tone: "You do not have permission to view this user." | Same pattern |
| User not found | `notice` with `risk` tone: "User not found." | Same pattern |
| Long content | All text fields truncate with `sg-truncate` at known max-width columns; UUID fields use `sg-code sg-truncate`; email uses `sg-truncate` with tooltip/full value accessible | Session table: IP and type columns truncate |
| Long display name | `sg-page-title` wraps — do NOT force nowrap on the h1 | n/a |
| Many sessions (stress) | Preview bounded to max 3 rows; "Manage sessions" CTA always present when sessions > 0 | Full table with pagination if needed |
| Many orgs (stress) | Preview bounded to max 3 orgs; "View all organizations" link when orgs > 3 | n/a |
| Keyboard only | All interactive controls reachable; focus ring visible via `--sg-ring` token | Same |
| No JS | Progressive disclosure `<details>` works natively; session link-outs work as plain `<a>` | Same |
