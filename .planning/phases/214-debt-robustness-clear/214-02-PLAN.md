<objective>
Harden `Sigra.Auth.delete_session/3` against foreign-token session revocation (IDOR/horizontal
privilege) by inserting a user_id ownership guard. Simultaneously resolve the IN-01 and IN-02
code-review nits: drop the unused `@return_to` socket assign and promote the five duplicated session
render helpers from both LiveViews into `Sigra.Admin.Components`.

Purpose: The admin revoke-session flow passes `user_id: user.id` in opts; without the guard, a
bug or adversarial caller could revoke any session token regardless of ownership. The D-08 guard
closes this at the library API layer, protecting all callers. The helper promotion eliminates the
silent-drift risk of byte-identical functions evolving independently across two LiveViews.

Output: Guard in `delete_session/3`; deny-path regression test; cleaned `user_sessions_live.ex`
(no `@return_to` assign, no private helper copies); cleaned `user_show_live.ex` (no private helper
copies); `Sigra.Admin.Components` extended with five new public helpers. D-08, D-09, D-10, D-11 resolved.

**Step 1 — Insert user_id guard into `delete_session/3` (per D-08).**

In `lib/sigra/auth.ex`, within `delete_session/3` (around line 1495), insert a user_id ownership
check INSIDE the `Telemetry.span` callback, wrapping the `session_store.delete/2` call. The guard
reads `user_id_constraint = Keyword.get(opts, :user_id)` before the span (to avoid re-reading inside
the anonymous function closure). Inside the Telemetry span:

```
case user_id_constraint do
  nil -> session_store.delete(hashed_token, store_opts)
  uid ->
    case session_store.fetch(hashed_token, store_opts) do
      {:ok, %{user_id: ^uid}} -> session_store.delete(hashed_token, store_opts)
      {:ok, _foreign} -> :ok
      {:error, :not_found} -> :ok
    end
end
```

The variable `user_id` that was previously bound from `Keyword.get(opts, :user_id)` for the audit
log must still be bound for the audit section that follows. Rename the guard binding to
`user_id_constraint` (or use the existing `user_id` binding if it was already present in the
pre-span section — check the actual line order in the live file before editing).

No change to the function signature, `@spec`, or `@callback delete/2` in the store. The audit log
block and its `user_id` / `actor_id` / `target_id` bindings are preserved after the span assignment.
