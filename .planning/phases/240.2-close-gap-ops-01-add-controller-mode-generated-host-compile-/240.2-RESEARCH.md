## Architecture Patterns

### System Architecture Diagram

```text
CI / local developer
  -> scripts/ci/passkeys-opt-out-smoke.sh
     -> run_leg("--no-admin --no-organizations --no-passkeys", "sigra_b2c_alpha")
        -> canonical LiveView B2C + OAuth + existing bounded limiter probe
     -> run_leg("--no-admin --no-organizations --no-passkeys --no-live", "sigra_b2c_controller")
        -> fresh Phoenix host
        -> local Sigra dependency + mix deps.get
        -> mix sigra.install (controller templates/routes/limiter)
        -> post-install mix deps.get
        -> assets.deploy -> compile --warnings-as-errors -> migrate -> boot -> curl /
        -> controller generated-host compile/boot proof
  -> focused ExUnit contracts
     -> assert both LiveView and controller legs are explicitly represented
  -> no browser, external OAuth, mail, device, or staging claim
```

The controller leg must share the generic lifecycle and differ only in fixed flags and a distinct app label. A distinct label matters because the harness derives the generated application/module paths, cleanup allowlist, port-variable name, log location, and assertions from that label. [VERIFIED: `scripts/ci/passkeys-opt-out-smoke.sh`]

**When to use:** Use for a new installer flag combination that must be proven as a fresh generated Phoenix application, rather than merely checked in template/source unit tests. [VERIFIED: `.planning/v1.48-MILESTONE-AUDIT.md`, `test/sigra/install/features/core_test.exs`]

### Pattern 2: Separate proof ownership

**What:** Keep the canonical LiveView B2C leg and controller B2C leg independent within the fresh-generator harness, while keeping the separate generated-auth runtime harness LiveView-only. [VERIFIED: `240.2-CONTEXT.md`, `test/sigra/install/generated_rate_limit_contract_test.exs`]

**Anti-Patterns to Avoid**

- **Changing the canonical leg’s flags:** Do not add `--no-live` to `sigra_b2c_alpha`; that destroys the locked LiveView profile rather than proving an additional controller profile. [VERIFIED: `240.2-CONTEXT.md`, `test/sigra/install/generator_passkeys_opt_out_test.exs`]
- **Applying the B2C-only OAuth/limiter probe to the controller label by accident:** The current probe hard-codes the LiveView B2C application module and is intentionally installed only for `sigra_b2c_alpha`; the controller closure requires lifecycle compile/boot proof, not a copied or mismatched runtime probe. [VERIFIED: `scripts/ci/passkeys-opt-out-smoke.sh`, `240.2-CONTEXT.md`]
- **Forgetting guarded cleanup:** Add the controller label to `cleanup_leg_dir`’s allowlist before it can be deleted; otherwise the harness deliberately refuses deletion. [VERIFIED: `scripts/ci/passkeys-opt-out-smoke.sh`]
- **Weakening the failing contract:** Change contracts to require distinct controller and LiveView leg markers; do not delete the existing `--no-live` expectation. [VERIFIED: `.planning/v1.48-MILESTONE-AUDIT.md`, `test/sigra/install/generated_rate_limit_contract_test.exs`]
- **Adding sleeps:** Boot readiness already uses bounded curl retries and the scope forbids wait-based proof. [VERIFIED: `scripts/ci/passkeys-opt-out-smoke.sh`, `240.2-CONTEXT.md`, `AGENTS.md`]

## Common Pitfalls

### Pitfall 1: Replacing instead of adding the B2C leg

**What goes wrong:** The canonical B2C profile silently becomes controller mode and LiveView ownership loses its fresh-host proof. [VERIFIED: `240.2-CONTEXT.md`]

**How to avoid:** Retain the existing exact `sigra_b2c_alpha` invocation and append a distinct `sigra_b2c_controller` invocation. Add source-contract checks for both. [VERIFIED: `scripts/ci/passkeys-opt-out-smoke.sh`, `test/sigra/install/generated_rate_limit_contract_test.exs`]

### Pitfall 2: Treating `--no-live` source presence as closure

**What goes wrong:** Controller-only routing/template or generated application compilation failures remain undetected. [VERIFIED: `.planning/v1.48-MILESTONE-AUDIT.md`, `test/sigra/install/features/core_test.exs`]

**How to avoid:** Let the controller leg reach `mix compile --warnings-as-errors`, `mix assets.deploy`, database migration, server boot, and curl readiness. [VERIFIED: `240.2-CONTEXT.md`, `scripts/ci/passkeys-opt-out-smoke.sh`]

### Pitfall 3: Fresh dependency ordering regression

**What goes wrong:** A dependency injected by `mix sigra.install` is not fetched before a generated-host compile attempt. [VERIFIED: `test/sigra/install/generated_rate_limit_contract_test.exs`, `scripts/ci/passkeys-opt-out-smoke.sh`]

**How to avoid:** Do not bypass `run_leg`; its post-install `MIX_ENV=dev mix deps.get` precedes probe/compile, and the existing contract guards that order. [VERIFIED: `scripts/ci/passkeys-opt-out-smoke.sh`, `test/sigra/install/generated_rate_limit_contract_test.exs`]

### Pitfall 4: Scope leak into OAuth/provider proof

**What goes wrong:** The controller leg begins to claim real OAuth, mail, or device behavior or duplicates the separate runtime suite. [VERIFIED: `240.2-CONTEXT.md`]

**How to avoid:** Keep inherited Google credentials unset globally, retain the disposable Cloak fixture only, and limit the new lane to compile/boot evidence. [VERIFIED: `scripts/ci/passkeys-opt-out-smoke.sh`, `240.2-CONTEXT.md`]
