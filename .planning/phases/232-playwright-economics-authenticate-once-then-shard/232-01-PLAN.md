<objective>
Build the phase's measurement instrument end-to-end and use it, on a real run, to record the
pre-change per-step baseline that D-31's proof ordering (PW-01 land -> PW-01 measured -> PW-03 ->
PW-02 -> PW-02 measured) depends on.

`scripts/ci/` instrument, its hermetic self-test, its `fast_checks` wiring, and a real observed run
read back by ID into an evidence ledger — proven end-to-end before any expansion task restructures
a workflow or a spec.

honestly today: `scripts/ci/ci-run-metrics.sh:93-125` is job-level only (D-11), and five of the six
Playwright seams have never been measured at step granularity at all. The instrument is therefore a
blocker for PW-02's *design*, not merely for PW-01's *proof*.
Output: `scripts/ci/ci-step-metrics.sh`, `scripts/ci/ci-step-metrics.test.sh`, a `fast_checks` step,
and `232-EVIDENCE.md` with `BEFORE-STEPS` captured against a real run ID.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions API -> local shell | Untrusted-shaped JSON (missing fields, zero-dates, empty arrays) crosses into a script whose output becomes committed evidence |
| Runner environment -> instrument | `GH_TOKEN` / `gh` credentials are ambient in CI when the instrument runs |
| Instrument -> committed ledger | A number that reaches `232-EVIDENCE.md` is treated as proven for the rest of the phase |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-232-01 | Information Disclosure | `ci-step-metrics.sh` stdout/stderr | medium | mitigate | Never echo a token or the `gh` environment; invoke `gh` bare via PATH (the same rule `ci-run-metrics.sh`'s header records). Self-test runs with no `GH_TOKEN` and a stub. |
| T-232-02 | Tampering | evidence produced by an unproven instrument | high | mitigate | `ci-step-metrics.test.sh` wired into `fast_checks` with explicit fail-closed cases D..H; the instrument cannot silently start returning empty or clamped-to-zero output without the self-test reddening. |
| T-232-03 | Repudiation | a duration claim with no traceable source | high | mitigate | Ledger slot grammar forces `Status: captured (run <id>)`, the run id repeated twice, and a fenced block naming the producing command — the same contract `p12` enforces for the 230 ledger. |
| T-232-04 | Spoofing | a PATH-shadowed `gh` leaking outside the self-test sandbox | low | mitigate | Stub is created under a `mktemp -d` sandbox with `trap cleanup EXIT`, exactly as `ci-run-metrics.test.sh` does. |
| T-232-SC | Tampering | npm/pip/cargo installs | low | accept | Vacuous: this phase changes no dependency manifest (RESEARCH § Package Legitimacy Audit). Any `npm install` / `mix deps` change would mean the design left the phase's scope and must be surfaced, not absorbed. |
