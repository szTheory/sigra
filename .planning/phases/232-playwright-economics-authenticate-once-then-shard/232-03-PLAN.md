Create `scripts/ci/playwright-shard-nonempty.sh`, a thin wrapper that runs a Playwright invocation and
then asserts it actually executed something. Header contract comment states: this is the ONE place a
Playwright invocation is proven non-empty; the hazard is that `--shard` suppresses Playwright's own
`No tests found` exit-1 so an empty run exits 0 with zero stdout (RESEARCH E-3, verified live against
the pinned 1.59.1); and the flag `--pass-with-no-tests` existing does not imply the default is safe on
the shard path (E-5).

CLI: `--report <path>` (default `.playwright/last-run-report.json`, resolved relative to the current
working directory, which callers set to `test/example/priv/playwright`), `--min <n>` (default `1`),
`--label <text>` (used in messages and in the step summary line), and a `--` separator after which
every remaining argument is passed through verbatim to `npx playwright test`. An unrecognised flag
before `--` prints to stderr and exits 2 having invoked nothing.

Execution order, and each step exists for a reason:
1. Delete the report path if present. Without this, a crashed invocation leaves the previous run's
   report on disk and the assertion reads a stale, healthy-looking count — a green on nothing by a
   second route.
2. Run `npx playwright test` with the passthrough arguments, capturing the exit code without letting
   `set -e` abort.
3. If the report file does not exist afterwards, fail closed with a message ending in the repo
   convention "the parse broke, this is not a pass". An absent report is a broken run, never an empty
   one.
4. If the report is not valid JSON or has no `.stats` object, fail closed the same way.
5. Compute executed as `.stats.expected + .stats.unexpected + .stats.flaky`. Deliberately exclude
   `.stats.skipped`: a test that Playwright found but did not run does not prove the leg did work.
   Record all four numbers in the message and, when `GITHUB_STEP_SUMMARY` is set, append one line
   naming the label and the four numbers so the count is readable from the run without downloading an
   artifact (this is the D-14 evidence surface).
6. If executed is below `--min`, print a GitHub `::error::` annotation naming the label, the observed
   number, the floor, and the E-3 explanation, then exit 1.
7. Otherwise exit with Playwright's own captured exit code. The wrapper adds a floor; it never converts
   a red into a green.

Create `scripts/ci/playwright-shard-nonempty.test.sh`, hermetic, structurally copied from
`ci-run-metrics.test.sh`: `mktemp -d` sandbox, `trap cleanup EXIT`, a PATH-shadowed recording `npx`
stub that writes a canned report and exits with a chosen code, letter-labelled cases, pass/fail
counters, no network. Cover at minimum:
A. stub writes a report with expected 39, exits 0 -> wrapper exits 0 and its output names 39.
B. stub writes a report with all four stats at 0 (the E-2 file-count trigger) -> wrapper exits 1 and
   the message contains the shard explanation.
C. stub writes nothing and exits 0 (the E-3 silent-empty trigger, where Playwright produced no report)
   -> wrapper exits non-zero, fail-closed.
D. a stale report with expected 5 is pre-seeded, the stub writes nothing and exits 0 -> wrapper still
   exits non-zero, proving the pre-delete in step 1 works. This is the case that proves the wrapper
   cannot be fooled by a previous invocation.
E. report present but malformed JSON -> non-zero.
F. stub writes expected 12 and exits 1 (real test failure) -> wrapper exits 1, propagating the code,
   and does not claim emptiness.
G. unknown flag before `--` -> exit 2 with zero recorded stub invocations.
H. `--min 39` with a report showing 12 -> exit 1, message names both 12 and 39.
I. `GITHUB_STEP_SUMMARY` pointed at a sandbox file -> after case A, that file contains a line naming
   the label and the counts.

Wire the self-test into `fast_checks` in `.github/workflows/ci.yml`, in the self-test region
