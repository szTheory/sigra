# Phase 16 — UI Design Contract

> Visual and interaction contract for the org user-facing surface: switcher dropdown, org landing/picker, create-org form, settings page (rename / slug / soft-delete), and members list. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Stack baseline:** Phoenix 1.8 generated `core_components.ex` + daisyUI 5 + Tailwind v4 + Heroicons. All templates in this phase ship as **generator templates** under `priv/templates/sigra.install/organizations/` (not compiled library components — per CONTEXT D-28 / D-29 UI Ownership Rule). Zero new library UI components.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (shadcn N/A — this is an Elixir/Phoenix project) |
| Preset | not applicable |
| Component library | daisyUI 5 (via Tailwind v4 plugin, already bundled in `priv/static/assets/default.css`) |

| Font | `var(--font-sans)` — system font stack inherited from Tailwind v4 defaults (ui-sans-serif, system-ui, sans-serif). No custom webfont. |

| xs | `gap-1` / `p-1` | 4px | Icon-to-label gap inside buttons and badges |
| sm | `gap-2` / `p-2` | 8px | Compact inline form fields, switcher menu item padding |
| md | `gap-4` / `p-4` | 16px | Default card padding, form field gap, table cell padding |
| lg | `gap-6` / `p-6` | 24px | Settings section padding, members table outer wrapper |

| 3xl | `py-16` | 64px | Max page-top spacing on landing hero |

**Exceptions:** none. All layout spacing is 4px-aligned.

## Typography

Inherit Phoenix 1.8 / Tailwind v4 defaults. Declared roles (exactly 4 sizes, exactly 2 weights):

| Role | Tailwind class | Size | Weight | Line Height | Usage |
|------|----------------|------|--------|-------------|-------|

## Color

60/30/10 allocation mapped to daisyUI semantic tokens (theme-swappable by host dev in v1.2):

| Role | daisyUI token | Hex (default light) | Usage |
|------|---------------|---------------------|-------|
| Dominant (60%) | `base-100` | #ffffff | Page background, card surfaces, modal panels, table rows |
| Secondary (30%) | `base-200` + `base-content/70` | #f2f2f2 / rgba text | Section card backgrounds (settings sections), table header row, disabled states, subtitle text |
| Accent (10%) | `primary` (btn-primary) | daisyUI primary | **Reserved for:** Primary CTA buttons only — "Create organization", "Save changes", "Switch" form submit in switcher, "Change role" confirm. Active org highlight bar in switcher dropdown. Role "Owner" badge. |
| Destructive | `error` (btn-error, alert-error, badge-error, text-error) | daisyUI error | Danger Zone section border-left + button, "Delete organization" confirm, "Remove member" confirm, form field errors, flash error toast |
| Warning | `warning` (alert-warning) | daisyUI warning | Slug-change advisory banner ("7-day redirect window") |

**Accent reserved-for list (explicit):**
1. Primary CTA buttons (one per screen, e.g. "Create organization", "Save", "Switch")
2. Active-org highlight row in switcher dropdown (`menu-active`)
3. "Owner" role badge (`badge-primary`)

**Accent NOT used for:** body links (use `link link-hover` default neutral), table row hovers (use `hover` zebra), secondary buttons (`btn-soft`), icons in body copy.

**Role badge variants:**
- Owner: `badge badge-primary` (accent — denotes elevated role)
- Admin: `badge badge-neutral` (neutral — visible but non-accent)
- Member: `badge badge-ghost` (lowest visual weight — default state)

**Destructive "red zone" treatment** (settings Danger Zone card):
```
<section class="mt-8 rounded-lg border border-error/40 border-l-4 border-l-error bg-base-100 p-6">
  <.header>Danger zone</.header>
  ...
</section>
```
Border-left-4 in `error`, full border in `error/40` tint, base-100 surface, `text-error` on the destructive button itself (`btn btn-error`).

## Copywriting Contract

### Voice

Match `phx.gen.auth` 1.8 tone: authoritative, terse, reversible-state language. No emoji. No exclamation marks except success confirmations. Destructive actions use clinical language ("Delete", "Remove", "Soft-delete") not friendly euphemisms ("Say goodbye", "Wave off"). Second person ("you", "your organization").

### Primary CTAs (one per screen)

| Screen | Primary CTA label | Button variant |
|--------|-------------------|----------------|
| `OrganizationsLive.Index` zero-state | `Create organization` | `btn btn-primary` |
| `OrganizationsLive.Index` picker state | `Open` (per-row) + `+ New organization` (secondary) | `btn btn-primary btn-sm` / `btn btn-soft btn-sm` |
| Create org form | `Create organization` | `btn btn-primary` |
| Settings — General (rename) | `Save name` | `btn btn-primary` |
| Settings — Slug (disclosed) | `Change slug` (disclosure trigger) → `Update slug` (form submit, destructive) | `btn` / `btn btn-error` |
| Settings — Danger Zone (disclosed) | `Delete organization` (disclosure trigger) → `Delete organization permanently` (form submit) | `btn btn-error btn-soft` / `btn btn-error` |
| Members list | `Invite member` (Phase 17 stub, disabled in Phase 16 with tooltip "Available in the next release") | `btn btn-primary` |
| Members row actions | `Change role` / `Remove` | `btn btn-ghost btn-xs` inside `<details class="dropdown dropdown-end">` |
| Switcher dropdown | `Switch` (per-org form submit, visually `menu-item`) + `+ Create organization` + `Organization settings` | `menu menu-sm` items |
| Signup first-org (via `OrganizationsLive.Index` zero-state after redirect) | `Create organization` + `Skip for now` secondary link back to `/` | `btn btn-primary` / `link link-hover text-sm` |

### Empty States

| Screen | Heading | Body |
|--------|---------|------|
| `OrganizationsLive.Index` — zero orgs, zero invites | `Create your first organization` | `You don't belong to any organizations yet. Create one to get started, or skip for now and an invitation link will bring you back here.` |
| `OrganizationsLive.Index` — zero orgs, pending invites | `You have {n} pending invitation(s)` | `Accept an invitation below, or create your own organization.` |
| Members list — single member (only self) | `You're the only member so far` | `Invite teammates to collaborate. Pending invitations appear below.` (invite CTA disabled in Phase 16, enabled in Phase 17) |
| Pending invitations section (Phase 16 stub) | `No pending invitations` | `Invitations sent from this page will appear here until they're accepted or revoked.` |
| Switcher dropdown — user in 1 org only | _no dropdown rendered_ | The switcher renders the active-org chip with role badge, but no menu — clicking is a no-op. `+ Create organization` link still visible as a secondary chip. |
| Switcher dropdown — user in 0 orgs | _not rendered at all_ | Phase 14's `:require_active_organization` redirect fires before any page with the switcher renders. |

### Error States

| Scenario | User-facing copy | Recovery path |
|----------|------------------|---------------|
| Slug taken at create | `That slug is already in use. Try another.` | Inline field error on slug input |
| Slug reserved | `That slug is reserved. Try another.` | Inline field error |
| Slug invalid format | `Slugs can only contain lowercase letters, numbers, and hyphens.` | Inline field error |
| Password wrong on slug/delete confirm | `That password is incorrect.` | Inline field error on password input; modal/form stays open |
| Typed-confirm mismatch on slug change | `Type {current_slug} exactly to confirm.` | Inline field error; submit button stays disabled until match |
| Typed-confirm mismatch on delete | `Type {org_name} exactly to confirm.` | Inline field error; submit button stays disabled until match |
| Last-owner guard trips on role change | `Cannot demote the last owner. Promote another member to owner first.` | Modal stays open, inline error above role dropdown |
| Last-owner guard trips on remove | `Cannot remove the last owner. Promote another member to owner first.` | Modal stays open, inline error above member name |
| Stale session pointer (org deleted / access revoked) | `That organization is no longer available. Choose another below.` | Flash on `/organizations` after redirect (Phase 14 D-09 copy) |
| 404 — slug not found OR not a member (enumeration-safe) | `Page not found` (Phoenix default 404 template, unchanged) | Navigate to `/organizations` |
| Sudo expired mid-form | `Your verification expired. Enter your password again.` | Flash + form re-renders password field empty; changeset errors preserved |
| URL slug mismatch + user IS member (auto-recover) | _no error_ — silent session pointer refresh per D-04 | N/A |

### Destructive Action Confirmations

All destructive confirmations use the **native `<dialog class="modal">`** pattern (daisyUI) — NOT a custom `<.modal>` component. Native `<dialog>` handles focus trap + Esc-to-close natively. Rendered via `modal.showModal()` / `modal.close()` JS, triggered from Phoenix LV events.

Typed-confirmation modals follow this exact copy template:

```
Title: {Action verb} {resource}?
Body:  {One-sentence consequence statement.}
       Type {token} below to confirm.
Input: [typed-confirm field, aria-describedby="confirm-help"]
Help:  "Type {token} exactly. This action {cannot|can} be undone."
Submit: {destructive label}   [disabled until input matches token]
Cancel: Cancel                [btn btn-ghost]
```

Per-action copy:

| Action | Token | Title | Body | Submit button | Undo-able? |
|--------|-------|-------|------|---------------|------------|
| Change slug | `{current_slug}` | `Change organization slug?` | `Your current slug {current_slug} will redirect to the new slug for 7 days, then become available for others. Existing links and bookmarks keep working during the redirect window.` | `Update slug` (btn-error) | Partially (7-day redirect) |
| Soft-delete organization | `{org.name}` | `Delete {org.name}?` | `This soft-deletes the organization. Members lose access immediately. An operator can restore it from the database until hard-delete runs.` | `Delete organization permanently` (btn-error) | Yes (soft-delete, operator restore) |
| Remove member | _no typed confirm_ | `Remove {email} from {org.name}?` | `{email} will be signed out of this organization immediately. You can re-invite them later.` | `Remove member` (btn-error) | Yes (re-invitation) |
| Change member role | _no typed confirm_ | `Change {email}'s role to {new_role}?` | Role-specific consequence: **member → admin**: `Admins can invite, remove, and change roles for other members.` / **admin → member**: `They will lose admin capabilities.` / **any → owner**: `Owners have full control including deletion.` / **owner → admin**: `They will lose owner capabilities. Another owner must remain.` | `Change role` (btn-primary) | Yes |

### Success Flashes (`<.flash kind={:info}>`)

| Action | Flash copy |
|--------|------------|
| Organization created | `Organization created.` |
| Organization renamed | `Name updated.` |
| Slug changed | `Slug updated. The old slug redirects for 7 days.` |
| Organization soft-deleted | `Organization deleted.` (redirects to `/organizations`) |
| Organization switched | `Switched to {org.name}.` |
| Member role changed | `Role updated.` |
| Member removed | `Removed {email} from {org.name}.` |

Error flashes use `<.flash kind={:error}>` — the same toast position (`toast-top toast-end`) as v1.0.

## Screen Anatomy

### 1. Header Organization Switcher (`<.org_switcher />`)

**Placement:** right side of header, left of user menu, inside `<header>` in generated `layouts.ex`. Host pastes per post-install instructions (D-24).

**Trigger:** daisyUI `<details class="dropdown dropdown-end">` — click to open, click-outside to close, Esc closes. No hover trigger (touch-friendly + matches GitHub/Linear pattern).

**Closed state anatomy (trigger chip):**
```
[avatar-initials] {org.name}  [role-badge]  [chevron-down]
```
- Avatar: 24px square, `bg-primary/10 text-primary-content` rounded, first 2 chars of org name
- Name: `text-sm font-semibold`, truncate at 20 chars with CSS ellipsis
- Role badge: `badge badge-xs` using role variants from Color section
- Chevron: `hero-chevron-down` 16px

**Open state contents:**
```
┌──────────────────────────────────────┐
│ ACTIVE                               │  ← menu-title, text-xs uppercase
│ [✓] {active_org.name} [role-badge]   │  ← menu-active, primary tint
├──────────────────────────────────────┤
│ SWITCH TO                            │  ← menu-title, only if other orgs exist
│ {other_org_1}  [role-badge]          │  ← each wraps a tiny <form method="post" action={~p"/organizations/switch"}>
│ {other_org_2}  [role-badge]          │
├──────────────────────────────────────┤
│ [icon] + Create organization         │  ← link to /organizations/new
│ [icon] ⚙ Organization settings       │  ← only if role in [:owner, :admin]
│ [icon] 👥 Manage organizations       │  ← link to /organizations
└──────────────────────────────────────┘
```

**Keyboard:** Native `<details>` handles Space/Enter to toggle. Tab order: trigger → first menu item → ... → last menu item → next focusable. Esc closes the details via JS hook (one-line `el.addEventListener('keydown', e => e.key === 'Escape' && el.removeAttribute('open'))`).

**ARIA:** `<summary>` gets `aria-label="Organization switcher"`, `aria-expanded` reflects `open` attribute. Each form-wrapped menu item has an `aria-label="Switch to {org.name}"`.

**Loading state:** no skeleton — `@user_organizations` is hydrated at `on_mount` before first render. If the list is empty at render time (should never happen for authenticated users under `:require_active_organization`), the trigger renders as the active chip only with no menu arrow.

**Branch B — `([], [_|_])` zero orgs + pending invites:**

### 4. Organization Settings — `OrganizationSettingsLive`

Route: `/organizations/:org/settings`. Three stacked sections, single page, no tabs, no sub-routes. Matches v1.0 `settings_live.ex` pattern (D-10).

**Layout:**
```
<.header>Organization settings<:subtitle>{org.name}</:subtitle></.header>

<section class="bg-base-200 p-6 rounded-lg mt-6">
  <h2 class="text-lg font-semibold">General</h2>
  <.form ... rename form, single name field, [Save name] button>
</section>

<section class="bg-base-200 p-6 rounded-lg mt-8">
  <h2 class="text-lg font-semibold">Slug</h2>
  <p class="text-sm text-base-content/70">Current: <code>{org.slug}</code></p>
  <%= if @slug_form_open? do %>
    <.form ... inline progressive disclosure: new slug + current password + typed-confirm field>
      <div role="alert" class="alert alert-warning alert-soft">
        <.icon name="hero-exclamation-triangle" /> {warning about 7-day redirect}
      </div>
      [Update slug] [Cancel]
    </.form>
  <% else %>
    <.button phx-click="open_slug_form">Change slug</.button>
  <% end %>
</section>

<section class="mt-8 rounded-lg border border-error/40 border-l-4 border-l-error bg-base-100 p-6">
  <h2 class="text-lg font-semibold text-error">Danger zone</h2>
  <p class="text-sm">Soft-delete this organization. Members lose access immediately.</p>
  <%= if @delete_form_open? do %>
    <.form ... current password + typed-confirm of org.name>
      [Delete organization permanently] [Cancel]

  <% else %>
    <.button variant={nil} class="btn btn-error btn-soft" phx-click="open_delete_form">

```

**Progressive disclosure (D-12):** Slug and Danger Zone sections start with a single button. Clicking flips `@slug_form_open?` / `@delete_form_open?` and reveals the form inline (no modal). Cancel button closes the form. Same-page state, no route changes.

### 6. 403 / Not-a-Member Page

Per D-04, slug-not-found and not-a-member both return **404** (enumeration prevention). Uses Phoenix default 404 template — **no new template ships in Phase 16**. ## Accessibility Contract

| Requirement | Implementation |
|-------------|----------------|
| Contrast ratio ≥ 4.5:1 for body text | daisyUI `base-content` on `base-100` meets WCAG AA by default in the daisyUI light theme |
| Contrast ratio ≥ 3:1 for large text (18px+ semibold) | Headings use `base-content` — meets AA |
| Focus visible on all interactive | Tailwind v4 default `outline` styles (do NOT remove) |
| Modal focus trap | Native `<dialog>` handles this — Tab cycles inside the dialog, Esc closes |
| Modal return focus | Native `<dialog>.close()` returns focus to the element that called `showModal()` |
| ARIA on switcher | `<summary aria-label="Organization switcher" aria-expanded={...}>`; menu role implicit via `<ul class="menu">` |
| Live region for slug auto-gen feedback | Slug preview under name input has `aria-live="polite"` |
| Form errors announced | `<.input>` from core_components wraps errors in `<p>` with error icon; field has `aria-invalid` and `aria-describedby` pointing to error |
| Role badge semantics | Badge has visible text ("Owner", "Admin", "Member") — color is not the sole carrier of meaning |
| Keyboard-only switcher | Space/Enter on `<summary>` toggles; Tab navigates items; Esc closes via 1-line JS hook |
| Destructive action ARIA | Modal `<dialog>` has `aria-labelledby` pointing to modal title, `aria-describedby` pointing to body copy |
| Error flashes | `role="alert"` already set on `<.flash>` in core_components — inherited |
| Disabled "Invite member" button | `disabled` attr + `aria-disabled="true"` + `title` attribute for hover tooltip + visible text stays legible |
