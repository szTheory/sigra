<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host scope -> admin policy behaviour | Host app declares admin rights; Sigra must only execute that explicit contract |
| router/plug -> LiveView mount | LiveView navigation can bypass Plug checks unless on-mount parity exists |
| requested admin org URL -> query/mutation scope | URL params choose admin scope and must not leak cross-org access |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-05 | E | admin policy resolution | mitigate | `Sigra.Admin.Policy` has no fallback admin inference; all grants come from `platform_admin?/1` and `admin_org_ids/1` only. |
| T-27-06 | E | LiveView admin auth | mitigate | `Sigra.LiveView.AdminScope` duplicates route protection in `on_mount/4`, covering the plug-only auth gap documented in 27-RESEARCH. |
| T-27-07 | I | org-scoped admin access | mitigate | `Sigra.Admin.Scope.resolve/4` distinguishes `/admin` from `/admin/organizations/:org` and denies out-of-scope org routes before any page render. |
| T-27-08 | I | query-after-fetch org leakage | mitigate | The resolved admin scope is structural and organization-specific; later query code must consume this object instead of filtering global results in templates. |
| T-27-09 | T | ambiguous admin route meaning | mitigate | Separate library LiveViews and route-mode resolution for `:global` and `:organization` keep scope explicit and test-covered. |
</threat_model>
