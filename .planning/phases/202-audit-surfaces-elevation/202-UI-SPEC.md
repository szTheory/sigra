# Phase 202 — UI Design Contract

> Visual and interaction contract for the Audit Surfaces Elevation phase (`audit_index_live.ex` + `audit_user_live.ex`). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Stack note:** This is an Elixir/Phoenix LiveView (HEEx) project with a hand-authored, cascade-layered `sg-*` BEM/token design system (`test/example/priv/static/assets/sigra_admin.css` and its two byte-identical copies). There is **no shadcn / Tailwind-config / React** surface — the shadcn initialization gate and registry safety gate are **not applicable**. Every value below is sourced from the ratified `:root --sg-*` token layer; this phase **composes existing tokens only** (REQUIREMENTS "no token-value redesign"). No new hex, no new tokens.
>
> **Phase posture:** In-place refactor + DRY + ratchet. Zero new dependencies, zero new routes, and (target) **zero new CSS** (browser-default `<details>` + existing `sg-filter-panel`/`sg-form-grid`/`sg-table-panel` chrome). Any new `sg-*` class triggers the CSS triple-copy golden-diff gate (D-13) and is discouraged.

## Spacing Scale

Declared values — the ratified `--sg-space-*` scale (4px base). All audit-surface spacing MUST use these tokens; no one-off pixel values.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| `--sg-space-1` | 4px (0.25rem) | Inline gaps within a cell stack (`sg-stack--1`), pill/badge internal gaps |
| `--sg-space-2` | 8px (0.5rem) | Compact clusters — quick-toggle chip gaps, applied-chip row gaps |
| `--sg-space-3` | 12px (0.75rem) | Results-list row rhythm (`sg-stack--3`), filter action-row gaps |
| `--sg-space-4` | 16px (1rem) | Default panel padding, table cell padding, form-grid gaps |
| `--sg-space-5` | 20px (1.25rem) | Secondary section separation |
| `--sg-space-6` | 24px (1.5rem) | Outer page-section rhythm (`sg-stack--6`): filter panel ↔ results ↔ pagination |
| `--sg-space-8` | 32px (2rem) | Wide-viewport panel inset (`@media` desktop) |
| `--sg-space-10` / `--sg-space-12` | 40px / 48px | Empty-state vertical breathing room |

**Density/whitespace rhythm proxy (Tier-2, D-11):** outer sections `sg-stack--6`, results list `sg-stack--3`, in-cell stacks `sg-stack--1`. Document this rhythm in the ledger Evidence column.

Exceptions: none. The disclosure `<summary>` affordance and all interactive targets (Apply filters / Clear / Export CSV / quick-toggle chips / applied-chip remove / pagination Prev/Next / inline-code `<summary>`) MUST present a **≥24×24px** hit target (target-size Tier-2 proxy, documented-as-manual).

## Typography

The ratified `--sg-text-*` size ramp and `--sg-leading-*` line-heights. Two weights only (regular body, semibold emphasis — brand face carries weight at headings). No new sizes introduced this phase.

| Role | Token | Size | Weight | Line Height |
|------|-------|------|--------|-------------|
| Body / cell text | `--sg-text-sm` | 14px (0.875rem) | 400 regular | `--sg-leading-normal` 1.5 |
| Label / pill / code / muted meta | `--sg-text-xs` | 12px (0.75rem) | 400 regular (600 for pill labels) | 1 (pills) / 1.5 (meta) |
| Section / panel heading | `--sg-text-md`–`--sg-text-lg` | 18px–23px (1.125–1.45rem) | 600 semibold | `--sg-leading-snug` 1.3 |
| Page title (per-user header) | `--sg-text-xl` | 30px (1.875rem) | 600 semibold | `--sg-leading-tight` 1.1 |

Notes:
- Raw codes (`row.id`, `row.action`) render as `<code class="sg-code">` at `--sg-text-2xs`/`--sg-text-xs` monospace **inside the inline disclosure** — they MUST remain real `code.sg-code` text nodes (not `data-*` attrs or JS-only clipboard payloads) so the content-equivalence helper still extracts 2 (D-06, Pitfall 1).
- Human-readable primary cell uses `action_label` (in an `sg-status-pill` toned by `audit_tone/1`) + optional `action_badge` (toned `info`).

## Color

The ratified `--sg-color-*` semantic tokens (light values shown; every token has a dark pair). The audit surfaces are operator data tables — **color is reserved, not decorative.** The 60/30/10 split maps onto the admin shell:

| Role | Token (light) | Usage |
|------|---------------|-------|
| Dominant (60%) | `--sg-color-subtle` `#f6f5f2` / `--sg-color-canvas` shell | Page canvas behind panels |
| Secondary (30%) | `--sg-color-panel` `#ffffff` / `--sg-color-panel-alt` `#fbfaf7` | Filter panel, table panel, list rows, cards |
| Accent (10%) | `--sg-color-brand` `#c2410c` (burnt orange; `--sg-color-brand-soft`/`-strong` for fills) | Primary action only — see reserved list |
| Status: risk/destructive | `--sg-color-risk` `#b42318` / `-soft` | Failure-tone audit rows/pills (`data-tone="risk"`), risk semantics only |
| Status: warn | `--sg-color-warn` `#a15c00` / `-soft` | Caution-tone audit signals |
| Status: ok | `--sg-color-ok` `#176b43` / `-soft` | Success-tone audit rows/pills |
| Status: info | `--sg-color-info` `#1d4ed8` / `-soft` | Impersonation/`action_badge` (`data-tone="info"`) |
| Text / muted / line | `--sg-color-ink` `#151515` / `--sg-color-muted` `#686868` / `--sg-color-line` | Body text, secondary meta, borders |

**Accent reserved for:** the single primary CTA per panel — `Apply filters` (`sg-btn--primary`). NOT for: Export CSV (`sg-btn--secondary`), Clear (`sg-btn--ghost`), quick-toggle chips, applied chips, table headers, links, or row borders. Status tones (risk/warn/ok/info) are driven exclusively by `audit_tone/1` data semantics — never hand-applied for emphasis.

**No new colors, no token-value changes** (REQUIREMENTS out-of-scope). Three-surface ember parity (`brandbook/tokens.json` ⇄ admin `--sg-color-brand` ⇄ auth accent) is preserved by not touching the token layer.

## Copywriting Contract

Both audit pages are already glossary-scoped (`glossary_test.exs:28-29`); all microcopy is auto-guarded one-term-per-concept (glossary-clean Tier-2 proxy, D-11/D-14). Preserve existing strings unless DRY consolidation requires a single shared phrasing — when consolidating, keep the **filter-aware index copy** as the richer canonical and parametrize per-page divergence (D-09).

| Element | Copy |
|---------|------|
| Primary CTA | **Apply filters** (`sg-btn--primary`, in the consolidated filter action row) |
| Secondary action | **Export CSV** (`sg-btn--secondary`) — stays in the filter action row, NOT relocated (D-04); checkpoint asserts it visible |
| Tertiary action | **Clear** (`sg-btn--ghost`) — resets to the unfiltered view |
| Advanced-disclosure summary | **More filters** (or equivalent glossary-clean phrasing) — `<summary>` for the native `<details>` holding text/date fields (D-02) |
| Quick-toggle labels | **Failures**, **Impersonation** — stay visible as folded-in summary controls outside the disclosure (D-01/D-02) |
| Inline-code disclosure summary | a glossary-clean affordance label (e.g. **Event codes** / **Details**) revealing the raw `event_id` + action code as `code.sg-code` (D-05); codes stay accessible for forensic/regulatory users |
| Empty state heading (index) | **No audit events match this view** |
| Empty state body (index) | "No audit events match the active filters. Clear one or more to widen the timeline." + **Clear all filters** link |
| Empty state heading (per-user) | **No audit events for this user** |
| Applied-filter chip-clear | **Clear all** (index) / **Clear all filters** (empty-state) — keep both as-is; navigation-only `<a>` |
| Pagination | `aria-label="Previous page"` / `aria-label="Next page"` — absent entirely when `multi_page?/1` is false (honest pagination, D-10) |
| Error state | LiveView/admin-scope errors flow through the existing admin authorization + flash path — no new error surface in this phase |

**Destructive confirmation:** **None.** Neither audit surface owns a destructive action or modal dialog. The overlay-axe and 7-APG-dialog Tier-2 gates are therefore **N/A** for both cells — cite N/A in the ledger (mirror `users-index-live:87`); do **not** fabricate an overlay/dialog pass (false Tier-2 claim fails Phase-204 adversarial review, D-11).

## Interaction & State Contract (phase-specific)

Beyond the static tokens above, the executor MUST honor these interaction contracts:

| Contract | Requirement | Source |
|----------|-------------|--------|
| State path | GET-form / URL-driven only — `handle_params/3` is the **single** state path. No `phx-click` toggles, no LiveView-assign disclosure state. | D-03 |
| Disclosure mechanism | Native CSS-only `<details>`/`<summary>` for **both** the advanced-filter disclosure and the inline-code disclosure. No `phx-hook`, no client JS, no motion → no reduced-motion/axe risk. | D-02, D-05 |
| Inline-code DOM placement | Both `<code class="sg-code">` nodes (id + action) MUST remain inside `[data-testid="admin-audit-desktop-results"]`, even when visually inside `<details>`, so `assertAuditResultEquivalence` still extracts exactly 2. Prefer `<details>`-in-Event-cell over a sibling `<tr>` (keeps `td:nth-child` 4-column contract frozen: Occurred=1, Event=2, Actor=3, Outcome=4). | D-06, Pitfall 1/2 |
| Mobile-first stacking | Desktop reduces to human columns + inline disclosure; mobile keeps the canonical stacked `<.audit_row show_detail show_codes>` card; disclosed codes MUST render in the mobile expansion too. | D-07 |
| Byte-coherence | Shared desktop-table row, pagination `<nav>`, and empty-state become **public** function components in `components.ex` (two LiveViews must share — private-to-one won't do). Legitimate per-page divergence stays out: breadcrumbs / `return_to` / page header / 6-key vs 5-key `@chip_keys`. | D-08, D-09 |
| Honest pagination | `<nav>` present iff `multi_page?/1` true (≥26 rows at page_size 25), absent otherwise. Prove with a deterministic ExUnit test **and** a seeded capture (dev DB) — proof must not be screenshot-only. | D-10 |
| Theme/matrix | Award-grade across 320–1440px, light/dark/system, empty/loading/error/permission-denied/long-content, keyboard, reduced-motion. | AUDIT-03 |
