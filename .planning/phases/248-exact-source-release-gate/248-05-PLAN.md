GitHub documents that workflow_run executes workflow code from the default branch and sets its own GITHUB_SHA to the latest default-branch commit; the triggering run is available in the workflow_run payload. The source Release Please workflow supports push and workflow_dispatch on main, and Plan 03 constrains its privileged evaluation job to that default branch. The observer therefore uses the payload only to identify the source run, re-queries that run by ID, and validates the authoritative response's repository, workflow ID/name, run ID, event, head branch, conclusion, and head SHA against the allowed source identity before writing a receipt. Both push and workflow_dispatch cancellations are receipted with the validated source_event. It does not check out or download source-run artifacts. When present, the version is read as JSON from the source commit's release manifest, and its expected tag is checked against that exact source SHA; an absent or mismatched tag is diagnostic data on a cancelled receipt, never a success.
</context>
