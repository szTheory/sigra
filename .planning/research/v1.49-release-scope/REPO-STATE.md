## Prerequisites, gates, and automatic closure evidence

1. **Freeze scope and source selection.** Use the outgoing v1.48 state and documented milestone-switch workflow; keep the separate latest-stable resolver issue out of this release goal. Establish a reviewed, committed source on `main`; the current Phase 244 branch and mixed worktree are not that source.
2. **Resolve candidate content.** Review/land only approved diffs; confirm install constraints against the selected release line; make the generated release PR's changelog section complete. `CHANGELOG.md` warns that Release Please inserts the version section below `Unreleased`, so notes left in that block ship under the wrong heading unless folded while the PR is open (`CHANGELOG.md:12-22`).
3. **Require final-head CI and publication gates.** The workflow runs Release Please on main pushes/dispatch; upon release creation it waits for `ci-gate` on the exact release SHA, then publishes from the tag checkout (`release-please.yml:11-18, 85-101, 120-131, 147-180`). The publish lane itself checks manifest/tag/version consistency (`release-please.yml:179-200` onward). Do not accept a green overall run when a required job skipped; record exact job conclusions and output, plus action run URLs/IDs.
4. **Persist independently re-fetchable outcomes.** Capture release PR number/head/base, generated version, release SHA, tag object/target, GitHub Release URL, CI gate job conclusion for that SHA, publish job conclusion, and post-publication Hex API version/retirement/latest-stable fields. Verify package files and the HexDocs root for that exact version. Store the receipt/JSON as committed evidence; compare installed dependency resolution separately and state whether it resolves to 1.5.x or the still-higher 1.20.0. The release's required acceptance is a positive Hex version/package/docs observation, not merely workflow success.
5. **Automation-first closeout.** On a failed action, capture the failed job log and repair a deterministic defect once; use one CI watcher per run and retain the structured run summary. Commit the compact release receipt with milestone evidence so the proof outlives workflow-artifact retention. If the API/ranking result cannot satisfy the chosen resolver claim, preserve that as an explicit blocker and do not mark the requirement passed.

No tests or CI workflows were run or dispatched. GitHub and Hex were queried read-only to inspect the protected main ref, current CI/PR checks, open PRs, and package metadata.
