<objective>
Fix the CoreComponents.button/1 `type` attribute warning that quarantines vault_promotion_test.exs.

Root cause: The installer templates emit `<.button type="submit" ...>` and `<.button type="button" ...>` calls. The phx_new 1.8.7 CoreComponents.button/1 declares `attr :rest, :global, include: ~w(href navigate patch method download name value disabled)` — `type` is not in the allowlist. Under `--warnings-as-errors`, every `<.button type=...>` call is a fatal compile error.

Fix: Strip `type` from all `<.button>` component calls in installer templates:
- `type="submit"` → remove entirely (HTML `<button>` inside a form defaults to submit)
- `type="button"` → convert to raw `<button type="button" ...>` HTML element

Sync the same changes to the three mirror locations: test/example/, test/fixtures/install_golden/, and remove @moduletag known_failure from the test.

Purpose: Restore vault_promotion_test.exs to green so the known_failure quarantine can be lifted.
Output: 12 modified files (4 templates + 4 example mirrors + 4 golden fixture mirrors) + 1 test file.
</objective>

**Fix rule:**
- `<.button type="submit" ...>` → remove `type="submit"` entirely. HTML `<button>` elements inside a `<.form>` default to `type="submit"`, so behavior is unchanged.
- `<.button type="button" ...>` → convert to a raw HTML `<button type="button" ...>` element (self-closing tag becomes `</button>`), preserving all other attributes (class, phx-click, id, etc.).
