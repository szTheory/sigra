# Fix the passkey-primary duplicate email label + duplicate id (v1.46 audit W-1)

**Already diagnosed — do not re-investigate, do not re-litigate the approach.** This is finding
`W-1` in `.planning/v1.46-MILESTONE-AUDIT.md` (severity `high`, `status: fixed-in-closeout`,
requirements `AUTHUI-02` / `AUTHUI-04` / `PROOF-03`).

In `priv/templates/sigra.install/core/login_html.ex`, the `@passkey_primary_enabled` branch renders
a visible email input in the primary passkey form **and**, inside the collapsed
`<details class="sigra-auth-disclosure">` ("Other ways to sign in"), `password_form/1` — whose own
email input carries the identical visible label. Both forms bind `for={@form}`, so both derive the
same `id="user_email"`. Expanding the disclosure produces the duplicate-label collision the project
owner rejected during PROOF-03 visual review.

**The fix is decided** and mirrors the pattern already established by quick task `260727-v15`
(PR #113) on the sibling `<%% else %>` branch: *the top/primary form takes the qualified label; the
disclosed `password_form/1` keeps the plain wording.* Here the primary form additionally takes an
explicit `id`, because unlike the magic-link case the passkey action is JS-driven and must be
unambiguously addressable.

## Verified facts (re-confirmed against the tree — do not re-derive)

- **Target is template line 44**, inside the `<%%= if @passkey_primary_enabled do %>` branch that
  opens at line 34. Unambiguous anchor: the `<.form ... id="passkey_login_form" ...>` opening at
  line 35; its `<.input field={f[:email]} ... autocomplete="username webauthn" ...>` is line 44.
  It is the only `f[:email]` input in the file carrying `autocomplete="username webauthn"`.
- **Explicit `id` wins and stays label-associated.** Stock phx 1.8 `.input` declares
  `attr :id, :any, default: nil` and assigns `id: assigns.id || field.id`, then renders
  `<label for={@id}>`. Confirmed in `test/example/lib/example_web/components/core_components.ex`
  at `:160` (attr), `:189` (assign), and `:210` / `:238` / `:259` / `:280` (`<label for={@id}>`).
- **`name` is unaffected by passing `id`.** `.input` derives `name` separately via
  `assign_new(:name, fn -> field.name end)`, so it stays `user[email]`.
- **The passkey JS is `name`-scoped and form-scoped, not id-scoped.** `findEmailInput/2` at
  `priv/templates/sigra.install/passkeys/passkey_browser.js:114-127` prefers
  `form.dataset.emailInput`, then falls back to
  `form.querySelector("input[name='user[email]']:not([data-passkey-email-shadow])")`. The template
  sets no `data-email-input`, so the fallback is the live path — and it is `form.querySelector`,
  so the id change cannot affect it. `test/sigra/install/features/passkeys_js_test.exs:495-518`
  stubs that exact selector by **name**; zero references to `user_email` anywhere in the JS,
  the JS tests, or the Playwright specs.
- **No ExUnit test asserts this label.** `test/sigra/install/auth_ui_contract_test.exs` contains
  zero `Email`-label matches. `generator_passkey_primary_login_test.exs:21` asserts the *button*
  copy `Email me a sign-in link` — untouched.
- **No Playwright selector needs changing.** Four `getByLabel(…Email…)` call sites exist under
  `test/example/priv/playwright/tests/`:
  - `admin-generated.spec.ts:71` — scoped to `page.locator("#login_form")` (that is
    `password_form/1`, label unchanged) with `exact: true`. **Confirmed unaffected.**
  - `organizations.spec.ts:463`, `:464`, `ga-uat-shift-left.spec.ts:146` — all on the
    invitation-accept page, not the login page. Unrelated.
- **The golden fixture mirrors this region verbatim**, with the branch opening at its own line 34
  and the target input at its own line 44 (line numbers happen to coincide with the template here
  because the surrounding `<%= if passkeys? do %>` generator lines collapse to nothing — still
  anchor on `id="passkey_login_form"`, not the number). The golden tree does **not** commit
  `core_components.ex` (the installer does not modify it), so the stock phx_new 1.8.8 `.input`
  semantics verified above are the ones that apply.
- **No gettext catalog work.** The repo commits only `test/example/priv/gettext/errors.{pot,po}`;
  the `sigra` domain has no committed catalog, so a new msgid falls through to itself.
- Current counts in **both** files: `label={dgettext("sigra", "Email")}` → `2`
  (lines 44 and 111); `label={dgettext("sigra", "Email for sign-in link")}` → `2` (lines 68, 85).

## Out-of-scope observations (record only — do NOT plan or fix here)

1. **A residual duplicate-id cluster remains inside the disclosure, and it is pre-existing.**
   `@form` and `@magic_link_form` are both built with `as: "user"`
   (`session_controller.ex:28-29`), so *every* `f[:email]` in this template derives `id="user_email"`.
   In the passkey branch that is currently four inputs (lines 44, 68, 111, 136); after this fix it
   is three — the magic-link form (68), `password_form/1` (111), and `enterprise_form/1` (136), all
   inside the same `<details>`. Their **labels** are all distinct
   ("Email for sign-in link" / "Email" / "Work email"), so the W-1 label collision is fully closed,
   but a page-wide "no duplicate DOM ids" assertion would still fail. Do not write such an
   assertion, and do not extend the fix to those inputs. The same pre-existing cluster is present
   in the else branch and was likewise untouched by `260727-v15`.
2. **The example demo twin is a different composition.**
   `test/example/lib/example_web/controllers/session_html.ex` uses plain `label="Email"` at `:78`
   and `:148` with no gettext, and solves its own passkey-email problem with a hidden
   `data-passkey-email-shadow` input at `:112`. **Explicitly rejected as the approach here:** that
   works in the example because its visible login form is top-level, whereas the template's password
   form sits inside a collapsed `<details>` — pointing the primary passkey action at a hidden field
   inside a collapsed disclosure would be worse UX. Untouched.

Also explicitly untouched, per the hard scope boundary: the disclosure focus ring, button variants
and `--primary` / `--secondary` classes, `sigra_auth.css`, every other piece of auth copy, and every
