# Quick Task 260621-in8: Fix `scripts/uat/up.sh --dev` compile-env PORT mismatch

## Problem

`scripts/uat/up.sh --dev` (host-run / proxy-mode `none`) fails to boot the example
Phoenix app with a `validate_compile_env` error:

> the application :example has a different value set for key ExampleWeb.Endpoint
> during runtime compared to compile time … Compile time … port: 4011 …
> Runtime … port: 59626

**Root cause:** `test/example/lib/example/organizations.ex:45` reads
`Application.compile_env!(:example, ExampleWeb.Endpoint)[:secret_key_base]`, which
marks the entire `ExampleWeb.Endpoint` config — including the volatile
`http: [port: …]` — as a compile-time invariant Phoenix re-validates at boot. The
`none)` branch picks a **fresh random free port every run** (`find_free_port`), but
`setup_host_example` reuses the cached `_build` compiled at the project's documented
local port 4011 → compiled 4011 ≠ this run's random port → boot fails.

`ensure_port_free()` (up.sh:572-581) compounds this: if the chosen port is taken it
bumps to another random `find_free_port`, so even a stable default can land on a
random port at runtime. Hence the server invocations also need
`--no-validate-compile-env` so the dev server still boots on a port bump.

## Tasks

### Task 1: Stable host-run port + tolerate compile-env drift on the dev server

**Files:** `scripts/uat/up.sh`

**Action:**

1. In the `none)` branch (≈ line 762), change the port default from a per-run random
   free port to the reserved, documented local port **4011**:

   - From: `SIGRA_EXAMPLE_PORT="${SIGRA_EXAMPLE_PORT:-${PORT:-$(find_free_port)}}"`
   - To:   `SIGRA_EXAMPLE_PORT="${SIGRA_EXAMPLE_PORT:-${PORT:-4011}}"`

   Rationale: the endpoint port is compile-frozen, so it must be stable across runs
   to keep the cached `_build` valid. 4011 is this project's local convention (4000
   collides with Rulestead Docker). Explicit `SIGRA_EXAMPLE_PORT=`/`PORT=` overrides
   still win via the `:-` defaults. Do NOT touch the `shared)` or `private-traefik)`
   branches — they don't host-run.

2. Add `--no-validate-compile-env` to the three host-run server invocations so an
   explicit override or an `ensure_port_free` port-bump still boots cleanly (only
   `secret_key_base`, static in `config/dev.exs:42`, truly needs compile stability;
   the port is a runtime concern):

   - `start_host_server()` background launch (≈ line 565): `mix phx.server` →
     `mix phx.server --no-validate-compile-env`
   - `--attach` foreground exec (≈ line 827): `iex -S mix phx.server` →
     `iex -S mix phx.server --no-validate-compile-env`
   - The printed `SIGRA_UAT_SERVER_COMMAND` string (≈ line 815): the trailing
     `iex -S mix phx.server` → `iex -S mix phx.server --no-validate-compile-env`

**Verify:**
- `bash -n scripts/uat/up.sh` (syntax check passes)
- `grep -n 'PORT:-4011' scripts/uat/up.sh` shows exactly the `none)` branch line
- `grep -c -- '--no-validate-compile-env' scripts/uat/up.sh` returns `3`
- The `shared)` / `private-traefik)` branches still use `find_free_port` (unchanged)

**Done:** `scripts/uat/up.sh --dev` defaults to a stable port 4011 and the host-run
server invocations pass `--no-validate-compile-env`; `bash -n` is clean.

## Out of scope (do NOT do here)

Refactoring `use Sigra.Organizations` so `secret_key_base` lives in its own config
key (removing the volatile port from the compile-time invariant for all generated
