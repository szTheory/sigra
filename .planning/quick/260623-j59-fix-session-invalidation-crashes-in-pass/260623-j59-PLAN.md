<objective>
Fix session invalidation crashes in the password-change and account-deletion flows by threading `session_store_opts` (`:repo` + `:session_schema`) from `auth.ex` down into the account modules, mirroring the already-shipped email-change fix (commit c2ab16f1, quick task 260622-nft).

Purpose: Both `password_change.ex` and `deletion.ex` invalidate sessions by calling `session_store.delete_all_for_user/2` but pass only `except_token: ...` (or `[]`). The default Ecto store (`Sigra.SessionStores.Ecto.delete_all_for_user/2`) does `Keyword.fetch!(opts, :repo)` and reads `:session_schema`, so it RAISES the moment the real store runs. Only mock-based unit tests ever exercised these paths, so the bug shipped. This is the same root cause already fixed for email-change.

Output:
- `lib/sigra/auth.ex` — `change_password` and `schedule_deletion` thread `session_store` + `session_store_opts` via the existing `session_store_and_opts/2` helper (mirror `confirm_email_change`).
- `lib/sigra/account/password_change.ex` — `maybe_invalidate_sessions` forwards `Keyword.get(opts, :session_store_opts, [])` (+ `except_token`) to `delete_all_for_user`.
- `lib/sigra/account/deletion.ex` — `revoke_sessions` forwards `Keyword.get(opts, :session_store_opts, [])` to `delete_all_for_user`.
- `test/example/test/example/accounts/session_invalidation_test.exs` — integration regression coverage against the REAL Ecto store (fails pre-fix, passes post-fix).

Scope notes:
- LIBRARY-ONLY fix. `auth.ex`, `password_change.ex`, and `deletion.ex` are library files with NO installer-template (priv/templates) or golden-fixture copies — unlike `user_token.ex` in 260622-nft, these flows have no generated-code mirror, so there is nothing to byte-sync. Confirm this during execution (Task 1 done-criteria).
- `lib/sigra/account/email_change.ex` is ALREADY correct (the reference). Do NOT modify it.
</objective>
